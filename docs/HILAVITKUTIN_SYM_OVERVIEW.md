# hilavitkutin-sym, Design Overview

`#![no_std]`, no alloc. Depends on `arvo` for the `bitfield!` macro and
`Bool`, `arvo-bits` for `Bits<N>`, and `notko` for `Maybe`. Generic
interned-identity core for the hilavitkutin ecosystem.

An interned identity is a small handle that stands in for a value, cheap
to copy and compared by integer equality. The string interner in
`hilavitkutin-str` is one instance of the idea: a string is folded to a
4-byte handle, equal strings yield equal handles, and the handle resolves
back to the string. That handle, its integer-equality identity, and the
two ways a value acquires one are not about strings. They generalise to
any domain that wants stable cheap identities, so they live here and the
string concern sits above as one consumer.

A domain acquires a handle one of two ways. It deduplicates an existing
value into a stable handle, which is interning: equal values give equal
handles and the handle resolves back to the value. Or it mints a fresh
unique handle with no backing value, which is generation: each mint is
distinct from every prior one and there is nothing to resolve. Strings
intern. A compiler pass that needs a fresh identity for a bound variable
it introduces generates. The core serves both from one handle type,
distinguishing the modes at the type level so a producer cannot be built
for the wrong one.

The handle carries a domain tag so that identities from different domains
are never confused. Two handles with different tags are never equal
whatever their ids, because the tag is part of the compared bits. That
disjointness by tag is the property consumers rely on: a minted identity
provably never equals an interned-string identity, not by luck of the
ids, but because the two live in different domains of one core.

## `Sym`, the identity handle

```rust
#[repr(transparent)]
#[derive(Copy, Clone, Eq, PartialEq, Hash, Debug, Default)]
pub struct Sym(SymLayout);
```

A 4-byte handle, integer equality across the whole 32-bit layout, `Copy`,
`repr(transparent)`, ABI-stable. The layout is declared on `SymLayout`
via `arvo_bits::bitfield!`:

| Bits | Field | Meaning |
|---|---|---|
| 0 to 27 | `id` (28-bit) | 268M identities per domain |
| 28 to 30 | `kind` (3-bit) | the domain tag, eight domains |
| 31 | `flag` (1-bit) | a domain-private flag; the string domain uses it for the const-versus-runtime origin, a domain that does not need it leaves it zero |

`SymLayout` generates per-field accessors (`kind()`, `id()`, `flag()`),
setters, and per-field mask constants. `Sym` exposes `Sym::new(kind, id)`
(flag zero) and `Sym::with_flag(self, bit)` to build a handle, plus
`kind()`, `id()`, `flag()`, and `to_bits()` (the raw `Bits<32, Hot>` view
for tests and persistence). Two `Sym`s with different `kind` values are
never equal, whatever their ids or flags, because `kind` is part of the
compared layout, and that is what keeps domains disjoint.

## `SymKind`, the domain tag

```rust
#[repr(transparent)]
#[derive(Copy, Clone, Eq, PartialEq, Hash, Debug)]
pub struct SymKind(Bits<3, Hot>);
```

The 3-bit tag naming which domain a handle belongs to. `SymKind::new`
builds one from a raw value. Eight domains are available; the flag bit is
a per-domain extra orthogonal to the tag.

The kind-assignment table is a documented convention owned here so two
domains cannot claim one tag. The current assignments:

| Kind | Domain |
|---|---|
| `0b000` | string domain. Its const and runtime origins are the flag bit (const 0, runtime 1), so both are one domain, not two tags. The tag is fixed at `0b000` because it equals the old string layout's reserved-field value and the flag equals the old origin bit, which keeps every baked string handle byte-identical. |
| `0b001` | a minted-binder domain used by a downstream compiler consumer, defined in that consumer's crate, recorded here so nothing else claims the tag. |
| `0b010` to `0b111` | free for future domains. |

## `Domain`, `InterningDomain`, `GenerativeDomain`

```rust
pub trait Domain {
    const KIND: SymKind;
}

pub trait InterningDomain: Domain {
    type Value: ?Sized;
}

pub trait GenerativeDomain: Domain {}
```

A domain is a marker type carrying its `kind` as an associated constant.
It refines into one of two modes. An `InterningDomain` names the value it
deduplicates. A `GenerativeDomain` marks the mint-only mode and names no
value. The refinement is what the producers bind against, so the mode is
a type-level fact and the wrong producer for a domain is a type error.

## `Interner`, the dedup-and-resolve producer

```rust
pub trait Interner<D: InterningDomain> {
    fn intern(&self, value: &D::Value) -> Sym;
    fn resolve(&self, sym: Sym) -> Maybe<&D::Value>;
}
```

The trait for a producer that folds a value to a stable handle and
resolves it back. `intern` returns a `Sym` tagged `D::KIND`; equal values
give equal handles (a within-domain flag may still distinguish origins,
as strings do). `resolve` returns the value for a handle of this domain,
or `Maybe::Isnt` for a handle the producer does not know. The string
interner in `hilavitkutin-str` is the first implementation: `StringInterner`
implements `Interner` for the single string domain, with the const linker
section plus a host arena as its backing and the flag bit selecting which
side resolves a handle.

## `Generator`, the mint-only producer

```rust
pub struct Generator<D: GenerativeDomain> {
    // monotonic counter over the 28-bit id width, plus a domain marker
}
```

The concrete producer for a generative domain. It holds a monotonic
counter over the 28-bit id width and mints a fresh handle on demand:

```rust
// mint returns a fresh Sym tagged D::KIND, or Isnt at the 28-bit ceiling.
pub fn mint(&mut self) -> Maybe<Sym>;
```

Each `mint` yields a `Sym` distinct from every prior mint of the same
generator, tagged `D::KIND`. At the 28-bit boundary it returns
`Maybe::Isnt` rather than wrapping the counter and reissuing a live id,
so freshness is never silently violated. No allocation, no arena: a
generative domain needs only the counter and the kind.

## Why a monomorphic handle plus typed producers

The handle is monomorphic (`Sym`, not a phantom `Sym<D>` parameterised by
domain). A phantom-typed handle would type-check the intern and mint
edges, but every field that can hold either domain (a compiler binder
that is a source name or a minted name) must erase it to a common type,
so the phantom buys type-checking only at a few edges the runtime `kind`
and the typed producers already cover, at the cost of an erasure
boundary. The handle stays monomorphic for storage; `Interner` and
`Generator` carry the domain type for the safety that matters.

## Design rule

No alloc. No std. No ecosystem dependency: this crate sits directly on
`arvo`, `arvo-bits`, and `notko`, so any consumer can build on it without
pulling in the string machinery. String interning is one domain, supplied
by `hilavitkutin-str`; it is not privileged here.
