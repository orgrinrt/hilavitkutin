# DependencyGraph to arvo CsrBidirectional adapter

Phase C wires the plan stage's stubbed steps (RCM, block-diagonal, spectral) to
their real arvo implementations. Those arvo functions (`rcm_reorder_via`,
`block_diagonal_via`, the `SparseLaplacian` spectral path) consume
`arvo_sparse::CsrBidirectional<N: Cap, NNZ: Cap, W>`. The engine's
`DependencyGraph` is its own bespoke CSR (`row_offsets`/`col_indices`/
`edge_kinds`) keyed on the engine's `usize` const-params and `UnitId`. This
round (C1a) builds the adapter that all the later C steps consume; it is the
foundation, so it lands first and alone.

## Current state

`DependencyGraph<const MAX_UNITS: usize, const MAX_EDGES: usize>` (`plan/graph.rs:59`)
holds `row_offsets: [USize; MAX_UNITS]`, `col_indices: [UnitId; MAX_EDGES]`,
`edge_kinds: [EdgeKind; MAX_EDGES]`, plus `unit_count` / `edge_count`. No
conversion to the arvo CSR exists. arvo ships `Csr<ROWS: Cap, NNZ: Cap, W: Copy>`
with public fields and `.with_transpose() -> CsrBidirectional`. `EdgeKind` is
`Copy`. `NodeId::new(USize)` builds an arvo node id. The `usize` to `Cap`
const-param bridge needs `arvo_tensor::cap` (merged arvo PR #68); the literal
`Cap(USize(n))` is rejected in const-generic position, the `const fn` form is
accepted (sketch `mock/research/sketches/202605290245_usize-to-cap-const-bridge.md`).

## Changes proposed

Add `arvo-tensor` to the workspace + engine Cargo deps (the engine does not yet
depend on it; `cap` and `cap_size` live there). Add
`DependencyGraph::to_csr_bidirectional(&self) -> CsrBidirectional<{cap(MAX_UNITS)},
{cap(MAX_EDGES)}, EdgeKind>`: allocate a `Csr` (arrays sized by
`cap_size(cap(MAX_UNITS))` / `cap_size(cap(MAX_EDGES))`, which equal MAX_UNITS /
MAX_EDGES), copy `row_offsets` into `row_ptr` within `unit_count`, copy each
`col_indices[e]` into `col_idx` as `NodeId::new(uid.index())` and `edge_kinds[e]`
into `values` within `edge_count`, then `.with_transpose()`. Carry the
`[(); cap_size(cap(MAX_UNITS))]:` / `[(); cap_size(cap(MAX_EDGES))]:` where-bounds.

Test: build a small known DAG, adapt it, assert per-row `nnz` / `row_col_indices`
/ `row_values` match the source edges, and the transpose carries the reverse
adjacency. This is the only behaviour C1a adds; C1b-C1d consume the adapter.
