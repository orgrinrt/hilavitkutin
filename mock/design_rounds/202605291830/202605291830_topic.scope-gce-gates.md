**Scope:** #626 (hilavitkutin side) scope `generic_const_exprs` gates

`generic_const_exprs` is a WATCH feature (kept per the 2026-05-29 design talk: GCE's only known
hole #97156 is const-`TypeId` into HRTB-subtyping types, which the stack never touches since
`TypeId` is banned; arvo's usage is the incomplete-implementation band, not unsound-by-design).
The disposition is: keep it where used, scope it out of crates that do not use it, and put a
`// SAFETY:`-style justification above each retained gate.

hilavitkutin gates GCE in two crate roots: `hilavitkutin-api/src/lib.rs:16` and
`hilavitkutin-str/src/lib.rs:10`. A source scan finds no GCE-requiring construct in either
crate (no `cap_size`, no `[T; <expr>]` array-length arithmetic, no `where [(); N]:` bound). GCE
does not propagate through dependencies, so consuming arvo types (which use GCE internally) does
not require the gate here. The likely outcome is that both gates are unused and removable.

This round confirms empirically (remove each gate, `cargo +nightly-2026-05-28 check --workspace`
+ full test): remove the gate from any crate that compiles clean without it; if a crate does
need it, restore the gate and add the soundness-justification comment above it. The arvo side of
#626 (12 gates) is a separate round in the arvo repo.
