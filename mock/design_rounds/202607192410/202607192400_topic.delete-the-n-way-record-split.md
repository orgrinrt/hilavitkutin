# Topic: delete the N-way record split

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `scheduler/mod.rs:2106-2136`, the single-trunk branch of `run_core_phase`.
**Grounded on:** consolidation spec `:770-771` and `:1840-1841`; roadmap r7 band 1 item R1; sketch
`mock/research/sketches/202607192200_r1-participation-without-record-slices/`.

The branch splits a single-trunk phase's records N ways, one ceil-sized slice per core, all cores
walking the same direction, with no commutativity gate. Canon specifies two threads from opposite
ends of a commutative fiber: "Single-trunk phases: head+tail convergence (2 threads, opposite ends,
~2x parallelism). Skip for non-commutative resource accumulation" (`:770-771`), and "Within any
commutative fiber, records are independent. Two threads process from opposite ends, converging in
the middle" (`:1840-1841`).

The branch also opens with the comment "Head+tail convergence (spec :770)", citing the line it
violates. The design prose repeated the same conflation until round `202607192100` corrected it, so
the docs already describe the state this round produces.

## What removing it costs

Single-trunk phases run serially until W1 builds head+tail. That is a real loss on exactly the
phases that most want parallelism, and it is still right: canon's parallelism comes from trunks, and
a single-trunk phase legitimately has none until the mechanism canon specifies exists. Keeping a
non-canonical mechanism because it beats nothing is how this became load-bearing.

## What it does not cost, established by experiment

An earlier pass in this arc concluded the deletion would strand trunks, on the grounds that
`run_this` (`:966`) gates participation by record slice while dispatch ownership is by trunk rank.
That was wrong. `run_this` is inside `worker_accum_unit_outer` (begins `:933`), which handles
accumulator-bearing carriers; those `continue` at `:873` and never reach `run_core_phase`. The
non-accumulator path calls `run_core_phase` unconditionally for every core on every phase and states
the invariant at `:913`: "every worker participates in each waist, even one that owned no trunk this
phase".

Two green regression tests hold the line either way:
`gate2_run_parallel.rs::every_producer_runs_when_cores_outnumber_records` and
`gate2_accumulator.rs::accumulator_in_a_two_trunk_phase_matches_single_core`.

## The A4 carve-out goes with it

The ordinary trunk-rank branch carries a comment explaining that the single-trunk branch keeps the
scalar morsel window because it dispatches a whole-phase mask rather than one fiber. With the branch
gone the carve-out describes nothing.

## Out of scope

Building head+tail (band W1). The accumulator region layout, which is canonical, separately reached,
and unaffected.
