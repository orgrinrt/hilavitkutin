## CHANGE: replace_resource and replace_value say what they do
Files: `mock/crates/hilavitkutin/src/scheduler/dirty.rs`.
Both methods call `mark_dirty` and discard the value. Their rustdoc said the value was installed and, for `replace_resource`, that the plan was recomputed. The docs now say the call marks the store changed for the next frame and installs nothing, and each body carries `FIXME(147e3897011f)` naming the missing data-plane install (and, for `replace_resource`, the plan recompute).
Verification: `grep -rn "FIXME(147e3897011f)" mock/crates` returns two matches, one per method. `CARGO_INCREMENTAL=0 cargo test -p hilavitkutin -p hilavitkutin-api` passes.

## CHANGE: the unmapped_unit_fused pair isolates its token
Files: `mock/crates/hilavitkutin/tests/ui/unmapped_unit_fused_{fail,pass}.rs`, `tests/ui/unmapped_unit_fused_fail.stderr`.
The failing file registered only an accumulator, so the fused chain had no column to bind and the diagnostic carried a second, unrelated error. Both files now register `Column<Xa>`, `Column<Ya>` and `Accum<Av>`, and both call `run_fused`. The twin adds one `impl RecordOp for LogOnlyWu` block and nothing else (apart from its header comment), and compiles. The committed diagnostic holds one error, the missing per-record map. The files were formatted first, then blessed with `TRYBUILD=overwrite`, then read.
Verification: `CARGO_INCREMENTAL=0 cargo test -p hilavitkutin --test ui` passes, three pairs. `grep -c "^error" tests/ui/unmapped_unit_fused_fail.stderr` returns 1.

## CHANGE: the run_fused append test asserts the outcome
Files: `mock/crates/hilavitkutin/tests/fused_append.rs`.
The ignored test discarded the `run_fused` result with `let _ =`. It asserts `Outcome::Ok(())` as its `run` twin does, so a failure of the entry itself cannot read as the missing append. The header now names the missing per-frame accumulator reset.
Verification: `cargo test -p hilavitkutin --test fused_append -- --include-ignored` shows `run_appends_one_value_per_record_each_frame` passing and the ignored test failing with `left: USize(0)`, `right: USize(2)` at frame 0; without the flag it is reported ignored.

## CHANGE: the catalogue row names the missing reset

`run.rs` and `run_parallel.rs` call `reset_accumulators` at frame start and `run_fused.rs` does not. The row and the ignore reason say the fused entry needs to refuse the carrier, or run the body and reset. Ticket `0fb716c5a463` is bumped with the same finding.
