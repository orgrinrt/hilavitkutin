# Topic: A2b dispatch loop inversion (fiber-outer/morsel-inner run)

**Date:** 2026-07-16
**Phase:** TOPIC
**Scope:** `hilavitkutin` engine: `Scheduler::run` dispatch loop, `FiberDispatch` docs, asm-gate fixtures
**Source:** blueprint `mock/research/202606201400_per-fiber-morsel-blueprint.md` slice 3, sketch `mock/research/sketches/202606202100_a2a-per-fiber-morsel-loop/FINDINGS.md`, roadmap `mock/research/202606201900_granular-roadmap-and-sketch-plan.md` (A2b)

## Problem

`Scheduler::run`'s record-bearing path is morsel-outer-SHARED: it windows
`[0, total)` by the uniform `Cfg::MORSEL_SIZE` and calls `dispatch_trunks`
once per window, so every fiber in every phase sees the same window. The
canonical shape (spec domain 12, "multiple morsels per fiber") is
fiber-outer/morsel-inner: each fiber walks its OWN window sequence over
`[0, total)` before the next fiber, keeping that fiber's co-located columns
L1-hot for its whole window run. The per-fiber window is already computed
(A3b: `FiberDispatch.morsel_size` carries the real domain-12 L1 window) but
the loop does not consume it. This is the load-bearing structural slice the
blueprint names S3, and the surface the adapt re-chunk actuation needs live.

## Settled shape (from the A2a sketch + run_parallel parity)

The A2a sketch proved the windowed per-trunk dispatch preserves const-DCE and
devirtualisation (`MorselRange` is a runtime argument no DCE site reads), and
surfaced two constraints the implementation must honour:

1. **Member selector is `fiber_mask & dirty`, not an overload of `dirty`.**
   Fiber membership and incremental skip are orthogonal masks; both live in
   the carrier-position index space (`build` validates registration order is
   topological, and `topo_order` holds unit indices, so a mask built from
   `topo_order[desc.start .. desc.start + desc.len]` composes directly with
   `dirty_units()`).
2. **Meta lifecycle ordering cannot ride descriptor order.** The
   `fiber_dispatch` descriptors are in runtime-plan phase order; the meta
   lifecycle bands (PlanStage < ScheduleReady < PassStart < consumer <
   ScheduleEnd) are ordered by the const grouping's rank-outer phase axis.
   A meta fiber's runtime-plan phase is unconstrained (meta units carry no
   store deps), so a descriptor-ordered walk could dispatch a ScheduleEnd
   unit before consumer work. `run_parallel` already solved this: the meta
   bands dispatch once per frame around the consumer work, and the consumer
   walk is gated to `consumer_mask`. The single-core inversion mirrors it.

The resulting `run` structure is phase-outer over the const phase axis
(exactly `dispatch_trunks`' loop, so band skipping, `On<V>` gating via the
trunk walk, and per-phase timing all keep their home), with the consumer
passes fiber-factored:

1. Phase pass `p` in the meta bands (`p < pre_consumer_phase_count` or
   `p >= consumer_phase_end`): one whole-range, all-ones dispatch per frame
   (not per window). This matches `run_parallel`'s designated-thread band
   dispatch; the plan band is skipped on clean frames as before.
2. Phase pass `p` in the consumer band: walk the fiber descriptors in order.
   Per descriptor, members = `fiber_mask & consumer_mask` (`& dirty` when the
   fiber is `morsel_local` and the frame has records). A fiber whose units
   sit in a different phase contributes nothing in pass `p` (its members lie
   in trunks whose roots' `PhaseAt != p`), so the const phase gate performs
   the fiber-to-phase filtering with no runtime phase map. A `morsel_local`
   fiber windows `[0, total)` by `desc.morsel_size` (fallback
   `Cfg::MORSEL_SIZE` when zero); an accumulator fiber (or a record-less
   frame) dispatches once over the whole range with no dirty gating (the
   per-frame append path is never skipped).

Ordering argument: phases run strictly in const order (barrier semantics
unchanged); within a phase, descriptors are walked in plan order and each
completes its full window sequence before the next, so a producer fiber's
whole range lands before a consumer fiber starts (stronger than the old
per-window interleave); within one (fiber, window) dispatch the carrier walk
is topological. Output-equivalence to the old shape follows from domain-16
(a clean unit skipped produces identical output) plus record-independence of
the morsel split (proven by `tests/morsel_outer.rs`: `ctx.each()` iterates
exactly the passed range).

## Behaviour deltas (intended, canonical-correcting)

- **Per-fiber windows are live.** Dispatch-call counts change from
  `ceil(total/MORSEL_SIZE)` uniform to `ceil(total/window_f)` per fiber.
- **Meta bands run once per frame**, not once per window. The old shape ran
  every dirty meta unit per window on multi-window frames; the self-hosting
  kernel design (E4) has the bands as per-pass lifecycle hooks.
- **Mixed carriers keep incremental skip.** The old global either/or (any
  accumulator fiber forced the whole frame unit-outer with an all-ones mask)
  becomes per-fiber: accumulator fibers always run whole-range; morsel_local
  fibers keep the dirty gate. Domain-16 output-equivalence holds; execution
  counts on mixed carriers change.
- **Per-phase timing is per frame.** `phase_accum[p]` folds one start/stop
  pair per phase per frame (previously per window). Scripted-clock tests
  that count `now_ns` reads rehab to the new counts.

## Fiber-mask realisation

Per-frame, before the phase loop, one pass over the descriptors builds each
fiber's member mask (`D::AdjRow` bits at `topo_order[start..start+len]`) into
a `<D::Fibers as Capacity>::Array<D::AdjRow>` on the stack. O(unit count)
bit-sets per frame total. Baking the masks into build-time state is a later
refinement (schedule-once-reuse would prefer it; the per-frame cost is one
pass over the unit list and the descriptor array is not generic over
`D::AdjRow` today), marked at the site.

## Re-walk cost (accepted, marked)

Each (phase, fiber, window) dispatch walks the whole carrier with the member
mask; fibers outside pass `p` still pay window-loop walks of bit tests. The
sketch's preferred direct-per-fiber-entry needs a fiber-to-const-phase map
that does not exist yet; the walk overhead is compile-time-folded branches
plus bit tests (never per-record cost), so the per-record body and the asm
contract are unaffected. Marked `FIXME` at the site, tracked #340.

## ASM-emission contract fixtures (first under the generalized discipline)

Two fixtures land in `mock/benches/asm_gate_fixtures` and the gate binary's
symbol list:

1. `asm_gate_windowed_fibers`: a two-pipeline (two-fiber) column chain
   dispatched through the inverted `run()`; gate check 1 (zero indirect call)
   hard-gates that the fiber-outer loop did not reintroduce a stored function
   pointer.
2. `asm_gate_resource_snapshot`: a column chain whose hot unit also reads a
   `Resource` scalar each record through the by-value ctx snapshot (PR #165);
   check 1 hard-gates, and the report surfaces checks 2-5 (stack spill /
   addressing) as the register-promotion evidence owed from the storage
   round. A dedicated zero-resource-memory-ops check needs loop-body
   segmentation in the disasm helper; deferred, tracked #340.

## Acceptance tests

- Blueprint S3 count test: two disjoint pipelines with distinct L1 windows
  (custom `RunCfg` budget), assert per-fiber execute-call counts
  `ceil(total/w_a)` and `ceil(total/w_b)`.
- Sketch dispatch-order test: per-execute morsel lengths follow each fiber's
  own window sequence (fiber A fully before fiber B within a phase).
- Meta parity: existing `gate2_meta_*` suites stay green (bands once per
  frame).
- Mixed-carrier skip: accumulator fiber runs on a clean frame while a clean
  morsel_local fiber is skipped.
