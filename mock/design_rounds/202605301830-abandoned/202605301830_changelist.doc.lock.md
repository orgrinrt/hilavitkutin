# Doc changelist: plan-derived topological dispatch tier

**Round:** 202605301830
**Phase:** DOC
**Scope:** Revise the engine `DESIGN.md.tmpl` dispatch-codegen and scheduler-run prose to describe topological dispatch over the retained WorkUnit instances. The slice-2 prose names registration-list order as the current behaviour and topological order as "the plan-driven slice"; this round is that slice. New backtick-named surfaces (`FiberSlot`, `CollectFiber`) are introduced into the document so the shipping contract and the source land aligned.

## Why a doc-surface change

The dispatch-codegen section of `crates/hilavitkutin/DESIGN.md.tmpl` documents `RunFiber` as the pre-codegen sequential walk and states that `Scheduler::run` walks the retained units in registration-list order, naming dependency-topological order as a later slice. This round makes the walk follow the execution plan's topological permutation. A heterogeneous typed unit list cannot be indexed by a runtime position, so the walk needs type erasure: the typed `WuCons` list walks once into a uniform slot array of `(erased instance pointer, monomorphised shim)` pairs, then the array is walked in the plan's permutation. Because `DESIGN.md.tmpl` is the shipping contract and the `design-doc-source-mismatch` lint expects every backtick-named type in it to exist in source, the new `FiberSlot` and `CollectFiber` surfaces are named in the document. The source changes are recorded in this round's src changelist under the structured `## CHANGE:` grammar.

## CHANGE: dispatch-codegen run-order prose FROM registration-list order TO topological order
File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`
Revise the paragraph describing `Scheduler::run`'s walk order (the slice-2 text that says the walk is registration-list order and names topological order as the plan-driven slice). The revised prose states: the execution plan's topological permutation is computed at `build()` time, where the registered bundle and store access set are in scope; `run()` walks a uniform slot array in that order. Note that the RCM renumber (`rcm_order`) stays an arena-layout concern, distinct from the dispatch order in `unit_meta`.
Verification: `grep -i "topological" mock/crates/hilavitkutin/DESIGN.md.tmpl` returns a match in the dispatch-codegen section referencing `Scheduler::run`.

## CHANGE: dispatch-codegen section GAINS a fiber-codegen erasure tier description
File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`
Add prose naming the `dispatch::fiber_codegen` tier: `FiberSlot` (the erased dispatch slot pairing an instance pointer with a monomorphised shim), and `CollectFiber` (walks the value-carrying `WuCons` / `WuNil` unit list emitting one slot per unit, with the per-unit bound matching the slice-1 `RunFiber` resource-only boundary). Frame it as the generics-level dispatch core for non-registration order, the type-erasure counterpart of `RunFiber`, distinct from the deferred per-fiber-shape `run_fiber<S: FiberShape>` LLVM-emitted path. Each slot's shim casts the erased pointer back to its concrete WorkUnit type, projects that unit's resource-only `EngineCtx`, and runs `execute`.
Verification: `grep "CollectFiber" mock/crates/hilavitkutin/DESIGN.md.tmpl` and `grep "FiberSlot" mock/crates/hilavitkutin/DESIGN.md.tmpl` each return a match.

## Notes

The dispatch order is topological; the plan dimensions are the scheduler's `D: PlanDims` (default `DefaultPlanDims`, the #652 bundle). The stored permutation is `<D::Units as Capacity>::Array<USize>`, which keeps the array length out of generic-const-expr position (GCE-free, the #652 unblock). Single-fiber resource-only scope matches slice 2; multi-fiber / per-core / morsel-loop layering is the C5 morsel loop (#343).
