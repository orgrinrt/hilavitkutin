# Topic

`Scheduler::run` currently walks the registered WorkUnits in registration-list order (slice 2, #646, merged): the typed `WuCons` value-list is walked by the slice-1 `RunFiber` recursion, which is type-positional. Correct pipelines need TOPOLOGICAL order: a unit that writes `Column<Nam>` must run before its readers. `compute_execution_plan` produces that order as a RUNTIME permutation over unit indices (`unit_meta[u].id = topo[u]`). A heterogeneous typed cons-list cannot be indexed by a runtime `usize`, so any non-registration order needs type ERASURE into a uniform, runtime-orderable form.

This round makes `run` dispatch in the plan's topological order via the proven erasure mechanism.

## The mechanism (proven, sketch 202605301032)

Walk the typed `WuCons` value-list ONCE into a uniform array of `(erased instance pointer, monomorphised shim)` slots, then walk that array in the plan's topological permutation. Each shim casts the erased `*const ()` back to its concrete WorkUnit type, projects that unit's own per-type `EngineCtx`, and runs `execute`. A bare monomorphised `fn(&Ctx)` pointer cannot carry a WorkUnit's `.with()`-time RUNTIME config (monomorphisation specialises over types, not values), so the slot pairs the per-type shim with a pointer to the retained instance (slice 2 already keeps the instances on the scheduler's `WuVals` list).

The sketch `mock/research/sketches/202605301032_topo-erased-shim-array/` (FINDINGS: WORKS) confirmed under nightly-2026-05-28: a heterogeneous typed cons-list walks into a uniform `(*const (), fn(*const (), &Frame))` array via a recursive `Collect` trait (pure generics, no `dyn`, no `TypeId`); the per-WU shim casts the erased pointer back, projects that unit's Ctx, runs execute; runtime instance config round-trips through the erased pointer; an arbitrary runtime permutation drives dispatch order. The mechanism is pure generics plus one `unsafe` back-cast per shim, no GCE / specialization / trait-solver exotica.

## Why this needed #652 first (the unblock)

The slice-3 build computes the topological permutation at `build()` time, where the registered `Wus` bundle and `Stores` access set are in scope, by calling the plan functions (`plan_inputs_from_bundle` then `compute_execution_plan`). The pre-convention attempt (sketch 202605301058, parked round 202605301058) FAILED here: `build()` is generic over `Wus`/`Stores`, and calling `compute_execution_plan::<const ENGINE_MAX_UNITS: Cap, ...>(..)` with named `Cap` module consts as const-generic arguments produced `error: unconstrained generic constant` (31 sites). A named `Cap` const whose value is `cap(16)` is an abstract const expression in a generic context; rustc's generic-const-exprs cannot use it as a const-generic argument there.

The capacity-as-type migration (#652, merged) dissolves this. `compute_execution_plan<D: PlanDims>` now takes a TYPE parameter; the `Scheduler` already carries `D: PlanDims = DefaultPlanDims`. The generic `build()` calls `compute_execution_plan::<D>(..)` with the scheduler's own `D` type, never a named `Cap` const, so there is no const-argument to leave unconstrained and no GCE evaluation. The slice-3 build()-side plan computation that the parked round could not compile now compiles cleanly. The stored permutation array becomes `<D::Units as Capacity>::Array<USize>` (GCE-free), not `[USize; cap_size(ENGINE_MAX_UNITS)]`.

## Build (reworked onto the merged PlanDims convention)

The build follows the parked C2 src CL with the named-`Cap`-const surface replaced by the scheduler's `D: PlanDims`:

1. New `dispatch/fiber_codegen.rs`: `FiberSlot<A> = (*const (), fn(*const (), &A, MorselRange))` (the erased dispatch slot); `fiber_shim::<A, W, RIdx>` casts the erased pointer back to `&W`, projects that unit's resource-only `EngineCtx` via the slice-1 `EngineCtx::project`, runs `invoke_wu_in_fiber`; `CollectFiber<A, Witnesses>` walks the `WuCons` / `WuNil` value-list emitting one slot per unit into a caller-provided `&mut [FiberSlot<A>]`, with the per-unit bound matching the slice-1 `RunFiber` impl exactly (the `for<'f>` `Ctx` GAT equality plus the two `ColPtrNil` column-projection bounds encoding the resource-only boundary).
2. `dispatch/mod.rs` re-exports `CollectFiber` / `FiberSlot`.
3. `Scheduler` gains `topo_order: <D::Units as Capacity>::Array<USize>` (the stored permutation: `topo_order[step]` is the list position of the unit dispatched at topological step `step`) and `topo_count: USize`. Plain index data, no borrows, movable with the scheduler.
4. `BuildError` gains `PlanFailed` (additive; the enum is `#[non_exhaustive]`); `compute_execution_plan` returns `Err` on a dependency cycle, mapped to `PlanFailed`.
5. `SchedulerBuilder::build` / `build_with` gain a `BWit` witness generic (inferred at the call site like `run`'s `Witnesses`) and the `Wus: BundleProject<Stores, BWit, D>`-shaped bound; each projects the bundle into `PlanInputs`, runs `compute_execution_plan::<D>`, reads the permutation off `unit_meta[u].id.index()` into `topo_order`, sets `topo_count = unit_count`. Store-arena drain and `MemoryProvider` handling unchanged.
6. `Scheduler::run` walks the slot array (built each run from the retained `WuVals`, since a stored instance pointer would be self-referential) in `topo_order[0..topo_count]` order via `CollectFiber`, replacing the slice-2 registration-order `RunFiber` walk. Instance-pointer validity is tied to the scheduler-owned `WuVals` field for the duration of the walk; `// SAFETY:` on each back-cast.

## Scope and deferrals

Single-fiber, resource-only, matching slice 2's boundary (the `ColPtrNil` column-projection bounds; real column buffers are the deferred B2b). Multi-fiber / per-core / morsel-loop layering is the C5 morsel loop (#343); the architect noted Shape X generalises (each fiber gets its own ordered slot slice). The slot array is the const-sized `<D::Units as Capacity>::Array<FiberSlot<A>>` (or built into a `D::Units`-sized buffer), no `Vec`. The plan-dimension budget is the scheduler's `D` (default `DefaultPlanDims`); the per-`Cfg` budget lift waits on rustc field access on generic constants (#345 / #641).
