## What this round fixes

The root `README.md` paragraph on `hilavitkutin-providers` (`:173`) says the crate ships the interner alone and that a memory provider and the column store are future work. It ships `ArenaColumnStorage`, `StaticBumpMemory` and the adapt kits. The paragraph is rewritten for what ships and `cargo mock` regenerates `docs/`, which has not run since before the branch.

The api design states the memory provider twice: as `pub unsafe trait MemoryProviderApi` in its own section (`hilavitkutin-api/DESIGN.md.tmpl:855`) and as `pub trait MemoryProvider: Send + Sync` in "Platform traits (domain 02)" (`:1589`), beside a `ThreadPool` and a `Clock` in their older shapes too. The class is a restatement of the platform contracts that did not move with them. The block is rewritten to the three traits as `src/platform.rs` declares them, with the unsafe trait's promises left to the section that carries them. No other `*.md.tmpl` states any of the three traits.

The differential at every worker count (`tests/run_parallel_skip_differential.rs`) runs a four-unit fixture whose units form at most two trunk roots in a phase, over four records, which is one window, with records and no accumulator. Ownership is `rank % ncores`, so at two roots the counts 2, 3, 4 and `MAX_CORES` place every unit alike, and neither the record-less walk (`scheduler/worker.rs:427-448`) nor the accumulator unit-outer walk (`worker.rs:124`) is entered. Its doc comment says the counts place the units differently, which is false for that fixture. The ignore strings it carries ask for the mask on both worker paths, so job 5 could turn it green with the record-less walk still ungated. A wider fixture is added beside it, not in place of it: six independent producers in the first phase, which is six trunk roots, a consumer two hops down the first producer's cone, and more records than the widest window the plan bakes, shown by the first frame running every producer more than once. The same fixture is built a second time with no records, which is the record-less walk, and a third time with an accumulator writer, which puts the whole frame on the unit-outer walk. Each runs the history through `run` and through `run_parallel` at 1, 2, 3, 4 and `MAX_CORES`.

The executed set becomes exact counts. `ran_since` is a yes or no per unit (`tests/skip_chain/mod.rs:143-146`), so a unit dispatched twice is invisible under idempotent writes. The wide differential holds the count of each unit in each frame under `run_parallel` to the count `run` gives in the same frame, times the cores that walk it: one on the windowed and record-less walks, where a trunk has one owner, and on the unit-outer walk the cores whose slice of the N-way tiling is not empty, as `accum_slice` tiles it (`resource/bindings/per_core.rs:116-123`). `run` itself is held to the cone of each step, exactly.

The accumulator writer is not held to the cone. What a skipped accumulator writer does is asked of op as `does_a_skipped_accumulator_writer_run_anyway_in_hilavitkutin`, and the plan (`PLAN.md:107`) has the build keep what the code does and the differential assert the same accumulator contents whether a unit ran or rested, which either answer must keep. That is what the accumulator variant asserts: the skipping run's accumulator holds the every-store-dirty run's records, in the same order, every frame.

The threaded provider test (`hilavitkutin-providers/tests/static_bump_memory.rs`) checks only that blocks do not overlap. A retried block whose padding was computed before the retry would be disjoint and misaligned and pass. It moves to a skewed buffer and asserts every block's alignment and bounds.

The panic tests (`tests/unit_panic_aborts.rs`) carry `child_runs_the_panicking_frame`, which passes in the parent run and asserts nothing, and they null the child's stderr, so an abort from any other cause passes. Each test now re-runs its own binary on itself (`--exact` with its own name) with the environment variable marking the child, so no test is a child entry alone, and the parent asserts the child's stderr carries the unit's panic message and the runtime's `panic in a function that cannot unwind`.

The benches build `StaticBumpMemory` over a `&'static mut` made from a box their `Drop` frees (`mock/benches/engine_vs_std/src/lib.rs:141-145`, the same in `resource_storage/axis_ce`, `variants/rcm_common` and `frame_wide/support/frame-wide-support`). The trait's promise 2 lets a block die with the provider, so no block outlives its memory, but the provider's own argument says the buffer is never released, and the caller made the lifetime up. `StaticBumpMemory` gains `from_raw_parts`, an `unsafe` constructor over a pointer and a length whose contract is the caller's: the bytes are valid, nobody else reaches them, and they stay so until the provider is dropped. `new` is the safe case of it. The benches use it and say why their `Drop` keeps the contract. The provider's safety comment for promise 2 is restated over the two constructors.

The doc comment on `execute_without_unwinding` (`dispatch/wu_fn.rs`) says the boundary costs nothing under `panic = "abort"` and one cold landing pad under unwinding. No assembly or bench is committed, so the claim is dropped.
