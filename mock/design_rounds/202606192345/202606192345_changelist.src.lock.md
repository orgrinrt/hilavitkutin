**Date:** 2026-06-19
**Phase:** SRC

## CHANGE: `Scheduler` gains field `phase_accum: [Cell<Nanos>; GATE2_MAX_UNITS]`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep "phase_accum: \[Cell<Nanos>; GATE2_MAX_UNITS\]" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match; initialised at the three constructor sites.

Per-frame per-phase duration accumulator (raw nanos). `dispatch_trunks` sums each
morsel's phase-slice duration here; `run` folds the per-frame total into
`phase_ema` once per frame, then zeroes it.

## CHANGE: `dispatch_trunks` accumulates per-phase duration instead of folding
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (the per-phase dispatch loop)
Verification: `grep -n "phase_accum\[p\]" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns at least one match; the in-loop `fold_ema` into `phase_ema` is gone from `dispatch_trunks`.

Adds the morsel's phase-slice duration into `phase_accum[p]` (saturating), no
seed read. Because `dispatch_trunks` runs once per morsel, this sums across the
frame's morsels rather than folding per morsel.

## CHANGE: `run` folds the per-frame phase totals into `phase_ema`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (beside the pass-duration EMA fold)
Verification: `grep -n "phase_ema\[pe\]" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns at least one match.

After the morsel loop, at the existing pass-duration EMA fold point, fold each
phase's per-frame total (`phase_accum[p]`) into `phase_ema[p]` with the same
`ema_seed`, then zero `phase_accum[p]`. Bounded by the phase count. This makes
the EMA per-frame, matching the DESIGN.

## CHANGE: `tests/r7_phase_ema.rs` gains multi-morsel + single-phase cases
File: `mock/crates/hilavitkutin/tests/r7_phase_ema.rs`
Verification: `cargo test -p hilavitkutin --test r7_phase_ema` passes.

- `multi_morsel_folds_per_frame_total`: a frame with `total > MORSEL_SIZE`
  records each phase's per-frame total, not a single morsel's slice.
- `single_phase_only_slot_zero`: a single-phase carrier touches only
  `phase_ema[0]`; a higher slot stays zero (restores the prior CL's named case).

## CHANGE: `tests/gate2_adapt_ema.rs` script extended for the per-phase clock reads
File: `mock/crates/hilavitkutin/tests/gate2_adapt_ema.rs`
Verification: `cargo test -p hilavitkutin --test gate2_adapt_ema` passes.

Per-phase timing samples `self.clock` inside `dispatch_trunks` (2 reads per
phase), so the scripted pass-duration EMA test now sees 6 clock reads per frame
(frame_start + 2 x nphases + frame_end) instead of 2. The `single_core` script
is extended to 18 values (6 per frame) with the SAME per-frame durations
(300 / 700 / 700), so the existing `0 / 300 / 350` EMA assertions are unchanged;
only the clock-read budget grows. The parallel test is unaffected (run_parallel
does not call dispatch_trunks).
