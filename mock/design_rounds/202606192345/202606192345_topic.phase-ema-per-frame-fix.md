# Topic: per-phase EMA per-frame fold fix (post-review)

**Date:** 2026-06-19
**Phase:** TOPIC
**Scope:** `hilavitkutin` engine (`dispatch_trunks` + `run` per-phase EMA fold)
**Source topics:** PR #147 review finding 1

## Current state

The per-phase EMA just landed (round 202606192301) folds the phase duration
into `phase_ema[p]` INSIDE `dispatch_trunks`. But `dispatch_trunks` is called
once per MORSEL window on the morsel-outer path (the common record-bearing
case), so the fold runs per (phase, morsel), not per frame. On a multi-morsel
frame (`total > MORSEL_SIZE`) frame 1 ends holding the last morsel's raw
duration, and later frames decay 1/8 per morsel, not per frame. The DESIGN says
"the same 1/8 EMA the pass-duration fold uses, seeded on the first frame", which
is per-frame semantics the code does not honor when there is more than one
morsel. The single-morsel N=4 test did not exercise it.

## Changes proposed

Make the code match the per-frame DESIGN (the natural reading of "per-phase
duration EMA": how long phase p took this frame, summed across its morsels).

1. Add a per-frame accumulator field `phase_accum: [Cell<Nanos>;
   GATE2_MAX_UNITS]` alongside `phase_ema`.
2. `dispatch_trunks` ADDS each phase's per-morsel duration into `phase_accum[p]`
   (saturating), instead of folding into `phase_ema`. No seed read there.
3. `run` folds each phase's per-frame total (`phase_accum[p]`) into
   `phase_ema[p]` once, at the existing pass-duration EMA fold point (same
   `ema_seed`, after the morsel loop), then zeroes `phase_accum[p]`. Bounded by
   the phase count.
4. `run_parallel` does not call `dispatch_trunks` and does not fold, so both
   stays zero there (the existing parallel invariant holds).

The DESIGN text is already correct (it describes per-frame); this round makes
the code honor it, so no DESIGN edit.

## Edge cases (catalogued as tests)

- multi-morsel single-core run (`total > MORSEL_SIZE`): each phase's EMA equals
  its per-FRAME total (summed across morsels), not a single morsel's slice. The
  case the prior round's single-morsel test missed.
- restore `single_phase_only_slot_zero`: a single-phase carrier touches only
  `phase_ema[0]`; a higher slot stays zero (the prior src CL named it; the
  shipped round consolidated it into the multi-phase test, a claim-vs-shipped
  drift the review flagged).
- existing `multi_phase_records_and_higher_slot_zero` and
  `parallel_path_leaves_phase_ema_zero` keep holding.
