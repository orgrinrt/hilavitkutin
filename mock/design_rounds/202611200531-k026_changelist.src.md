# src changelist

Round topic `202611200531-k026_topic.the-bench-reads-its-build-from-the-crate.md`, the only flat topic, and the locked doc changelist of this round. The source below gives the crate what the design now says and moves the bench onto it. It replaces `202611200531-k026_changelist.src.deprecated.md`, whose crate half was built as written and whose bench half was built in a few places differently; the last section says where.

## `mock/crates/hilavitkutin-build/`

- `src/linker.rs` (new): `Linker` with `Toolchain` and `Named`, its `name` and `leaves`; `linker_of::<S>()`, a walk over the set that takes the member of `LinkerGroup`; `linker_named`, the same walk over the three linker pragmas by name; `ToolchainLinker` with `RustLld` and `Other`, and `ToolchainLinker::of` over the text of rustc's target description; `rust_lld_mark` and `RustLldMark`. The two field readers come from the bench's `toolchain.rs` without their allocations.
- `src/choice.rs`: the alias `Linkers`, the three linker pragmas as one set, crate-private, which `linker_named` walks.
- `src/roster.rs`: `ChecksumFreshness`, group `Free`, workspace reach, one key written where `Shared` says it is owed.
- `src/pragma.rs`: `Slot` gains `ChecksumFreshness`, at its end so no pragma's bit moves.
- `src/generated.rs`: `write_set_config::<S, W>(site, out)`, public, the walk `write_generated` ran for each of its two sets and now calls.
- `src/lib.rs`: the new module, the new names in the public list, and the roster table's row for `ChecksumFreshness`.
- `tests/linker.rs` (new): every linker pragma answers its own name and mark and a set with none answers the toolchain; `linker_named` gives back what `linker_of` gave for each and nothing for an unknown name; `leaves` holds for a mark that starts as the tool's does and fails for another linker's, for a mark where none is due and for a text that only starts as the toolchain's does; the toolchain linker is `RustLld` only where both fields say so, with the three descriptions the bench's test held; `rust_lld_mark` over a real version line, a line with no source, and another program's line.
- `tests/generated.rs`: `write_set_config` of one set writes that set's lines and `write_generated` holds the same lines for both profiles; `ChecksumFreshness` in both sets of a prototype writes its key once.
- `tests/common/mod.rs` and `tests/pragma.rs`: the new pragma is in the lists the tests walk, and its reach has its line.

## `mock/benches/support/build-call/`

- `Cargo.toml`: `hilavitkutin-build` by path.
- `src/lib.rs`: `Arm` the enum goes. `Quantity` is a trait with `KIND: Kind`, implemented by the unit types `Build`, `Relink` and `Replay`; `Kind` is the enum a call matches on, with its label and the reading of a label back. `Profile::of_the_crate` gives the crate's profile for the bench's.
- `src/arm.rs` (new): `Arm`, a struct built by `Arm::of::<S, Q>()`: the kind, the linker, what the set says of incremental, the tools the set needs, and the set's cargo configuration lines and rustc flags per profile, written by the crate. `Arm::of` asserts `checked::<S>()` in a `const` block. `Arm::refusal` says why an arm cannot run: a set holding neither `Incremental` nor `NoIncremental`, a set the host target does not admit, and a set that needs a tool, with a marker naming the ticket filed for the finding of tools.
- `src/cargo.rs`: `command` takes the arm and the profile. `CARGO_INCREMENTAL` and `-Zchecksum-freshness` go; the arm's lines go on as `--config`, and its rustc flags as one `--config build.rustflags=[...]` where it has any. The marker for the ticket goes.
- `src/toolchain.rs`: `default_mark`, `string_field`, `object_field`, `GNU_COMPATIBLE` and their markers go. `own_mark`, a function over the description, the version line and the host, and `Toolchain::own_mark` over it, ask `ToolchainLinker::of` and `rust_lld_mark` and word the refusal. The marker on `resolve` goes: the looking is the caller's by the stamped row the topic names.
- `src/linker.rs`: `named` and `expected_mark` go. `refusal` takes the recorded linker name and the mark, asks `linker_named` and `Linker::leaves`, and refuses a name the crate does not know. `NO_MARK` is the text a line carries where the linker left nothing.
- `src/record.rs`: the header and `Line` gain `linker` and `quantity` as their last two columns, so a reader of an older file by position still reads it. `is_replay` goes; `check` reads the quantity column and refuses a quantity it does not know. The module text says where the expected mark comes from now.
- `src/call.rs`: `Call` holds the `Arm` struct. `ready` and `ready_with` take an `Arm` value and do not start for one with a refusal; `bench_call` is generic over the set and the quantity; the line is written with the linker's name and the quantity's.
- `tests/`: `marks.rs` builds its lines with the two columns, keeps every refusal it held, and gains a named linker held to its tool's mark (`Mold` passing on a mold mark and refused on lld's), `Bfd` passing on no mark and refused on one, and an unknown linker name refused; its last test, of the mark's working out, moved to the crate's `tests/linker.rs`. `record.rs`, `controls.rs`, `environment.rs`, `lock.rs` and `space.rs` name arms by type through `tests/common/mod.rs`. A new `arm.rs`: the quantity and linker of an arm come from its types; the keys and flags a set writes per profile; the command carries them as `--config` and sets no build choice in the environment; a set with neither incremental value is refused; a set needing a tool is refused with the tool's name; a call of a refused arm does not start.

## `mock/benches/support/build-fixture/`

- `src/manifest.rs`: the marker on `workspace` goes. Its text says the two profiles' `opt-level` and debug keys are the fixture's own, as the design leaves them to a consumer's manifest, and that the keys of an arm's pragmas reach the build on cargo's command line.

## The arms

- `mock/benches/build-static/arms/llvm_incremental` and `llvm_non_incremental`: `bench_call::<(ChecksumFreshness, Incremental), Build>` and `bench_call::<(ChecksumFreshness, NoIncremental), Build>`; each manifest takes `hilavitkutin-build` by path.
- `mock/benches/link-static/arms/default_relink` and `default_replay`: `bench_call::<(ChecksumFreshness, NoIncremental), Relink>` and the same set with `Replay`.

## What is run

The suites of `hilavitkutin-build` and of the bench tree by `cargo mock test -p hilavitkutin-build --benches`. Then `build-static` and `link-static` at their small point, 25 crates, by `cargo mock bench run`, so the cells that were measured under the old route are shown to run and pass their checks under the new one; the run directories are committed. `measured.rs` keeps its rows: they cite runs of the same configuration, and a row is replaced when a run measures its key at a new point.

## Tickets

`build_call_s_target_spec_reading_linker_mark_and_cargo_flags` and `a_link_static_arm_carries_its_linker_and_quantity_in_a_type` close with this round. One is filed: an arm whose set needs a tool finds it as a consumer's script does.

## Comparison to deprecated changelist

### `mock/crates/hilavitkutin-build/`

Unchanged in what it builds: `Linker` with `Toolchain` and `Named`, `Linker::leaves`, the walk over `LinkerGroup`, `ToolchainLinker` with `RustLld` and `Other`, `ToolchainLinker::of`, `RustLldMark`, `ChecksumFreshness` in group `Free` written once where `Shared` says so, and its `Slot`. Added here: the `Linkers` alias in `choice.rs`, which the deprecated text did not name, and the test files named as they are (`tests/common/mod.rs` and `tests/pragma.rs`) where the deprecated text left the choice open.

### `mock/benches/support/build-call/`

`Arm` and `Arm::of` live in a module of their own, `src/arm.rs`, where the deprecated text put them in `lib.rs`. The refusals moved out of `Arm::of` into `Arm::refusal`, which `Call` asks before it starts, so a test can read a refusal without a panic; and one refusal is new, of a set with neither `Incremental` nor `NoIncremental`, since such a set would leave the choice to cargo's default and the `CARGO_INCREMENTAL` variable is gone. `Call::ready` and `ready_with` take an `Arm` value where the deprecated text made them generic; only `bench_call` is generic over the set and the `Quantity`. `Kind`, `Build`, `Relink` and `Replay` are as before. `Toolchain::mark` is named `own_mark`, with a free function of the same name under it so a test can hand it a description, and `GNU_COMPATIBLE` still goes. `Line` gains its two columns at the end where the deprecated text put them after `arm`: `measured.rs` reads the committed files of older runs by position. `NO_MARK` is new. The command's tests are in `arm.rs` where the deprecated text put them in `environment.rs`, which sets its process environment and so holds one test; `Mold` and `Bfd` are held in `marks.rs` as before.

### `mock/benches/support/build-fixture/`

Unchanged.

### The arms

The same four calls. The lockfiles and `mock/benches/src/lib.rs` are dropped from the list: the lockfiles are not tracked and the driver names nothing that changed.

### What is run

The same, with the test command written as it is run.

### Tickets

Unchanged.
