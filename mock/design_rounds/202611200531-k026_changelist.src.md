# src changelist

Round topic `202611200531-k026_topic.the-bench-reads-its-build-from-the-crate.md`, the only flat topic, and the locked doc changelist of this round. The source below gives the crate what the design now says and moves the bench onto it.

## `mock/crates/hilavitkutin-build/`

- `src/linker.rs` (new): `Linker` with `Toolchain` and `Named`, its `name` and `leaves`; `linker_of::<S>()`, a walk over the set that takes the member of `LinkerGroup`; `linker_named`, the same walk over the three linker pragmas by name; `ToolchainLinker` with `RustLld` and `Other`, and `ToolchainLinker::of` over the text of rustc's target description; `rust_lld_mark` and `RustLldMark`. The two field readers come from the bench's `toolchain.rs` without their allocations.
- `src/roster.rs`: `ChecksumFreshness`, group `Free`, workspace reach, one key written where `Shared` says it is owed.
- `src/pragma.rs`: `Slot` gains `ChecksumFreshness`, at its end so no pragma's bit moves.
- `src/generated.rs`: `write_set_config::<S, W>(site, out)`, public, the walk `write_generated` ran for each of its two sets and now calls.
- `src/lib.rs`: the new module, the new names in the public list, and the roster table's row for `ChecksumFreshness`.
- `tests/linker.rs` (new): every linker pragma answers its own name and mark and a set with none answers the toolchain; `linker_named` gives back what `linker_of` gave for each and nothing for an unknown name; `leaves` holds for a mark that starts as the tool's does and fails for another linker's, for a mark where none is due and for a text that only starts as the toolchain's does; the toolchain linker is `RustLld` only where both fields say so, with the three descriptions the bench's test held (own lld, a C compiler driver, an lld the toolchain does not carry); `rust_lld_mark` over a real version line, a line with no source, and another program's line.
- `tests/generated.rs`: `write_set_config` of one set writes that set's lines and `write_generated` holds the same lines for both profiles; `ChecksumFreshness` in both sets of a prototype writes its key once.
- `tests/pragma.rs` or `tests/choice.rs`, whichever holds the bits apart: the new pragma is in the list the test walks.

## `mock/benches/support/build-call/`

- `Cargo.toml`: `hilavitkutin-build` by path.
- `src/lib.rs`: `Arm` the enum goes. `Quantity` is a trait with `KIND: Kind`, implemented by the unit types `Build`, `Relink` and `Replay`; `Kind` is the enum a call matches on. `Arm` is a struct built by `Arm::of::<S, Q>()`: the kind, the linker, whether the set holds `Incremental`, and the set's cargo configuration lines and rustc flags per profile, written by the crate. `Arm::of` asserts `checked::<S>()` in a `const` block, refuses a set the host target does not admit, and refuses a set that needs a tool, with a marker naming the ticket filed for the finding of tools.
- `src/cargo.rs`: `command` takes the arm and the profile. `CARGO_INCREMENTAL` and `-Zchecksum-freshness` go; the arm's lines go on as `--config`, and its rustc flags as one `--config build.rustflags=[...]` where it has any. The marker for the ticket goes.
- `src/toolchain.rs`: `default_mark`, `string_field`, `object_field`, `GNU_COMPATIBLE` and their markers go. `Toolchain::mark` asks `ToolchainLinker::of` and `rust_lld_mark` and words the refusal. The marker on `resolve` goes: the looking is the caller's by the stamped row the topic names.
- `src/linker.rs`: `named` and `expected_mark` go. `refusal` takes the recorded linker name and the mark, asks `linker_named` and `Linker::leaves`, and refuses a name the crate does not know.
- `src/record.rs`: the header and `Line` gain `linker` and `quantity` after `arm`. `is_replay` goes; `check` reads the quantity column and refuses a quantity it does not know. The module text says where the expected mark comes from now.
- `src/call.rs`: `Call` holds the `Arm` struct; `ready`, `ready_with` and `bench_call` are generic over the set and the quantity; the line is written with the linker's name and the quantity's.
- `tests/`: `marks.rs` builds its lines with the two columns, keeps every refusal it held, and gains a named linker held to its tool's mark (`Mold` passing on a mold mark and refused on lld's), `Bfd` passing on no mark and refused on one, and an unknown linker name refused; its last test, of the mark's working out, moves to the crate's `tests/linker.rs`. `record.rs`, `controls.rs`, `environment.rs`, `lock.rs` and `space.rs` name arms by type. `environment.rs` gains: the command of an incremental set carries `profile.dev.incremental = true` and no `CARGO_INCREMENTAL`, and the command of a set with `Bfd` carries the flag in `build.rustflags`. A new `arm.rs`: a set needing a tool is refused by `Arm::of`.

## What is run

The suites of `hilavitkutin-build` and of `build-call` by `cargo mock test`. Then `build-static` and `link-static` at their small point, 25 crates, by `cargo mock bench run`, so the cells that were measured under the old route are shown to run and pass their checks under the new one; the run directories are committed. `measured.rs` keeps its rows: they cite runs of the same configuration, and a row is replaced when a run measures its key at a new point.
