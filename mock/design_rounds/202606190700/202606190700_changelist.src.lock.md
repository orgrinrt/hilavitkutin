## CHANGE: `SchedulerMetrics` gains field `idle_ns: Cell<Nanos>`
File: `mock/crates/hilavitkutin-api/src/meta.rs`
Verification: `grep "pub idle_ns: Cell<Nanos>" mock/crates/hilavitkutin-api/src/meta.rs` returns one match; the `Default` impl initialises it to `Nanos::from_raw(0)`.

The current frame's worst-core idle. Read by an `OnMeta<ScheduleEnd>` hook as
the phase-imbalance signal. Sits beside `ema_pass_duration_ns` /
`last_record_count` / `change_seen_count` in the engine-owned metrics block.

## CHANGE: `waist_barrier` signature FROM `(pool, expected)` TO `(pool, core, expected, now)`
File: `mock/crates/hilavitkutin/src/thread/barrier.rs`
Verification: `grep "now: impl Fn() -> Nanos" mock/crates/hilavitkutin/src/thread/barrier.rs` returns one match.

The follower branch (the worker that parks until the sense flips) samples
`now()` before the park loop and again after it breaks, and adds the raw-nanos
delta into `pool.idle_accumulator[core.0]` with a `Release` `fetch_add`, guarded
by `core.0 < pool.idle_accumulator.len()` (the worker count can exceed
`MAX_CORES`). The last-arriver branch is untouched: a bottleneck core records no
idle. `now` is `impl Fn() -> Nanos` (monomorphised, no dyn). The single-core
fast path (`expected == 1`) takes the last-arriver branch and never times.

## CHANGE: `run_parallel` ScheduleEnd fold reduces `idle_accumulator` into `idle_ns`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (the per-frame meta fold, beside the pass-duration EMA and change_seen_count)
Verification: `grep -n "m.idle_ns.set" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match.

After the EMA fold (all workers re-parked), max-reduce
`pool.idle_accumulator[0..len()]` into `idle_ns` (worst-core idle), then reset
every accumulator slot to zero for the next frame. Single-core `run` and
`run_fused` never call `waist_barrier`, so they leave `idle_ns` at zero.

## CHANGE: add white-box `Scheduler::__idle_ns` accessor
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep -n "pub fn __idle_ns" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match.

Reads `meta_block.metrics.idle_ns` after a frame. An accumulator-bearing carrier
takes the unit-outer no-barrier path (zero idle by design), so it cannot be the
readback channel for a barrier-driven signal; the white-box accessor lets a
column-pipeline test read the metric directly.

## NEW TEST: `tests/r5_core_idle.rs`
File: `mock/crates/hilavitkutin/tests/r5_core_idle.rs`
Verification: `cargo test -p hilavitkutin --test r5_core_idle` builds and the green cases pass.

Edge-case catalogue (the workspace TDD discipline: every edge case formalised as
a test):

- `single_core_run_no_idle`: single-core `run` over a 2-phase column pipeline,
  `idle_ns == 0` (no waist barrier crossed). Invariant.
- `accum_unit_outer_no_idle`: an accumulator-bearing carrier under
  `run_parallel`, `idle_ns == 0` (unit-outer path bypasses the barrier).
  Invariant.
- `imbalanced_parallel_records_idle`: a multi-trunk column pipeline under
  `run_parallel` with a strictly-increasing counter clock. For `ncores > 1` at
  least one follower parks, so `idle_ns > 0` deterministically (an increasing
  clock makes any park record a positive delta). For `ncores == 1` the
  single-core invariant applies (`idle_ns == 0`). This is the measurement case.
