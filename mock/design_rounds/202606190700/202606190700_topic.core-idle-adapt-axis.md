# Topic: core-idle adapt axis (domain 22)

**Date:** 2026-06-19
**Phase:** TOPIC
**Scope:** `hilavitkutin` engine (thread barrier + scheduler fold), `hilavitkutin-api` (`SchedulerMetrics`)
**Source topics:** spec domain 22 (self-observation / adapt), Topic 6 axis I (waist barrier), `SchedulerMetrics` EMA surface

## Current state

The self-hosting meta pipeline already folds three adapt signals into
`SchedulerMetrics` at `ScheduleEnd`: `ema_pass_duration_ns` (frame-time EMA),
`last_record_count` (throughput numerator), and `change_seen_count`
(input-change rate). The runtime data plane carries the per-core idle storage
the spec calls for: `PoolFrame.idle_accumulator: [AtomicU64; MAX_CORES]` and a
paired `park_count`, both documented as the "Topic 5 core-idle axis", read by
the adapt subsystem at `ScheduleEnd`. Nothing writes them yet. The
`idle_accumulator` is dead storage, so the per-core idle signal that should
drive the "phase balance shifted, re-select per-phase configs" adapt trigger
does not exist.

The barrier primitive that is the natural measurement point is
`thread::barrier::waist_barrier`. Its follower branch parks on `barrier_sense`
until the last arriver flips the sense. A worker that finishes its trunks for a
phase early arrives first and parks while slower cores grind; that park IS the
core-idle the adapt axis wants to measure. The last arriver never parks, so it
accrues no idle, which is correct (it was the bottleneck, not the starved core).

## The gap

Idle has to be measured where the park happens, not wrapped at a caller. An
earlier attempt wrapped the `worker_main` call site of `waist_barrier`; it read
zero because the engine has more than one wait site and the wrapped site was not
always on the taken path. The robust point is inside the primitive itself: every
waist a worker crosses goes through `waist_barrier`, so timing the follower park
there captures all of it regardless of which dispatch path the frame took. This
matches the workspace guidance to revisit the substrate rather than wrap around
it: the barrier owns "how long did I wait", and the caller supplies the clock.

`waist_barrier` currently takes only `(pool, expected)`. To time its own park it
needs the owning core id (to index `idle_accumulator`) and a way to read the
monotonic clock. The clock cannot be a field on `PoolFrame` without either a
generic `Clk` parameter on the frame (which the worker boundary erases) or a
type-erased function pointer. The caller (`worker_main`) already holds the
concrete `Scheduler<.., Clk>` and its clock, so the cleaner shape is to pass the
clock read in as `impl Fn() -> Nanos`: monomorphised, no dyn, no new frame field.

## Changes proposed

1. `waist_barrier` gains `core: USize` and `now: impl Fn() -> Nanos`. The
   follower branch samples `now()` before the park loop and again after the
   sense flips, and adds the delta (raw nanos) into `idle_accumulator[core]`
   with a `Release` `fetch_add`, bounds-checked against
   `idle_accumulator.len()` (the worker count can exceed `MAX_CORES`, so the
   index is guarded, never assumed in range). The last-arriver branch is
   untouched: a bottleneck core records no idle.

2. `worker_main` passes its `core_id` and `|| s.clock.now_ns()` at the call
   site.

3. `SchedulerMetrics` gains `idle_ns: Cell<Nanos>`: the current frame's
   worst-core idle (the max across `idle_accumulator[0..len()]`). Worst-core,
   not sum, because the adapt trigger is "is some core starved relative to the
   others", which the max expresses directly. Raw current-frame value for this
   slice; an EMA fold of the idle signal is a noted follow-up, consistent with
   the other metrics but not required to make the signal exist.

4. `run_parallel`'s `ScheduleEnd` fold (where the pass-duration EMA and
   `change_seen_count` already land, all workers re-parked) reduces
   `idle_accumulator[0..len()]` to its max into `idle_ns`, then resets the
   accumulators to zero for the next frame. Single-core `run` and the fused
   path never call `waist_barrier`, so they leave `idle_ns` at zero, which is
   the correct reading (no inter-core park means no idle).

5. A white-box `__idle_ns` accessor for tests to read the metric after a frame
   without an accumulator readback (an accumulator-bearing carrier takes the
   unit-outer no-barrier path, which by design produces zero idle, so it cannot
   be the readback channel for a barrier-driven signal).

## Edge cases (catalogued as tests per the workspace TDD rule)

- single-core `run`: `expected == 1`, the last-arriver path runs with no park,
  idle stays zero. Invariant; must hold after measurement lands.
- accumulator unit-outer parallel: `carrier_unit_outer` bypasses the waist
  barrier entirely, idle stays zero. Invariant.
- imbalanced multi-core column pipeline (`ncores > 1`, at least one waist): at
  least one follower parks, idle is positive. The measurement case. A strictly
  increasing clock makes any follower park record a positive delta, so the
  assertion is deterministic, not timing-dependent. Guarded for `ncores == 1`
  hosts (no follower ever parks there, so the single-core invariant applies).
- balanced multi-core: cores arrive close together, idle is small but the
  follower still records a positive delta under an increasing clock. Folded into
  the imbalanced case (same assertion, `idle_ns > 0`); a tight-vs-loose
  threshold is not asserted because real wall-clock balance is not
  deterministic.

## Not in scope

The remaining adapt axes (`active_units`, `stolen_count`, per-phase/per-fiber
EMA reshape, the `select_adapt_config` threshold logic that consumes `idle_ns`)
stay for follow-up rounds; this round makes the idle signal exist and proves it
through the barrier primitive.
