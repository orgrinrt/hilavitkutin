# Doc changelist: core-idle adapt axis

**Date:** 2026-06-19
**Phase:** DOC
**Round:** 202606190700

## File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`

Extend the `SchedulerMetrics` / meta-bridge paragraph (the one naming
`pass_count`, `last_record_count`, `change_seen_count`) with the `idle_ns`
cell. State:

- `idle_ns` is the current frame's worst-core idle: the maximum across the
  per-core `idle_accumulator` slots the waist barrier fills.
- The barrier times its own follower park (a worker that finishes a phase
  early and waits at the waist for slower cores), so per-core idle is measured
  at the primitive every waist crosses, not wrapped at a caller.
- Single-core `run` and the fused path never cross a waist barrier, so they
  leave `idle_ns` zero, which is the correct reading (no inter-core wait means
  no idle).
- An `OnMeta<ScheduleEnd>` hook reads it as the phase-imbalance signal (the
  adapt trigger to re-select per-phase configs).

No new backticked type names beyond `idle_ns` (a field on the already-documented
`SchedulerMetrics`), so the design-doc-source-mismatch lint is satisfied by the
field landing in the src CL.
