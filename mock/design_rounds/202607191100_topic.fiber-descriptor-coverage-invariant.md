# Topic: descriptor coverage is now a load-bearing invariant on both dispatch paths

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** State the fiber-descriptor coverage invariant in the design, catalogue its
violation as a test, and add the parity assert the parallel branch is missing.
**Driver:** PR #171 review finding 1.

## What changed underneath us

Before A2b, both dispatch paths passed an all-ones mask, so every live unit ran whether
or not any fiber descriptor named it. Descriptor coverage was a plan-quality question
with no correctness consequence at dispatch.

A2b made `run` walk fiber descriptors and pass each fiber's member mask. A4 did the same
for `run_core_phase`. The union of those masks has now replaced all-ones on both paths,
so **a live unit that no descriptor covers does not run at all**, on either path.

That invariant is currently guarded only by two `debug_assert`s in
`derive_phase_dispatch_order` (`plan/mod.rs:463`, `:473`). The flatten loop itself
truncates silently: its bound is `while u < uc && u < units.len() && next < cap`, so a
plan whose fiber count exceeds the descriptor pool capacity drops the overflow, and in a
release build the failure mode is not a panic or an error but a unit that quietly never
executes. Wrong output, no signal.

This is not a regression from A4. `run` took the same exposure at A2b and nobody noticed
then, which is the point: A4 doubles the number of sites depending on a debug-only
invariant, and that is the right moment to write the invariant down rather than let it
stay implicit at two call sites.

## What to do about it

Three things, in increasing cost, and only the first two belong in this round.

**State the invariant in the design.** The descriptor set must cover every live unit,
because the dispatch mask is now their union. Currently no design surface says so, which
means a future change to the flatten loop's bounds has nothing to check itself against.

**Catalogue the violation as a test.** A plan that exceeds the descriptor capacity must
not silently skip units. Per the catalogue discipline the test is written now with the
intended assertion and left red, since the fix is the third item and this round is not
taking it. Writing it now is what stops the case being lost; whether it goes green today
is a separate question.

**Make the truncation release-visible.** The real fix is that `build` refuses a plan it
cannot fully describe, rather than returning a scheduler that will under-dispatch. That
is a change to the build contract with its own blast radius (it turns a silent
degradation into a build failure, which is correct but is a behaviour change consumers
see), so it wants its own round and its own decision about the error shape. Left to the
follow-up the catalogued test tracks.

## Also in this round

Two one-line review items on the A4 branch. The parallel branch omits the
