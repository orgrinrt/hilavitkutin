# Src changelist: delete spawn_fn and its trampoline on both tiers

**Date:** 2026-07-19
**Phase:** SRC
**Topic:** `202607192800_topic.retire-the-fn-pointer-spawn.md`
**Doc CL:** `202607192810_changelist.doc.lock.md`

## CHANGE: `OsThreadPool::spawn_fn` and `trampoline` ARE DELETED

File: `mock/crates/hilavitkutin/src/platform/os.rs`

`spawn_fn` (`:114`) takes a bare `fn()` and smuggles it through `pthread_create`'s `*mut c_void` as a
`usize`. `trampoline` (`:132`) is its entry point and names it in its own safety comment: "`raw` was
produced from a `fn()` pointer in `OsThreadPool::spawn_fn`". Both go together.

`tramp<F>` (`:163`) and the generic `spawn` (`:181`) stay. They are separate machinery: the closure is
copied by value under `PtrSizedClosure::<F>::CHECK`, and that is the live path the engine uses.

Verification: `! grep -q "fn spawn_fn" mock/crates/hilavitkutin/src/platform/os.rs`, and
`grep -c "extern \"C\" fn" mock/crates/hilavitkutin/src/platform/os.rs` drops from two to one.

## CHANGE: `StdThreadPool::spawn_fn` IS DELETED

File: `mock/crates/hilavitkutin/src/platform/std_tier.rs`

Same function on the std tier (`:106`), also unreferenced. Until D2 it was the working half against a
no-op `spawn`; D2 inverted that by making `spawn` real, so this is now the dead half on both tiers
rather than just one.

Verification: `! grep -q "fn spawn_fn" mock/crates/hilavitkutin/src/platform/std_tier.rs`.

## What the checks found before the deletion

Reachability: zero callers for either `spawn_fn`, tests included. That test alone would have cleared
the deletion.

Design templates: **`BACKLOG.md.tmpl:190` names `spawn_fn`**, backticked. That is the check that
mattered. A deletion run on the caller-grep alone would have removed a symbol a template still cites,
leaving a portability note pointing at code that no longer exists and no way for a reader to tell
whether the concern had been answered or abandoned. The doc CL rewrites it to say which.

Live-code citation: neither `spawn_fn` is cited by the live path as its rule. `tramp<F>` and `spawn`
share no code with them.

Three checks, and the second one was the only one that caught anything. That is the third time today
the reachability grep passed and something else did not.

## Expected test movement

None. 132 binaries green, unchanged. `os_thread_pool_spawn.rs` exercises the generic `spawn`, not
`spawn_fn`, and must stay green.

## Not in scope

`tramp<F>`, the generic `spawn`, and the `OnceLock` MSRV backlog note.
