## CHANGE: `hilavitkutin/BACKLOG.md.tmpl` POSIX cast note

The entry at `:190` reads:

> **POSIX fn*/void* cast in `platform/os.rs` `spawn_fn`.** The current pattern smuggles `fn()` via
> `usize` as a `pthread_create` argument. POSIX does not guarantee that `fn*` and `void*` have
> matching size ... the threading-std implementation round should switch to `Box<fn()>` or a static
> work-queue slot to be POSIX-clean.

It becomes a record of how the concern was resolved, rather than an open item pointing at deleted
code.

The resolution is neither option the note proposed. `Box<fn()>` would allocate, which the engine path
forbids, and the static work-queue slot was never built. What shipped is the generic
`spawn<F: FnOnce() + Send + 'static>`, which copies a pointer-sized closure by value into the
`pthread_create` argument under `PtrSizedClosure::<F>::CHECK`, a compile-time size and alignment
assertion. The closure captures a data pointer, so no function pointer is cast and the `fn*`-versus-
`void*` parity question does not arise. An over-fat closure is a compile error, never an allocation.

Worth keeping rather than deleting outright: a reader who finds the code gone and the note gone has
no way to tell whether the concern was addressed or abandoned. The rewritten entry says which.
