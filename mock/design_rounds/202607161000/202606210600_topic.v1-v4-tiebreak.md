# Topic: V1-vs-V4 tiebreak rule (op, 2026-06-20)

**Date:** 2026-06-20
**Phase:** TOPIC
**Round:** 202606210600
**Relates to:** `202606210600_topic.bench-decision.md`, `202606210600_topic.v4-plugin-interop-axis.md` (both frozen).

The criterion for the run-2 judgment between V1 (blob + scalar snapshot, native monomorphised
dispatch) and V4 (type-erased static-shape, plugin/wasm-interop):

- **If V4 falls NOTICEABLY behind V1** (a real, measurable per-call regression): choose **V1**.
  The native-monomorphised-dispatch win is the one we take over V4's speculative plugin-interop
  upside.
- **If V1 and V4 are near-identical or differ only minorly**: choose **V4** (or the hybrid that
  uses the erased-shape boundary), because then the plugin/wasm dynamic-loadability benefit
  (`202606210600_topic.v4-plugin-interop-axis.md`) is essentially free and worth having.

So the bar for V4 is "not noticeably slower than V1." Run-1 had them at parity on the scalar
latency axes (M1); run-2 confirms whether that parity holds before applying this rule.
