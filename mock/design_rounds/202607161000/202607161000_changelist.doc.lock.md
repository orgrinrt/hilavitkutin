# Doc changelist: resource storage model, bench-settled + hybrid addressing

**Date:** 2026-07-16
**Phase:** DOC (this changelist opens it)
**Round:** 202606210600 (resource storage model; topics: r5-underspecification,
resource-handle-storage-model, storage-model-pressure-test, bench-decision,
v4-plugin-interop-axis, v1-v4-tiebreak, bench-run2-resolution, hybrid-decision)
**Scope:** fold the bench-decided value layout and op's hybrid addressing decision
(2026-07-02) into the canonical design docs, so the source round that follows
implements against an up-to-date oracle.

## Current state

`mock/crates/hilavitkutin/DESIGN.md.tmpl` carries the domain-19 resource-handling
statement in its pre-bench form: stack-local caching and pointer separation are
stated, but the addressing is described as a monomorphised `ResourcePtr<T>`
recorded at drain ("records a `ResourcePtr<T>` derived from the column base
pointer"), and the collection (`Seq`/`Map`) access discipline and the erased
static-shape addressing are absent. The round's research artifacts
(`mock/research/202606210600_storage-bench-findings.md`,
`mock/research/202606210600_resource-storage-model-canonical-addendum.md`) hold
the settled model; the design docs do not yet.

## Changes proposed

### `mock/crates/hilavitkutin/DESIGN.md.tmpl`

1. **Domain-19 section (`## Resource handling (domain 19)`).** Expand to the
   full settled model: the value is a one-record contiguous blob (per-resource,
   arena-reserved), NOT decomposed per-member columns and NOT shape-bound shared
   columns (both refuted by the six-variant bench: decomposed loses
   intra-resource locality and crosses the column-count cap; shape-bound carries
   cross-core false sharing plus a resize hazard). Scalar members snapshot to the
   dispatch stack before the morsel loop; `Seq`/`Map` collection members are
   live-streamed (the snapshot copies only the pointer-plus-length view, never
   elements). State the noalias invariant (handle store and value columns at
   separate provenance; the snapshot gives the hot loop stack provenance).
   Add the erased static-shape addressing: the binding records an erased base
   pointer plus a static shape descriptor; the typed view is recovered by a
   backcast at projection time. In-process this is parity with a monomorphised
   pointer; it exists so a resource value can cross a dynamic-library or wasm
   extension boundary near-natively. It applies to every resource uniformly
   (global-capable), so any resource is extension-visible without a per-resource
   design change.

2. **Dispatch/context section (the `EngineCtx` paragraphs).** State that the
   resource projection is a by-value snapshot: projecting a unit's Context copies
   each read-set resource value out of the store into the Context itself (the
   Context lives on the dispatch stack frame, so the copies are the domain-19
   stack-local region), and the `resource()` accessor borrows the snapshot, not
   the arena. Resources are read-only through the Context; the write-back half of
   domain 19 activates when a mutable resource surface ships.

3. **Builder/drain section (`build(storage, record_count)` paragraph).** The
   drain still reserves a one-record column per `Resource<T>` and writes the
   staged value in; it now records the erased base plus the value's static shape,
   from which the typed `ResourcePtr<T>` is backcast at projection. Zero-sized
   resources keep the dangling-pointer path.

### Not touched

`mock/crates/hilavitkutin-api/DESIGN.md.tmpl`: the api contract surface is
unchanged by this round (the `Ctx` GAT is unconstrained, `ResourceProviderApi::
resource` keeps its signature, `Decompose` stays the per-member seam). The
`ResourceSnapshot<'phase, R>` item already described there is the adapt-boundary
snapshot (Topic 8 axis A), a different mechanism from the per-morsel dispatch
snapshot; no edit needed.

## Source-round preview (locked by the follow-on src changelist, listed here for
review context only)

Engine-internal, additive: an erased resource pointer plus shape descriptor in
`resource/`, `ResourceBinding` re-founded on them, the resource projection in
`dispatch/engine_ctx.rs` switched from pointer-cons to value-cons (the snapshot),
and the projection unsafe deref retired. The api crate is untouched.
