# The linking crate on arvo-numeral, and the dead arvo lines

**Date:** 2026-11-20
**Phase:** topic
**Scope:** `hilavitkutin-linking` (design, source, manifest), the five dead arvo manifest lines, the lto smoke fixture manifest

This is job 1 of the port of hilavitkutin onto current arvo (`mock/research/202611200345_arvo-port-plan/README.md`, "Job 1"). The sketch `202611200443_two-arvo-revisions-side-by-side` found that cargo resolves the old arvo and arvo `dev` side by side, so the linking crate can move first while its neighbours stay on the old revision.

The linking crate carries an OS error code as the old `arvo::USize`, entered by its tuple constructor at `src/backend/unix.rs:131` and `src/backend/windows.rs:82`, held by `LinkError::LoadFailed` at `src/error.rs:30`. It does no arithmetic on the code. Current arvo's `arvo_numeral::USize` takes an adaptation, no preset names one yet, and its doors are `from_host` and `host`. The round declares one alias in the crate for the code's type over an explicit `Adapt<R, O>`, entered by `from_host`, and the design says the alias becomes the stack's default strategy when arvo's step 4 lands.

The doc comment at `src/error.rs:8` names `arvo::ISize`, which the crate never uses and which contradicts the field's own unsigned note. The round drops that sentence.

Which rounding and overflow the alias names is a stamp from stack-coord and is asked before the doc changelist locks. The proposal is `Adapt<TowardZero, Saturate>`: the crate never rounds, since a host integer is on the grid, and a code that left its range must not wrap into a different valid code. A wrapping choice is the other reading.

Three more things fall in the same round. The manifest lines of `arvo-bits` in the linking and providers crates, of `arvo` in the extensions crate, of `arvo-bitmask` in the api and of `arvo-comb` in the engine are dead and go, each shown dead by a build without it. The fixture manifest `hilavitkutin-extensions-macros/tests/lto_smoke_fixture/Cargo.toml:35` moves to the same revision if it names an arvo path and loses the line if it does not. And the tool `mock/tools/old-arvo-names` counts the old arvo paths per crate.
