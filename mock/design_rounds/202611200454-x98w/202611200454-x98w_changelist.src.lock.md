# src changelist

Round topic `202611200454-x98w_topic.linking-on-arvo-numeral-and-the-dead-arvo-lines.md`, under the locked `202611200454-x98w_changelist.doc.lock.md`.

## Changes proposed

### 1. `OsCode` and `LinkError`

`mock/crates/hilavitkutin-linking/src/error.rs`: `use arvo::USize` goes, and the file declares `pub type OsCode = USize<Adapt<TowardZero, Saturate>>` over `arvo_numeral::USize` with `Adapt` from `arvo_format` and the two policies from its `rounding` and `overflow` modules, as the design says. `LinkError::LoadFailed` carries `platform_code: OsCode`. The doc comment on the enum no longer names `arvo::ISize`: the field is unsigned, and the sentence contradicted the note under it. `src/lib.rs` re-exports `OsCode` beside `LinkError`.

### 2. The backends enter a code by `from_host`

`src/backend/unix.rs` and `src/backend/windows.rs`: the `arvo::USize` import goes, `read_errno` and `read_last_error` return `OsCode`, and each ends in `OsCode::from_host(..)` where it ended in the tuple constructor. Nothing else in either file changes.

### 3. The test that holds the code

`mock/crates/hilavitkutin-linking/tests/os_code.rs`: a code goes in by `from_host` and comes out by `host` unchanged for zero, an errno, a Windows error code and the largest `usize`, and a `LinkError::LoadFailed` carries the code it was built with. It fails if the alias saturated or rounded a member.

## Manifests, not gated

`mock/crates/hilavitkutin-linking/Cargo.toml` takes `arvo-numeral` and `arvo-format` in place of `arvo`, and `mock/Cargo.toml` pins both at arvo `dev` `6def883183ebe9b96c90da16cee148010eb89226` beside the old pins, which the other crates keep until the pin job. `hilavitkutin-extensions-macros/tests/lto_smoke_fixture/Cargo.toml` names an arvo path in no source of the fixture, so its `arvo` line goes with the notko patch that only that arvo needed.

## Not changed

The api, the engine, the sym, str and persistence crates, `hilavitkutin-build` and `mock/benches/support`.
