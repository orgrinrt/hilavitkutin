Round topic `202611200454-x98w_topic.linking-on-arvo-numeral-and-the-dead-arvo-lines.md`.

## Changes proposed

### 1. The linking crate carries its OS code as an alias over `arvo_numeral::USize`

`mock/crates/hilavitkutin-linking/DESIGN.md.tmpl`, four places.

The opening section names the foundational dependencies as notko for the fallibility ladder and arvo-numeral with arvo-format for the numeric type of a platform code. It no longer names arvo-bits for boolean values, which the crate never used.

The public items section counts eight items and gains `OsCode`: the type of an OS error code, an alias over `arvo_numeral::USize` with an explicit `Adapt<TowardZero, Saturate>`, entered by `from_host` and read by `host`. The `LinkError` bullet says it carries `OsCode` platform codes.

The error paragraph of the shape section says OS error codes are carried as `OsCode` values, non-negative on both the unix errno and the Windows `GetLastError` ranges, and that the crate does no arithmetic on a code. It says the adaptation is declared here because no strategy preset names one yet, that the alias becomes the stack's default strategy when arvo's step 4 lands, and that the rounding and overflow are the stamp of stack-coord for this crate only, settled for the stack in the numeral vocabulary job. The choice is rounding toward zero and saturation: the crate never rounds, a host integer being on the grid, and a code that left its range must not wrap into a different valid code.

The dependencies section lists notko, arvo-numeral and arvo-format, and says both arvo revisions of the workspace resolve side by side, as the sketch `202611200443_two-arvo-revisions-side-by-side` shows, until the pin job.

It is a doc comment in `src/error.rs` and not in the design, so it is a source change in the src changelist. The design never named `ISize`.
