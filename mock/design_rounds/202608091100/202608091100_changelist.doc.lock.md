# Doc changelist: widths come from the types, and the coverage the rustdoc owes

**Date:** 2026-08-09
**Phase:** DOC
**Topic:** `202608091100_topic.widths-tied-to-the-mechanism-and-a-dead-gate.md`

Two document edits. The first retracts a claim the shipped design makes that is
not true of the shipped code. The second states what the crate's tests must
cover, because a documented effect nothing tests is the same defect as a
declared width nothing constrains.

## CHANGE: the width-derivation paragraph, from the mask to the associated type

File: `mock/crates/hilavitkutin-sym/DESIGN.md.tmpl:91-98`

The current text says the width is counted from the layout's generated mask, and
defends that choice with: "a layout that lied would have to lie about its mask,
which its own accessors read through."

**That is false and the review proved it by construction.** `get_kind` returns
`self.kind()`, the bitfield's inherent accessor, which uses the macro's mask
directly. The forwarded `KIND_MASK` constant has no reader outside the test law,
so a layout may forward any mask at all and every accessor still round-trips.

Replacement states the derivation that holds: the width comes from `Self::Kind`
and `Self::Id`, the associated types the accessors are typed against, read
through a `FieldWidth` trait whose blanket impl over `Bits<N, S>` yields `N`. A
layout cannot lie about those, because `get_kind` must return what the bitfield
hands it, and a wrong associated type is a type error rather than a silent
disagreement.

The paragraph also records the count. Five appearances of one class, each fix
moving the number one rung down: from a test asserting a literal, to a declared
constant, to a constant checked against another constant, to a constant checked
against a mask nothing reads. The rung that ends it is a value the code uses.

Verification: `grep -c 'accessors read through it' DESIGN.md.tmpl` returns 0,
and the replacement names `FieldWidth`.

## CHANGE: add the coverage contract to the design document

File: `mock/crates/hilavitkutin-sym/DESIGN.md.tmpl`, new section after the widths
section.

The document describes eight layout operations, three shape operations, an
exhaustion boundary, a flag documented as domain-private, and a promise that
comparison is integer equality over the whole handle. **No test exercises any of
the eight layout operations.** The section states the standing requirement that
every documented effect, boundary and edge case carries a unit test, and names
the classes the source changelist then builds:

- Each accessor round-trips at each shape's real width, at zero, at the maximum
  the field holds, and at a value with alternating bits.
- Writing one field disturbs no other. This is the bitfield failure the mask
  laws never covered, because a field overlap is invisible to every law that
  reads one field at a time.
- A zeroed layout reads zero in every field.
- Raw-bit equality and handle equality agree, which is the crate's stated
  central promise and was asserted nowhere.
- The exhaustion boundary refuses, and keeps refusing.
- A span of ids belongs to exactly one origin, at both ends of that span.

Verification: the section exists and each bullet has a named test in the source
changelist.
