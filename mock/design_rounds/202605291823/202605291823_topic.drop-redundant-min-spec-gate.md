# Topic: drop the redundant min_specialization gate in hilavitkutin-api

**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** `hilavitkutin-api/src/lib.rs` feature gates, `column_value.rs` doc accuracy
**Source:** unstable-feature soundness sweep (task #625), `unstable-features.md`

## Context

`hilavitkutin-api/src/lib.rs` gates both `#![feature(min_specialization)]`
(line 18) and `#![feature(specialization)]` (line 26). The full
`specialization` gate was retained by task #623 because
`ColumnValue::BIT_WIDTH` uses a blanket `default const` overridden by sub-byte
arvo impls, which `min_specialization` rejects. The full feature is a strict
superset of the min subset: when it is enabled, the min gate enables nothing
additional.

Task #625 originally framed the min gate as an actively-used feature needing
the std-internal carve-out discipline (a `// SAFETY:`-style justification plus a
gotcha audit). That framing predates the #623 finding. With the full gate
present and covering the only specialization use in the crate (`column_value`),
the min gate is dead. The correct resolution is removal, not documenting a gate
that does nothing.

## Empirical confirmation

Removing `#![feature(min_specialization)]` from `hilavitkutin-api/src/lib.rs`
and running `cargo +nightly-2026-05-28 check -p hilavitkutin-api -p hilavitkutin
--all-targets` compiles clean. `min_specialization` is gated in no other
shipping crate root. So nothing depends on the min subset specifically; the full
gate covers all specialization usage.

## Doc accuracy drift

`column_value.rs` module and trait docs state the blanket impl "uses
`min_specialization`". That is inaccurate: the blanket `default const` overridden
by concrete impls is exactly the shape `min_specialization` rejects (per #623),
so it uses the full `specialization` feature. The doc gets corrected to name the
full feature and to point at the spec-free redesign tracked as task #631.

## Changes proposed

1. Remove `#![feature(min_specialization)]` from `hilavitkutin-api/src/lib.rs`.
2. Correct the `column_value.rs` module doc and trait doc: name `specialization`
   (full) rather than `min_specialization`, and note that the spec-free redesign
   is tracked as #631.

No change to the forbidden full `specialization` gate itself, which stays with
its tracked-exception comment until #631 (an op-level contract decision) lands a
spec-free `ColumnValue`. No `.md.tmpl` documentation changes.
