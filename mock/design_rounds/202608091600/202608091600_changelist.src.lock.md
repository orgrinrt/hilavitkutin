## CHANGE: the `FieldWidth` rustdoc no longer claims to be the whole guarantee

File: `mock/crates/hilavitkutin-sym/src/shape.rs`

The doc argues that a wrong associated type is a type error because `get_kind`
returns `Self::Kind` and its body returns what the bitfield hands back. Nothing
enforces that body.

Established by construction rather than by reading, which is the only way
anything in this arc has been established. `WideKindLayout` was given
`type Kind = Bits<9, Hot>` and `type Id = Bits<22, Hot>` over its genuine five
and twenty-six bit fields, converting in both directions, with `KIND_BITS`,
`ID_BITS`, `COUNTER_BITS` and `origin_ceiling` moved to match. It compiles, and
**every shape-level width law passes**, `every_shape_declares_the_widths_its_layout_actually_has`
included, because each reads a declared width against a declared type and the
two agree.

The round-trip law fails, because a nine-bit maximum written through a five-bit
field reads back truncated. The whole-handle law fails alongside it, because the
four bits the narrower field vacates then belong to nothing.

So the guarantee is the chain, not any one link: the declaration is pinned to the
type by `FieldWidth`, and the type is pinned to the field by the round trip.
Neither end alone. The rustdoc says that, and no longer says this is the last
rung, because four rounds have now named a mechanism and stopped looking.

Verification: `grep -c 'the rung that ends'` returns 0 in `shape.rs` and in
`DESIGN.md.tmpl`; both name the round trip.

## CHANGE: `tests/layout.rs` derives its widths instead of restating them

File: `mock/crates/hilavitkutin-sym/tests/layout.rs`

The macro was instantiated with literal `Bits<5, Hot>` and `Bits<26, Hot>`,
which restate what each layout already declares. **That is this crate's whole
recurring defect, sitting in the suite written to catch it.**

It is the weak form rather than the silent one, since a mismatch is a type error
against the real accessors. It is still a hand-written number saying what another
artifact says, and the round that removes the last of them should not add two.

Now derived from `<L as SymLayoutOps>::Kind` and `::Id`. The catch survives and
moves later: under the converting layout above, the derived form fails the
round-trip law at runtime where the literal form failed to compile. Later, and by
a law that constrains rather than by a number that happens to agree.

Verification: no `Bits<` literal appears in a `layout_suite!` invocation, and the
converting construction still fails the suite.

## FINDING: `cargo fmt --check` cannot be held clean here, and the cause is upstream

Files: `mock/crates/hilavitkutin-str/src/lib.rs`,
`mock/crates/hilavitkutin-str/tests/{const_fnv1a,ergonomics,interner,str_const}.rs`

Round six claimed `cargo fmt --check` reports zero diffs. It reports five, all
import ordering, all in `hilavitkutin-str`. **That claim was false and this round
does not replace it with another one**, because the state it describes is not
reachable.

Established by construction, after one wrong hypothesis was discarded:

1. `cargo fmt -p hilavitkutin-str` makes the five diffs go. `cargo fmt --check`
   then reports zero. The tree is clean at that moment.
2. Committing an **unrelated** file leaves it clean. That result is what made the
   first hypothesis look wrong, and it is why it is recorded here.
3. Committing **those files** brings all five back. The autofix reformats what is
   staged, so an unrelated commit was never going to show it.

So mockspace's autofix and the crate's own `cargo fmt` disagree about import
ordering, and the autofix wins on every commit that touches the file. The crate is
edition 2024, which sorts lowercase items after uppercase
(`{FNV_OFFSET, FNV_PRIME, const_fnv1a}`); what lands is the other order.

Nothing in this repository resolves that. Editing the files reverts on commit,
and there is no `rustfmt.toml` here to reconcile: the disagreement is between the
autofix's rustfmt invocation and the crate's edition. **It is upstream work in
mockspace**, recorded rather than worked around, because a workaround in the
consumer is what this workspace's rules forbid and what would hide it.

No `lint:allow` line moves under any of the five, so nothing is wrongly
suppressed and the strict gate is unaffected. The cost is to the record, which is
the whole reason this is written down rather than left as a green claim.

**The general lesson, which is the fourth round's worth of it.** Round six's
verification ran a command that was not the gate's command. This round's first
attempt at a cause ran a probe that could not have observed the effect. Both
produced a confident answer. A verification has to be able to fail for the reason
being tested, exactly as a test does.
