## CHANGE: the width-derivation section, from the type to the round trip

File: `mock/crates/hilavitkutin-sym/DESIGN.md.tmpl`

The current text says the associated type is the rung that ends the class,
because a layout naming a width its field does not have is a type error. That is
true only of a layout whose accessors forward. **An accessor may convert**, and
one that does satisfies every signature while the field stays narrower.

Replacement says what holds: the type pins what the accessors are compiled
against, and the round trip pins that the field behind them is that wide. The
declaration reaches a value the code uses through both together, and neither
alone is sufficient.

It also drops the claim that this is the last rung. Four rounds named a mechanism
and stopped looking, and the honest statement is what is currently checked and by
what, not that the question is closed forever.

Verification: `grep -c 'is the rung that ends'` returns 0 in both the design
document and `shape.rs`, and the round-trip law is named in both.
