## Changes

### CHANGE 1: `hilavitkutin/DESIGN.md.tmpl`, the refusal is sticky per binding

The appending-past-capacity paragraph said every later append on the accumulator is refused and that the accepted records stay in its live prefix. That holds on one thread only. It now says the refusal is sticky per binding, that on one thread the accumulator is one binding so the kept records are a prefix of the appends asked, and that under `run_parallel` each core appends through its own binding, so the kept records depend on the worker count while the `AccumRefused` value does not.

### CHANGE 2: `hilavitkutin/DESIGN.md.tmpl`, the regions start after the leading records

The per-core paragraph placed core c's region at `lo_c` and compacted into `[0, sum live)`, over the records the leading meta bands appended on the shared binding (ticket `521dedc08497`). It now places the region at `len + lo_c`, with its cap clipped to what is left of the capacity, and compacts into `[len, len + sum live)`. The merged live length counts the leading records, the merged `wanted` adds every refused append and saturates, and a region left with no room refuses. The region-skew sentence names the leading records as one more way a last region runs short.

### CHANGE 3: `hilavitkutin/DESIGN.md.tmpl`, every run entry resets

The `run_fused` paragraph said it never resets the accumulators, and the drain paragraph said `run` does. Both now say every run entry resets at frame start, so `run_fused`'s verdict is its own frame's. Ticket `0fb716c5a463` (the fused entry runs only the map of an appending unit) is unchanged.

### CHANGE 4: `hilavitkutin-api/DESIGN.md.tmpl`, the accumulator writer

The refusal paragraph after the bridge block said the accepted records are the prefix the frame asked for first. It now says the same as CHANGE 1, from the caller's side, and that `len` is the live length of the binding the body appends through.

### CHANGE 5: `hilavitkutin-api/DESIGN.md.tmpl`, `AccumRefused` and `RunCfg`

The section said a value is only built by the engine. `new` is public and the tests build values to compare against, so it now says `new` builds a value from its two parts, the engine builds the frame's from its counts, and a value claims nothing beyond its parts. `RunCfg::Err` is no longer read anywhere, so `DefaultRunCfg` no longer names one, the section says the error type lives inside `Out`, and the `impl RunCfg` example drops its `type Err` line.
