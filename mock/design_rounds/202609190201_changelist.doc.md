## CHANGE: the one-pointer closure FROM a sentence in the engine design TO a contract the api names and the engine forces

Files: `mock/crates/hilavitkutin-api/DESIGN.md.tmpl` (Platform traits), `mock/crates/hilavitkutin/DESIGN.md.tmpl` (Platform implementations).

The api design says what every closure the engine hands `ThreadPoolApi::spawn` is: no wider and no more aligned than one pointer, so an executor can move it into a thread's argument slot without allocating. The api names that as `OnePointerClosure<F>`, whose associated const fails the build for a wider or over-aligned `F` at monomorphisation; the engine forces it at its spawn site, and an executor may force it too. The engine design's sentence points at the gate.

## CHANGE: the threads the engine owns FROM joined, pinned and provided TO none

Files: `mock/agent/rules/cookbook.md.tmpl` ("I need threading"), `mock/DESIGN.md.tmpl` (module table, Thread pool + Executor), `mock/PRINCIPLES.md.tmpl` (Pre-allocated thread pool), `mock/crates/hilavitkutin/DESIGN.md.tmpl` (module table), `mock/agent/rules/implementation.md.tmpl` (Static composition), `mock/agent/MAIN.md.tmpl` (the pool bullet).

Op: "Consumer supplies it". The cookbook says the consumer's executor provides the implementation. `Scheduler::Drop` signals shutdown and waits on the exit counter until every worker has left its mainloop; there is no handle to join. The pool is the consumer executor's: the engine sizes its per-core programs by the executor's worker count and chooses a core assignment, and pinning a thread to a core is the executor's, as the engine backlog already says. The thread module's table row and the plan parameter say core assignment, not core pinning.

File: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl` (Entry point).

## CHANGE: the worker count the engine runs on FROM whatever the executor reports TO clamped into `1..=MAX_CORES`

File: `mock/crates/hilavitkutin/DESIGN.md.tmpl` (Platform implementations).

The design was silent. The engine's per-core state is sized by `MAX_CORES`; past it the extra workers are never handed a closure. At zero the engine hands the executor one closure anyway, since a frame nobody runs would return as though it ran.

## CHANGE: persistence's dependencies FROM str and rkyv TO str, api and the substrate

Files: `mock/crates/hilavitkutin-persistence/DESIGN.md.tmpl` (Dependencies), `mock/mockspace.toml` (the comment over the ecosystem `forbidden-imports` lines).

Op: "Builds on str and api". The list names `hilavitkutin-str`, `hilavitkutin-api` for `MemoryProviderApi`, and arvo and notko, and says `rkyv` is the archive format the file-backed round takes on, not yet a dependency. The lint comment stops saying the ecosystem crates have no cross-dependencies.
