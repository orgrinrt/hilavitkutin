# Source changelist: sym peer collision and a generic kind width

**Phase:** IMPL
**Doc changelist:** `202608082215_changelist.doc.lock.md`
**Scope:** `mock/crates/hilavitkutin-sym/src/**`, `tests/**`.

## The shape, as the locked doc changelist settled it

One trait carries the layout. `Standard` is its default impl and is
byte-identical to the current layout, so the string domain's `0b000` tag and
every baked handle survive untouched.

The widths total 32 and are therefore related by arithmetic. That arithmetic
lives in each impl, where expressions are legal, and every bound names the
trait. An inline derivation in type position would need a forbidden feature.

## CHANGE: new module `shape`, trait `SymShape`

File: `mock/crates/hilavitkutin-sym/src/shape.rs`

```
SymShape
  KIND_BITS / ORIGIN_BITS / COUNTER_BITS   as associated consts
  Kind / Origin / Counter                  as associated Bits types
```

`Standard` implements it at kind 3, origin 0, counter 28. `ORIGIN_BITS` of zero
means one origin, which is the single-minter case and the current behaviour.

Verification: `grep "pub trait SymShape" src/shape.rs` returns one match;
`grep "impl SymShape for Standard" src/shape.rs` returns one match.

## CHANGE: `SymKind` FROM `SymKind(Bits<3, Hot>)` TO `SymKind<S: SymShape>(S::Kind)`

File: `mock/crates/hilavitkutin-sym/src/kind.rs`

The tag takes its width from the shape. `from_raw` keeps its ergonomic
literal constructor and its existing lint allowance.

Verification: `grep "pub struct SymKind" src/kind.rs` shows the shape parameter.

## CHANGE: `Domain::KIND` FROM `SymKind` TO a shape-parameterised tag

File: `mock/crates/hilavitkutin-sym/src/domain.rs`

A domain declares the shape it belongs to, so a domain of one shape cannot
supply a tag to a producer of another. `InterningDomain` and `GenerativeDomain`
inherit it unchanged in every other respect.

Verification: `grep "type Shape" src/domain.rs` returns one match.

## CHANGE: `Sym` and `SymLayout` become shape-parameterised

File: `mock/crates/hilavitkutin-sym/src/handle.rs`

`Sym` carries its shape. The bitfield declaration stays as `Standard`'s layout
and the generic form derives its field positions from the shape's widths.
`repr(transparent)`, `Copy`, and integer equality over the whole layout are
unchanged, which is the crate's central promise and must not move.

Verification: `cargo test -p hilavitkutin-sym` passes the existing layout
assertions unchanged for `Standard`.

## CHANGE: `Generator::new` FROM a zero-seeded constructor TO an origin-taking one

File: `mock/crates/hilavitkutin-sym/src/generator.rs`

**This is the defect.** `Generator::new` set the counter to `ZERO` and `mint`
stepped it by one, so two generators for one domain emitted bit-identical
handles, comparing equal rather than merely failing to match.

A generator is constructed for an origin. Under a shape with `ORIGIN_BITS = 0`
there is exactly one origin, and the constructor for that case takes no argument,
so the engine's single-minter use is unchanged. Under a shape with origin bits,
the only constructor available takes the origin, so a collision requires two
peers to claim the same origin explicitly.

Pre-1.0, so the old `new` is removed rather than deprecated, per the workspace
rule against legacy shims.

`mint` composes origin and counter into the id field. The exhaustion contract is
unchanged in kind: at the counter ceiling it returns `Maybe::Isnt` rather than
wrapping, and the ceiling is now the shape's counter width rather than a fixed
28.

Verification: `grep "pub fn mint" src/generator.rs` returns one match, and the
new test below fails without the change.

## CHANGE: new test, two origins never collide

File: `mock/crates/hilavitkutin-sym/tests/origins.rs`

The test that would have caught this. Two generators of one domain at two
origins, minting the same count each, must produce zero equal handles. Under a
single-origin shape the same test asserts that one generator's mints are
pairwise distinct, which is the contract the old wording actually gave.

**It must fail against the current code**, and that is recorded here as a lock
criterion rather than assumed: a test written for a fixed defect that passes
before the fix is not evidence of anything.

## CHANGE: `hilavitkutin-str` and other consumers take `Standard` explicitly

Files: whatever `cargo check` names.

The string domain keeps its `0b000` tag and its flag semantics under `Standard`.
Consumers name the shape where the type demands it and change in no other way.
If any consumer needs more than a type parameter added, that is a finding and
goes in this changelist rather than being absorbed silently.
