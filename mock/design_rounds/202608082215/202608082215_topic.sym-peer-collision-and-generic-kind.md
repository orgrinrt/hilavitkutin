# Topic: a minted Sym is not unique across peers, and its kind width is fixed at three bits

**Phase:** TOPIC
**Scope:** `hilavitkutin-sym`. Two defects in the interned-identity core, found by a consumer design panel that proposed to build on it.

## Where this comes from

A design panel for a downstream consumer proposed `Sym` as its identity carrier
and then tested the premise it was relying on: that two peers' handles cannot
collide. They can. The panel measured 132 of 144 scenarios false-identifying,
including all 24 in which the two peers shared no value at all.

That result is about this crate rather than about the consumer, so it is fixed
here. The second defect surfaced in the same reading: the three-bit kind width is
a hardcoded policy, and a consumer that needs four domains and a consumer that
needs forty both get eight.

## Defect one: every generator starts at zero

`Generator::new` sets its counter to `ZERO` and `mint` steps it by one. Two peers
each holding their own generator for the same domain therefore emit
**bit-identical** sequences: peer A's first mint and peer B's first mint are the
same 32 bits.

`Sym` compares by integer equality over the whole layout, and that is the
crate's central promise. So two unrelated things minted on two peers compare
**equal**, which is worse than the alternative. If handles from different peers
were merely incomparable, a consumer would get a wrong answer it could detect.
Falsely equal is silent: nothing looks broken.

The crate's own documentation makes the shape of the problem clear without
naming it. `mint` returns `Maybe::Isnt` once the 28-bit space is exhausted,
"rather than wrapping the counter and reissuing a live id", so the design already
holds that reissuing a live id is unacceptable. Two peers reissuing each other's
ids is the same fault arriving from a direction the counter cannot see.

The engine's single-process use never hits this, which is why it has stood. A
consumer with more than one minter for one domain does hit it, on its first two
mints.

Directions worth weighing in the doc changelist, none settled here:

- **Make the origin part of the handle.** Split the id into an origin field and a
  counter, so two peers occupy disjoint id ranges by construction. Costs id
  space, and the split width is another fixed policy unless it composes with
  defect two.
- **Make the origin part of the generator, not the handle.** A seeded
  constructor partitions the space by convention. Cheaper, and it cannot be
  enforced: nothing stops two peers choosing the same seed.
- **Make single-minter a type-level property of the domain.** A domain declares
  whether it is minted in one place or many, and only the second form can be
  constructed with an origin. Illegal states become unrepresentable, which is the
  house discipline, at the cost of a second marker trait.
- **Refuse to solve it here and document it.** A minted handle is meaningful only
  within one producer, stated as a contract. Cheapest, and it pushes a sharp edge
  onto every consumer, which is the failure the stack exists to prevent.

## Defect two: the kind width is a hardcoded three bits

`SymKind` wraps `Bits<3, Hot>` and the layout gives kind three bits, id
twenty-eight, flag one. Eight domains, always. A consumer wanting four domains
pays five wasted domain slots it cannot convert into id space; a consumer wanting
sixteen cannot have them at all.

The width is a consumer policy wearing a substrate constant, which is the
`toolbox not policer` distinction this stack draws.

**The constraint that shapes the answer.** The widths are related by arithmetic:
`id = 32 - 1 - kind`. Writing that relation inline puts an expression in type
position, which needs `generic_const_exprs`, which is forbidden. The workspace
rule for exactly this shape is to carry the derived quantity as a **trait
contract** with associated types and consts, so the arithmetic happens in an impl
where expressions are legal and the bound names a contract instead.

So the direction is a `SymShape`-style trait carrying the kind and id widths and
their `Bits` types, with the current three-and-twenty-eight split as one impl and
the default. What the trait is called, whether the flag bit is part of it, and
whether `Sym` becomes generic over it or gains a second generic form, are the doc
changelist's questions.

**Compatibility.** The string domain is fixed at kind `0b000` for
byte-compatibility with baked string handles, and that must survive. Any shape
that keeps the default split keeps that property; a consumer choosing a different
split is choosing a different handle format and does not interoperate with baked
handles, which is a statement the design should make rather than leave implicit.

## What this round also carries

The launcher migration topic in this round left three strands, and two were
incomplete on `dev`:

- The `[build-dependencies]` mockspace entry survived in
  `hilavitkutin-persistence`, and the workspace `mockspace` dependency survived
  in `mock/Cargo.toml`. There is no `build.rs` anywhere in the workspace, so the
  dependency did nothing except pin an engine revision. That revision no longer
  exists on the mockspace remote, so **a fresh clone of `dev` could not build**;
  only a machine with a warm cargo cache could.
- Four local lints in `mock/lints/` were superseded by the renamed pack, which
  now registers `no-alloc`, `no-runtime-registration`, `no-runtime-spawn` and
  `no-std`. Registered twice, they made the gate refuse to run at all. The two
  genuinely local lints stay.

Both are harness plumbing and neither touches crate source or design documents,
matching the launcher-migration topic's own scoping.

## The gate, and why the red is not what it looked like

The launcher-migration topic recorded pre-existing red and blessed one
`--no-verify` for its own commit, saying the next source commit in those crates
would be the one to clear it. This is that commit, so the red was measured.

Most of it was not real. The pack's split-trait migration left every lint on the
engine's new `per_file` default of `true`. Seven lints walk `all_sources`
themselves, so each finding was reported once per file in the crate, and `no-std`
additionally reported every module file as a crate root missing its attribute.
Against this workspace that inflated roughly 400 real violations into roughly
4,660.

That is a defect in the pack rather than here, and it is fixed there. With it
fixed, `hilavitkutin-sym` passes the commit gate clean, which is what lets this
round open its source window honestly rather than under a blessing.

The remaining workspace-wide debt is real and belongs to the engine-completion
arc, untouched by this round.
