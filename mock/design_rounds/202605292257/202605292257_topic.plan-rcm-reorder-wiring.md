## Current state

Plan step 4 (`steps::rcm_reorder`, `plan/steps.rs:209`) is a pass-through stub: it ignores the dependency graph and returns the topological order unchanged. The runner (`plan/mod.rs:344`) calls it and discards the result into a `_reordered` binding. The C1a adapter (`DependencyGraph::to_csr_bidirectional`, merged) and arvo's loose-CSR `rcm_reorder_via` are both in place, so the stub can be replaced with the real bandwidth-reduction reordering.

## Change

Replace the stub with a real Reverse Cuthill-McKee pass. `rcm_reorder` builds the bidirectional CSR via the C1a adapter, calls `arvo_sparse::rcm_reorder_via`, and converts the resulting `NodeId` permutation back to `UnitId`. The runner stops discarding the result and persists it on `ExecutionPlan`.

The reordering is not the dispatch order. Dispatch stays topological: the `unit_meta` array remains topo-position-indexed, so every unit still runs after its dependencies. RCM produces a bandwidth-minimising permutation over the undirected dependency adjacency. Per `DESIGN.md.tmpl:45` and the consolidated core-design renumber section, that permutation feeds arena layout (and, in a later sub-round, fiber grouping order). C1b wires the arena-layout half: compute the permutation through the C1a adapter and carry it on the plan for the dispatch-codegen pass (C2) to consume. The permutation is a renumber, computed once at plan time, zero runtime cost, exactly the renumber shape the consolidated core design describes.

## Out of scope

Block-diagonal (step 5, C1c) and spectral (step 6, C1d) stay stubbed. The fiber-grouping-order consumption of the RCM permutation is deferred to C1d, where the spectral-versus-greedy reconciliation is settled by bench, not by hand.
