# api-surface-says-what-ships

**Date:** 2026-11-14
**Scope:** `hilavitkutin-api` design text, rustdoc and diagnostics; the api items nothing uses; `hilavitkutin-providers` docs that name the api.
**Source topics:** tickets `diagnostics_name_builder_methods_that_do_not_exist`, `hilavitkutin_api_keeps_trunkcons_phasecons_trunknil_phasenil`, `standardcodegen_claims_lock_free_dispatch_with_an_empty_core`, `hybridexecutor_run_is_a_no_op_that_reports_success`, `hilavitkutin_hilavitkutin_api_design_md_tmpl_980_still_shows`, `the_first_sections_of_the_api_design_still_name_provider_pro`.

The api crate is the contract a consumer writes against, and three of its surfaces say things the source does not: the design template, the rustdoc, and the diagnostics a refused bound prints. Measured on `33c8c2f3`.

## The design template

`mock/crates/hilavitkutin-api/DESIGN.md.tmpl` opens on a `Provider` trait with `const KIND: ProviderKind`, a `ProviderKind` enum, a `LinkedBin<T: ?Sized>` marker and a `Dispatch` with GATs. The source has `BuilderInput` (`type Init; type Dispatch;`, unsealed), `Dispatch<Wus, Stores, Platform>` as a trait parameterised by the three accumulators, the routers `UnitDispatch`, `StoreDispatch`, `PlatformDispatch` (and `KitDispatch` in the kit crate), and `ExtensionSurface<T: ?Sized>` in place of `LinkedBin`. There is no `ProviderKind`. The names recur through the WorkUnit, Kit, store and map sections (lines 17 to 140, 296, 336 to 352, 850 to 880, 1212, 1251 to 1262, 1426 to 1438, 1528).

Two sealing snippets show shapes the crate does not use: `Depth` at line 1334 carries `#[allow(private_bounds)]`, and `Executor` at line 1622 seals through `mod private`. The crate has one seal, `mod sealed { pub trait Sealed {} }` at `src/lib.rs:19`, public inside a private module, so no `private_bounds` allow is needed anywhere and none is left in src.

## The rustdoc and diagnostics

`src/builder_input.rs`: the module doc says `Dispatch` declares three GATs, the `NextPlatform` docs call the builder two-parameter (it has six), a doc names a `SchedulerBuilder::extend` that does not exist, and the `on_unimplemented` note on `BuilderInput` says it is sealed, which it is not. `src/work_unit.rs:233` names `.add_unit::<W>()`. `src/store.rs` names `add_kit` and says `Replaceable` opts into `replace_resource`, where `replace_value` is the one bounded on it (`hilavitkutin/src/scheduler/dirty.rs:97`). `src/platform.rs:411` says `Sealed` is `pub(crate)`. In providers, `src/lib.rs`, `src/interner.rs`, `src/metrics/mod.rs`, `src/metrics/kit.rs` and `README.md.tmpl` name `add_resource` and `add_kit`, and the metrics module doc names the round that wrote it.

## Items nothing uses

`TrunkCons`, `PhaseCons`, `TrunkNil` and `PhaseNil` are carriers whose rustdoc names the `RunPipeline` and `RunPhase` nest a closed round deleted. The canon supersedes the nested carriers (`the_nested_value_carrier_walk_runs_a_trunk_over_a_carrier_of_fibers_and_the_scheduler_run_is_re_pointed_onto_it_in_a_later_step`, superseded by `trunk_isolation_comes_from_a_flat_carrier_walk_gated_by_const_phase_and_trunk_and_the_nested_value_carriers_are_superseded`), and nothing consumes them.

`StandardCodegen` implements `DispatchCodegen` with `type CoreDispatch = ()` and states `LockFreeDispatch` and `Scheduled`, two property markers no bound reads. The engine design (`mock/crates/hilavitkutin/DESIGN.md.tmpl:161`) intends a lowering through a `type CoreDispatch = impl Fn(..)`, which is not built. The canon carries neither marker.

`HybridExecutor::run` returns `Ok` without walking a program. The canon keeps it as the default executor (`the_executor_is_an_open_sealed_trait_monomorphised_into_the_scheduler_with_a_hybrid_default`), so it is not removed; the walk it should run is the worker mainloop in `scheduler/`, which is the engine lane's.

## What this round does

The design template is rewritten where it names what the source does not have, against the source, and the two snippets show the one seal. The rustdoc and diagnostics above say what ships. The four carriers are removed. The two marker impls on `StandardCodegen` come off with the traits, since nothing bounds on them and a property marker on an empty codegen is a false claim; the lowering that earns them brings them back. `HybridExecutor` is left as it is and handed to the engine lane.
