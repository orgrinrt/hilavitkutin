# Topic: P1 R3b — change_class numerator via store_dirty

**Date:** 2026-06-20
**Crate:** hilavitkutin (engine) + hilavitkutin-api (SchedulerMetrics)
**Tracked:** #341 (P1 adapt), completion-arc R3b

## Hypothesis

The change_class adapt axis (input-drift classification, domain-22 :2019-2026)
reuses the existing `store_dirty: Cell<AccessMask<D::Stores>>` signal: a frame
whose store_dirty was non-empty saw an input change. Count those frames into a
`SchedulerMetrics.change_seen_count` scalar so an `OnMeta` hook derives the change
rate. No new instrumentation.

## Test vehicle

`store_dirty` is only set via `replace_resource<T: PlanAffecting>`, and
`PlanAffecting` is `sealed::Sealed`, so an external `tests/` integration test
cannot trigger it. The test is therefore an INTERNAL `#[cfg(test)]` white-box test
in `scheduler/mod.rs`: build a scheduler with one registered store, set
`store_dirty` directly to a non-empty mask, run a frame, assert
`meta_block.metrics.change_seen_count` incremented; a clean frame does not. Reads
the engine-internal field directly (in-crate), no consumer Ctx needed.

## Change

Add `change_seen_count: Cell<USize>` to `SchedulerMetrics`. In the single-core
`run` fold, capture `!store_dirty.is_empty()` before the reset, increment the
count if changed. Single-core `run` only; parallel/fused follow.
