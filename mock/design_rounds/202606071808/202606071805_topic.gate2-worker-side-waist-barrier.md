# Topic: GATE-2 worker-side waist barrier (deviation §4 reconciliation)

**Date:** 2026-06-07
**Phase:** TOPIC
**Scope:** `hilavitkutin-api` (`PoolFrame`), `hilavitkutin` (`thread/barrier.rs`, `scheduler/mod.rs`), engine tests
**Source:** deviation ledger `mock/research/202606072100_gate2-canonical-deviation-ledger.md` §4; bench evidence `mock/benches/engine_vs_std` (commit `ac1b305`); canonical spec domain 17 (`:1601-1633`) + Topic 6 axis I (barrier).

## Current state

`Scheduler::run_parallel` is **main-orchestrated** (deviation §4, an agent-call with a stated bench trigger). Per frame the main thread publishes each waist-bounded phase as a separate frame-protocol step and waits every worker done before publishing the next:

```
while p < nphases { frame_publish(pool); frame_await_done(pool, ncores); }
```

Each worker (`worker_main`) does ONE phase per wake, deriving the phase from the sequence value (`p = (seq - 1) % nphases`), then `frame_done_arrive`. So a frame with `nphases` phases costs `nphases` full park/wake round-trips of every worker. The shipped `phase_barrier_arrive` / `phase_barrier_reset` (`thread/barrier.rs`, centralised counter on `PoolFrame.phase_arrived`) are unused by `run_parallel`; the multi-episode barrier reset (the deferred E3 in the keystone sketch) was sidestepped because the naive arrive+reset has a sense-reversing race.

## Why change it (bench-justified, the §4 trigger is met)

The deviation ledger set the trigger: "if per-phase parking dominates, the canonical worker-side barrier is the escalation." The expanded bench now shows it does. `wide_parallel` (4 column-disjoint heavy trunks) parallel ratios: **2.45x at N=4096**, then 0.53x / 0.34x / 0.28x at 64K / 1M / 4M. The small-N 2.45x is the per-frame barrier cost: two phases (the wide arm is one phase, but multi-phase workloads pay per phase) and the publish/await round-trips dominate a frame that does microseconds of real work. The win is already there at scale; the small-N loss is the main-orchestrated barrier, exactly what §4 predicted.

## Canonical position

Spec domain 17 (`:1601-1633`): each core runs a compiled program that sequences its own fibers and hits phase-sync points internally; "spawn N threads, each runs its compiled program, join when complete. No scheduler loop." The barrier is **worker-side**, inside the per-core program: workers stay hot across phases within a frame and synchronise at each waist via a stack-atomic spin / futex, not a main-thread round trip per phase. Topic 6 axis I specifies the centralised counter (last arriver resets + wakes).

## Change proposed

Move the waist barrier worker-side, so a frame is ONE publish/await round-trip regardless of phase count; workers cross each waist via a **sense-reversing barrier** (the correct fix for the deferred-E3 reset race).

1. **`hilavitkutin-api` `PoolFrame`**: add `pub barrier_sense: AtomicU32` (the generation/sense word the reversing barrier flips each episode). Init `0` at every construction site (the bench `PoolFrame{}` literals, `empty_pool_frame()`, and any test constructors). The existing `phase_arrived` stays as the count.

2. **`hilavitkutin` `thread/barrier.rs`**: add `waist_barrier(pool, expected)` (sense-reversing, futex-backed):
   - snapshot `let sense = pool.barrier_sense.load(Acquire)`;
   - `let prior = pool.phase_arrived.fetch_add(1, AcqRel)`;
   - if `prior + 1 == expected`: `phase_arrived.store(0, Relaxed)` then `barrier_sense.store(sense + 1, Release)` (or `fetch_add(1)`), then `atomic_wake_all(&pool.barrier_sense)`;
   - else: loop `atomic_wait(&pool.barrier_sense, sense)` until `barrier_sense.load(Acquire) != sense`.
   This is reusable `nphases - 1` times per frame with no reset race: a fast worker that loops to the next episode waits for the NEXT sense flip, never the stale count. Keep `phase_barrier_arrive`/`reset`/`observe` (the adapt subsystem reads `phase_arrived` via `observe`); `waist_barrier` is the new dispatch-path primitive. (Decide at SRC time whether `waist_barrier` supersedes `phase_barrier_arrive` for dispatch and the old fn stays adapt-only, per no-legacy-shims: if nothing else calls `phase_barrier_arrive`, fold it in.)

3. **`hilavitkutin` `scheduler/mod.rs`**:
   - `run_parallel` main side: replace the `while p < nphases { frame_publish; frame_await_done }` loop with a single `frame_publish(pool); frame_await_done(pool, ncores)` per frame.
   - `worker_main`: per wake, run ALL phases hot:
     ```
     last = frame_await(&s.pool, last);
     if shutdown { frame_exit_arrive; return; }
     for p in 0..nphases {
         s.run_core_phase::<Witnesses>(&s.gate2_phase, &s.gate2_trunk, s.gate2_n,
             USize(core_id), USize(p), ncores, total, msize);
         if p + 1 < nphases { waist_barrier(&s.pool, ncores); }
     }
     frame_done_arrive(&s.pool, ncores);
     ```
   - The phase derivation `p = (seq-1) % nphases` is gone (workers no longer do one-phase-per-wake); each wake is one full frame.

4. **Tests**:
   - `tests/gate2_run_parallel.rs` fan-in (2 phase-0 producers + waist + phase-1 combiner) must stay correct: the combiner runs only after both producers, now enforced by the worker-side `waist_barrier`, not the main round-trip. The checksum (`Av + Bv`) catches a broken barrier.
   - Add a **3-phase** fixture (producer -> mid -> sink, two interior waists) so the sense-reversing barrier is exercised TWICE per frame, across multiple frames (`mark_dirty` + re-run), asserting correctness on barrier REUSE (the property the deferred-E3 reset race would have broken).
   - `tests/frame_protocol.rs` is unaffected (`frame_publish`/`frame_await`/`done` unchanged; only the per-frame phase loop moves worker-side).

## Validation / how red moves

After this lands, re-measure `wide_parallel` parallel at N=4096: the per-frame cost drops from `nphases` round-trips to one, so the small-N parallel ratio should fall well below the current 2.45x (toward the 1.60x gate ceiling and below). Large-N parallel stays a win (the barrier was already amortised there). No single-core arm changes (`run()` is untouched). branching/accumulator single-core stay red-by-design (this barrier is a parallel-path mechanism; their gaps are materialisation/dispatch, separate gates).
