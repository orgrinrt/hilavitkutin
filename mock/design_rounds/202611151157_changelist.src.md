# src changelist

Round topic `202611151157_topic.hilavitkutin-build-sets-a-consumer-up.md`, doc changelist `202611151157_changelist.doc.lock.md`. The other flat topic, `202607200100_topic.b1-cap-lifting-completion.md`, is about the scheduler's scratch arrays and takes nothing from this changelist either.

The source follows the sketch `mock/research/sketches/202611191725_script-macro-offered-from-a-no-std-crate/`, where the whole mechanism ran: the macro from a `no_std` crate, the first build that wires, a `config.toml` left alone, a git checkout and an unpacked crate declined, and `cargo package` passing its verify build.

## mock/crates/hilavitkutin-build/src/prototype.rs (new)

- `Prototype`, an enum of the scripts the crate offers: `Default` and `Deterministic`.
- `Prototype::tune`, a `const fn` over `PragmaSet`: `Default` returns the set as it is, `Deterministic` returns it without `FastMath`.
- `Prototype::configure`, which resolves the build through the script's `Env` closure and writes the directives. It writes no warning of its own, since `script!` says the one thing there is to say after it has looked at the wiring.

## mock/crates/hilavitkutin-build/src/wiring.rs (new)

- `WRAPPER_NAME`, the wrapper's file name, which `bootstrap.rs` now reads instead of spelling it twice.
- `Tree`, whose the workspace root is: `Own`, or `Fetched` for a root under `CARGO_HOME` or one that holds `Cargo.toml.orig`.
- `WrapperFile` (`Current`, `Stale`, `Missing`) and `ConfigFile` (`Named`, `Unnamed`, `Missing`), what the script found on disk. `ConfigFile::read` decides `Named` or `Unnamed` from the file's text, by a `rustc-workspace-wrapper` key whose value ends with `WRAPPER_NAME`.
- `Plan`, what the script does next: whether it writes the wrapper, whether it writes the config file, and which `Notice` it prints. `Notice` is `Silent`, `Wired` (the files were written and the next build takes the flags), `AddLine` (a `config.toml` exists without the line) or `Dropped` (the wiring is in place and cargo names another wrapper).
- `plan`, a `const fn` from the value of `RUSTC_WORKSPACE_WRAPPER`, the `Tree`, the `WrapperFile`, the `ConfigFile` and whether the prototype writes flags, to a `Plan`. A `Fetched` tree writes nothing and says nothing. A wrapper named as ours or as `clippy-driver` is silent. A `Dropped` notice is held back where no pragma writes a flag, as the warning of `configure_with` is today.
- `write_cargo_config`, the text of the `config.toml` written where there is none: a `[build]` table with the one line.
- `write_notice`, the `cargo::warning` line of a `Notice`, naming the directory written to or the line to add.

## mock/crates/hilavitkutin-build/src/script.rs (new)

- `script!`, exported with `#[macro_export]`, taking a `Prototype` variant by name. Its expansion is the script's std code: it prints what `Prototype::configure` wrote, asks `cargo locate-project --workspace` from `CARGO_MANIFEST_DIR`, reads the two files, calls `plan`, writes what the plan names (the wrapper with mode 0755 on unix) and prints the notice. It names `::std` by absolute path and `$crate` for everything of the crate's. Where cargo gives no root it prints one warning and writes nothing. Where `CARGO_HOME` is not set it takes `.cargo` under the home directory.

## mock/crates/hilavitkutin-build/src/bootstrap.rs

- `write_directives` writes `cargo::rerun-if-env-changed=RUSTC_WORKSPACE_WRAPPER` in place of `cargo::rerun-if-changed=build.rs`. A script kept at another path made the old line name a file that is not there, which has cargo rerun the script on every build.
- `configure_with` keeps its warning for a script that calls it directly, and shares the resolving half with `Prototype::configure`.
- The module doc shows the one-line script.

## mock/crates/hilavitkutin-build/src/lib.rs

- `prototype`, `wiring` and `script` are declared, and `Prototype`, `Tree`, `WrapperFile`, `ConfigFile`, `Plan`, `Notice`, `plan`, `write_cargo_config`, `write_notice` and `WRAPPER_NAME` are exported. The crate doc says the script is one line and that the first build writes the wiring.

## The thirteen build scripts

- `mock/crates/<crate>/build.rs` of `hilavitkutin`, `-api`, `-api-macros`, `-conformance`, `-ctx`, `-extensions`, `-extensions-macros`, `-kit`, `-linking`, `-persistence`, `-providers`, `-str` and `-sym` becomes `fn main() { hilavitkutin_build::script!(Default); }` under its doc line.
- `mock/crates/hilavitkutin-frozen-authors/build.rs` stays as it is. The file is in that crate's `LEDGER.toml`, and it is a consumer's script written against `configure`, which keeps working. It is the one script that holds the older call to its contract.
- `mock/.cargo/config.toml` and `mock/.cargo/hilavitkutin-rustc-wrapper` stay committed and unchanged: they are what the first build of this workspace would write.

## mock/crates/hilavitkutin-build/tests/wiring.rs (new)

- `plan` over the whole product of its inputs, against a table written out by hand: every wrapper value (unset, empty, ours, `clippy-driver`, another), both trees, three wrapper files, three config files, flags or none.
- The cases that must fail are stated in it: a `Fetched` tree with every file missing plans no write, and a `Stale` wrapper in a wired workspace plans the write with a silent notice.
- `ConfigFile::read` over texts that name the wrapper, name another wrapper, name none, and carry the key in a comment.
- `write_cargo_config` and each `write_notice` as literal text, and a refusing writer is reported by both.

## mock/crates/hilavitkutin-build/tests/prototype.rs (new)

- `Deterministic` writes no `arvo_fast_math` cfg and keeps the loop flags; `Default` writes what `configure` writes less the warning; neither writes a `cargo::warning`.

## mock/crates/hilavitkutin-build/tests/script.rs (new)

- A scratch workspace under the test's temporary directory, one crate whose script at `scripts/anywhere.rs` is the one line, built by the pinned cargo offline with no wrapper named: both files appear, the wrapper has the text of `write_wrapper` and its executable bit, and the build prints the `Wired` notice once. A second build with the written config prints no notice.
- The same workspace with a `config.toml` that has no line: the file is byte-identical after the build and the notice names the line.
- The same workspace holding `Cargo.toml.orig`: nothing is written.
- This binary builds through cargo three times, so it is marked heavy in the test configuration.

## mock/crates/hilavitkutin-build/tests/bootstrap.rs

- `the_committed_wrapper_is_the_written_one` is deleted: the script keeps the file to the text.
- `the_wrapper_appends_the_variable_and_nothing_else` runs the text of `write_wrapper` written to the test's temporary directory, in place of the committed copy.
- The literal directives in three tests take the new rerun line.

## What a consumer sees

`script!` and `Prototype` are added, and the first line `write_directives` writes changes. `configure`, `configure_with`, `write_wrapper` and the rest keep their signatures, so kaski's and loru's scripts build as they are and move to the one line when they choose.
