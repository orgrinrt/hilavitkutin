## mock/crates/hilavitkutin-build/src/prototype.rs (new)

- `Prototype`, an enum of the scripts the crate offers: `Default` and `Deterministic`.
- `Prototype::tune`, a `const fn` over `PragmaSet`: `Default` returns the set as it is, `Deterministic` returns it without `FastMath`.
- `Prototype::configure`, which resolves the build through the script's `Env` closure, writes the directives, and hands the resolved `BuildConfig` back in a notko `Outcome`. It writes no warning.

## mock/crates/hilavitkutin-build/src/wiring.rs (new)

- `WRAPPER_NAME`, the wrapper's file name, which `bootstrap.rs` reads.
- `Tree`, whose the workspace root is and whether the host can run the wrapper: `Own`, `Fetched` for a root under `CARGO_HOME` or one that holds `Cargo.toml.orig`, `NoShell` for a host that is not unix, and `Foreign` for a root other than the one the wrapper cargo names sits in.
- `Tree::of`, a `const fn` that decides the tree from the root, the cargo home, whether the root holds `Cargo.toml.orig`, whether cargo's wrapper sits elsewhere, and whether the host is unix. A root is under the cargo home by whole path components.
- `WrapperFile` (`Current`, `Stale`, `Missing`) and `ConfigFile` (`Named`, `Unnamed`, `Missing`). `ConfigFile::read` decides `Named` or `Unnamed` from the file's text: a `rustc-workspace-wrapper` key whose value is a path with the file name `WRAPPER_NAME`, read under the `[build]` table, as the dotted `build.rustc-workspace-wrapper` at the top of the file, or inside an inline `build = { .. }` table, and nowhere else.
- `Plan`, what the script does next: whether it writes the wrapper, whether it writes the config file, and which `Notice` it prints. `Notice` is `Silent`, `Wired`, `AddLine`, `Dropped` or `NoShell`.
- `plan`, a `const fn` from the value of `RUSTC_WORKSPACE_WRAPPER`, the `Tree`, the `WrapperFile`, the `ConfigFile` and whether the prototype writes flags, to a `Plan`. A `Fetched` or `Foreign` tree writes nothing and says nothing. A `NoShell` tree writes nothing and says `NoShell` where there are flags. The wrapper variable names the wrapper by its file name, and `clippy-driver` the same way.
- `write_cargo_config`, the text of the `config.toml` written where there is none.
- `write_notice`, the `cargo::warning` line of a `Notice`. The `Wired` line says the wiring is in place and a build of that workspace takes the flags from the next one on. The `Dropped` line says cargo was started without the wrapper the config file names, in words that hold for the first build of a workspace of several members and for a cargo started elsewhere.
- `write_watch`, the two `cargo::rerun-if-changed` lines that name the wrapper and the config file.

## mock/crates/hilavitkutin-build/src/script.rs (new)

- `script!`, exported with `#[macro_export]`, taking a `Prototype` variant by name. Its expansion writes the prototype's directives to standard output, asks `cargo locate-project --workspace` from `CARGO_MANIFEST_DIR`, calls `Tree::of`, reads the two files, calls `plan`, writes what the plan names (the wrapper with mode 0755), prints the notice, and in an `Own` tree prints what `write_watch` writes. Where cargo gives no root it prints one warning and writes nothing. Where `CARGO_HOME` is not set it takes `.cargo` under the home directory.
- Cargo's wrapper sits elsewhere where `RUSTC_WORKSPACE_WRAPPER` names a file called `WRAPPER_NAME` that is not this root's own wrapper file, both paths made canonical where they can be.
- Each file is written under a name of the script's own beside its place and then moved there: the wrapper by a rename, and the config file by a hard link, which refuses where a file is already there. A config file another script wrote in the meantime is left as it is.
- The expansion keeps no text in memory: a sink over `std::io::Write` takes the crate's texts to standard output or the file, and a sink that compares holds the wrapper on disk to `write_wrapper`.
- The lint `forbidden-imports` reads the macro's body as this crate's own imports. Its `use` lines of std carry a `lint:allow` naming the ticket `forbidden_imports_reads_the_body_of_an_exported_macro_as_the` until the lint's fix lands in mockspace and this repository's pin moves to it; the allows go in the commit that moves the pin.

## mock/crates/hilavitkutin-build/src/bootstrap.rs

- `configure_with` keeps its warning for a script that calls it directly, and shares the resolving half with `Prototype::configure`.
- The module doc shows the one-line script.

## mock/crates/hilavitkutin-build/src/lib.rs

- The crate doc no longer says the crate writes the generated config file as part of every script, or that `bootstrap` carries the whole `build.rs`.

## mock/crates/hilavitkutin-build/tests/wiring.rs (new)

- `plan` over the whole product of its inputs. What is said comes from a table of thirty-six rows written out by hand, a wrapper whose path only ends with the wrapper's name among them, and what is written from two more, one row for each `WrapperFile` and each `ConfigFile`, every expected value a literal.
- A `Fetched` and a `Foreign` tree plan no write and no notice over the same product, and a `NoShell` tree plans no write and its notice where there are flags.
- `Tree::of` over a table of roots, cargo homes and the three flags, a root that only shares the cargo home's leading letters among them.
- `ConfigFile::read` over texts that name the wrapper in each of the three forms, and over texts that name another wrapper, a wrapper whose name only ends with ours, none, the key in a comment, or the key under another table.
- `write_cargo_config`, each `write_notice` and `write_watch` as literal text, and a refusing writer is reported by all three.

## mock/crates/hilavitkutin-build/tests/prototype.rs (new)

- Over both profile names cargo passes and an unknown one: `Default` writes what `configure` writes less the warning, `Deterministic` writes what `configure_with` without `FastMath` writes, and neither writes a `cargo::warning`.
- `Prototype::tune` over the default set of every `Profile`.

## mock/crates/hilavitkutin-build/tests/script.rs (new)

- A scratch workspace built by the pinned cargo offline, with a rustc that writes its arguments down. The first build writes both files, the wrapper with its executable bit, and prints the `Wired` notice once, and the crate's rustc has no flag of ours. The second build prints no notice, and the crate's rustc takes the flags.
- A workspace of eight members built with eight jobs: the first build leaves both files whole, at least one script says `Wired`, every other says `Wired` or `Dropped`, and none says the wiring could not be written. The second build says nothing and every member's rustc takes the flags.
- A wrapper overwritten with another text in the wired workspace is written again by the next build. Cargo dates a script's run from its start, so the build after that runs the script once more, which writes nothing, and the one after it compiles nothing.
- A `config.toml` without the line is byte-identical after the build and the notice names the line.
- A workspace holding `Cargo.toml.orig` is written nothing.
- A workspace whose `.cargo` cannot be made says the wiring could not be written, and the build passes.
- A workspace under a directory whose `.cargo/config.toml` names the wrapper there is a `Foreign` tree: nothing is written into it, and its crate takes the flags.
- A path dependency that is a member of a second workspace: the second workspace is wired, in the first build of the outer workspace and again in a later one, and the dependency's rustc takes no flag. This is the case the design states it cannot tell apart, held as it is.
- Not held by a build: the `CARGO_HOME` branch end to end, since a build under another cargo home has no dependency sources offline; the decision itself is `Tree::of`, held in `tests/wiring.rs`, and the sketch's git dependency shows the whole. The branch where cargo gives no root, and the host that is not unix, whose decision is `Tree::of` and `plan`.

## Comparison to deprecated changelist

### mock/crates/hilavitkutin-build/src/prototype.rs (new)

Unchanged in source. `Prototype`, `Default`, `Deterministic`, `Prototype::tune` over `PragmaSet` without `FastMath`, and `Prototype::configure` through `Env` handing back the `BuildConfig` in an `Outcome` are as the deprecated text has them.

### mock/crates/hilavitkutin-build/src/wiring.rs (new)

`Tree` gains `Foreign` and `NoShell` beside `Own` and `Fetched`, and `Tree::of` decides it, where the deprecated text had a root under `CARGO_HOME` or holding `Cargo.toml.orig` as the only ones left alone and the macro deciding. `ConfigFile::read` reads the key under `[build]` alone and by file name, where the deprecated text took it under any table, by the end of the value, and missed the inline form; `ConfigFile` keeps `Named`, `Unnamed` and `Missing`, and `WrapperFile` keeps `Current`, `Stale` and `Missing`. `write_watch` is new. `Notice` gains `NoShell`; the `Wired` and `Dropped` texts are reworded, and `Silent` and `AddLine` are unchanged, as are `Plan`, `plan`'s signature and `WRAPPER_NAME`.

### mock/crates/hilavitkutin-build/src/script.rs (new)

`script!` calls `Tree::of`, tells from `RUSTC_WORKSPACE_WRAPPER` whether cargo's wrapper sits elsewhere, writes each file beside its place and moves it there, and prints the watch lines. The question to cargo from `CARGO_MANIFEST_DIR` is unchanged.

### mock/crates/hilavitkutin-build/src/bootstrap.rs

Unchanged.

### mock/crates/hilavitkutin-build/src/lib.rs

`write_watch` joins the exports, and two sentences of the crate doc that described the script before this round are corrected.

### the thirteen build scripts

Unchanged.

### mock/crates/hilavitkutin-build/tests/wiring.rs (new)

The expected writes are literal rows, where the deprecated text's test computed them with the implementation's own expressions. The `Foreign` and `NoShell` trees, `Tree::of`, the wrapper named by a longer file name, the table forms of the config file and `write_watch` are added.

### mock/crates/hilavitkutin-build/tests/prototype.rs (new)

Every profile name and every `Profile`, where the deprecated text's test sampled the release profile alone.

### mock/crates/hilavitkutin-build/tests/script.rs (new)

The second build is held to its rustc taking the flags, which the deprecated text's test did not look at. A workspace of several members built in parallel, a stale wrapper, a `.cargo` that cannot be made, a workspace wired from above and a path dependency in a second workspace are added. The branches no build holds are named.

### mock/crates/hilavitkutin-build/tests/bootstrap.rs

One case is added, a wrapper whose path only ends with the wrapper's name.

### what a consumer sees

Unchanged, and `write_watch` is one more export.
