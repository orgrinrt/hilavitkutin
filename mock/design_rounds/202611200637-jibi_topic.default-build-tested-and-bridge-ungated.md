# Topic: the default build is what the tests run, and the interner bridge is ungated

**Date:** 2026-11-20
**Round:** 202611200637-jibi
**Source:** review pass 3, `mock/research/notes/202611200600_review-pass-3-hila-consumer-surface.md`

Round 202611200518-zrf9 put every default implementation behind a feature and left a build on default features carrying the contracts alone, as op ruled: "Default to contracts only." Review pass 3 found two places where the branch does not hold that. The engine and `hilavitkutin-providers` each name themselves as a dev-dependency with their features turned on (`os`, and `static` with `portable`), so every test of either crate builds with every implementation, and the default build a consumer gets is tested by nothing. And the bridge `impl InternerApi for StringInterner<A>` sits behind `portable` though it rests on nothing a feature gates: `hilavitkutin-str` is an unconditional dependency, and coherence refuses the impl in a consumer's crate (E0117, the probe beside the report). A contracts-only consumer with its own arena then cannot reach its interner through the contract at all.

## What this round does

The two self dev-dependencies go. The engine's tests that need the os tier already carry `cfg(feature = "os")`; each providers test binary that needs an implementation names its feature as `required-features`. `cargo mock test -p <crate>` then runs the crate's suite on its default build, and `--features` runs it with an implementation on. A compile-fail twin in each crate holds that a default build names no implementation: `OsClock` in the engine, `StaticBumpMemory` and `MemoryArena` in providers. A pass test in providers runs a consumer's own `ArenaInterner` through `InternerApi` on the default build.

The bridge moves out from behind `portable` into a module of its own and is named in the design. The frozen crate's dependency on the engine stops turning on `os`, which nothing in it uses, with its line in `BREAKS.toml`.

The smaller findings of the same pass go in with it: the engine design names both its other features, the two backlogs stop saying what the ruling made wrong, the cross-target probe's header comment, and a SAFETY comment on the free list's node write.

The feature names and the reading of "a/b" are op's to make formal and are question tickets, not this round's work.
