# Src changelist: A3b per-fiber L1 morsel-window formula

**Date:** 2026-07-16
**Phase:** IMPL (this changelist opens it)
**Doc CL:** `202607161410_changelist.doc.lock.md`

## CHANGE: trait `RunCfg` gains `L1_USABLE` / `MIN_MORSEL` / `MAX_MORSEL` consts
File: `mock/crates/hilavitkutin-api/src/run_cfg.rs`
Consumer-tunable defaults per domain 12: `L1_USABLE = USize(24_576)` (32 KB
detection-fallback times 0.75), `MIN_MORSEL = USize(64)`, `MAX_MORSEL =
USize(8192)`. Toolbox pattern (same as `MORSEL_SIZE`).
Verification: `grep -c "const L1_USABLE\|const MIN_MORSEL\|const MAX_MORSEL" mock/crates/hilavitkutin-api/src/run_cfg.rs` returns 3.

## CHANGE: scalar `ResourceFootprint` impls in the api footprint module
File: `mock/crates/hilavitkutin-api/src/footprint.rs`
Explicit `L1_BYTES = USize::ZERO` impls for the bare scalar primitives
(`u8`..`u128`, `usize`, `i8`..`i128`, `isize`, `bool`, `char`, `()`, plus
`arvo::USize` and `arvo::Bool`), via a local macro: a bare-scalar resource value
is the degenerate single-`Field` case. A blanket over `ColumnValue` is rejected
(it would make the derive a coherence conflict for every consumer struct).
Verification: `grep -c "impl ResourceFootprint for" mock/crates/hilavitkutin-api/src/footprint.rs` returns at least 2 (macro expansion sites) and `cargo check` accepts `Resource<u32>` under the new fold bound.

## CHANGE: `StoreElemBytes` arms FROM flat scalar sizes TO the R5 footprint model
File: `mock/crates/hilavitkutin/src/plan/project.rs`
`Resource<T>` / `StagedResource<T>` arms require `T: ResourceFootprint` and
report `<T as ResourceFootprint>::L1_BYTES`; the `Accum<T>` arm reports zero
(unit-outer dispatch); `Column<T>` and `Virtual<T>` are unchanged.
Verification: `grep -A2 "StoreElemBytes for Resource" mock/crates/hilavitkutin/src/plan/project.rs` shows `L1_BYTES`, and `grep -A4 "StoreElemBytes for Accum" mock/crates/hilavitkutin/src/plan/project.rs` shows `USize::ZERO`.

## CHANGE: `PlanInputs` carries the per-store size array and the morsel budget
File: `mock/crates/hilavitkutin/src/plan/inputs.rs`
New fields `store_sizes: <CS as Capacity>::Array<USize>` and `morsel_budget:
MorselBudget` (`MorselBudget { l1_usable, min_morsel, max_morsel }`, a plain
`Copy` value struct defined alongside). `plan_inputs_from_bundle` gains a
`budget: MorselBudget` parameter and a `Stores: StoreSizes<CS>` bound, filling
both.
Verification: `grep -c "pub struct MorselBudget" mock/crates/hilavitkutin/src/plan/inputs.rs` returns 1; `grep "store_sizes" mock/crates/hilavitkutin/src/plan/project.rs` shows the fill in `plan_inputs_from_bundle`.

## CHANGE: `compute_fiber_morsel_windows` FROM record-count partition TO the L1 window formula
File: `mock/crates/hilavitkutin/src/plan/steps.rs`
Signature becomes `(inputs: &PlanInputs<D::Units, D::Stores>, fibers:
&FiberGrouping<D>)`. Per fiber: union the write masks of the fiber's units,
sum `inputs.store_sizes` over the union bits, then
`(l1_usable / sum).clamp(min_morsel, max_morsel) & !3`; a zero sum takes the
`max_morsel` window. Slots past `fiber_count` stay zero. The plan runner
(`plan/mod.rs` step 9) passes the new arguments; step order is unchanged (the
topic retires the reorder premise).
An unbudgeted plan (a direct `compute_execution_plan` call whose inputs carry
`MorselBudget::ZERO`; every build path threads real consts) falls back to the
whole record range in one morsel per fiber, keeping direct-plan tests and the
core-program fiber proxy inert.
Verification: `grep -A3 "clamp" mock/crates/hilavitkutin/src/plan/steps.rs` shows the formula, and `tests/r6_morsel_window_formula.rs` passes un-ignored.

Verification: `grep -c "MorselBudget" mock/crates/hilavitkutin/src/scheduler/mod.rs` is at least 2.

## CHANGE: `r6_morsel_window_formula` FROM catalogued-ignored TO green contract
File: `mock/crates/hilavitkutin/tests/r6_morsel_window_formula.rs`
The `#[ignore]` drops; the body builds a scheduler over a write column plus a
write `Seq`-bearing resource fixture and asserts the window equals the formula
(including the multi-morsel case the catalogue names) plus the zero-write
`MAX_MORSEL` case. Tests pinning the placeholder or the old A3a per-marker
values are rehabbed: `a1_fiber_morsel_size` (window value),
`plan_runner` (partition test becomes the per-fiber budget test),
`a3a_store_sizes` (Resource row becomes the zero-footprint scalar row), and
test-local resource value types across the suite gain zero-footprint
`ResourceFootprint` impls.
Verification: `cargo test -p hilavitkutin --test r6_morsel_window_formula` passes without `--ignored`.
