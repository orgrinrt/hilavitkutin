## Current state

`compute_fiber_morsel_windows` (plan step 9) fills `plan.morsel_windows` with a
record-count PARTITION placeholder (per-fiber record shares summing to the record
count), not the spec's per-fiber L1 WINDOW size. The A3a fold
(`StoreElemBytes`/`StoreSizes`/`store_sizes`, plan/project.rs) exists but is
uncalled, and its `Resource<T>` arm mis-models the footprint as the flat scalar
size (the re-chart's flagged drift). The catalogued contract
`tests/r6_morsel_window_formula.rs` is red-ignored. The footprint substrate
(`CollectionBytes` + `ResourceFootprint` + the derive, #163/#164) is merged and
unconsumed.

## Resolutions this round settles

1. **The formula lands as specced (domain 12):**
   `window = (L1_usable / Σ write_sizes).clamp(MIN_MORSEL, MAX_MORSEL) & !3`,
   per fiber, where `Σ write_sizes` sums the per-store byte sizes selected by the
   UNION of the fiber's units' write masks (a store written by two units in one
   fiber counts once). A fiber with zero write bytes takes the `MAX_MORSEL`
   window (nothing constrains its L1 write budget). `plan.morsel_windows[f]`
   becomes a WINDOW size; a fiber covers the record range in
   `ceil(record_count / window)` morsels. This is the designed semantics flip the
   A1 slice documented as pending; tests pinning the partition placeholder are
   rehabbed to the window contract and `r6_morsel_window_formula` goes green.

2. **The budget knobs are `RunCfg` consts (toolbox, not policy):**
   `L1_USABLE` (default `24_576` = the spec's 32 KB detection fallback times
   0.75), `MIN_MORSEL` (default `64`, one micro-morsel interval; spec marks the
   floor configurable), `MAX_MORSEL` (default `8192`, spec-fixed default).
   Consumer-tunable by writing the const, like `MORSEL_SIZE`. Hardware L1
   detection (domain: platform tiers) later overrides the DEFAULT source, not the
   knob. `build` threads `DefaultRunCfg`'s values; `build_with::<Cfg>` threads
   `Cfg`'s.

3. **The step-reorder premise dissolves.** The 2026-06-19 audit flagged that
   step 9 needed per-fiber write bytes "which classify_columns (step 11)
   produces". With the per-store size array on `PlanInputs` and the write masks
   plus the step-8 fiber assignment both available at step 9, the sum needs
   nothing from column classification. Step order is unchanged; the reorder is
   retired as a dissolved premise, not deferred work.

4. **`Resource<T>` footprint sourcing and the coherence call.** The fold's
   `Resource<T>`/`StagedResource<T>` arms read `<T as ResourceFootprint>::L1_BYTES`
   (the R5-correct collection footprint). A blanket
   `impl<T: ColumnValue> ResourceFootprint for T` would cover every consumer
   struct and make the `#[derive(ResourceFootprint)]` impl a coherence conflict,
   so it is rejected. Instead the api ships explicit zero-footprint impls for the
   bare scalar primitives (an unsigned/signed integer, `bool`, `char`, plus
   `arvo::USize` and `arvo::Bool`): a bare-scalar resource value is the
   degenerate single-`Field` case and contributes nothing to the L1 write
   budget. Consumer struct values use the derive.

5. **`Accum<T>` contributes zero** to the L1 morsel budget (unit-outer dispatch
   per the re-chart), correcting A3a's scalar-size arm. `Virtual<T>` stays zero.
