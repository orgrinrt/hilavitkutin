## Changes proposed

### 1. A section on the host data path

`mock/crates/hilavitkutin/DESIGN.md.tmpl`, a new section `### Host import and dump` after `Scheduler::replace_value` and `Scheduler::replace_resource`:

- `Scheduler::import::<C>(at, records)` copies `records` into the column store `C` from record `at`, and `Scheduler::dump::<C>(at, len, sink)` pushes records `at` to `at + len` into a `notko::sink::BulkPush` sink. `C` is `Column<T>` or `Buffered<T, M>`, bound by the existing `ColMember` and `Kept`, so an accumulator, a virtual or a resource does not compile there.
- A buffered column takes an import on both of its reservations, so the next pass reads it and the boundary that follows does not drop it; a dump reads the side the next pass reads, the one the last boundary published.
- `import` marks the store changed for the next frame through the same bit `mark_dirty` sets, with a `FIXME` naming the ticket for the per-record mark and a red test asking only the morsels that cover the import to rerun.
- A range reaching past the store's record count is refused with `HostRefused::PastCount` before any record moves.
- Both run between frames, on the thread that holds the scheduler; a borrow of column memory does not outlive the call.

## Not changed

`mark_dirty` stays the call after a host write made some other way. `replace_value` stays the resource path.
