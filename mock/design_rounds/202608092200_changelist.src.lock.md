# Src changelist: mint, and see whether they collide

**Date:** 2026-08-09
**Phase:** IMPL
**Doc CL:** `202608092200_changelist.doc.lock.md`

Both laws are written and watched fail against the construction that motivated
them, before the code that satisfies them.

## CHANGE: a shape-generic disjointness law, which is the crate's promise

File: `mock/crates/hilavitkutin-sym/tests/origins.rs`

Disjointness was tested for `SixteenMinters` alone, over a shape laid out
correctly. Nothing asserted it for a shape generally, so `WideKind` gaining an
origin would have been unguarded, and that is precisely the gap the seventh
review walked through.

The new law mints from every origin of every shape and asserts no two handles are
equal. It is the crate's own promise stated as a test instead of as prose.

Evidence, by construction, and it is the finding of the round: `WideKind` given
four origin bits over a twenty-six bit id, with origins shifted for a
twenty-eight bit space, passes **all six** shape laws. Origins zero and four then
mint the identical handle, 67108864, because origin four's base is 2^26 and
truncates to zero. That is the falsely-equal peer collision this branch exists to
eliminate, reachable through the extension point the branch added.

## CHANGE: origins must fit the id field they are placed in

File: `mock/crates/hilavitkutin-sym/src/shape.rs`, tests

The mechanism behind the above. `origin_base` and `origin_ceiling` return
`Uint<28, Hot>`, and `Uint::<28>::from_raw` does not truncate, so a shape may
place origins beyond its own `ID_BITS` and the excess wraps into another
origin's run.

The law asserts, for every shape and every origin, that both base and ceiling fit
that shape's `ID_BITS`. It is separate from the disjointness law on purpose: one
names the property the crate promises, the other names the mechanism that breaks
it, and a law naming only the property leaves the next reader to rediscover why.

**The `Uint<28, Hot>` in the trait is not fixed here and is documented instead.**
Twenty-eight is `Standard`'s id width sitting where a shape cannot override it,
which is the same substance as the constant this branch lifted, one level down.
Making the type follow the shape is a design question this round does not have
the answer to; the two laws contain the hole meanwhile.

## CHANGE: `Sym` and `SymKind` bound equality on the layout, not the shape

File: `mock/crates/hilavitkutin-sym/src/handle.rs`, `src/kind.rs`

`#[derive]` puts `S: PartialEq + Eq + Hash + Default + Debug` on the impls while
`SymShape` requires only `Copy + 'static`. A legal shape deriving less yields a
handle with **no equality at all**, which is the crate's central promise absent
by construction. All three shipped shapes derive everything, which is why nothing
noticed.

Hand-written impls bounded on `S::Layout`, which already requires `Copy + Eq +
Debug`.

Verification: a shape deriving only `Copy, Clone, Debug` still yields a `Sym`
that compares, written as a test rather than asserted.

## Evidence

The collision construction is a source-level `impl`, so it cannot be committed as
a test without failing the suite it now fails by design. What is recorded instead
is its exact failure text, which the new law produces and which a reader can
reproduce in one edit: set `WideKind` to four origin bits over twenty-six id
bits, shift origins by twenty-four, and the law reports

> `WideKind places an origin base at 67108864, past its own 26 id bits`

while the other six shape laws pass. Before this round it minted the colliding
handle silently.

The derive regression is committed as a test rather than described, because it
can be: `a_shape_deriving_the_minimum_still_yields_a_comparable_handle` stops
compiling with `E0277` if the impls go back to a derive, verified by doing it.
