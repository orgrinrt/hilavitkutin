## Resolved design (architect read, agent a8dcb4c5)

The fork was the per-fiber morsel-local signal: a fiber is morsel-local iff no unit in it writes an accumulator, but fibers are formed plan-side from store access masks that do not distinguish accumulator stores, while the accumulator distinction is type-level (`AccumBinding`). The read resolved it to **Shape A with the drain as the production site**:

- The accumulator-`StoreId` set is produced at the store drain (`resource/bindings.rs`, where `Sv<Accum<T>, _>` nodes are visible as distinct type-level facts, the same layer `AccumFreeBindings` folds) as a small flat bitmask (`Mask`-shaped over `D::Stores`), no alloc, no new trait machinery beyond the existing const-fold pattern.
- That accumulator-store set is threaded through `compute_plan` into fiber formation. For each `Fiber<D>`, `morsel_local: Bool` is computed once (the fiber's `columns` set intersected against the accumulator-store set: empty intersection means morsel-local).
- `Scheduler::run` walks the structured plan (`phases -> trunks -> fibers`) and gates the morsel-outer-versus-unit-outer choice per fiber on `fiber.morsel_local`, retiring the whole-pipeline `accum_free` field once per-fiber lands.

Shape B (derive at dispatch) was rejected: the accumulator-store set is not available at run time in any field and the type-level information is gone by then, so B reduces to A anyway. Shape C (an `Accumulator` column class in `classify_columns`) is a useful refinement but does not itself solve the bridge, since `classify_columns` receives only access-mask bitmaps; the bridge lives at the drain.
