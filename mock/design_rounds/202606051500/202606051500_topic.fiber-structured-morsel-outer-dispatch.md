# Topic: fiber-structured morsel-outer dispatch with a per-fiber morsel-local guard

**Date:** 2026-06-05
**Scope:** hilavitkutin engine (`mock/crates/hilavitkutin`), `Scheduler::run` and the per-fiber dispatch metadata it walks. GATE 1, the next slice after the whole-plan morsel-outer guard.
**Source topics:** the single-core dispatch completion arc topic (`202606050203_topic.single-core-dispatch-completion.md`, slice 1 as scoped there); the dispatch-build-plan memo (`mock/research/202605282100_engine-dispatch-build-plan.md`, Phase C/D); the consolidation spec (`202604200055/202603181200`, fiber/trunk/phase vocabulary); the prior neutral `feature-dev:code-architect` read on the dispatch shape (agent a81e51cf).

## The honest state this starts from

`Scheduler::run` (`scheduler/mod.rs:602`) dispatches with a WHOLE-PLAN `accum_free` guard: when the entire bundle writes no accumulator (computed type-level via `AccumFreeBindings` over the binding nodes) and the record count is non-zero, it runs morsel-outer (one morsel runs every unit's body before the next morsel, walking the flat `topo_order`); otherwise unit-outer (each unit completes its whole record range first). Both are correct. The whole-plan guard already dispatches the GATE-1 exit bench (an element-wise chain, whole-plan accumulator-free) morsel-outer, so it is not the bench result that this slice changes.

What the whole-plan guard does NOT do: a plan with a mix of accumulator-bearing and accumulator-free fibers falls entirely to unit-outer, even for the morsel-local fibers. The designed form is per-fiber: walk the plan's real `phases -> trunks -> fibers` structure (the nesting `derive_phase_dispatch_order` at `scheduler/mod.rs:260` already contains) and dispatch each fiber morsel-outer when that fiber is morsel-local, unit-outer otherwise. Correct for every plan; fast where provable.

## Decided shape (from the prior architect read and the arc topic)

- `run()` walks the structured plan, not the flat `topo_order`: per phase sequentially, per trunk, per fiber; per fiber, window the record range into morsels and dispatch the fiber's units in order per morsel (morsel-outer) when the fiber is morsel-local, else dispatch each unit over the whole range (unit-outer). Single-core needs no thread barriers; phase ordering is sequential execution.
- The dispatch keeps the column-capable runtime-indexed local-slice path (`CollectFiber` builds one `FiberSlot` per unit; the slot's `fiber_shim` projects the unit's full `EngineCtx` and runs `execute`). The fn-pointer is a local array entry (the devirtualizable form, not a stored-field call). This path is proven by the engine-vs-std bench and is not changed.

## The open fork this round must resolve: the per-fiber morsel-local signal

A fiber is morsel-local iff no unit in it writes an accumulator: the per-record Context accessors (`each` / `read(i)` / `write(i)`) are morsel-relative by construction, so the only cross-record surface is the accumulator append/reduce path. The hard part is WHERE that bit is computed and HOW, given a layer mismatch:

- Fibers are formed plan-side (`group_fibers` / `classify_columns` in `plan/steps.rs`) from per-unit store ACCESS MASKS (`PlanInputs.access`, a 64-store `Bits` window per unit). Those masks record "unit u touches store s" with no accumulator-versus-column distinction. `classify_columns` only tags `Internal` / `Input` / `Output`, never accumulator.
- The accumulator-versus-column distinction is type-level: the `AccumBinding` node in the Write `AccessSet`, which `AccumFreeBindings` folds into the whole-plan `accum_free: Bool`. The plan does identify accumulator stores in one place already: `AccumSlot.store_id` inside a fiber's `head_tail: Maybe<HeadTailConvergence>`, but `head_tail` is present only for the OPTIMIZED head+tail convergence case, so `head_tail.is_isnt()` is not a complete "no accumulator" signal.

Candidate shapes (to be chosen in the doc CL, informed by the architect read):

- A. A per-fiber `morsel_local: Bool` field on `Fiber<D>` (or an equivalent per-fiber descriptor), computed once at fiber formation from the set of accumulator `StoreId`s the plan already identifies, then read by `run()`. Aligns with the engine's schedule-once-dispatch-many principle.
- B. Derive the bit at dispatch time in `run()` from the fiber's `columns` set intersected with the accumulator-store set. No new plan field; recomputed per run.
- C. Surface the accumulator-store set into the plan inputs as a first-class classification (extend `classify_columns` with an `Accumulator` class fed from the type-level binding classification), then A or B reads it.

The bridging question (how the type-level accumulator-store set reaches the plan-side fiber/classification layer) is the load-bearing part and is the subject of a neutral architect read dispatched alongside this topic.

## Plan access from `run()`

`run()` does not retain the `ExecutionPlan` (store-backed per #655). Three shapes: retain a `Copy` of the whole `ExecutionPlan` (large, duplicates the store, contradicts #655); read the phase/trunk/fiber pools back from the store via `PlanHandle` in `run()` (no duplication; the read is once-per-run over O(fibers), not per-record); derive a compact per-fiber dispatch descriptor at build time alongside `topo_order` (small, retained like `topo_order` already is, no hot-loop store indirection). The compact-descriptor shape is the leaning per the precompute-the-dispatch-structure principle, but it composes with the morsel-local-signal decision above; resolved together in the doc CL.

## Slice boundary

This round ships the structured per-fiber walk plus the morsel-local guard, correct for every plan (unit-outer fallback) and morsel-outer for provably morsel-local fibers. TDD red-first: a plan with one accumulator-bearing fiber and one accumulator-free fiber, asserting the accumulator-free fiber dispatches morsel-outer (its intermediate stays resident across the morsel) while the accumulator fiber stays unit-outer, and that results are correct under both. Fiber-formation refinement (accumulator boundaries becoming fiber boundaries so more of a general plan is morsel-local) and the codegen/fusion tier (Phase D, #340, the actual single-core gap-closer per the re-bench finding) are later, by sequencing.
