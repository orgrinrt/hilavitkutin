## Change

`block_diagonalise` becomes `(graph) -> BlockPartition<MAX_UNITS>`, wiring `arvo_sparse::block_diagonal_via` over the bidirectional CSR. The runner runs it once globally and projects per-phase trunk skeletons: for each phase (a waist-delimited topo-position range), one trunk per distinct block id among the phase's units, setting `Phase.id`, `Trunk.id`, and `Phase.trunk_count`. `Trunk.components` stay empty: components are fibers, formed in the next sub-round.

Each block is a weakly-connected component of the dependency graph: an independent sub-graph sharing no edges, hence column-disjoint, which is exactly the zero-sync trunk invariant. A block that straddles a waist contributes a trunk to each phase it touches; the projection stays well-defined.

No alignment check fires yet. Distinct blocks are column-disjoint by construction (no inter-block edges), so `PhaseAlignmentMismatch` has no concrete, testable condition before column classification (step 11). The runner drops the `feasible`/`Err` path; the `PlanError` variant stays reserved for the later column-classification check. This is a deliberate deviation from the design note's "raise PhaseAlignmentMismatch", because a gate that cannot fire on a real fault is a lying gate.
