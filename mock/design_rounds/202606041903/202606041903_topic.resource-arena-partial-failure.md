# Topic: assert the resource-arena partial-failure cleanup directly

**Date:** 2026-06-04
**Scope:** hilavitkutin engine test surface (`tests/resource_bindings.rs`). Test hardening only, no source-behaviour change.
**Source topics:** #656 note 1 (the PR #114 resource-arena reviewer notes).

The resource-arena drain (`resource/bindings.rs` `DrainStores`) reserves one column per non-ZST resource. On a reservation failure it returns `Err(BuildError::AllocationFailed)`, and the store, dropped on the `Err` arm, frees every column reserved so far. That no-leak-on-partial-failure invariant is real (the store's `reserve` sets a failed slot to `Isnt` and frees the prior successful slot via `ArenaColumnStorage::Drop`), but the test suite only asserts it in halves: `resource_bindings_drop_deallocates` proves `Drop` frees every reserved column on the success path, and `allocation_failure_returns_err` proves the `Err` propagates. The conjunction (one resource reserves, the next fails, build returns `Err` AND the one reserved column is freed) is reasoned-correct but never directly asserted.

## The gap

A leak on the partial-failure path (the store not dropped on the `Err` arm, or `Drop` not freeing the reserved-so-far columns) would pass both existing tests yet leak memory in production. The missing assertion is the count conjunction: successful allocations equal frees on the failure path.

## Round change

Add one test to `tests/resource_bindings.rs`: a `CountingProvider`-wrapped `BumpProvider` sized to hold exactly one 64-byte-aligned column (the store reserves each column with `CACHE_LINE_ALIGN = 64`). Register two non-ZST resources; the first reserves, the second overflows the buffer. Assert build returns `AllocationFailed`, and that the live-column counts balance: one successful allocation, one free (the reserved column released when the store drops on the `Err` arm).

Adjust `CountingProvider::allocate` to increment the `ALLOCS` counter only when the inner allocate returns non-null, so the counter tracks successful allocations (live columns) rather than attempts. A null-returning attempt reserves nothing, so it must not count. The existing counting tests all allocate successfully, so their counts are unchanged; the counter now matches `BumpProvider`'s own success-only count and makes the partial-failure balance assertion meaningful.

## Test plan

The new test asserts `ALLOCS == 1` and `DEALLOCS == 1` after a build that fails on the second resource. It is a regression guard: the cleanup it covers already works, so it passes from the moment it is written. It discriminates the leak it guards against (if the `Err` arm leaked, `DEALLOCS` would be 0). The existing counting tests (`resource_bindings_drop_deallocates`, `zst_resource_round_trips_without_reserving`) stay green under the count-on-success change (their allocations all succeed).

## Out of scope

#656 note 2 (the `BumpProvider` 64-byte absolute-alignment guarantee) stays deferred: it is only observable once a column type's correctness depends on the 64-byte base, and the current POD types satisfy their natural alignment. No `#[repr(align(64))]` on the test buffer this round.
