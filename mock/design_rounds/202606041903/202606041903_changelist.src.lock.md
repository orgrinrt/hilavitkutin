## CHANGE: count successful allocations in the test `CountingProvider`

File: `mock/crates/hilavitkutin/tests/resource_bindings.rs`
`CountingProvider::allocate` increments the static `ALLOCS` counter before delegating to the inner bump allocator, so a null-returning (failed) attempt counts as an allocation. Change it to increment `ALLOCS` only when the inner allocate returns a non-null pointer, so the counter tracks successful allocations (live columns), matching `BumpProvider`'s own success-only `allocs` count. The existing counting tests allocate successfully throughout, so their `ALLOCS` totals are unchanged.
Verification: `grep -A4 "fn allocate" mock/crates/hilavitkutin/tests/resource_bindings.rs` shows the `ALLOCS.fetch_add` guarded by a non-null check in the `CountingProvider` impl.

## CHANGE: add the partial-failure cleanup test

File: `mock/crates/hilavitkutin/tests/resource_bindings.rs`
Add `partial_failure_frees_the_reserved_columns`: a `CountingProvider::<64>` (one 64-byte-aligned column fits, two do not), two non-ZST resources registered, build asserted to return `BuildError::AllocationFailed`, then `ALLOCS == 1` and `DEALLOCS == 1` (one column reserved before the failure, freed when the store drops on the `Err` arm). Uses the shared `COUNTING_LOCK` and counter-reset preamble like the other counting tests.
Verification: `grep "fn partial_failure_frees_the_reserved_columns" mock/crates/hilavitkutin/tests/resource_bindings.rs` returns one match; `cargo test -p hilavitkutin --test resource_bindings` passes.

## Tests

The new test is the deliverable. It is a regression guard (the cleanup already works) that discriminates a leak on the partial-failure path: were the store not freed on the `Err` arm, `DEALLOCS` would be 0. The existing `resource_bindings` tests stay green under the count-on-success adjustment.

## Out of scope

#656 note 2 (`BumpProvider` 64-byte absolute alignment) stays deferred.
