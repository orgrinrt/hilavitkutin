## What this round locks

Slice 2 stands up the self-hosting meta layer: the four meta lifecycle
virtuals as real fired virtuals, the `MetaAccess` gate restricting the four
meta resources to meta work units, and the irreducible kernel that fires the
virtuals in canonical order around the dispatch the engine already drives.
The consumer-facing payoff (an adaptation work unit on `OnMeta<ScheduleEnd>`,
phase-overlap pipelining, domain-22 reshaping) is slice 3 / E8.

The topic posed five design questions. The resolution memo answered them
against the canonical Q9 source (`design_rounds/202604200055/202603141800_topic.hilavitkutin-core-design.md:716-814`) plus consolidation `:2119-2137`/`:1989`. This DOC CL records the resolved design and the one toolchain-forced surface deviation the de-risk sketch surfaced.

## Resolved design (the five questions)

1. **Carrier shape.** Meta work units register in the SAME builder carrier as
   consumer work units, not a separate meta-carrier. The canonical is explicit:
   "meta units are in the same DAG, dispatched the same way" (`:781`). One
   phase-ordered dispatch runs everything in lifecycle order; the slice-1
   fired-flag gate selects which run.

2. **Lifecycle ordering.** Carried by the existing waist-based phase grouping,
   not by multiple dispatch passes. Each work unit's lifecycle rank
   (plan-stage / consumer / epilogue) is computed at const-eval from its
   schedule type, the same point the grouping computes masks, and seeds the
   phase key so plan-stage work units land in early phase(s), consumers in the
   middle, epilogue (`ScheduleEnd`) work units last. This is the canonical's
   "scheduler adds the `ScheduleReady` edge automatically; consumers never
   declare it" (`:726`) expressed structurally through the rank rather than
   through a per-work-unit injected read-mask bit. It resolves slice-1's known
   gap (the grouping does not infer a `Virtual<V>`-write to `On<V>` scheduling
   edge) for the meta edges specifically: the rank orders the phases directly.

3. **`MetaAccess` mechanism.** A sealed marker trait implemented on the four
   meta resource types. The marker and the four resource types land in slice 2;
   the compile-time `Context` enforcement bound (consumer work units cannot
   reach `meta::*`) is slice 3.

4. **"Wait for plan work units".** The plan-stage work units occupy the early
   phase(s); the kernel fires `ScheduleReady` at the plan-to-consumer phase
   boundary (after the plan phase trunks complete), which is the "wait"
   expressed structurally.

5. **Cadence.** `PlanStage` fires only on a plan-dirty frame (the existing
   `plan_dirty` seed on the scheduler); `PassStart` / `ScheduleReady` /
   `ScheduleEnd` fire every pass.

## Forced surface deviation: `OnMeta<V>` not `On<meta::V>`

The canonical writes meta work units as `WorkUnit<On<meta::PlanStage>>`
(core-design `:720`/`:757`/`:764`). The de-risk sketch
(`202606082000_e4-slice2-lifecycle-classify`) proved that const-time lifecycle
classification of a meta work unit versus a consumer work unit CANNOT use the
same `On<V>` marker: a blanket `impl<V> Lifecycle for On<V>` (consumer default)
plus a specific `impl Lifecycle for On<meta::PlanStage>` (meta) conflict
(E0119), a negative bound `V: !MetaVirtual` is not expressible, and full
specialization is forbidden (`unstable-features.md`).

The escape (proven `WORKS`): meta work units declare a distinct schedule marker
`OnMeta<V>` (versus consumer `On<V>`). Three disjoint `Lifecycle` impls then
classify every schedule with no overlap and no specialization:

```rust
impl Lifecycle for Always                    { const RANK: Rank = RANK_CONSUMER; }
impl<V> Lifecycle for On<V>                  { const RANK: Rank = RANK_CONSUMER; }
impl<V: MetaVirtual> Lifecycle for OnMeta<V> { const RANK: Rank = <V as MetaVirtual>::RANK; }
```

`MetaVirtual` is implemented only on the four closed-set meta markers
(`PlanStage` / `ScheduleReady` / `PassStart` / `ScheduleEnd`), each carrying a
const lifecycle rank. A const fold over a mixed carrier yields the correct
per-unit rank array.

Behaviour is unchanged: meta work units are still gated on lifecycle virtuals
and the scheduler self-hosts. Only the schedule marker the meta work unit writes
differs from the canonical spelling. This is a documented toolchain-forced
deviation per `chart-the-path` (record the divergence and its justification).
