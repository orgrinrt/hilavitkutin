### 1. The refusal of a bare column marker names the registration (finding 3)

The first note is as it was.

The expected output of the two trybuild arms that hand a bare marker to `.with` carries the new line, and no other arm's output moved.

### 2. A frozen file brings in no file from outside the ledger (finding 5)

`mock/lints/frozen_no_outside_source.rs` is the lint `frozen-no-outside-source`. In the `src/` of a frozen crate it refuses an attribute that sets the key `path`, bare or under `cfg_attr`, and the names `include`, `include_str` and `include_bytes` as whole words of code. A macro is refused by its name with or without the `!`, since a macro can be imported under another name and called by that; the import line is where the finding lands. `mockspace.toml` binds the lint to the frozen authors crate at error on commit, build and push, beside its siblings.

`mock/lints/frozen/scan.rs` gains `has_word`, the whole-word test `frozen-no-recursion-limit` had as a private function, and `words`, which reads each line of code for one of a set of words. The recursion lint uses `has_word` from there now, so the test is written once.

### 3. The recursion lint says what the design says (finding 4)

The module doc of `mock/lints/frozen_no_recursion_limit.rs` no longer says the api promises that a unit list compiles at the default limits. It says the frozen crate's design has the crate raise no limit. The finding's message loses the same reason and reads "a frozen crate raises no `recursion_limit`".

### 4. The conformance crate's manifest names its readme (finding 1)

`mock/crates/hilavitkutin-conformance/Cargo.toml` has `readme = "README.md"`, and its description is the readme's tagline. Both went in with the doc changelist's commit, since a manifest is no gated file.

## The proving checks, each against what holds it

The note: `tests/trybuild/column_marker_registered.stderr` and `buffered_marker_registered.stderr` of the api crate, regenerated and read. The api crate's whole suite passes with them, doctests included.

The new lint: thirteen tests in `mock/lints/frozen_no_outside_source/tests.rs`. They cover a path attribute bare, under `cfg_attr` and broken over lines; each of the three macros; spacing before the `!` and a path before the name; an import under another name; both constructs in one file; and the look-alikes that have to pass, which are a plain module, a name that only contains one of the words, the word `path` where it is no attribute's key, and comments and strings. One runs the lint through the runner with a `lint:allow` marker on the line and sees the finding stay. With the path test forced false five of them fail, and with the three macro names changed six fail.

The lint crate's tests are 91 and pass, the 78 there were and these thirteen. `cargo mock` runs the new lint over the frozen authors crate at error and passes: no frozen file has either construct.

## Departures from the design

The design says a frozen file carries none of the `include!` macros. The lint refuses the three names as words of code, which is wider: a function named `include` in a frozen file would be refused too. The narrower form misses a macro imported under another name, and the frozen crate has no use for the word.
