## Changes proposed

### 1. The refusal of a bare column marker names the registration, in `hilavitkutin-api/DESIGN.md.tmpl`

"Store types" gains one sentence after the one that says the marker alone does not compile: the note on `BuilderInput` names `start()` and `start_from(value)` as the two ways a column is registered.

### 2. A frozen file brings in no file from outside the ledger, in `hilavitkutin-frozen-authors/DESIGN.md.tmpl`

"The ledger" names a fourth lint: a frozen file carries no `path` attribute and none of the `include!` macros. The reason is the ledger's own: a file compiled into the crate is a file of the crate, and the ledger has to have an entry for each.

Why refuse the constructs and not follow them. The ledger lint reads the crate's directory. Following a path would have it resolve module paths as the compiler does, for a construct no frozen file uses and no consumer's unit needs.

### 3. The conformance crate has a readme

`mock/crates/hilavitkutin-conformance/README.md` is new and its manifest names it. It is the crate's public page: what the crate is, the three instruments, how it is taken, the status and the licence. The manifest's description loses "no_std, no alloc" and is the readme's tagline word for word; the fact moved to the status paragraph.
