## What the report found, and what each one is

Finding 1. `hilavitkutin-conformance` is a crate this branch adds and it has no readme of its own, and its manifest names none. Its design says the crate ships (the mutants "ship in the crate" for a consumer who holds a runner of their own), so the manifest is not to say `publish = false`. It gets a readme. The workspace-wide gap is on ticket e372d72cd856 and stays there; this is the one instance the branch added.

Finding 2. Thirteen commit subjects of the branch are not of the house form, and one commit body says how the change came about. All of them are pushed. A pushed commit's text changes only by rewriting pushed history, which this seat does not do, so nothing is built for it. The lander's merge carries its own subject.

Finding 3. The compile error for a bare column marker handed to `.with` ends on the general note of `BuilderInput`, which tells the author to write an impl for `Column<T>`. Nobody outside the api crate can write that impl, and it is the opposite of what is wanted: the column is to be registered with its start. Op's words of 13 November on the column start, recorded in `202611132307/202611132304_topic.column-start.md`, ask that the wrong call be a compile error; an error that points the author the wrong way does half of that. The note gains a sentence that names the two ways a column is registered.

Finding 4. The module doc of the lint `frozen-no-recursion-limit` says the api promises that an author's unit list compiles at the default limits. The api's design says otherwise: past some thirty units a consumer raises the limit, and the note on `Holds` tells them so. The frozen design says only that the frozen crate raises no limit. The lint's doc is reworded to that.

Finding 5. A frozen file could bring in a file the ledger has no entry for, through a `#[path]` attribute on a module or one of the `include!` macros, and the file could sit under the unfrozen `tests/`. The frozen design already says the ledger lint fails "when a file of the crate has no entry", and a file compiled into the crate is a file of the crate wherever it lies. So this is a hole in what was built against the design and not a new rule. The ledger lint walks the crate's directory and cannot see where a path attribute leads, so the cheap and total form is to refuse the two constructs in a frozen file. No frozen file uses either today (`git grep` for `include` and `#[path` under the crate's `src/` finds nothing).

## What this round decides

One thing, in the frozen design: a third lint beside the two that keep the crate written as a consumer could write it. It refuses a `path` attribute and the `include!`, `include_str!` and `include_bytes!` macros in the `src/` of a frozen crate. A frozen crate that needed one would be reaching for a file outside its ledger, and there is no escape, as with its two siblings.

The rest decides nothing: a diagnostic's wording, a lint's doc, a readme.
