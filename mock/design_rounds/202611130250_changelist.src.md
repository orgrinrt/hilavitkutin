# Src changelist: notko by https

**Date:** 2026-11-13
**Phase:** SRC
**Round:** 202611130249 (notko-by-https, branch `work/notko-by-https`)

Spells the notko git source by `https`, as kaski's manifest does, so a graph holding both repositories' crates resolves one notko. The commit the lock names does not change: `1a978e5c2db6c8f68bf94a6fcae266394f172b17` before and after. No lint severity moves and no source file changes.

## CHANGE: the workspace names notko by `https`
Files: `mock/Cargo.toml`.
The `notko` entry in `[workspace.dependencies]` becomes `git = "https://github.com/orgrinrt/notko.git"`, with the same branch, version and features. The ten arvo entries keep their `rev` and their `ssh` spelling.
Verification: `grep -n 'notko = ' mock/Cargo.toml` shows the `https` spelling and the original `branch`, `version` and `features`; `grep -c 'ssh://git@github.com/orgrinrt/arvo.git' mock/Cargo.toml` prints 10.

## CHANGE: a `[patch]` section unifies the old arvo crates' notko
Files: `mock/Cargo.toml`.
The arvo crates at the pinned rev declare `notko` as `git = "ssh://git@github.com/orgrinrt/notko.git", branch = "dev"` in their own workspace manifest (nine of them take it with `notko.workspace = true`) and none names `notko-hlist`. A `[patch."ssh://git@github.com/orgrinrt/notko.git"]` section points `notko` at the `https` source, so those crates resolve to the same package as the workspace entry.
Verification: with the section removed, `cargo fetch` in `mock/` writes a second `notko` package into the lock, one `ssh` and one `https`; with it present the lock holds one.

## CHANGE: the lock holds one notko, on the `https` source
Files: `mock/Cargo.lock`.
The one `notko` package takes the source `git+https://github.com/orgrinrt/notko.git?branch=dev#1a978e5c2db6c8f68bf94a6fcae266394f172b17`, the same commit its `ssh` entry named. Regenerated by cargo, then held at that commit with `cargo update -p notko --precise`, since the branch head had moved to `0a13d99a33027ad1314e5da2c036dffab8d061e5` and a source respelling is not the place to take a notko bump. No other lock line moves.
Verification: `grep -c 'name = "notko"' mock/Cargo.lock` prints 1 and its `source` line begins `git+https://`; `git diff --stat -- mock/Cargo.lock` shows one line changed.

## CHANGE: the LTO smoke fixture carries the same patch
Files: `mock/crates/hilavitkutin-extensions-macros/tests/lto_smoke_fixture/Cargo.toml`, `mock/crates/hilavitkutin-extensions-macros/tests/lto_smoke_fixture/Cargo.lock`.
The fixture is its own workspace root and path-depends on `hilavitkutin-extensions`, which takes notko from this workspace's entry, while the fixture names arvo, and through it notko, by `ssh`. A patch in this workspace's manifest does not reach another root, so after the respelling a build of the fixture rewrote its tracked lock to hold two notko packages. The fixture gets the same `[patch]` section, and its lock is held at `1a978e5c2db6c8f68bf94a6fcae266394f172b17`, the commit it named before.
Verification: `grep -c 'name = "notko"' mock/crates/hilavitkutin-extensions-macros/tests/lto_smoke_fixture/Cargo.lock` prints 1 with an `https` source; `cargo check --release` in the fixture directory passes and leaves `git status` clean.
