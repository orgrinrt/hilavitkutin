# Topic: the N-way record split is not head+tail convergence

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `scheduler/mod.rs:2106-2136`, the single-trunk parallel branch, and the design
prose that names it.
**Grounded on:** consolidation spec `:770-771` and `:1838-1844`; roadmap
`202607191500_engine-roadmap-r7.md` band 1 item R1.

`run_core_phase` has a branch for the case canon cares most about: a single-trunk phase, where
trunk-level parallelism has nothing to distribute because there is only one trunk. Canon's answer
is head+tail convergence, and it is specific about the shape. Consolidation spec `:770-771`:
"Single-trunk phases: head+tail convergence (2 threads, opposite ends, ~2x parallelism). Skip for
non-commutative resource accumulation." Spec `:1840-1841`: "Within any commutative fiber, records
are independent. Two threads process from opposite ends, converging in the middle."

The branch does something else. It computes a ceil-sized slice per core, `per = (total + ncores - 1)
/ ncores`, and gives every core its own `[lo, hi)` window of the record range. That is an N-way
partition, all cores walking the same direction, with no commutativity gate. On eight cores it makes
eight slices where canon specifies two threads from opposite ends.

## Why this is drift rather than an alternative

Both shapes give every record exactly one owner, so both are correct in the narrow sense the
existing test checks. The difference is what canon is buying with the restriction, and the answer
is in the sentence right after: "Skip for non-commutative resource accumulation." Two threads from
opposite ends have exactly one meeting point, and the accumulator merge at that point is a single
join between two stack-local regions. An N-way split has N regions and N-1 joins, and the branch
performs it with no commutativity check at all, on any workload.

The amendment at `202606111800:447-450` says so directly: single-fiber record splitting exists
"only as a constrained two-way head-and-tail convergence in a single-trunk commutative phase, never
as an N-way record or morsel partition."

The authority question that phrasing raises was settled on 2026-07-19: neither standalone document
blanket-supersedes the other, and each conflict resolves on its own merits with the consolidation
spec as tiebreak. That settles this one rather than blocking it, because the tiebreak document
states the 2-way requirement itself, at both `:770-771` and `:1840-1841`. The amendment is a
clarifying gloss consistent with the spec, not a competing rule.

## The comment cites the line it violates

The branch opens with "Head+tail convergence (spec :770)". Spec `:770` is the line that says two
threads. The code beneath it splits N ways. So the citation is accurate about where the requirement
lives and wrong about what the code does, which is the most durable kind of wrong: a reader
checking whether the branch is canonical finds a specific citation and stops.

The design prose repeats it. `mock/crates/hilavitkutin/DESIGN.md.tmpl:299-303` describes "The
head+tail convergence branch (a single-trunk waist-bounded phase split by record range across
cores)", which names the canonical mechanism and then defines it as the drifted one. That is the
failure mode the workspace rule on canonical design describes: an intermediate artefact encodes a
stray, and everything downstream reads it as settled.

## What removing it costs, and why that is correct

Deleting the branch leaves single-trunk phases running serially until head+tail is built. That is a
real loss of parallelism on exactly the phases that most want it, and it is still the right move.
Canon's parallelism comes from trunks; a single-trunk phase legitimately has none until the
mechanism canon specifies exists. Keeping a non-canonical mechanism because it is faster than
nothing is how the drift became load-bearing in the first place, and the longer it stays the more
of the engine is built against it.

The replacement is roadmap band W1, whose substrate (`HeadTailConvergence`, `RecordRange::Head` and
`Tail`, `thread::Convergence`, the `commutative` flag already computed at `plan/mod.rs:422` and read
nowhere) exists and is unwired.

## Out of scope

Building head+tail (band W1). The accumulator unit-outer path, which is separately canonical and
wired. Any change to the ordinary trunk-rank branch beyond removing the carve-out that exists only
to describe this one.
