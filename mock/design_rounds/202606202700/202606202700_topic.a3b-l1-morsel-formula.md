# Topic: per-fiber morsel A3b (L1 window formula wired into the plan)

**Date:** 2026-06-19
**Phase:** TOPIC
**Scope:** `hilavitkutin-api` RunCfg consts + `hilavitkutin` compute_plan + r6 catalogue flip
**Source topics:** A3 sketch `202606202400`, A3a (PR #160), granular roadmap `202606201900`

## Current state

A3a shipped `store_sizes` (per-store element bytes). `plan.morsel_windows` still
holds the placeholder record-count partition. The L1 formula needs per-fiber write
bytes (Σ element bytes over a fiber's write columns) and L1/min/max bounds.

## Changes proposed (A3b)

1. RunCfg: add `L1_USABLE` (24576), `MIN_MORSEL` (64), `MAX_MORSEL` (8192) assoc
   consts (consumer-tunable defaults, toolbox-not-policer).
2. `compute_plan` gains 3 `USize` params (l1_usable/min/max) + a `Stores:
   StoreSizes<..Stores>` bound. After `compute_execution_plan` returns Ok(plan),
   overwrite `plan.morsel_windows`: per fiber, union `inputs.writes[u]` over the
   fiber's units (`fib.units[k].index().0`, mirroring the morsel_local walk) ->
   fiber write mask; sum `store_sizes` over set bits -> Σ write_bytes; apply
   `(l1_usable / Σ).clamp(min, max) & !3` (Σ==0 -> max). Replaces the partition
   with real windows; the plan VALUE changes, run() consumption is unchanged
   (still Cfg::MORSEL_SIZE until A2b-2), so existing run() tests stay green.
3. The 2 `compute_plan` callers pass `<DefaultRunCfg as RunCfg>::L1_USABLE` etc.
4. Flip `tests/r6_morsel_window_formula.rs` catalogue-red green: assert a fiber
   with `record_count > MAX_MORSEL` gets a window <= MAX_MORSEL (multiple morsels).

## Not in scope

A2b-2 (run() consuming morsel_windows fiber-outer + fiber_mask + asm fixture).
