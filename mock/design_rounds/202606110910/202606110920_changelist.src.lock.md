# SRC changelist: GATE-2 E4 — run_parallel meta parity

**Date:** 2026-06-11
**Phase:** IMPL
**Round:** 202606110855 (GATE-2, task #685, branch `feat/hilavitkutin-parallel-engine-gate2`)
**Doc CL:** `202606110910_changelist.doc.lock.md`

Two behaviours land: the worker-side plan-band skip on clean frames (phase-loop
path) and once-per-frame ordered meta bands on the unit-outer accumulator path.

Mechanism note (a refinement inside the locked doc's framing): the designated
core for the unit-outer meta bands is the MAIN thread, and the ordering
barriers are the existing frame `publish` / `await` pair. Leading meta bands
dispatch on the main thread after the per-frame epoch and `pass_count` advance
and before `frame_publish` (so every worker's consumer work happens-after
them); trailing bands dispatch after `frame_await_done` plus the accumulator
merge (so they happen-after all consumer work, and an epilogue hook's appends
land after the merged consumer data, matching single-core buffer order). This
reuses the frame protocol as the two barriers instead of adding worker-side
ones; no new sync word.

Known constraint (documented, not a stopgap): a LEADING-band meta unit that
appends to a consumer accumulator on the parallel unit-outer path is
unsupported; the per-core region rebase lays out record slices from the buffer
start and would clobber pre-publish appends. Canonical leading-band meta work
(plan recompute, pass-start measurement) writes meta state, not consumer
accumulators; the epilogue (`ScheduleEnd`) band, where the canonical
metrics-reading hook lives, runs after the merge and appends correctly.

## CHANGE: consumer-band const fns in grouping
File: `mock/crates/hilavitkutin/src/plan/grouping.rs`
Verification: `grep "pub const fn pre_consumer_phase_count" mock/crates/hilavitkutin/src/plan/grouping.rs`; `grep "pub const fn consumer_phase_end" mock/crates/hilavitkutin/src/plan/grouping.rs`; `grep "pub const fn consumer_mask" mock/crates/hilavitkutin/src/plan/grouping.rs`.

Three const fns mirroring `plan_phase_count`'s shape (ranks from `masks_of`,
phases from `final_phases_of`):

- `pre_consumer_phase_count`: number of leading phases occupied by units with
  rank below `RANK_CONSUMER` (max such phase + 1; zero when none).
- `consumer_phase_end`: end of the consumer band (max phase among units with
  rank at or below `RANK_CONSUMER`, + 1; equals `pre_consumer_phase_count`
  when no consumer unit exists).
- `consumer_mask<.., Adj>() -> Adj`: per-carrier-position bit mask with the bit
  set for every unit whose rank is `RANK_CONSUMER` (the mask `run_gated`
  consumes). All-ones-over-live-positions when the carrier has no meta units.

## CHANGE: worker phase loop skips the plan band on clean frames
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (`worker_main`)
Verification: `grep "plan_phase_count" mock/crates/hilavitkutin/src/scheduler/mod.rs` shows a `worker_main` call site; test `gate2_parallel_plan_skip` green.

`worker_main`'s per-frame phase loop starts at
`plan_phase_count::<WuVals, Stores, GW, ..>()` instead of `0` when the frame is
not plan-dirty (`s.first_frame` is false; `run_parallel` clears it between
frames while every worker is parked, so the read is stable per frame under the
publish/await happens-before, the same discipline as `virtual_epoch`). All
workers compute the same start, so the interior waist-barrier counts stay
matched. Mirrors single-core `dispatch_trunks`.

## CHANGE: unit-outer slice walk gated to the consumer band
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (`worker_accum_unit_outer`)
Verification: `grep "consumer_mask" mock/crates/hilavitkutin/src/scheduler/mod.rs` shows the worker call site; test `gate2_parallel_meta` green.

`worker_accum_unit_outer` gains the `GW` type parameter plus the
`BundleMasks` / `ConstCapacity` / `AdjRow` bounds `worker_main` already
carries (the caller threads them through). The whole-carrier `run` over the
rebased per-core bindings becomes a const-folded branch on the band counts:
when `pre_consumer_phase_count` is zero and `consumer_phase_end` equals
`phase_count` (no meta units) the existing `run` call stays (byte-identical
fast path); otherwise the walk is `run_gated(per_core, meta_block,
slice-morsel, consumer_mask, ZERO, epoch)`, so meta units no longer ride the
per-core slice walk once per core. The record-less arm (core 0 runs the
carrier once) takes the same gating, so a meta unit does not double-run
against the main-thread bands.

## CHANGE: main-thread meta bands around the unit-outer frame
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (`run_parallel`)
Verification: `grep "pre_consumer_phase_count" mock/crates/hilavitkutin/src/scheduler/mod.rs` shows two `run_parallel` call sites (leading + trailing loop bounds); test `gate2_parallel_meta` green.

Gated on `carrier_unit_outer()`: after the epoch + `pass_count` advance and
before `frame_publish`, the main thread dispatches the leading meta phases
`start..pre_consumer_phase_count` (where `start` is `plan_phase_count` on a
clean frame, `0` on a plan-dirty one) via the same `dispatch_core` empty-morsel
walk the record-less phase arm uses, with `core = 0, ncores = 1` so it owns
every trunk in those phases. After `frame_await_done` and the accumulator
merge, it dispatches the trailing phases `consumer_phase_end..nphases` the
same way. A carrier with no meta units has empty ranges on both sides and an
unchanged frame. The phase-loop (non-unit-outer) path is untouched here: its
workers already dispatch meta bands in phase order under the waist barrier.

## CHANGE: behavioral tests
File: `mock/crates/hilavitkutin/tests/gate2_parallel_meta.rs` (new), `mock/crates/hilavitkutin/tests/gate2_parallel_plan_skip.rs` (new)
Verification: `cargo test -p hilavitkutin --test gate2_parallel_meta --test gate2_parallel_plan_skip` green.

TDD, fail-first against current source:

- `gate2_parallel_meta` (unit-outer path): multi-core OS pool, records present,
  one shared `Accum`. Carrier: an `OnMeta<PassStart>` unit counting executions
  in a test atomic (no accumulator write), an `Always` consumer appending a
  marker per dispatch over its slice, an `OnMeta<ScheduleEnd>` hook appending
  `pass_count` read through the bridge. Two frames assert: the pass-start
  count is exactly 1 then 2 (the once-per-core bug would give one per
  participating core), the buffer is the merged consumer markers followed by
  the frame's `pass_count` (1 then 2), and lengths match. A sibling
  `carrier_band_bounds` test pins this carrier's band shape against the
  grouping const fns directly (ranks 2/3/4, phases 0/1/2, pre 1, cend 2).
  Fixture note: accumulator appends saturate at the reserved capacity (which
  equals the record count at build), so the record count is sized with
  headroom for the per-core markers plus the epilogue append; an
  exactly-full buffer silently drops the epilogue append by design.
- `gate2_parallel_plan_skip` (phase-loop path): multi-core OS pool, records
  present, no accumulator. Carrier: an `OnMeta<PlanStage>` unit counting
  executions in a test atomic plus a record-writing consumer. Frame 1: count
  positive (the plan band ran). Frame 2 (clean): count unchanged (the worker
  loop started past the plan band). The per-morsel multiplicity of the meta
  band on record-bearing paths is the documented single-core limitation and is
  not asserted against.
