**Date:** 2026-06-11

This round brings the meta pipeline (lifecycle bands, plan-band skip, the
slice-3 bridge) to `run_parallel`. The bridge threading already reached both
worker paths and `pass_count` already advances per frame before the publish, so
the round lands the two missing behaviours: the worker-side plan-band skip on
clean frames (phase-loop path) and once-per-frame ordered meta bands on the
unit-outer accumulator path (designated core).

## Current state

The engine `DESIGN.md.tmpl` self-hosting section documents the single-core meta
pipeline through the slice-3 bridge paragraph and says nothing about the
parallel path; a reader cannot tell whether meta work units behave under
`run_parallel`, and the actual answer today is "incorrectly on the unit-outer
path" (a meta unit runs once per participating core, unordered across cores).

The same file also still carries a `## Scheduler::run no-op transitional body`
section claiming `run` returns `Cfg::Out::default()` with no dispatch walk. That
has been false since the GATE-1 capstone (compiled per-trunk monos, morsel loop,
incremental skip all shipped); the section is drift that contradicts both the
shipped source and the surrounding design prose.

## Changes proposed

### `mock/crates/hilavitkutin/DESIGN.md.tmpl`

1. **Extend the self-hosting section** (after the bridge paragraph) with a
   parallel-path paragraph covering both worker paths:
   - Phase-loop path: lifecycle bands are phases under the rank-outer grouping,
     so the worker phase loop plus the worker-side waist barrier already orders
     meta bands across cores; the plan-band skip mirrors single-core
     `dispatch_trunks` (a precomputed leading plan-phase count, the frame's
     plan-dirty signal read under the publish/await happens-before, the worker
     loop starting past the plan band on a clean frame).
   - Unit-outer path: meta bands run exactly once per frame on a designated
     core, ordered around the per-core record slices by the worker barrier
     (leading bands, barrier, per-core consumer slice work gated to the
     consumer band, barrier, trailing band). A carrier with no meta units keeps
     the current behaviour unchanged.
   - The `MetaBlock` cross-thread discipline: the main thread writes the block
     only between frames while every worker is parked; workers only read it
     during a frame, under the same publish/await happens-before the virtual
     epoch uses.
2. **Delete the `## Scheduler::run no-op transitional body` section** (drift;
   `run` has been the full compiled dispatch since GATE-1, and the section's
   "what the no-op body does NOT do" list now describes things the body does).

No other template changes. The api crate's docs are untouched (no api surface
changes this round).
