# Topic: A3-redo-1 — CollectionBytes + ResourceFootprint traits

**Date:** 2026-06-20
**Phase:** TOPIC
**Scope:** `hilavitkutin-api` (new footprint module + arvo-tensor dep) + a unit test
**Source topics:** A3 re-chart `202606210000`, A3-sketch-2 `202606210100` (WORKS), granular roadmap `202606201900`

## Current state

The morsel formula needs `Σ write_resource_collection_sizes` (canonical R5). The
A3-2 sketch proved the surface: a `CollectionBytes` trait (Seq/Map -> N*elem, Field
-> 0) + a per-resource `ResourceFootprint { const L1_BYTES }`. These belong in
`hilavitkutin-api` (the contract crate consumer resource types impl/derive them
from). This slice lands the trait machinery; it does NOT touch `StoreElemBytes`
(re-bounding that on ResourceFootprint forces every resource value type to impl it,
deferred to A3-redo-2's derive), so no scaling break.

## Changes proposed (A3-redo-1, additive)

1. `hilavitkutin-api/Cargo.toml`: add `arvo-tensor.workspace = true` (for
   `cap_size`, the const-accepted `Cap -> usize` projection; inline `N.0.0` is
   rejected in const position).
2. New `hilavitkutin-api/src/footprint.rs`: `CollectionBytes { const BYTES }` with
   `Seq<U,N>` -> `cap_size(N) * ceil(U::BIT_WIDTH/8)`, `Map<K,V,N>` ->
   `cap_size(N) * (ceil(K)+ceil(V))`, `Field<T>` -> 0; and the `ResourceFootprint
   { const L1_BYTES }` trait (definition only; impls/derive land in A3-redo-2).
   Exported from lib.rs.
3. Unit test: a fixture resource with a `Field`, a `Seq<_,N>`, a `Map<_,_,N>` and a
   hand `ResourceFootprint` impl, asserting `L1_BYTES == N_seq*elem + N_map*(k+v)`
   (Field contributes 0).
