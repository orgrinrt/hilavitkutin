# Src changelist: morsel-outer dispatch when accumulator-free

**Date:** 2026-06-05
**Phase:** SRC
**Round:** 202606050220 (single-core-dispatch-completion, branch `feat/hilavitkutin-single-core-dispatch`)

Slice 1 of GATE 1. `Scheduler::run` dispatches unit-outer (each unit completes its whole record range before the next unit runs), which materialises every intermediate column at full record count. This slice makes the nesting morsel-outer (one morsel runs the whole unit sequence before the next morsel, so intermediate columns stay cache-resident) when the pipeline writes no accumulator, the case in which every cross-unit dependency is morsel-local by construction (the per-record `read` / `write` accessors are morsel-relative; the only cross-record surface is the accumulator append path). A pipeline that writes accumulators keeps the existing unit-outer dispatch, the cross-record-safe form. The accumulator-free decision is whole-pipeline this slice, computed once at `build` from the bundle's `AccumWrite` projection; per-fiber accumulator-granular windowing is a later slice.

This is correct for every plan: accumulator-free plans gain the cache-resident nesting, accumulator plans keep their current behaviour. For an accumulator-free pipeline the two nestings produce identical per-record results (each record is independent), so the behaviour change is observable only in dispatch order, which the new test asserts directly.

## CHANGE: `Scheduler` gains field `accum_free: Bool`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
The scheduler records whether its registered work-unit bundle writes any accumulator, so `run` can choose the dispatch nesting without re-deriving it per frame. Set at `build` (where the `Wus: WorkUnitBundle` bound is in scope) and on the `Default` empty scheduler.
Verification: `grep "accum_free" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns the field declaration plus its `build`-time and `Default` initialisers and the `run` read.

## NEW: `AccumFreeBindings` trait in `resource/bindings.rs`
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
A compile-time fold over the bindings node types reporting whether the chain holds no `AccumBinding`. `BindingNil` is `Bool::TRUE`; `ResourceBinding` / `ColumnBinding` / `VirtualBinding` pass their tail's value through; `AccumBinding` short-circuits to `Bool::FALSE`. The node types are distinct, so the per-type impls do not overlap (no specialization). This is the accumulator-presence signal: `<Wus as WorkUnitBundle>::AccumWrite` is the bundle-wide accumulation (fold) of every unit's whole write set, not the accumulator-store writes, so it is non-empty for any pipeline that writes anything and cannot serve as the signal. An `AccumBinding` in the chain means an `Accum<T>` store was registered, which is the only way a unit can write an accumulator.
Verification: `grep "trait AccumFreeBindings" mock/crates/hilavitkutin/src/resource/bindings.rs` returns the trait declaration plus its per-node impls.

## CHANGE: `build` computes `accum_free` from the bindings' `AccumFreeBindings` fold
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
`accum_free = <<Vals as BindingsFor>::Bindings as AccumFreeBindings>::ACCUM_FREE`. `build` and `build_with` carry the where-bound `<Vals as BindingsFor>::Bindings: AccumFreeBindings`. No `AccumBinding` in the bindings chain means no accumulator store is registered, so no unit can write one and the whole pipeline is morsel-local.
Verification: `grep "AccumFreeBindings" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns the import, the two `build`-site reads, and the two where-bounds.

## CHANGE: `Scheduler::run` dispatch nesting becomes morsel-outer when `accum_free`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
When `accum_free` and the record count is non-zero, the morsel loop is the outer loop and the unit walk over `topo_order` is the inner loop (one morsel runs every unit before the next morsel). Otherwise the existing unit-outer loop runs unchanged (it also covers the record-less frame, dispatching each unit once over an empty morsel). The slot materialisation, the `topo_order` walk order, and the morsel-size guard are unchanged.
Verification: `tests/morsel_outer.rs` asserts the dispatch order is morsel-outer for an accumulator-free pipeline; `cargo test -p hilavitkutin` is green.

## NEW: `tests/morsel_outer.rs`
File: `mock/crates/hilavitkutin/tests/morsel_outer.rs`
Red-first. An accumulator-free pipeline of two units over a record count spanning multiple morsels under a small `MORSEL_SIZE`; each unit records its tag into a shared interior-mutable `Resource` on every dispatch. The recorded sequence is morsel-outer (`[u0, u1, u0, u1, ...]`) under the new nesting and unit-outer (`[u0, u0, ..., u1, u1, ...]`) under the old; the test asserts morsel-outer, so it fails before the `run` change and passes after.
