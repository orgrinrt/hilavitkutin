# review-fixes-second-pass

Round topic for the fixes the second review of `work/hv-leaf` (tip `eb71f2e4`) asked for. The report is `mock/research/202611132042_review-hv-leaf/REVIEW-2.md`. It returned merge after fixes with ten findings.

## Scope

- `hilavitkutin-str` design (finding 4): the `str_const!` snippet carries `#[link_section = ".hilavitkutin_strings"]` with a leading dot, and a dot-prefixed section gets no `__start_` and `__stop_` symbols, so the snippet as written would not link. The section name is `hilavitkutin_strings` on Linux and `__DATA,__hvkstr` on Apple, as `section.rs:39,43` and `macros.rs:16,20` have it. The macOS line names `getsectiondata` on a section the code does not use, and is brought to the code.
- `hilavitkutin-str` design and source (finding 1): `StaticStrEntry::new` is a public, documented way to make a const handle for a string nobody registered, against the design's "`str_const!` is the only way to create const handles". It becomes `#[doc(hidden)]` like `Str::__make`, and the design says both are hidden and not for callers.
- `hilavitkutin-str` tests (finding 5): the entry test compares `str_const!` with `StaticStrEntry::new` and pins one known 28-bit value.
- `hilavitkutin-persistence` design (finding 8): the sentence that names the arvo revision and says arvo's own `dev` no longer carries it is workspace history in a document that renders publicly. It is removed; the pin itself is ticketed already.
- `hilavitkutin-persistence` tests (finding 2): a catalogue test, ignored with the ticket `462b061b94ed`, that finds two `str_const!` strings sharing their low 28 bits and states what evict should do. The design does not say how this resolves, so the test states the intended behaviour (distinct keys for distinct strings) and stays red where it runs.
- `hilavitkutin-sym` (finding 3): a `compile_fail` doctest that `Generator::single` in a constant is a build error for a one-origin shape with no room for its origin.
- `hilavitkutin-extensions-macros` (finding 10, the small part): the smoke test runs the `cargo` that runs the tests (`env!("CARGO")`), not whichever one is first on the path.
