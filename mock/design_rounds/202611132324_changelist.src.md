## What the source now says

### 1. A column of either kind is registered with its start, in `hilavitkutin-api`

`store.rs` has the sealed trait `Starts` over `Column<T>` and `Buffered<T, M>`, the one carrier `Started<S: Starts>`, and on each marker `start_from(value)` for every element type and `start()` under `HasTrivialCtor`, both `const fn`. `StartsFromDefault` is bounded on `Starts` and has one blanket impl where the element type has a `Default`. `StagedBuffered<T, M>` is gone, and so is `impl BuilderInput for Column<T>`: the bare marker names a column in a unit's lists and registers nothing.

### 2. One drain for both columns, in `hilavitkutin`

`resource/bindings/column.rs` has the trait `Kept`, which gives the kind of a marker. `BindingsFor` and `DrainStores` have one arm for `Started<S>` and none for a bare `Column<T>`. The drain reserves by the kind and writes the start to every record of every reservation before the scheduler exists.

### 3. The reach cuts are constants of the carrier, in `hilavitkutin` (review 2, finding 3)

`plan/reach_cut.rs` has `CarrierCuts`, whose three associated constants are the cut mask, the consumer mask and the unit count. `scheduler/worker.rs` reads them where it called `reach_cuts`, `consumer_mask` and `group_n` on every core of every pass. A constant of a generic type needs the bounds it is evaluated under, so `worker_accum_unit_outer`, `worker_main` and `Scheduler::run_parallel` now ask `const BundleMasks`, `const ConstCapacity` and `const BitAccess` where they asked the plain bounds.

### 4. The frozen lints hold an edit to the trunk (review 2, findings 1 and 2)

`mock/lints/frozen_ledger.rs` reads `file` and `hash` of every break, refuses a last break whose hash is not the ledger line's, and compares the ledger with the one at the merge base with `origin/dev`: a hash that moved with no new break is refused, and so is a moved hash of a line the trunk has locked. `mock/lints/frozen/scan.rs` reads an attribute from `#` to its closing bracket over the whole text, so `frozen-no-feature-gate` and `frozen-no-recursion-limit` see one broken over lines.

### 5. The public page

The root `README.md` registers its example columns with a start, says how a column of either kind starts, names `hilavitkutin-conformance`, and no longer shows three builder methods that do not exist. The catalogue row on `run_fused` says the columns between two fused units stay at their start.

That a unit of the first pass reads the start from a plain column nothing wrote is `hilavitkutin/tests/column_start.rs`, module `plain`, over a provider filled with `0xA5`. It was committed red in `7adf0b9e`, ahead of the drain's write in `970c3a43`.

That a compared write of the start's own value by a unit at the close of the first pass marks nothing changed is `a_close_restating_the_start_in_the_first_pass_marks_nothing_changed` in the same module, with `a_close_writing_another_value_in_the_first_pass_wakes_the_reader` as its control. With the api's compare forced to always write (`write_at.rs`, the `Differs` arm), the first fails with four windows handed to a reader that was owed none.

Every registration in the engine's tests, the frozen authors' tests, the provider examples and the bench tree carries a start. The tests that filled a whole column with one value before the first pass register that value as the start instead.

## Departures from the design, each with its reason

`Started::into_inner` is a plain function and not a `const fn`. A carrier of a generic value cannot be taken apart in a constant without the value's destructor being callable there (E0493).

The engine's arm for `Started<S>` asks `S: Member` beside `Kept`. The store list is a list of members, and the bound is what lets the arm name the marker in it.

`Buffered`'s start functions sit under `M: BufferMode`, the bound the marker already has.

The design's proving checks speak of every hidden seed. What stays planted through the scheduler's hidden accessors in the engine's tests is data that differs from record to record, one side alone of a buffered column, a sentinel written between two passes, and the seed of an accumulator, which is no column and has no start. A start is one value for a whole column and reaches none of those.

A column a kit owns still has no binding and no start. That is the design's own marker, on ticket `a_column_registered_twice_no_longer_builds_and_a_kit_s_owned`.

`Scheduler::run_parallel` asks the three `const` bounds named under 3. The doc changelist counted no break there. `build` already asks `const BundleMasks` of the unit list and evaluates the reach rule under `const ConstCapacity`, and every call of `run_parallel` in the engine's tests, the frozen authors' tests and the bench tree builds unchanged. A caller generic over the unit list would have to carry the `const` form.

What the frozen ledger does not hold is the unlocking of a line and the removal of a frozen file together with its line. The designs say nothing of either, so neither is decided here: question ticket 174ba049e794 asks op.

Review 2's remarks on the text of commits `57dc2c99` and `0025165d` stand unanswered in the source. Both commits are pushed, and their text changes only by rewriting pushed history.
