## Changes proposed

### CHANGE: add `## Virtual flag system (domain 10)` section to DESIGN.md.tmpl

Describe the canonical design from spec `:685-714`, prose-naming the new mechanism (the concrete new types/fns are backticked only once they ship in the src CL, to keep the design-doc-source-mismatch lint green; existing types `Virtual`, `On`, `VirtualFirerApi`, `Bits` may be backticked):

- Bit-packed fire flags: one bit per registered `Virtual` type, packed u8 into u64 words (arvo-bitmask), with the hierarchical zero-skip (u64 == 0 skips 64, u8 == 0 skips 8). The virtual's index is const-folded from its compile-time type identity.
- Fire: a WU calls the virtual-firer (the existing `VirtualFirerApi::fire::<V>()` surface), which is one byte load, one OR, one byte store. The B3 no-op becomes a real flag set.
- Per-(virtual, consumer) bit tracking: each `On<V>` consumer has its own bit for the virtual it gates on. A fire sets all consumer bits for that virtual. A consumer dispatches when its bit is set, and the bit is cleared on first dispatch (clear-on-dispatch, not on completion), so a re-fire during execution re-runs the consumer the next pass with no lost fires.
- Epoch-based reset: a global u8 epoch increments per pass; "flag set" means flag value equals the current epoch, so per-pass reset is one increment, not a memset, with a full clear only on epoch wraparound (every 256 passes).
- Affinity-ordered bit assignment: co-firing virtuals are bin-packed into the same byte/word at plan time (two-level greedy: u64 words then bytes), so connector-heavy passes leave cold words zero. Plan-time, zero runtime cost.

State that `On<V>` gating is a runtime bit-test folded into the per-member dispatch gate (the same shape as the dirty-skip mask), not a new dispatch path, so devirtualisation is preserved (the composition with the const-gated `RunGatedTrunk` / `dispatch_core` walk is de-risked by a sketch before the src CL).
