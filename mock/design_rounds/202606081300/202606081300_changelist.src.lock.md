# Src changelist: GATE-2 E4 slice 1 — virtual firing + On-gating

**Date:** 2026-06-08
**Phase:** SRC (DRAFT -> IMPL)
**Round:** 202606081200 (topic `202606081200_topic.gate2-e4-virtual-firing-and-on-gating.md`, doc CL `202606081300_changelist.doc.lock.md`)
**Scope:** make virtual firing and `On<V>` dispatch-gating real. Today `VirtualFirerApi::fire` is a no-op (`engine_ctx.rs:1054`) and every WU dispatches as `Always` because the dispatch carrier bounds `W: WorkUnit` (= `WorkUnit<Always>`). This slice ships the per-virtual fired-flag store (domain-10 bit-packed, epoch-reset), the schedule-gate dispatch generalisation, and the real firer, so a producer WU can fire `Virtual<V>` and an `On<V>` consumer runs in response.

## Current state

`hilavitkutin-api` ships `Always`, `On<V>`, and `WorkUnit<Schedule = Always>` (work_unit.rs); the `Schedule` is a type param with per-impl associated types. There is no way for the dispatch carrier to recover a heterogeneous WU's `Schedule` (a free `WorkUnit<S>` bound is unconstrained, `E0207`). `VirtualBinding<T, Tail>` (bindings.rs:163) exists in the bindings cons-list, one node per `Virtual<T>` marker, with no backing data. The engine dispatch (`RunFiber` fiber_run.rs:76, `RunGatedTrunk` trunk_gate.rs) bounds `W: WorkUnit` and reads `<W as WorkUnit>::{Read,Write,Ctx,execute}`, i.e. always the `Always` impl. `EngineCtx`'s `VirtualFirerApi::fire<V>` is a no-op (engine_ctx.rs:1050-1062).

Proven before this CL: sketch `202606081400_e4-schedule-gated-walk` (the `Scheduled`/gate compile-time dispatch over a mixed carrier) and sketch `202606081700_e4-scheduled-blanket-coherence` (the blanket `impl<W: WorkUnit<Always>> Scheduled for W` coheres with explicit `On<V>` impls, and the real carrier bound is `W: HasSchedule + WorkUnit<<W as HasSchedule>::Sched>`).

## Scope boundary (slice 1a vs 1b)

This CL ships the per-virtual epoch-reset fire-flag layer (domain-10 "bit-packed fire flags" + "epoch-based reset", spec `:689-694`, `:709-713`) and the gating + firing that rides on it. The per-(virtual, consumer) bit layer with clear-on-dispatch (spec `:702-707`) and the affinity-ordered plan-time bit bin-packing (spec `:696-700`) are slice 1b (a following round on this branch); they are additive layers on top of the per-virtual flags, not a rework. The per-virtual epoch flag is a correct subset for fire / gate / per-pass-reset and for multiple consumers of the same virtual within a pass (all see the flag, end-of-pass epoch increment clears it); it is not a stopgap. The during-execution-after-dispatch re-fire edge (no-lost-fires) is what 1b's clear-on-dispatch adds. Recorded in BACKLOG by this CL.

## Changes proposed

### CHANGE: add trait `ScheduleGate` to hilavitkutin-api
File: `mock/crates/hilavitkutin-api/src/work_unit.rs`
A marker-level trait naming the two schedule kinds for the engine to gate on, with no engine-state dependency in the api (the api cannot see engine bindings). `pub trait ScheduleGate {}` impl'd for `Always` and `On<V>` (`impl ScheduleGate for Always {}`, `impl<V> ScheduleGate for On<V> {}`). The runtime fired-state read lives engine-side (next CHANGE); the api trait only bounds `HasSchedule::Sched`.
Verification: `grep "pub trait ScheduleGate" mock/crates/hilavitkutin-api/src/work_unit.rs` returns one match; `grep "impl ScheduleGate for Always" ...` and `grep "impl<V> ScheduleGate for On<V>" ...` each return one.

### CHANGE: add trait `HasSchedule` + blanket impl to hilavitkutin-api
File: `mock/crates/hilavitkutin-api/src/work_unit.rs`
`pub trait HasSchedule { type Sched: ScheduleGate; }` plus the blanket `impl<W: WorkUnit<Always>> HasSchedule for W { type Sched = Always; }` (proven coherent by sketch 202606081700, so every existing Always WU gains `HasSchedule` with zero churn). An `On<V>` WU adds an explicit `impl HasSchedule for ThatWu { type Sched = On<V>; }` as new code. Named `HasSchedule` not `Scheduled` because `dispatch_codegen` already ships an unrelated `Scheduled` trait-alias for `LockFreeDispatch` (collision avoided per no-reinvent).
Verification: `grep "pub trait HasSchedule" mock/crates/hilavitkutin-api/src/work_unit.rs` returns one; `grep "impl<W: WorkUnit<Always>> HasSchedule for W" ...` returns one; the engine + api test suites compile with no new impl on existing Always WUs.

### CHANGE: per-virtual fired flag on `VirtualBinding`
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
Give `VirtualBinding<T, Tail>` a fired-flag cell carrying the epoch value at which `T` last fired (`Cell` of the arvo epoch type; "set" = value == current epoch). Add `__fire(epoch)` (set), `__is_set(epoch) -> Bool` (value == epoch), and the field plus its constructor wiring. This is the domain-10 per-virtual fire flag; bit-packing across virtuals into `Bits` words is the slice-1b/affinity refinement (per-virtual cell is the correct, testable first shape).
Verification: `grep "fn __is_set" mock/crates/hilavitkutin/src/resource/bindings.rs` returns one match; the firer test (below) observes a set flag after a fire.

### CHANGE: epoch counter on the runtime + per-pass increment
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Add a per-pass `virtual_epoch` (arvo `u8`-width epoch) to the scheduler runtime, incremented once per `run` / `run_parallel` pass before dispatch, so "flag set" decays automatically next pass (spec `:709-713`; full clear only on 256-wrap). Thread the current epoch into the dispatch walk alongside the existing dirty mask.
Verification: `grep "virtual_epoch" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns matches at the field, the increment, and the dispatch call sites; a two-pass test shows a pass-N fire does not gate a consumer in pass N+2 absent a re-fire.

### CHANGE: generalise the dispatch carrier bound from `W: WorkUnit` to schedule-recovered
File: `mock/crates/hilavitkutin/src/dispatch/fiber_run.rs`, `mock/crates/hilavitkutin/src/dispatch/trunk_gate.rs`
Change `RunFiber for WuCons<W, Tail>` and `RunGatedTrunk`'s member walk from `W: WorkUnit` to `W: HasSchedule + WorkUnit<<W as HasSchedule>::Sched>` (the bound proven by sketch 202606081700), and replace every `<W as WorkUnit>::{Read,Write,Ctx,execute}` projection with `<W as WorkUnit<<W as HasSchedule>::Sched>>::...`. Gate the per-member execute on an engine-side schedule check (next CHANGE), ANDed with the existing dirty bit. The `Always` arm const-folds the gate to `true` (zero cost, devirt preserved, the existing element_wise/branching paths unchanged); the `On<V>` arm reads the fired flag.
Verification: `grep "HasSchedule + WorkUnit" mock/crates/hilavitkutin/src/dispatch/fiber_run.rs` returns a match; the full engine suite is bit-identical for all-Always workloads (every existing test passes); the D6 ASM gate stays zero-`blr` (the gate is a const/flag test, not a call).

### CHANGE: `VirtualProject` write-virtual bundle + `EngineCtx` field (firer keying)
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`, `mock/crates/hilavitkutin/src/resource/bindings.rs`
Architecture constraint discovered in impl: `EngineCtx` carries only the projected read/write column + accum bundles, NOT the virtual bindings, so `fire<V>` has no handle to a fired flag. Resolution mirrors the shipped accumulator path exactly. Add a `VirtualProject<'frame, W, I>` (mirror of `AccumProject`) that projects `W`'s `Virtual<T>` markers from the full `bindings` into a `WVirt` bundle of `&'frame` stamp-cell refs (the `VirtualBinding<T>` stamp cells reached through the bindings chain). Add a `write_virtuals: WVirt` field to `EngineCtx` with a nil default (`WVirt = VirtNil`, mirroring `WAccum = AccPtrNil`) so every existing Always-WU `Ctx` alias that writes no virtual compiles unchanged. `EngineCtx::project` gains the `VirtualProject<'frame, W, _, Out = WVirt>` bound and projects `write_virtuals` from `bindings` (like `write_accums`).
Verification: `grep "write_virtuals" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` returns matches at the field + project; existing all-Always tests compile with no `Ctx`-alias change.

### CHANGE: real `VirtualFirerApi::fire` replacing the no-op
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs:1050-1062`
`fire<V>()` resolves the projected `&Cell` stamp ref from `write_virtuals` via a `VirtualFire<V, I>` selector over the bundle (inferred `I`, exactly like `ResolveAccumAppend` resolves the accum len-cell via `AccumSelector<T, I>` at `engine_ctx.rs:1009`, so no `E0207`) and sets the stamp to the current epoch (one store; internal fire non-atomic per spec `:716-717`). The `W: Contains<Virtual<V>>` bound proves the projection holds `V`. Replace the no-op body. The epoch reaches `fire` via an `EngineCtx` `epoch: USize` field set at `project` time. Proven shape: sketch `202606081800_e4-gate-firer-trait-shapes` (`VirtualProject` + `VirtualFire` infer the index list, no turbofish).
Verification: the firer test observes the consumer running after a fire; `! grep "B3 no-op" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` (the no-op comment is gone).

### CHANGE: engine-side schedule gate `GateWith` resolving the virtual binding from full bindings
File: `mock/crates/hilavitkutin/src/dispatch/trunk_gate.rs` (the `RunGatedTrunk` member-gate site) + `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` (the `VirtualStampSelector` shared keying primitive)
A new `VirtualStampSelector<V, Index>` (engine_ctx.rs) mirrors `AccumSelector<T, Index>`: structural over the binding nodes (`Here` matches a `VirtualBinding<V, _>` head, `There<I>` recurses any node kind), returning `&Cell<USize>` (CHANGE 3's stamp). It is the SHARED keying primitive: the firer (CHANGE 7) and this gate resolve the same cell by identity, so a fire is observed by the gate, no global virtual index. A new `GateWith<A, GI>` trait (engine_ctx.rs) dispatches the per-member readiness on `<W as HasSchedule>::Sched`: `impl<A> GateWith<A, Here> for Always` returns `Bool::TRUE` (const-foldable, DCE'd, zero cost), pinning `GI = Here`; `impl<A, V, GI> GateWith<A, GI> for On<V> where A: VirtualStampSelector<V, GI>` reads the cell and returns `Bool(stamp == epoch)`. `GI` is the SIXTH element of each unit's `RunFiber` witness tuple `(RIdx, RCIdx, WCIdx, WAIdx, WVIdx, GI)` (NOT a separate list): `RunFiber`'s `WuCons` impl carries it and bounds `<W as HasSchedule>::Sched: GateWith<A, GI>` to pin it, so `GI` infers alongside the projection indices (folding it into the already-determined Witnesses tuple avoids the weak-inference of a separate `SchedW` var; the separate-list shape compiled but left the tuple tail ambiguous at the bare `run()` call site). `RunGatedTrunk` destructures `GI` from the tuple head and gates `Member::IS && dirty.bit(Pos::INDEX).0 && GateWith::open(bindings, epoch).0`. The runtime `epoch: USize` threads as a value arg through `run_trunk` / `dispatch` / `dispatch_core` / `RunFiber::{run,run_gated,run_head}` (and the Approach-A `RunTrunk`/`RunPhase`/`RunPipeline` nests); the scheduler holds a `virtual_epoch: USize` field incremented once per pass in `run` / `run_parallel` / `run_fused` / `run_one_trunk`. No `SchedW` generic on the dispatch traits or scheduler methods (`run` stays `run<Witnesses, GW>`). The builder/plan-layer bounds (`WorkUnitBundle`, `BundleProject`, `UnitAccess`) also generalise `W: WorkUnit` to `W: HasSchedule + WorkUnit<<W as HasSchedule>::Sched>` so an `On<V>` unit registers + projects. Proven shape: sketch `202606081800_e4-gate-firer-trait-shapes` (firer + gate + inference) and the `gate2_virtual_firing` test (fired `On<Tick>` runs, unfired `On<Never>` skips, in one pass). Devirt preserved (Always folds to true; On<V> is a load+cmp, no call).
Verification: `grep "trait GateWith" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` returns one; `grep "trait VirtualStampSelector" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` returns one; `tests/gate2_virtual_firing.rs` asserts `On<Tick>` consumers ran and the `On<Never>` consumer did not; the all-Always suite (163 tests) shows no regression; D6 ASM gate stays zero-`blr`.
Verification: `! grep -A3 "fn fire" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs | grep "B3 no-op"` (the no-op comment is gone); the firer test observes the consumer running after a fire.

## Test plan

TDD, fail-first. New `mock/crates/hilavitkutin/tests/gate2_virtual_firing.rs`:
1. `fire_then_on_consumer_runs`: a producer WU (`Always`, writes `Virtual<Tick>`, fires it) ordered before an `On<Tick>` consumer; after `run`, the consumer observed it ran (writes a sentinel column the test reads).
2. `absent_fire_on_consumer_skips`: same graph, producer does NOT fire; the `On<Tick>` consumer does not run.
3. `multi_consumer_same_virtual`: two `On<Tick>` consumers both run after one fire in the same pass.
4. `epoch_resets_across_pass`: a fire in pass N does not gate the consumer in pass N+1 without a re-fire (per-pass epoch decay).
5. all-Always regression: an existing all-`Always` workload is bit-identical (run the existing engine suite; no new behaviour for Always WUs).
6. D6 ASM gate: the dispatch bodies stay zero-`blr` (the gate is const-folded for Always and a flag read for On<V>, never a call).

Each test fails before the corresponding CHANGE lands (no firing, no gating today) and passes after. Lock + close the round after green + the all-green audit.
