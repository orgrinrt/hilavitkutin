## CHANGE: add `unit_outer` accumulator-pipeline test to `tests/morsel_outer.rs`
File: `mock/crates/hilavitkutin/tests/morsel_outer.rs`
A second test exercising the `accum_free == false` branch: two WorkUnits each writing `Accum<Av>` (so an accumulator store is registered and the pipeline is not accumulator-free) over a record count spanning multiple morsels, each recording its tag once per dispatch. The recorded sequence must be unit-outer in shape: each unit's per-morsel dispatches are contiguous, never interleaved. The assertion is order-agnostic on which unit the plan dispatches first (both are appenders, so the plan may order either first); it pins that the two units are not interleaved, which is what would happen if the guard wrongly routed an accumulator pipeline to morsel-outer. This is a regression guard on already-correct behaviour, so it passes from the first run.
Verification: `cargo test -p hilavitkutin --test morsel_outer` runs two tests, both green; the new test asserts a contiguous (unit-outer) dispatch sequence for an accumulator pipeline.

## CHANGE: name the single-cross-morsel-surface assumption in `Scheduler::run` doc
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
The `run` doc comment (or the morsel-outer branch comment) gains a sentence stating that the morsel-outer nesting is sound only because the accumulator append path is currently the single Context surface whose effect crosses a morsel boundary (`read` / `write` are morsel-relative, `each` / `reduce` / `batch` are morsel-confined, `fire` is a no-op at this stage), so widening `fire` to real cross-record edge semantics must revisit the `accum_free` guard.
