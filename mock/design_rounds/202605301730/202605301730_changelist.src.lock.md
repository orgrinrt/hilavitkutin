## Intent

Replace the ~209 `const _: Cap` plan-dimension parameters across the engine's `plan/`, `thread/`, `dispatch/`, and `adapt/` modules with a single `D: PlanDims` type parameter whose associated types are each an arvo `Capacity`. This escapes the `generic_const_exprs` overflow that blocks threading plan dims through generic scheduler code (the C2-slice-3 ICE) and lets the engine consume the migrated arvo containers/algorithms. Behaviour-preserving: array sizes are identical (`Dim<N>::Array<T>` is `[T; N]`), algorithms unchanged, bench-neutral by construction. The design and the dimension inventory are in the locked doc CL and the TOPIC.

The arvo dep is re-bumped to the #651 migration (`mock/Cargo.lock`, committed atomically with this round). The 6 current compile errors (`plan/laplacian.rs` `SymmetricLaplacian` + its `LinearOperator` impl + `apply`; `plan/steps.rs` calls to `rcm_reorder_via` / `block_diagonal_via` / `k_way_partition`) resolve as a consequence of threading `Capacity` through, not as a separate fix.

## The dimension mapping

Each former `const MAX_*: Cap` (or single-letter alias) maps to a `PlanDims` associated `Capacity` type. A struct/function that carried a subset of these const generics takes one `D: PlanDims` and projects the subset it needs; a structure that genuinely sizes by a single dimension may take a single `C: Capacity` instead. The mapping:

`MAX_UNITS` -> `D::Units`, `MAX_STORES` -> `D::Stores`, `MAX_EDGES` -> `D::Edges`, `MAX_PHASES` -> `D::Phases`, `MAX_TRUNKS` -> `D::Trunks`, `MAX_TRUNKS_PER_PHASE` -> `D::TrunksPerPhase`, `MAX_FIBERS` -> `D::Fibers`, `MAX_LANES` -> `D::Lanes`, `MAX_COLUMNS` -> `D::Columns`, `MAX_COMPONENTS_PER_TRUNK` -> `D::ComponentsPerTrunk`, `MAX_UNITS_PER_FIBER` -> `D::UnitsPerFiber`, `MAX_COLUMNS_PER_FIBER` -> `D::ColumnsPerFiber`, `MAX_CORES` -> `D::Cores`. The `N`/`E` aliases in `laplacian.rs` and the `F`/`C`/`P` aliases in `adapt/arena.rs` map to `Units`/`Edges` and `Fibers`/`Cores`/`Phases` respectively.

The per-element rewrite per site: `const MAX_X: Cap` parameter -> a `D: PlanDims` parameter (one per item, replacing the whole subset); field/return `[T; cap_size(MAX_X)]` -> `<D::X as Capacity>::Array<T>`; `where [(); cap_size(MAX_X)]:` -> dropped; local scratch `[v; cap_size(MAX_X)]` -> `<D::X as Capacity>::filled(v)`, indexed build -> `<D::X as Capacity>::from_fn`; value-position `cap_size(MAX_X)` -> `cap_size(<D::X as Capacity>::CAP)`; array indexing through `.as_ref()` / `.as_mut()`. Structs with a `Capacity::Array` field that previously derived `Copy`/`Clone` get manual impls bounded on the associated-type arrays (the `#[derive]` would wrongly require `D: Copy`).

## Deviations from plan (reconciled at lock)

The mechanical threading surfaced refinements the family-level plan left open, all behaviour-preserving:

- Some structures took TWO `Capacity` params rather than `D: PlanDims` or a single `C`, because their two axes vary independently per call site: `PlanInputs<CU, CS>` (units + stores), `DirtyMasks<CF, CS>` (fibers + stores OR fibers + columns, instantiated both ways), `SymmetricLaplacian<'data, U, E, F>` (units + edges), `AdaptArena<'arena, CF, CC, CP>` (fibers + cores + phases). This matches the existing two-const-param shapes and keeps the `project.rs` projection machinery clean.
- `synthesise_core_programs<D, PC, TC, FC>` takes `D: PlanDims` for the plan dims plus three extra `Capacity` params (`PC`/`TC`/`FC`) that size the unmigrated api `CoreProgram`'s `usize` min-const-generic arrays (not plan dimensions).
- `const fn new()` constructors throughout the plan structs lose `const` (arvo's `Capacity::filled`/`from_fn` are not const). These are plan-stage scratch constructors never used in a const context after the migration; the `Send`/`Sync` static assertion was rewritten to name `ExecutionPlan<DefaultPlanDims>` rather than construct it.
- Manual `Debug` impls on the array-holding structs use `finish_non_exhaustive` (the opaque `Capacity::Array` GAT carries no `Debug` bound).
