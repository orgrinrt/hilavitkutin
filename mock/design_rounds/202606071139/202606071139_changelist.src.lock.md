## Summary

Add the GATE-2 N-core dispatch entry in its inline (single-threaded) form:
`Scheduler::run_parallel`. It integrates the R4a per-(core, phase) masks
(`dispatch/core_mask`) with the shipped `run_gated` carrier walk, dispatching
the canonical waist-bounded phases as per-core column-disjoint trunk programs
joined by waist barriers. The barrier between phases collapses to the loop
boundary in this single-threaded form; real worker threads replace the
sequential core sweep at the next step without changing the partition.

## CHANGE: method `Scheduler::run_parallel` FROM `absent` TO `pub fn run_parallel<Witnesses, GW>(&mut self, ncores: USize) -> Cfg::Out`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep "pub fn run_parallel<Witnesses, GW>" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match.

Behaviour: resets accumulators, fills per-unit `phase[]` / `trunk[]` via
`grouping_arrays::<WuVals, Stores, GW, D::Units, D::Stores, D::AdjRow>`,
computes the phase count, then for each phase `p` and each core `c` runs a
morsel-loop `run_gated` walk gated by
`core_phase_mask::<D::AdjRow>(&phase, &trunk, n, c, p, ncores)`. The phase
loop is outermost (the waist barrier). Output-equivalent to `run` for a pure
read-after-write carrier. Accumulator (unit-outer) carriers are out of scope
this round (a red arm until the threaded executor step).
