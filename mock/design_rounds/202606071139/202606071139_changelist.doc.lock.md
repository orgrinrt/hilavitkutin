## Doc surface assessment

No `*.md.tmpl` edits this round. The change adds one internal scheduler
method (`Scheduler::run_parallel`) whose documentation surface is its
rustdoc, authored inline in `scheduler/mod.rs` alongside `run` /
`run_one_trunk` / `run_fused`. The engine `DESIGN.md.tmpl` does not yet
enumerate per-method scheduler dispatch entries (it describes the dispatch
model, not the method list), so adding `run_parallel` there now would not
match an existing pattern and would couple a still-evolving GATE-2 surface to
the design doc before the threaded form settles.

The public dispatch surface is documented at the model level (waist-bounded
phases, per-core trunk programs, runtime ownership masks), which already
holds in the shipped design rounds and the consolidation spec Steps 5 and 8.
`run_parallel` is the inline realisation of that model; when the threaded
executor lands and the N-core dispatch entry point is final, a doc-sync round
adds it to `DESIGN.md.tmpl` as the canonical GATE-2 run entry.

## Why no design drift

The method follows the canonical model verbatim: waist-bounded phase axis
(R2, not depth), per-phase round-robin trunk-to-core ownership (R4a), single
-core as the one-core degenerate (no special path). It introduces no new
vocabulary and no new public type; `Witnesses` / `GW` mirror
`run_one_trunk`'s inferred type parameters.
