subsystem's non-degradation invariant:

- Adaptation exists to improve performance and must never degrade it: an
  adaptive run must be no slower than the non-adaptive baseline on any workload,
  and strictly faster on an imbalanced one. This is the make-or-break property;
  an adaptive scheduler that loses to its own baseline is worse than none.
- The invariant is formalised as a catalogued behavioural-contract test suite
  (`tests/adapt_perf_contracts.rs`), defined ahead of the machinery so the
  implementation is built against the contract rather than retrofitted to it.
