# Topic: adapt performance contracts (the make-or-break cases)

**Date:** 2026-06-19
**Phase:** TOPIC
**Scope:** `hilavitkutin` engine tests (a catalogued behavioural-contract suite for the adapt subsystem); a short DESIGN note on the non-degradation invariant
**Source topics:** spec domain 22 (adapt), the catalogue-edge-cases-as-tests discipline, op directive (2026-06-19)

## Why this round exists

The adapt subsystem's entire reason to exist is that adaptation IMPROVES
performance, and never degrades it. That is the make-or-break property: an
adaptive scheduler that sometimes makes a workload slower than the non-adaptive
baseline is worse than no adaptation, because it adds runtime sampling +
re-selection cost for a net loss. The EMA timing axes (pass_duration, phase_ema,
fiber_ema), the idle/core-balance signal, and every heuristic that consumes them
(`select_adapt_config`, tier-1 morsel re-chunk, strategy reselect, predictive
parking, P/E-core routing) all exist to serve that one contract.

Per op and the catalogue-edge-cases-as-tests rule: define these cases NOW, as
tests, even though the machinery that turns them green is not built yet. The
cases make or break the whole subsystem, so they must be formalised and never
lost. They stay catalogued-red (`#[ignore = "catalogue: ...; tracked #341"]`)
until `select_adapt_config` + the actuation paths land; the assertion each test
will carry states the INTENDED contract (the comparison, the workload, the
tolerance), not a watered-down version that passes today.

## The contracts (each becomes one catalogued test)

The shared shape: run a workload twice on the same input, once with adaptation
OFF (the baseline) and once with adaptation ON (converged over enough frames),
and compare. The toggle (`StandardAdaptKit` vs `OffAdaptKit`) and a
deterministic-enough measurement harness are the machinery these depend on.

1. **EMA adaptation never degrades a balanced workload.** On a workload already
   balanced across phases/cores, adaptation must not make it slower:
   `adapted_time <= baseline_time * (1 + epsilon)`. Adaptation that loses on the
   easy case is disqualifying (it means the sampling + re-selection overhead is
   not amortised).

2. **EMA adaptation improves an imbalanced workload.** On a workload with a
   skewed per-phase / per-core load, adaptation must converge to a strictly
   faster steady state than the baseline: `adapted_steady_time < baseline_time`.
   This is the core value proposition; if it does not hold, the subsystem fails
   its purpose.

3. **`select_adapt_config` reduces the bottleneck phase.** After re-selection,
   the bottleneck phase's `phase_ema` is lower than before re-selection (the
   tuning actually targets the slow phase, not an arbitrary one).

4. **Tier-1 morsel re-chunk reduces worst-core idle.** Re-chunking an imbalanced
   morsel distribution lowers `idle_ns` (the core-balance signal) without raising
   total time.

5. **Strategy reselect never regresses throughput.** Switching a phase's strategy
   between frames leaves throughput non-decreasing at steady state.

6. **Predictive parking reduces wasted wait without adding latency.** The wait-
   tier selection lowers spin/park waste relative to a fixed strategy without
   increasing frame latency.

7. **P/E-core routing improves throughput on heterogeneous cores.** Routing hot
   work to performance cores improves throughput versus uniform routing on a
   machine with a P/E split (guarded off on uniform-core hosts).

## How they stay honest until green

Each test's body, until the machinery exists, is a marker that documents the
exact contract and fails-on-run (`unimplemented!` with the contract text +
`tracked #341`); the test is `#[ignore]`d so it does not block the gate but is
discoverable via `cargo test -- --ignored`. When the adapt on/off toggle and
`select_adapt_config` land, each body is filled with the real comparative
measurement and the `#[ignore]` removed. The contract (the test name + doc +
the comparison it will assert) is the durable artefact; it is defined now so the
implementation is built against it, not retrofitted to whatever it happens to do.

## Not in scope

Building the machinery (`select_adapt_config`, the adapt on/off measurement
harness, the actuation paths). This round only formalises the contracts as a
catalogued test suite plus a DESIGN note naming the non-degradation invariant.
