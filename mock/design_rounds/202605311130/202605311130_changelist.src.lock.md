# Source changelist

Store-back the plan's six flat CSR pools on the scheduler's `ColumnStorage`.
`build` computes the full plan (as before, for the cycle check + topo order),
drains the resource columns, then reserves the plan columns at a continued
`StoreId` namespace and copies the flat arrays in, keeping a `Copy`
`PlanHandle`. TDD: a round-trip test reads a store-backed column back and
confirms it matches the computed plan, written and confirmed red before the
store-backing lands.

## CHANGE: new `PlanHandle` struct in `scheduler/mod.rs`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
`pub struct PlanHandle` (Copy): the base plan-column index plus the live phase
/ trunk / fiber / unit counts. The plan columns are a closed set, so the column
`StoreId`s are a fixed offset off the base, exposed as `pub fn phases_id()` /
`trunks_id()` / `fibers_id()` / `unit_meta_id()` / `morsel_sizes_id()` /
`rcm_order_id()` returning `StoreId`, plus count accessors. `PlanHandle::empty()`
for the no-plan default.
Verification: `grep "pub struct PlanHandle" src/scheduler/mod.rs` returns one match.

## CHANGE: `compute_topo_order` becomes `compute_plan` returning the full plan
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Rename the private `compute_topo_order` to `compute_plan`, returning
`Outcome<ExecutionPlan<DefaultPlanDims>, BuildError>` (Err = `PlanFailed` on a
cycle) instead of just the permutation. A small `extract_topo_order(&plan)`
reads the permutation off `unit_meta` (the loop that was inside
`compute_topo_order`).
Verification: `grep "fn compute_plan" src/scheduler/mod.rs` returns one match.

## CHANGE: store-backing helpers `store_column` + `store_plan` in `scheduler/mod.rs`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
`store_column<T: ColumnValue, CS: ColumnStorage>(storage, id, src, count)`:
reserve `id` for `count` records, `copy_nonoverlapping` the live prefix in via
`column_ptr_mut` (under a SAFETY note), map any reserve failure to
`BuildError::AllocationFailed`. `store_plan<CS>(plan, storage, base)`: reserve +
copy the six flat pools (phases, trunks, fibers, unit_meta, morsel_sizes,
rcm_order) at `base + offset`, return the `PlanHandle`.
Verification: `grep "fn store_plan" src/scheduler/mod.rs` returns one match.

## CHANGE: `Scheduler` gains `plan_handle: PlanHandle`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Add the field. The plan persists in `storage`; `plan_handle` locates it. The
`Default` impl sets `PlanHandle::empty()`. A `#[doc(hidden)] pub fn __plan_handle()`
accessor mirrors `__storage`.
Verification: `grep "plan_handle" src/scheduler/mod.rs` returns matches.

## CHANGE: `build` / `build_with` store-back the plan after draining
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Both call `compute_plan` (cycle returns before allocating, as today), extract
the topo order, drain the resource columns (the drain advances `next_id` to the
resource count `N`), then `store_plan(&plan, &mut storage, next_id)` reserves the
plan columns at `N..N+6` and returns the `PlanHandle`, which the constructed
`Scheduler` carries.
Verification: `cargo test -p hilavitkutin` builds; existing build call sites
unchanged (no new turbofish).
