# SRC changelist: GATE-2 E8 — clock-sourced pass-duration EMA

**Date:** 2026-06-11
**Phase:** IMPL
**Round:** 202606110948 (GATE-2, task #341, branch `feat/hilavitkutin-parallel-engine-gate2`)
**Doc CL:** `202606110957_changelist.doc.lock.md`

The adapt subsystem's data spine: the scheduler gains a clock provider slot,
samples `now_ns` at frame start and end in every run entry, and folds the
frame duration into an EMA cell on the engine-owned meta block with the
canonical 1/8 weight. An `OnMeta<ScheduleEnd>` hook reads the cell through the
existing slice-3 bridge; because the fold happens after the last pass, the
hook in frame N reads the EMA as of frame N-1, which is the prediction
semantics (the consumer budgets the next frame from the prior frames'
average). The duplicate pre-bridge `SchedulerMetrics` is deleted.

## CHANGE: clock slot on the builder and the scheduler
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep "pub fn clock" mock/crates/hilavitkutin/src/scheduler/mod.rs`;
`grep "struct NullClock" mock/crates/hilavitkutin/src/scheduler/mod.rs`;
`grep "type DefaultClock" mock/crates/hilavitkutin/src/scheduler/mod.rs`;
test `gate2_adapt_ema` green.

The spec's builder surface names a `.clock(my_clock)` override; the engine
pattern for a defaulted provider type is the null-provider pair
(`NullMemoryProvider` / `NullColumnStorage`). Both land:

- `NullClock`: zero-sized `ClockApi` impl whose `now_ns` returns zero. Exists
  so the no_os build has an unconditional default type; a no_os consumer that
  wants real timing supplies its own clock via DI (the platform-tiers
  decision).
- `DefaultClock`: cfg-pair alias. `OsClock` under `feature = "platform-os"`
  (the crate default feature, so doing nothing gets real monotonic timing on
  the os tier), `NullClock` otherwise.
- `SchedulerBuilder` gains a trailing `Clk` type parameter and a `clock: Clk`
  field. `Scheduler::builder()` returns the `DefaultClock`-typed builder with
  `DefaultClock::new()` (const on both arms). A new
  `fn clock<C2: ClockApi>(self, clock: C2)` swaps the slot, returning the
  re-typed builder; it does not ride the `BuilderInput` `.with` routing
  (platform inputs there drop their value; the clock value must be retained).
- `Scheduler` gains a trailing `Clk = DefaultClock` type parameter
  (unbounded on the struct) and a `clock: Clk` field. `build` / `build_with`
  thread the builder's clock value through; the bare-scheduler construction
  site initialises `DefaultClock::new()`. The four full-generic impl blocks
  (and the `Drop` impl) thread the parameter; only the run-entry block bounds
  it `Clk: ClockApi`.

## CHANGE: ema_pass_duration_ns cell on the api meta SchedulerMetrics
File: `mock/crates/hilavitkutin-api/src/meta.rs`
Verification: `grep "ema_pass_duration_ns" mock/crates/hilavitkutin-api/src/meta.rs`;
api suite green.

`meta::SchedulerMetrics` gains `pub ema_pass_duration_ns: Cell<Nanos>` next to
`pass_count`, zero-initialised in `new()`. Same cross-thread discipline as
`pass_count`: the engine writes it only between frames (workers parked, or
single-core between run calls); an `OnMeta` hook reads it during the frame
under the publish/await happens-before. No new accessor work; the slice-3
`ctx.meta::<SchedulerMetrics>()` bridge already exposes the struct.

## CHANGE: fold_ema helper in the engine meta module
File: `mock/crates/hilavitkutin/src/meta.rs`
Verification: `grep "fn fold_ema" mock/crates/hilavitkutin/src/meta.rs`; its
in-file unit tests green (`cargo test -p hilavitkutin --lib`).

`pub(crate) fn fold_ema(prev: Nanos, sample: Nanos, seed: Bool) -> Nanos`:
the seed frame returns the raw sample; later frames step one eighth of the
gap toward the sample in integer nanos, branching on direction because the
type is unsigned (`prev + (sample - prev) / 8` when the sample is at or above
the previous value, `prev - (prev - sample) / 8` otherwise; an eighth via
shift or divide, whichever the `UFixed` surface carries). One helper shared
by all three run entries, unit-tested directly: seed case, upward fold,
downward fold, equal-sample fixpoint.

## CHANGE: frame sampling and fold in run, run_parallel, run_fused
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep -c "fold_ema" mock/crates/hilavitkutin/src/scheduler/mod.rs`
returns at least 3; tests `gate2_adapt_ema` green.

Each of the three frame entries (`run` at the top of its body,
`run_parallel` on the main thread before `frame_publish`, `run_fused` at the
top of its body) captures `let frame_start = clock.now_ns()` and
`let seed = first_frame` before any pass work, and at frame end (after the
last pass in `run` / `run_fused`; after `frame_await_done`, the merge, and
the trailing meta bands in `run_parallel`, still on the main thread) reads
`now_ns` again and writes
`metrics.ema_pass_duration_ns.set(fold_ema(prev, end - start, seed))`. The
write point is between frames in every entry, so no new sync is needed.
`run_one_trunk` / `run_all_trunks` are partial drivers, not frames; they do
not sample.

## CHANGE: TDD tests with a scripted deterministic clock
File: `mock/crates/hilavitkutin/tests/gate2_adapt_ema.rs` (new)
Verification: `cargo test -p hilavitkutin --test gate2_adapt_ema` green;
written first and observed red (accessor field missing / fold absent).

A `ScriptClock` (`AtomicUsize` cursor over a const `Nanos` script; `Send +
Sync + 'static` per the `ClockApi` bounds) makes the fold exactly assertable.
Three arms:

- **Single-core scripted**: fixture mirrors `gate2_meta_metrics` (consumer
  column WU + an `OnMeta<ScheduleEnd>` hook appending its read of
  `ema_pass_duration_ns` to an accumulator), built with
  `.clock(ScriptClock::new(&[1000, 1300, 2000, 2700, 3000, 3700]))`. Three
  `run` frames produce durations 300, 700, 700; the EMA after each frame is
  300 (seed), 350, 393. The hook reads the cell before the frame's fold, so
  the appended sequence asserts exactly `[0, 300, 350]`. Record capacity
  sized with headroom over the appends (the saturation lesson).
- **Parallel scripted**: fixture mirrors `gate2_parallel_meta`'s epilogue
  hook with the four-value script `[1000, 1300, 2000, 2700]`; two
  `run_parallel` frames; the hook's frame-2 read asserts the seed value 300.
- **Os-clock arm** (`cfg(feature = "platform-os")`): default builder, no
  `.clock` call; after two `run` frames the hook's second read asserts a
  nonzero value (wall-clock is not scripted; nonzero monotonic is the
  contract).
