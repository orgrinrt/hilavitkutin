# GATE-2 E8 adapt, slice 1: Clock-sourced pass-duration EMA through the bridge

**Date:** 2026-06-11
**Phase:** TOPIC
**Scope:** scheduler Clock wiring, `MetaBlock` EMA field, the duplicate `SchedulerMetrics` drift, a deterministic-clock test
**Source:** canonical consolidation spec domain 22 (executor reorganisation triggers, frame time prediction T3 #65, `:2042-2080`) + domain 23 (SchedulerMetrics resource); roadmap r2 §1 + §4 (adaptivity is a runtime parameter fed into the static walk, never structural mutation); task #341 (adapt subsystem) + #345 E8 half (plan recompute, later slice)

## Problem

The E4 meta pipeline is complete: the engine owns a `MetaBlock`, maintains
`pass_count` per pass, and an `OnMeta<ScheduleEnd>` hook reads it through the
`MetaAccess`-gated bridge, single-core and parallel alike. The adapt subsystem
(domain 22) now has its substrate but no data: the canonical frame-time
prediction surface (EMA of pass duration, read by consumers for frame budgeting
and cadence decisions) does not exist, because nothing in the scheduler reads a
clock.

Truth-of-impl:

- `ClockApi` (api platform contract, `now_ns -> Nanos`) and two impls
  (`OsClock` os tier, `StdClock` std tier) exist; `HasClock` exists. The
  scheduler neither stores nor calls a clock; the spec's builder surface names
  a `.clock(my_clock)` override that is not built.
- The adapt module ships the axis marker family (`PassDurationAxis`,
  `FiberEmaAxis`, ...) as on/off config markers; no axis carries data yet.
  `AdaptArena` is dead code (the warning in the engine lib).
- **Drift:** `scheduler/metrics.rs` carries a second, pre-bridge
  `SchedulerMetrics` (`frame_time_ns` / `morsels_dispatched` /
  `changes_detected`, a `Copy` struct re-exported from `scheduler`), written
  for the old resource-shaped read surface. The bridge round hard-proved meta
  state is engine-owned (`MetaBlock`), not a consumer resource; the api
  `meta::SchedulerMetrics` (with `pass_count`) is the one true type. Two
  same-named types is exactly the confusion the vocabulary discipline exists
  to prevent.

## Proposed slice

1. **Reconcile the duplicate.** Delete `scheduler/metrics.rs` and its
   re-export (pre-1.0, no shims). Its `frame_time_ns` concept lands as the
   EMA field below; `morsels_dispatched` / `changes_detected` return with
   their own data sources in later slices if the design still wants them.
2. **Clock on the scheduler.** The builder gains a clock slot per the spec
   builder API; the built scheduler stores the provider. Default: the os-tier
   `OsClock` (the platform-tiers decision: os + no_os only; no_os consumers
   supply their own via DI). The type rides the builder generics the same way
   the memory provider does.
3. **Pass-duration EMA in the MetaBlock.** `meta::SchedulerMetrics` gains
   `ema_pass_duration_ns` (an interior-mutable cell, like `pass_count`).
   `run`, `run_parallel`, and `run_fused` read `now_ns` at frame start and
   end and fold the duration with the canonical EMA weight 1/8 (spec T5
   vectorised-update basis): first frame seeds the raw duration, later frames
   fold `ema += (sample - ema) / 8` in integer nanos. Single-core and
   parallel write at the same point (frame end, workers parked), so the
   cross-thread discipline is unchanged.
4. **Bridge read.** An `OnMeta<ScheduleEnd>` hook reads
   `ctx.meta::<SchedulerMetrics>().ema_pass_duration_ns` (frame-time
   prediction, the domain-22/23 consumer surface). No new accessor work; the
   slice-3 bridge carries it.
5. **TDD with a deterministic clock.** A test `ClockApi` impl yielding a
   scripted `now_ns` sequence; assert the seed frame equals the raw duration
   and the second frame equals the 1/8 fold exactly. A second assertion on
   the os path only checks nonzero monotonicity (wall-clock is not scripted).

## Out of scope (later E8 slices)

Per-fiber / per-phase EMAs and the reorganisation triggers (morsel-size
recompute, per-phase config re-selection, record-count plan recompute, #345);
predictive parking; `stolen_count` / `idle_ns` (parallel counters);
`AdaptArena` revival. Each lands with its own round once the pass-duration
spine exists.
