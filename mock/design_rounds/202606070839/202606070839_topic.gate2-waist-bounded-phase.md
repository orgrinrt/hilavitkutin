## What this round corrects

The shipped const grouping (`plan/grouping.rs`) computes the phase axis as
longest read-after-write DEPTH (`compute_phases`). The course-correction
established that the canonical phase axis is WAIST-bounded, not depth: a phase is
a DAG section between waist points (concurrency minima), so a producer to
consumer chain with no interior narrowing is ONE phase (one trunk, dispatched
morsel-outer), where depth would split it across many phases and over-sync.

R2 replaces the depth phase axis with a waist-bounded one, computed at const time
by feeding the per-unit access masks through arvo's `waist_detect_const` (R1b,
merged). The within-phase trunk grouping (`compute_trunks`) is unchanged in
shape; it now keys on the waist-phase.

## The canonical mapping (mirrored from the runtime)

The authoritative waist to phase mapping is the shipped runtime `compute_waists`
(`plan/steps.rs:314-326`): phase 0 starts at topo position 0, and each waist
position opens a new phase at the next position, so the waist unit is the last of
its phase. Equivalently `phase[k] = count of waist flags at positions strictly
before k`. The const grouping mirrors this exactly, so the const phase axis
matches the runtime plan's phase boundaries.

## Mechanism (proven by S2)

For the registered bundle's folded `AccessMask` arrays (`reads`, `writes`, count
`n`):

1. Build the unit by unit RAW adjacency over the row word `Adj` (the engine's
   `D::AdjRow`): row `i` bit `j` set iff `reads[j]` overlaps `writes[i]` (edge
   `i -> j`), via the const `AccessMask::overlaps` + const `BitAccess::with_bit_set`.
2. Run `arvo_graph::waist_detect_const::<CU, Adj>(&adj, &identity_order)` over the
   unit capacity `CU` (identity order = registration order, build-validated
   topological), getting per-position waist flags.
3. Phase per unit = prefix count of waist flags before its position.

S2 proved the full chain const-evaluates over real arvo types and that the
waist-bounded phase genuinely differs from depth (hourglass: waist `[0,0,0,0,1,1]`
vs depth `[0,1,1,2,3,3]`).

## What lands

1. `plan/dims.rs`: bound `PlanDims::Units` with `ConstCapacity` (so generic
   engine code can run the const waist over `D::Units`); `Dim<N>` already impls
   it, `DefaultPlanDims` unaffected.
2. `plan/grouping.rs`: add const `compute_phases_waist<CU, CS, Adj>` (adjacency
   build + `waist_detect_const` + prefix-count); DELETE depth `compute_phases`
   (no legacy shim); thread a row-word type param `Adj: [const] BitAccess +
   Identity` and `CU: [const] ConstCapacity` through `phase_of` / `trunk_of` /
   `phase_count` / `is_member` (not `group_n`, which only counts).
   `compute_trunks` keeps its shape, keyed on the waist-phase.
3. `dispatch/trunk_gate.rs`: thread `Adj` (+ `CU: ConstCapacity`) through `Member`
   and `RunGatedTrunk` to the `is_member` call (`Adj` fixed through the
   recursion, like `CU` / `CS`).
4. `scheduler`: `run_one_trunk` passes `Adj = D::AdjRow`.
5. Tests: rewrite `tests/gate2_const_grouping.rs` to a topo-valid hourglass
   fixture asserting the waist-bounded phase `[0,0,0,0,1,1]` (contrast depth
   `[0,1,1,2,3,3]`) + trunk `[0,0,0,0,4,5]`; update `tests/gate2_gated_walk.rs`
   to pass `Adj`. `tests/morsel_outer.rs` stays green (a producer to consumer
   chain has no interior waist, so it is one phase).

The const grouping inherits the runtime's `D::AdjRow` width cap (64 default); a
consumer needing more than 64 units sets a wider `D::AdjRow`, which needs wide
`Bits` const `BitAccess` (a separate arvo round), not on this path.
