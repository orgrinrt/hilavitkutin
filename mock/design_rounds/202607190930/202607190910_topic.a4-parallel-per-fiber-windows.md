# Topic: per-fiber morsel windows on the parallel dispatch path

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** Give each fiber its own plan-baked L1 morsel window on the GATE-2 parallel
path, matching what A2b did for the single-core path, so the window the plan computes
is the window every dispatch path actually uses.
**Sketch:** `mock/research/sketches/202607190900_a4-parallel-per-fiber-windows/FINDINGS.md`
(WORKS, source-grounded derivation).
**Roadmap:** `mock/research/202607181300_engine-roadmap-r6.md`, Phase A leaf A4.

## What is wrong today

A3b computes a per-fiber L1 window from the fiber's write-byte footprint and bakes it
into `FiberDispatch.morsel_size`. A2b made `Scheduler::run` consume it: the single-core
loop is phase-outer, fiber-outer, morsel-inner, and each `morsel_local` fiber walks its
record range in windows of its own size.

The parallel path did not follow. `run_core_phase` still windows every fiber in the
phase by one scalar `Cfg::MORSEL_SIZE` handed down from `worker_main`
(`scheduler/mod.rs:865`, consumed at `:2149-2170`). So the same pipeline gets
cache-sized windows on one core and a uniform const window on many, and the domain-12
formula is half-consumed.

## What the sketch corrected about the planned approach

Two things, both recorded because the plan of record said otherwise.

**A4 is not a lookup; it is the same loop inversion.** The roadmap inherited from the
per-fiber morsel blueprint the framing that A4 threads per-fiber sizes in "through a
unit-to-fiber-size lookup, which needs a `gate2_fiber` mapping". That does not fit the
dispatch shape. `RunTrunkDispatch::dispatch_core` (`dispatch/trunk_dispatch.rs:143-170`)
walks the entire carrier in one call, firing every in-phase trunk root the core owns,
all under a single `MorselRange`; the morsel loop is outside it. One call therefore
already spans every fiber in every owned trunk, and those fibers have different windows.
A per-unit size lookup cannot express that, because the size has to select the loop and
the loop is outside the call. The fix is to restructure the loop fiber-outer, exactly as
A2b did.

**`gate2_fiber` is not needed, so the question of how it interacts with #690 is moot.**
A fiber-outer loop is driven by the `FiberDispatch` descriptors, which already carry the
fiber's `topo_order` slice and its window, and `run_core_phase` takes `&self`, so they
are already in scope. No third `[USize; GATE2_MAX_UNITS]` array is added, and the
decision recorded in r6 about landing it pre-lift or mid-lift against #690 no longer
applies. The decision was sound for the shape it assumed; the shape changed.

## The shape

Inside `run_core_phase`, the ordinary trunk-rank branch becomes fiber-outer. For each
fiber descriptor, build the fiber's member mask from its `topo_order` slice, pick its
window (`morsel_size` when the fiber is `morsel_local` and the value is non-zero, else
the scalar fallback), and walk `[0, total)` in that window, calling `dispatch_core` per
morsel with the fiber mask in the `dirty` position.

Four invariants hold, each established in the sketch against shipped source. The dirty
mask is a per-unit member gate, so a fiber-restricted mask runs exactly that fiber's
units. Trunk-rank ownership is invariant under the mask, because `rank` advances for
every in-phase root independently of `dirty` and the caller resets it per call, so each
core owns the same trunks in every per-fiber call. Const-DCE is untouched, because every
DCE site reads neither the range nor the mask. And the waist barrier is per phase rather
than per morsel, so restructuring the loop inside `run_core_phase` does not move it.

The `tphase == 1` head+tail branch keeps the scalar window and says so in source: it
dispatches over a whole-phase mask rather than one fiber, so a per-fiber window does not
map onto it. That is r6's settled decision, carried here unchanged.

## Cost, and where it is measured

A core now walks the carrier once per fiber rather than once per morsel, and it walks
fibers it does not own, because the ownership test lives inside the walk. Whether that
is cheaper depends on fiber count against morsel count. This is the same overhead class
A2b accepted on the single-core path, tracked as a FIXME at #340, whose resolution
(plan-baked member masks plus a fiber-to-phase map) would skip the no-op walks on both
paths at once. G2C-M is the bench that measures it, since it already covers this path's
scaling curve.

## What this leaves alone

The accumulator path (`worker_accum_unit_outer`) keeps its unwindowed per-core walk.
Whether the L1 window belongs inside it is A6, and it resolves from G2C-M rather than
here. The three-site ceil-slice partition is G2C-0 and G2C-1a.
