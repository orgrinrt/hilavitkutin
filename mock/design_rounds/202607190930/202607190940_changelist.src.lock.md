# Src changelist: per-fiber morsel windows on the parallel dispatch path

**Date:** 2026-07-19
**Phase:** SRC
**Topic:** `202607190910_topic.a4-parallel-per-fiber-windows.md`
**Doc CL:** `202607190930_changelist.doc.lock.md`
**Sketch:** `mock/research/sketches/202607190900_a4-parallel-per-fiber-windows/FINDINGS.md`
(WORKS, source-grounded derivation; the shape below is the one it proved)

## Scope

One source file plus one test file. The ordinary trunk-rank branch of `run_core_phase`
becomes fiber-outer, morsel-inner, each fiber windowed by its own plan-baked size. The
head+tail branch and the record-less branch are unchanged, and the accumulator path is
out of scope.

No new scheduler field is added. The sketch established that the `FiberDispatch`
descriptors already carry everything the loop needs and are in scope from `&self`, so
the `gate2_fiber` array the roadmap anticipated is not built.

## CHANGE: `Scheduler::run_core_phase` ordinary branch FROM `morsel-outer over dispatch_core` TO `fiber-outer, morsel-inner, per-fiber window`

File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (the `else` branch, currently
`:2149-2170`)

The current branch loops morsels of the scalar `msize` and calls `dispatch_core` once
per morsel over an all-ones mask. It becomes: for each of the `fiber_dispatch_count`
descriptors in plan order, build the fiber's member mask from its `topo_order` slice,
select its window (`morsel_size` when the fiber is `morsel_local` and the value is
non-zero, else the scalar `msize` fallback), and walk `[0, total)` in that window,
calling `dispatch_core` per morsel with the fiber mask in the `dirty` position and a
freshly zeroed `rank`.

Verification: `grep -n "fiber-outer / morsel-inner (A4)" mock/crates/hilavitkutin/src/scheduler/mod.rs`
returns one match inside `run_core_phase`, and the engine suite passes.

## CHANGE: `Scheduler::run_core_phase` head+tail branch GAINS an explicit scalar-window note

File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (the `tphase.0 == 1` branch)

Behaviour unchanged. The branch keeps the scalar `msize`, and gains a comment stating
why a per-fiber window does not apply to it (it dispatches over a whole-phase mask
rather than one fiber). This is r6's settled A4 decision, made visible at the site so a
later reader does not treat the scalar as an oversight.

Verification: the branch's morsel loop still reads `msize`, and the comment names the
whole-phase mask as the reason.

## CHANGE: `tests/a4_parallel_fiber_windows.rs` IS ADDED

File: `mock/crates/hilavitkutin/tests/a4_parallel_fiber_windows.rs`

Red-first acceptance tests for the parallel path, mirroring the shape `a2b_loop_inversion.rs`
uses for the single-core path. Two disjoint pipelines with different write widths get
different plan-baked windows; running through `run_parallel` on more than one core must
produce per-fiber morsel counts derived from those windows rather than from
`Cfg::MORSEL_SIZE`, and the output columns must be identical to the single-core result
over the same input.

Verification: `cargo test -p hilavitkutin --test a4_parallel_fiber_windows` passes, and
the expectations are computed from `__fiber_morsel_size` rather than hardcoded.

## CHANGE: `asm_gate_fixtures` GAINS `asm_gate_parallel_fiber_windows`

File: `mock/benches/asm_gate_fixtures/src/lib.rs`, plus its name in `FIXTURE_NAMES`
(`mock/benches/src/bin/asm_gate.rs`, count 6 to 7)

Per the cross-cutting ASM-emission contract discipline, the typestate-bearing slice
lands its fixture. The fixture drives the same two-chain carrier through
`run_parallel`, so the A4 loop compiles and runs under the gate build.

**Honest limitation, recorded rather than glossed:** the fixture does NOT prove the
parallel dispatch body is devirtualised. `run_core_phase` emits no scannable symbol
(`nm` finds neither it nor `worker_main` in the dylib, both inlining into the spawned
worker closure), so the gate's check 1 covers only this wrapper's own body, which is
pool setup and the readback hash. The parallel walk itself is unscanned. The
single-core `asm_gate_windowed_fibers` fixture remains the only real devirtualisation
evidence for the per-fiber loop shape, and the two paths share the `dispatch_core` walk
it does cover. A FIXME at the fixture states this and names what closing it needs (a
`#[no_mangle]` shim the worker calls, or teaching the gate to resolve the closure
symbol), tracked at #340. Reading the gate's PASS as parallel-path devirtualisation
evidence would be exactly the green-gate blind spot this note exists to prevent.

Verification: `cargo run --bin asm_gate` reports 7 fixture wrappers plus 1 out-of-line
mono and PASS, with `asm_gate_parallel_fiber_windows` in the scanned list.

## Not in scope

fiber-outer shape introduces on both paths (tracked at #340).
