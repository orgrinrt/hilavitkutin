# Post-review fixes for the bundle-to-PlanInputs projection

The projection round (202605300651) landed the `plan::project` module but the local review surfaced two gaps to close before merge.

First, the load-bearing path (`BundleProject` / `plan_inputs_from_bundle`) had no in-crate test: only the standalone feasibility scratch exercised the bundle walk, over stand-in types rather than the real `WorkUnit` / `AccessSet` / `PlanInputs`. The per-unit mask fill, the `unit_count` accumulation, the commutativity copy, and the nested witness inference through the real contract went unverified. This round adds an integration test over a two-work-unit bundle with overlapping access sets, using a permissive test context shim (the same shape the scheduler-builder tests use). It also restores the test file name the prior src changelist named, closing the changelist-vs-source drift the review flagged.

Second, the projection inherits `AccessMask`'s single-word backing: indices past 63 silently drop. The sibling `DirtyMask` already guards this with a compile-time assertion; the projection did not. This round adds the matching assertion at the projection entry points so a store list wider than the skeleton backing fails at compile time rather than running with partial coverage.

Neither fix changes the projection's shape or the public surface; both are correctness and verification hardening below the documented contract, so no `*.md.tmpl` changes.
