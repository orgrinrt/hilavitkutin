## Design resolution 1: cardinality-1 retains scalar promotion

The decomposition model puts a column of scalars at the floor, so a naive reading would force even a single-scalar `Resource` (a `Field<T>`) through a column indirection. That would discard the LLVM register-promotion the heritage R5 / domain-19 work established (a scalar `Field<T>`, ≤16 bytes, staged stack-local before the morsel loop, promoted to a register, only-accessed-fields loaded). The resolution: `ColumnStorage` special-cases cardinality one. A `Field<T>` decomposes to a length-1 column, and the dispatch codegen stages it stack-local with separate pointer provenance from the bulk columns (domain 19), so it promotes rather than paying a per-record load. The unified floor does not cost the scalar its register; the cardinality-1 path is the fast path, not a slow special case.

## Design resolution 2: trait-only first, derive deferred

`Decompose` is the real new design work (walking a struct's fields, recursing through nested structs to scalar leaves, expanding `Seq` / `Map` elements). The natural ergonomic end state is a `#[derive(Decompose)]`. This round ships the trait shape with hand-written impls only; the derive is deferred to a later round once the trait shape has proven out against the concrete engine types being migrated. A derive written before the trait shape settles would have to be rewritten when the shape moves. The BACKLOG records the derive as the deferred item.

## The contract shape

`ColumnStorage` sits between `MemoryProviderApi` (the raw allocator the consumer supplies) below and the per-morsel Context accessors (`ColumnReaderApi` / `ColumnWriterApi`, already shipped) above. It owns columns of `ColumnValue` scalars and hands out base pointers the dispatch codegen turns into per-morsel raw reads.

```rust
// hilavitkutin-api. Raw-pointer access (R6): a slice borrow alongside a
// resource pointer from the same context defeats LLVM noalias and forces
// a per-iteration reload (the T6 bench, 1.28-1.40x). Type-native stride.
pub trait ColumnStorage {
    type Error;

    /// Reserve column `id` for `len` records of scalar `T`, 64-byte
    /// aligned, stride `size_of::<T>()`. Allocates through the bound
    /// MemoryProvider. Re-reserving an existing id resizes it.
    fn reserve<T: ColumnValue>(&mut self, id: StoreId, len: USize)
        -> Outcome<(), Self::Error>;

    /// Base pointer of column `id`. Raw, not a slice (R6).
    /// # Safety: `id` names a column reserved for `T`; the caller proves
    /// the record index stays below `len(id)`.
    unsafe fn column_ptr<T: ColumnValue>(&self, id: StoreId) -> *const T;
    unsafe fn column_ptr_mut<T: ColumnValue>(&self, id: StoreId) -> *mut T;

    /// Record count of column `id`.
    fn count(&self, id: StoreId) -> USize;

    /// Advisory release (reader-count model: free at zero). A no-op on
    /// the naive placeholder; the columnar engine reclaims arena space.
    fn release(&mut self, id: StoreId);
}
```

`Decompose` maps an aggregate to its scalar column leaves. The leaf set is a cons-list of `Field<S>` markers in field order, reached by recursing through nested structs to `ColumnValue` leaves.

```rust
// hilavitkutin-api. `Field<S>` is the base case; a multi-field struct
// yields one leaf per field, recursing. Seq / Map elements expand the
// same way when the element is not itself a scalar.
pub trait Decompose {
    /// Cons-list of this aggregate's scalar column leaves (Field<S> per
    /// scalar leaf). `Empty` for a unit aggregate.
    type Leaves: StoreBundle;
}
```

The persistence boundary (`evict` / `inject`, R2) is not in this round's trait; it is the C6 resource-resolution / persistence concern (task #344) and folds in when that migration lands. The core contract this round is reserve / pointer / count / release, the minimum to back resources and the plan.

## The markers as views

`Resource` / `Column` / `Virtual` / `Field` / `Seq` / `Map` stay as the declaration-and-access surface; underneath, they all reduce to scalar columns in one `ColumnStorage`. `Resource` and `Column` differ in intent and access pattern, not mechanism: `Resource` holds persistent, infrequently-written state (config, providers, the plan), cardinality one or more, staged stack-local for register promotion; `Column` holds hot per-morsel records accessed via the raw morsel-offset read / write. Both back onto the same store. `Virtual` carries no backing (DAG edge only). `Field` / `Seq` / `Map` are the resource field layouts the `Decompose` recursion bottoms out in.

A default arena-backed `ColumnStorage` impl ships in `hilavitkutin-providers` (phase 2, the placeholder; the DESIGN already reserves that crate for "future ColumnStorage defaults"). Bespoke per-subsystem arenas are forbidden going forward; the principle states it and the phase-3 lint enforces it.
