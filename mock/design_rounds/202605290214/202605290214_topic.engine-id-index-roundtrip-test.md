# Round-trip test for the engine-id index accessors

Round 202605290203 added `index` / `from_index` to the four engine ids, built on
arvo's `to_raw` / `from_raw`. `from_raw` performs no range check (the caller owns
in-range discipline). The accessor pair is new public surface, so it earns a
direct round-trip test rather than relying only on the transitive coverage from
the plan tests.

## Current state

The accessors ship and are exercised indirectly by plan-graph construction in the
existing suite. No test asserts the `from_index(USize(k)).index() == USize(k)`
inverse directly.

## Changes proposed

Add `tests/engine_id_index.rs` to `hilavitkutin-api`: for each id
(`UnitId`/`FiberId`/`PhaseId`/`TrunkId`), assert the index round-trip holds at a
few in-range values, including the width ceiling for each id's `Uint<N>`. The
test fails loudly if arvo ever retunes a `Warm` container, which is the exact
drift the parent round's accessors are meant to absorb safely.
