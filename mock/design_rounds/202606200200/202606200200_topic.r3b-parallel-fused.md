# Topic: R3b change_seen_count in run_parallel + run_fused

**Date:** 2026-06-20
**Crate:** hilavitkutin
**Tracked:** #691, #341, completion-arc R3b

## Change

PR #144 maintained `change_seen_count` (the change_class numerator) in the
single-core `run` fold only. `run_parallel` and `run_fused` reset `store_dirty`
without counting it, so an `OnMeta<ScheduleEnd>` hook reading `change_seen_count`
under those paths read stuck-at-zero beside the live siblings. This round mirrors
the single-core capture-and-increment into both folds: capture
`!store_dirty.get().is_empty().0` before the per-frame reset, increment
`change_seen_count` in the EMA fold when set. The metric is then consistent across
all three run paths, so the DESIGN qualifier added in round 202606200100 is
removed. A parallel-path white-box test (multi-core thread pool, `__mark_store_dirty`)
asserts the count through the bridge.
