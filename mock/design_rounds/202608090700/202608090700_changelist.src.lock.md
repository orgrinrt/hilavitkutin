# Source changelist: a width nobody writes

**Phase:** IMPL
**Doc changelist:** `202608090700_changelist.doc.lock.md`
**Scope:** `mock/crates/hilavitkutin-sym/src/**`, `mock/crates/hilavitkutin-str/src/**`.

Verifications run against `git show HEAD` after the autofix, **and any claim
about a diff verified against the diff**. The previous round's commit message
asserted eleven allow comments were moved when its diff changed none, because
the formatter undid the move inside the same commit.

## CHANGE: `SymLayoutOps` carries masks, not widths

File: `src/shape.rs`, `src/handle.rs`

`KIND_WIDTH` and `ID_WIDTH` are replaced by `KIND_MASK` and `ID_MASK`, each
forwarded from the mask its own `bitfield!` generated. The width is counted from
a mask by `width_of`, a free function, so no implementation can supply a
different answer.

Round four tied a shape's declaration to a hand-written number the layout also
wrote. Two statements of one fact can agree and both be wrong about the field.
A layout that lies now has to lie about its mask, which its own accessors read
through.

Verified by construction, before and after: the reviewer's counter-example, a
layout declaring nine and twenty-two over a genuine three and twenty-eight
bitfield with a shape declaring the same, **passed** under round four and under
the first attempt at this round, and **fails** now with the shape named. Written,
observed, deleted.

## CHANGE: `Interner` carries the domain's shape

File: `src/interner.rs`, `hilavitkutin-str/src/interner.rs`

Both methods took and returned a bare handle, so a domain on any shape but the
default could not have an interner: a probe refused to compile with `expected
Standard, found WideKind`. The design document already said otherwise, so source
contradicted the tier that governs it and half the producer surface was welded to
the default while the branch's thesis is that the shape is a parameter.

Verification: `git show HEAD` shows both signatures carrying `D::Shape`.

## CHANGE: allowances that the formatter cannot move

Files: `src/shape.rs`, `hilavitkutin-str/src/interner.rs`

The previous round recorded that an allow on a line ending in `{` cannot survive
rustfmt and concluded nothing was wrongly suppressed. **That conclusion was
wrong**: the strict gate reported live violations at exactly those items, so the
allows were decorative and the gate passed only because those lints are advisory.

`#[rustfmt::skip]` on the affected items keeps the allow where the lint reads it.
It was never a wall for op.

Verification: the strict gate over both crates drops from fourteen findings to
five, and the five that remain are pre-existing rather than introduced here.

## CHANGE: the violations this branch introduced

File: `src/shape.rs`

Three `&str` test-helper parameters with no allowance, now `&'static str`.
