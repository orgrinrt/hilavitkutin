# Topic: the tautology moved down a rung twice, and a reader's note for the archive

**Phase:** TOPIC
**Scope:** `hilavitkutin-sym`, `hilavitkutin-str`. Closes the restatement class by
deriving instead of declaring, makes the interner honour the shape, and states
what four rounds actually did for a reader arriving cold.

## The pattern, stated once, because naming instances has not worked

Four rounds. Each one fixed an instance of the same defect and asserted in its
commit message that the class was closed. Three of those assertions were false
and are now in permanent history.

**Rung one.** A test asserting a constant equals the literal its own definition
sets. Deleted in round three, reinstated in round three, deleted again in round
four.

**Rung two.** A shape declaring widths nothing tied to its layout. Round four
tied them to `SymLayoutOps::KIND_WIDTH` and said the class was gone.

**Rung three, where it actually still lives.** `KIND_WIDTH` is a hand-written
literal restating the same bitfield's own `kind: 3 at 28`. A reviewer built a
layout declaring `KIND_WIDTH = 9` over a three-bit field, with a shape declaring
the same, and **all four shipped laws pass**. So round four moved the restatement
down one rung and reported it eliminated.

The lesson is not about widths. It is that **a check written by hand from the
same source as the thing checked cannot constrain it**, however many layers of
indirection sit between them. The only way out is to derive the check from the
artifact rather than to write it beside the artifact.

## What closes it

`arvo::bitfield!` emits a `<field>_MASK` constant for every field. A layout's
width is therefore **derivable**: the population count of its own mask. Nobody
writes the number, so nobody can write it wrong.

Verified before this topic was written rather than after: the counter-example
layout passes every law today, which is the hole, and must fail once the widths
are derived.

## Also in this round

**`Interner` ignores `Domain::Shape`.** Both its methods take and return a bare
handle, so a domain on any shape but the default cannot have one. A probe refused
to compile with `expected Standard, found WideKind`. The design document already
says otherwise, so source contradicts the tier that governs it, and half the
producer surface is welded to the default while the branch's whole thesis is that
the shape is a parameter.

**The rustfmt conclusion was wrong, and worse than wrong.** The previous round
recorded that an allow on a line ending in `{` cannot survive the formatter, and
concluded nothing was suppressed that should not be. The strict gate reports
**eight live violations at exactly the items whose allows sit in bodies**, while
same-line allows at neighbouring items are silent. So those allows are decorative
and the gate passes only because those lints are advisory. `#[rustfmt::skip]`
fixes it. It was never a wall for op, and the previous round's changelist says it
was.

**And that round's commit message claims eleven allows were moved back.** Its diff
changes zero allow lines: the formatter undid the move inside the same commit, so
the claim describes an intention rather than a change.

New violations this branch introduced: an allow naming one lint where two fire,
and three `&str` parameters with no allow at all.

## A reader's note, owed to the archive

Four rounds, each correcting the previous one's account of itself. A cold reader
following the closed rounds in order will believe the widths were grounded at
round four. They were not, and this topic is where that is written down.

## Lock criteria

- The counter-example layout **fails** once widths derive from masks, observed
  before and after, and deleted after being observed.
- No width in the crate is a hand-written number that some other artifact also
  states.
- `Interner` is shape-generic, demonstrated by a domain on a non-default shape
  having one.
- The strict gate reports zero `no-bare-*` violations in the two crates this
  branch touches.
- Every claim in this round's changelist verified against `git show HEAD` after
  the autofix, and **any claim about a diff verified against the diff**, which is
  what the previous round did not do.
