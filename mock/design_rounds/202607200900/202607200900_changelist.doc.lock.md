# Doc CL: Swap Semantics Under the Blob Layout

**Date:** 2026-07-19
**Round topic:** `202607200500_topic.replaceable-swap-semantics.md` (#697)
**Scope:** the three A2-5 mis-grounded doc artifacts that still state the
bench-refuted member-by-member layout as canon, plus the `PlanAffecting`

## CHANGE: engine swap paragraphs FROM member-by-member rule TO S1 blob install

File: `mock/crates/hilavitkutin/DESIGN.md.tmpl` (the two paragraphs
between the accumulator regioning text and the region-boundary sharing
text; currently "A `Replaceable` swap is a member-by-member copy..." and
"This is stated here because the code cannot yet express it...").

Replacement content: a `Replaceable` swap installs the whole value as
one blob write through the same `Selector<V, Index>` witness the drain
and the projection read use, plus a store-dirty mark; no other pointer
derivation exists on the swap path. The member-by-member wording was
grounded on the pre-bench storage layout and is refuted under the
bench-decided blob layout (A2-5); the prior revert of the one-line
install was a mis-citation, and the blob write is the specified
install, not the excluded one. Collection-bearing values gain per-record
element writes only when the #344 collection wiring lands (S3); until
then the collection halves of a swapped value are stated as out of
scope, tracked by the catalogued test.

Verification: `grep -c "member-by-member" mock/crates/hilavitkutin/DESIGN.md.tmpl`
returns 0; `grep -c "Selector" mock/crates/hilavitkutin/DESIGN.md.tmpl`
returns at least 1 in the swap paragraph.

## CHANGE: engine plan-dirty wording FROM first-frame-only band gate TO S2 trigger

File: `mock/crates/hilavitkutin/DESIGN.md.tmpl` (same swap section,
continuation paragraph).

Replacement content states the S2 wiring: `replace_resource<T:
PlanAffecting>` locates `Resource<T>` through the same witness shape,
performs the identical install and store-dirty mark, and sets the
plan-dirty bit for `T`; `run` / `run_parallel` enter the plan band when
`first_frame` OR any plan-dirty bit is set, consuming and clearing the
bits on entry.

Verification: `grep -c "plan-dirty" mock/crates/hilavitkutin/DESIGN.md.tmpl`
returns at least 1.

## CHANGE: api `PlanAffecting` FROM sealed BuilderInput marker TO open marker

File: `mock/crates/hilavitkutin-api/DESIGN.md.tmpl` (section
"### `PlanAffecting: BuilderInput + Sealed`").

Per the A2-3 ruling, `PlanAffecting` is an open marker trait on
resource value types: the section header and code block drop the
`private::Sealed` and `BuilderInput` supertraits (`pub trait
PlanAffecting {}`), the prose drops the sealed framing and states
per-type consumer opt-in mirroring `Replaceable`, and the S4
exclusivity is cross-referenced. The dirty-bit array, `RunCfg` cap, and
toolbox-not-policer framing stay as written. The lifetime-contract
mention of `impl PlanAffecting` declarations stays valid and unchanged.

Verification: `grep -c "PlanAffecting: BuilderInput" mock/crates/hilavitkutin-api/DESIGN.md.tmpl`
returns 0.
