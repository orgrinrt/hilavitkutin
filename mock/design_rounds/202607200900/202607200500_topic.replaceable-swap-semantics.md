# Topic: Replaceable Swap Semantics, Implemented and Benched

**Date:** 2026-07-19
**Scope:** the `Replaceable` / `PlanAffecting` replacement surface: `replace_value`, `replace_resource`, the plan-dirty trigger, the trait relationship, and the artifacts the A2-5 mis-citation left carrying refuted-layout language.
**Design input:** the swap-semantics specification draft (`mock/research/202607200200_replaceable-swap-semantics-spec.md`, clauses S1 to S7), synthesised from the expert panel and the exclusivity sketch. Op held ratification (2026-07-19) until the spec is implemented and benched; this round is that implementation, and its evidence is what returns to op for the ratification call.
**Related:** #697 (this round), #696 (PlanAffecting open marker, A2-3, absorbed here), A2-5 (the commissioning record), the seed pre-freeze resolution batch.

## The problem

Canon has no swap specification. The shipped `replace_value` marks dirty without installing (the D1 install was reverted after the A2-5 mis-citation was found); `replace_resource` is callable only for a type no consumer registers (its `PlanAffecting` bound is sealed with one run-config implementor); the plan-dirty trigger canon promises (a swapped plan-affecting resource forces plan recompute) is unwired end to end (the band gate reads `first_frame` only); and three artifacts (the engine DESIGN template's swap paragraph, the `replace_value` FIXME, the catalogued test's ignore reason) still state the bench-refuted member-by-member layout as if it were canon.

## What this round does

1. **S1 install.** `replace_value<V: Replaceable>` performs the whole-blob
   `ptr::write` through the same `Selector<V, Index>` witness the drain and
   the projection read use, plus `mark_dirty`. No other pointer derivation.
2. **S2 wiring.** `PlanAffecting` unseals to an open marker on resource
   value types (A2-3): the seal and the `BuilderInput` supertrait drop.
   `replace_resource<T: PlanAffecting>` locates `Resource<T>` (unifying with
   S1's witness shape), performs the identical install and store-dirty mark,
   and sets the plan-dirty bit for `T`; `run` / `run_parallel`'s band gate
   becomes `first_frame OR any plan_dirty bit`, consuming and clearing the
   bits.
3. **S4 exclusivity.** hilavitkutin-api ships
   `impl<T: PlanAffecting> !Replaceable for T` under
   `#![feature(negative_impls)]` (WATCH tier), making `PlanAffecting`
   dominant with E0751 at the consumer impl site (sketch
   `202607193310`, WORKS both arms).
4. **S6 tests.** Blob-address byte-identity across a swap;
   double-swap-before-run, last value wins; ZST swap; swap of an unread
   resource; `replace_resource` causes plan-band entry on a non-first frame;
   compile-fail on the double impl. The catalogued red at
   `tests/resource_bindings.rs` gains its correct ignore reason and loses
   the ignore when the install lands.
5. **Artifact corrections.** The three A2-5 mis-grounded artifacts replace
   the member-by-member language with the spec's install semantics.
6. **Benches (the ratification evidence).** On the upgraded bench harness:
   the swap write cost across value sizes, and the next-frame cost asymmetry
   between a `replace_value` store-dirty cone and a `replace_resource` plan
   band, measured against the same workload without a swap as baseline.
