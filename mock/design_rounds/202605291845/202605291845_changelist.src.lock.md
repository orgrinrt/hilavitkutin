# Source changelist

Lift the engine's plan + thread const-generic dimension vocabulary from
`const MAX_X: usize` to `const MAX_X: arvo::Cap`. The transform per the doc
changelist: param type `usize` to `Cap`; `[T; MAX_X]` to `[T; cap_size(MAX_X)]`;
`[(); cap_size(MAX_X)]:` where-bounds threaded through every generic item the
compiler demands; `#121` lint:allows dropped on lifted sites; concrete-dim call
sites wrapped in `cap(N)`. Internal indexing `usize` (#72) and the
`thread/class.rs` module constant `MAX_CORES: usize = 256` are out of scope.

## CHANGE: lift dimension const params usize TO Cap across the engine const-dim surface
Files: `mock/crates/hilavitkutin/src/plan/{graph,inputs,unit,phase,trunk,fiber,access,dirty,column,core_program,steps,mod}.rs`, `mock/crates/hilavitkutin/src/thread/{mod,assignment}.rs`, `mock/crates/hilavitkutin/src/adapt/arena.rs`, `mock/crates/hilavitkutin/src/dispatch/{mod,fiber_dispatch,core_dispatch}.rs`
Every `const MAX_X: usize` dimension param (`MAX_UNITS`, `MAX_EDGES`,
`MAX_STORES`, `MAX_FIBERS`, `MAX_PHASES`, `MAX_TRUNKS`, `MAX_LANES`,
`MAX_COLUMNS`, `MAX_COLUMNS_PER_FIBER`, `MAX_CORES` param, `MAX_PHASES_PER_CORE`,
`MAX_TRUNKS_PER_CORE`, `MAX_FIBERS_PER_CORE`) becomes `const MAX_X: Cap` on every
struct, impl, and fn declaring it; each `[T; MAX_X]` array field/local becomes
`[T; cap_size(MAX_X)]`; `[(); cap_size(MAX_X)]:` where-bounds are added wherever
the compiler requires them; the `#121` `lint:allow(no-bare-numeric)
lint:allow(arvo-types-only)` comments on lifted param sites are removed. `arvo::Cap`
and `arvo_tensor::{cap, cap_size}` are imported where used. The lift covers the
whole engine const-dimension surface, not only plan/thread: `adapt/arena.rs`
`AdaptArena<MAX_FIBERS, MAX_CORES, MAX_PHASES>` lifts because it composes the
lifted plan types (compiler-forced), and the `dispatch/` family
(`FiberDispatch<MAX_CORES>`, `CoreDispatch<MAX_FIBERS>`, `codegen_fiber`,
`codegen_core`) lifts for consistency. The same logical `MAX_CORES` / `MAX_FIBERS`
are `Cap` in plan/thread, so leaving dispatch on `usize` would split one
dimension across two representations.
Verification: `grep -rnE "const MAX_[A-Z_]+: *usize" mock/crates/hilavitkutin/src/` returns only the `thread/class.rs` module constant `pub const MAX_CORES: usize = 256` (a fixed array size, not a generic param). `cargo +nightly-2026-05-28 check -p hilavitkutin --manifest-path mock/Cargo.toml` is green.

## CHANGE: wrap concrete-dimension call sites in cap(); gate downstream test crates
Files: `mock/crates/hilavitkutin/src/**` inline tests, `mock/crates/hilavitkutin/tests/{core_assignment,plan_inputs,plan_runner,plan_types,synthesise_core_programs,dispatch_codegen,dispatch_types}.rs`, `mock/crates/hilavitkutin/examples/**`
Any instantiation of a lifted type with a literal `usize` dimension (`Foo::<8, 16>`,
`const MAX_UNITS: usize = 8` locals) becomes `cap(N)` (a `Cap` const). Each
separate integration-test compilation unit that names a lifted
`[(); cap_size(N)]:`-bounded type must enable `#![feature(adt_const_params)]` +
`#![feature(generic_const_exprs)]` + `#![allow(incomplete_features)]` at its crate
root so its own trait solver can normalise the const bounds. Without the gates the
cross-crate well-formedness check overflows; this is a property of
`generic_const_exprs` (the consuming crate evaluates the bound), not a
recursion-depth issue, so the feature gates are the fix, not a raised
`recursion_limit`. arvo's `tests/live_counts.rs` carries the same gates for the
same reason.
Verification: `cargo +nightly-2026-05-28 test -p hilavitkutin --manifest-path mock/Cargo.toml` builds and runs every lib + integration test green.
