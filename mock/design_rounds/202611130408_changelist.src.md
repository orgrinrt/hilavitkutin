# Src changelist: an over-capacity accumulator append is a value

**Date:** 2026-11-13
**Phase:** SRC
**Round:** 202611130358 (branch `work/overflow-is-a-value`), roadmap step HV1b
**Source topics:** `202611130400_topic.overflow-is-a-value.md`

The source follows the locked doc changelist (`202611130402_changelist.doc.lock.md`). The append path stops asserting; each accumulator binding counts every append it was asked for beside its live length, the per-core path of `run_parallel` publishes and merges that count, and every run entry returns the first refusing accumulator through `RunCfg::Out`. The stalled-join comment in `run_parallel` goes. A committed feature carries the truncating mutant the overflow suite is shown failing against.

## CHANGE: `AccumRefused` and the run config's output
Files: `mock/crates/hilavitkutin-api/src/accum_refused.rs` (new), `src/lib.rs`, `src/run_cfg.rs`.
`AccumRefused` holds the registration position (`accum()`) and a `notko::lend::Exhausted` (`exhausted()`), private fields, `const fn` accessors, one `const fn new`. `RunCfg::Out` is bound on `From<notko::Outcome<(), AccumRefused>>`; `DefaultRunCfg` takes `Out = notko::Outcome<(), AccumRefused>` and `Err = AccumRefused`.
Verification: `grep -n "type Out" mock/crates/hilavitkutin-api/src/run_cfg.rs` shows the bound and the default.

## CHANGE: the append contract is stated once
Files: `mock/crates/hilavitkutin-api/src/context.rs`.
`ResolveAccumAppend::resolve_append` carries the one statement of the refusal (counted as asked, written only while nothing was refused and the live length is below the capacity, sticky, returned by the run). `AccumWriterApi::append` points at it.
Verification: `grep -c "asserts and panics" mock/crates/hilavitkutin-api/src/context.rs` returns 0.

## CHANGE: the binding counts `wanted`
Files: `mock/crates/hilavitkutin/src/resource/bindings/mod.rs`, `src/dispatch/engine_ctx/lists.rs`, `src/dispatch/engine_ctx/selectors.rs`.
`AccumBinding` gains `wanted: Cell<USize>` and the hidden accessor `__wanted_cell`; the drain zeroes it, `ResetAccumulators` zeroes it beside the live length, and `AccumColPtr` borrows it through `AccumSelector`.

## CHANGE: the sticky refusal in `resolve_append`
Files: `mock/crates/hilavitkutin/src/dispatch/engine_ctx/ctx_writers.rs`, `mock/crates/hilavitkutin/Cargo.toml`.
The assert goes. The append writes and bumps both counts only when `wanted == len` and `len < cap`; otherwise it bumps `wanted` alone (saturating). Invariant: `wanted >= len`, refused exactly when `wanted > len`, both cells written only by the thread that owns the binding for the frame. The feature `mutant-truncating-append` drops the `wanted` bump on the refused branch and nothing else. Keeping the assert would be a strategy read on that one branch.

## CHANGE: the per-core walks carry `wanted`
Files: `mock/crates/hilavitkutin/src/resource/bindings/per_core.rs`, `src/scheduler/worker.rs`, `src/scheduler/mod.rs`, `src/scheduler/builder.rs`, `src/scheduler/defaults.rs`.
`rebase_accums` gives each core fresh live and `wanted` cells. `CollectAccumLive` becomes `CollectAccumCounts` and writes both counts. The scheduler gains `gate2_accum_wanted`, sized and initialised as `gate2_accum_live`; each worker zeroes and publishes its row of both with Relaxed stores before `frame_done_arrive`. `MergeAccums` takes the per-core rows as `PerCoreCounts` and sets the shared `wanted` to the merged live length plus the shared binding's own refused appends plus every core's `wanted_c - live_c`.

## CHANGE: the verdict and the three run entries
Files: `mock/crates/hilavitkutin/src/resource/bindings/refusal.rs` (new), `src/scheduler/verdict.rs` (new), `src/scheduler/run.rs`, `src/scheduler/run_fused.rs`, `src/scheduler/run_parallel.rs`.
`FirstRefusal` walks the bindings tail first (the store list is prepended, so that is registration order) and returns the first accumulator with `wanted > len`. `frame_verdict` builds `Cfg::Out` from it once for all three entries, which drop their `Cfg::Out: Default` bound and return it after the last band. `run_parallel` reads it after the trailing bands with every worker parked; the comment calling a stalled join the accepted failure mode is replaced by what holds now (no over-capacity append can keep a worker from arriving; a body panic still can, ticket `b62d69a9eb2f`).
Verification: `grep -rn "Cfg::Out::default\|accepted failure mode" mock/crates/hilavitkutin/src` finds nothing.

## CHANGE: tests
Files: `mock/crates/hilavitkutin/tests/overflow_is_a_value.rs` (new), `tests/common/mod.rs`, `tests/accum_dispatch.rs`, `tests/fused_append.rs`, `tests/accum_per_frame_reset.rs`, `tests/gate2_parallel_meta.rs`, `tests/gate2_adapt_ema.rs`, `tests/r5_core_idle.rs`, `mock/catalogue.md`, the three `hilavitkutin-providers` examples.
The new suite builds an input column seeded with each record's index (the `each` index is morsel-local), a guard accumulator registered first and an accumulator a skewed emitter asks `N + 3` appends of (`N = 512`). `run` and `run_parallel` on `FixedWorkers` executors reporting 1, 2, 4 and `MAX_CORES` return the same `AccumRefused` (position 1, `wanted` 515, `had` 512) over two frames each, with the refusing buffer holding each core's first appends and the guard, laid out directly after it in the arena, holding exactly its own records. `FixedWorkers` joins the shared test executor module and reuses its `spawn`. The `#[should_panic]` test in `accum_dispatch.rs` becomes `accum_append_past_reserved_capacity_is_refused_as_a_value`. The region skew is catalogued: `a_skew_that_fits_the_reservation_is_accepted_at_every_worker_count`, ignored on `run_parallel_refuses_a_multi_append_skew_that_fits_the_reser` (ticket `9979e2632a6a`) with its ledger row. Comments that said an over-capacity append asserts now say it is refused.
