# Runtime megaround post-review fixes

`pr-reviewer-senior` audit of PR #75 surfaced three findings that the locked round 202605101036 claimed delivered but did not. Two are direct spec-vs-source mismatches; one is a documentation clarity issue around a footgun that the prior round shipped publicly. Each fix lands in this round via the standard mockspace flow.

## Locked decisions (from PR #75 and the prior round)

The prior round's locked claims stand. This round fixes the source-state drift, not the design.

### A1. `scheduler/result.rs` retires

Prior round's src CL Pass 6 claimed the file was deleted; verification command was `! test -f mock/crates/hilavitkutin/src/scheduler/result.rs`. The file is still on disk with `pub enum PipelineResult { Completed, Failed, Poisoned }`. It is orphaned (no `pub mod result;` in `scheduler/mod.rs`) but `test -f` returns true. The prior round's `## CHANGE: ...` verification was never run.

This round's src CL deletes the file. Spec stays as it was; source catches up.

### A2. `Scheduler::plan_dirty` lifts to const-generic-via-Cfg

Prior round's src CL Pass 6 specified `[AtomicBool; Cfg::MAX_PLAN_AFFECTING_RESOURCES]`; source landed `[AtomicBool; 256]` hardcoded with a `lint:allow(no-bare-numeric)`. The hardcode defeats the per-Cfg typestate: any consumer overriding `MAX_PLAN_AFFECTING_RESOURCES` either silently overruns or mismatches with no type-system signal.

This round's src CL lifts the array dimension to `Cfg::MAX_PLAN_AFFECTING_RESOURCES.0` (the inner `usize` extracted from the `arvo::USize` trait constant) under `feature(generic_const_exprs)`. The crate's `lib.rs` gains the feature flag. The reviewer's recommendation here is exact; the implementation matches it.

### A3. `AdaptWu`'s `Ctx<'frame>` placeholder clarification

`AdaptWu`'s Ctx is `AdaptCtxPlaceholder<'frame>` shipped publicly. Its `Stub` provider satisfies the seven `HasX` bounds with `unimplemented!()` no-ops. The reviewer flagged that this is a footgun: any consumer registering `AdaptWu` and calling `Scheduler::run` panics at the first `ScheduleEnd` if the engine were to actually invoke the WU.

The footgun is unreachable today because `Scheduler::run` is itself `unimplemented!()` (Pass 6 froze the signature, body lands across follow-up rounds). The two unreachables collapse into the same wall: until the executor body lands, no consumer can reach AdaptWu's execute. When the executor body lands, AdaptWu's Ctx is replaced by the engine's real Ctx in the same round.

This round documents the invariant explicitly in `AdaptWu`'s rustdoc and renames the placeholder to make the stub status visible at the type level. No type-system change; the source change is rustdoc + identifier rename.

## Out of scope (deferred to subsequent rounds)

Per the reviewer's "concerns" tier, the following are NOT addressed in this round:

- Three tombstone test files (`pipeline_result.rs`, `adapt_config.rs`, `thread_pool.rs`). They are placeholders commemorating retired APIs. The no-legacy-shims rule says the audit trail is git log + locked CL; deleting them is correct, but a separate round handles test-suite curation cleanly.
- Missing trybuild fixture + MIRI.md from the prior round. A future round either ships them or files a `## CHANGE:` deferral block on the prior round's claims.
- `ema_update`'s `&mut [USize]` slice type. `USize` is platform-pointer-width; EMA samples are not pointer-shaped (latencies are nanoseconds → u64; counts are 32-bit). The right shape is a domain-specific `Sample` alias rooted on `UFixed<{ibits(64)}, {fbits(0)}, Hot>`. Deferred to the round that wires the actual EMA body (Pass-7 follow-up).

- Does not re-litigate any design decision from the prior round. The lift of `Scheduler<Cfg>` typestate, the dirty-bit-array semantics, the AdaptWu access shape, the cfg-gated EMA paths — all stay as the prior round locked them. This round fixes execution drift only.
- Does not introduce new types or new public API. The `Scheduler<Cfg>` where-clause widens by one `where` bound (`Cfg::MAX_PLAN_AFFECTING_RESOURCES.0` const-eval), which is structural cleanup of the typestate, not a new surface.
