## What is wrong

`build` reserves every column and accumulator through the provider and records the base address it was handed. The scheduler then moves: the provider is moved into `storage`, `storage` into the scheduler, and the scheduler out of `build`. A provider whose buffer is an array inside the struct moves with it, so every recorded base points at a stack slot that no longer holds the buffer.

Thirty-two test files define such a provider (thirty-one under `crates/hilavitkutin/tests`, one in `crates/hilavitkutin-persistence/tests/cold_store.rs`), and each of the twelve trybuild fixtures under `crates/hilavitkutin/tests/ui/` carries a copy. They pass because the stack slot happens to survive. Miri says what it is, at a85939b6, on `tests/resource_snapshot.rs`:

```
test erased_backcast_roundtrip ... error: Undefined Behavior: memory access failed: alloc42401 has been freed, so this pointer is dangling
   --> crates/hilavitkutin/tests/resource_snapshot.rs:123:30
help: alloc42401 was allocated here:
   --> crates/hilavitkutin/src/scheduler/builder.rs:203:12
help: alloc42401 was deallocated here:
   --> crates/hilavitkutin/src/scheduler/builder.rs:273:4
```

Line 203 is `let mut storage = storage;` and 273 is the end of `build`: the buffer lived in that local. The whole run is `mock/research/202611140512_sound-memory-provider/miri-resource-snapshot-before.txt`.

The test providers are the symptom. The cause is that `MemoryProviderApi` is a safe trait (`crates/hilavitkutin-api/src/platform.rs:28`) and the engine's unsafe code reads and writes through what `allocate` returns, after moves the trait says nothing about. A safe impl can make the engine touch freed memory, which is a soundness hole in the engine, not in the tests.

## What the engine relies on

Read off the code (`builder.rs`, the storage reserve path, `run` and `run_parallel`), not off the design:

1. A non-null block is aligned to `align` and valid for reads and writes of `len` bytes.
2. It stays valid, at the same address, until the matching `deallocate` on that provider or until the provider is dropped. Moving the provider does not move or free it.
3. Two live blocks do not overlap.
4. `allocate`, `deallocate` and `protect` may be called from several threads at once, since the trait is `Sync` and the scheduler is driven across cores.

These are promises the implementer makes and the engine cannot check, which is what an `unsafe trait` is for. The trait becomes `unsafe trait MemoryProviderApi`, its safety section states the four, and every impl becomes `unsafe impl` with a `// SAFETY:` naming how it keeps them. The existing per-method `# Safety` sections stay: they are the caller's half.

## One sound provider, in the providers crate

Moving thirty-two files to `tests/stable_provider` as the plan names it leaves the twelve fixtures and the persistence test with their own copies, since neither can include a module from `crates/hilavitkutin/tests`: fourteen `unsafe impl`s of one thing, each with its own safety argument. The canon rows `later_modules_of_the_providers_crate_add_column_storage_clock_and_memory_defaults_per_consumer_demand` (held) and `clock_and_libc_unix_memory_provider_defaults_land_in_their_own_rounds_when_consumer_demand_surfaces` (provisional) put a memory default in `hilavitkutin-providers`, in its own round, when a consumer asks. Three test trees asking is that demand, and this is its round.

The default is a bump provider over a `&'static mut [MaybeUninit<u8>]`: `no_std`, no allocation, and the four promises hold by construction. The buffer is `'static` and exclusively the provider's, so no move of the provider touches it (2); the cursor is an atomic advanced by compare-exchange, so concurrent callers get disjoint blocks (3, 4); the address is aligned, not the offset (1). `deallocate` and `protect` do nothing, which the contract permits. A test makes the buffer by leaking a `Vec`; an embedded consumer hands it a `static`.

`tests/stable_provider/mod.rs` then shrinks to the leak and the byte fill, and its `Cell` cursor behind an `unsafe impl Sync` goes, since that impl claims a thread-safety the cursor does not have. `NullMemoryProvider` and `OsMemoryProvider` in the engine become `unsafe impl`, each with its argument: the null one returns null always, the os one maps fresh pages that only `munmap` in `deallocate` frees.
