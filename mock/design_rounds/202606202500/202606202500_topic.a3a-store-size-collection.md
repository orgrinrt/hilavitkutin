**Date:** 2026-06-19

## Current state

The A3 sketch proved the per-store element-byte-size collection + per-fiber
write-byte sum. The L1 window formula (A3b) needs the size array. The plan stage
is generic over `D: PlanDims` (dimensions), which does NOT carry the store marker
types, so `store_sizes` (reads `ColumnValue::BIT_WIDTH` per marker) is computed at
the build layer (Stores known) and threaded into the plan in A3b. A3a lands the
collection machinery itself.

## Changes proposed (A3a, additive)

Add to `plan/project.rs`, mirroring the existing `StoreAccumKind` /
`AccumStoresMask` / `accum_stores_mask`:
- `StoreElemBytes { const BYTES: USize }` with disjoint per-marker impls:
  `Column`/`Resource`/`Accum`/`StagedResource` over `T: ColumnValue` give
  `(BIT_WIDTH + 7) / 8`; `Virtual<T>` gives `USize::ZERO` (no record bytes).
- `StoreSizes<CS>` fold over the `Stores` cons-list (sibling of
  `AccumStoresMask`) writing each store's bytes into a slot.
- `store_sizes::<Stores, CS>()` entry (sibling of `accum_stores_mask`).
- Unit test: a known 4-store carrier yields the expected per-store byte sizes +
  a zero slack tail.
