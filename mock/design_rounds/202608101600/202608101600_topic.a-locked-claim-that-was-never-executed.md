# A locked claim that was never executed

**Date:** 2026-08-10
**Phase:** TOPIC
**Scope:** `docs/`

Round thirteen's doc changelist says the overview's false header goes, and names
its own verification: `grep -c 'no template behind this file'` returns 0.

**It returns 1.** The changelist locked, the round closed, and that edit was
never made. Every other change the round described did land, which is why nothing
noticed: the round was verified by running its tests and its gate, and neither
reads a changelist.

This is the fifth false locked claim on this branch and the first that is a
described edit simply not performed rather than a measurement taken wrongly. It
is worse in kind. A wrong measurement is a claim about a number; an unexecuted
edit is a claim that work exists which does not.

## What the header should say

The file is generated, from `DESIGN.md.tmpl`, under a name the current mockspace
no longer emits, which is why a generator run would delete rather than update it
and why no same-named template exists to find. Round nine inferred from that
absence that the file was hand-written and wrote a header saying so. Both halves
of that header are false.

The honest statement is that it is a **stale rendering**: correct at the time it
was emitted, superseded by the template, and awaiting the rename migration that
owns every overview in this directory. A reader landing on it should be told to
read the template instead, and should not be invited to hand-edit a file the
generator will delete.

## The procedural gap this exposes

A round's verification lines are checked by whoever wrote them, at the moment
they are written, when the intent to make the edit is indistinguishable from
having made it. Nothing downstream reads them.

Naming that here rather than proposing a mechanism: the lint that would close it
is `cl-claim-sketch-discipline.md`'s claim-verifier, which is tracked upstream
and does not exist yet. Until it does, the discipline is to run every
verification line as a command against `git show HEAD` before locking, which is
what this round does for its own.
