## CHANGE: `hilavitkutin/DESIGN.md.tmpl`, the accumulator region paragraph

From rounds `202607192110` and `202607192610`, against `dev`'s rewrite of the same paragraph in rounds `202611130402` to `202611130554`. Both sides rewrote it and they meant different things, so neither text is taken.

`dev` meant: the leading meta bands append first, so a core's region starts at `len + lo_c`; a region has a `wanted` cell beside its live length; an append past a region's cap is refused. All of that stays word for word.

The branch meant three things. The region start is not "the same head+tail record-slice start the morsel-local path uses", because that path is the N-way split being deleted, so the clause becomes "the regions tile `[0, total)` one per core". The regioning is N-way by design and is a different mechanism from head+tail convergence. And the worker's region boundaries and the merge's read offsets are one function of `(total, ncores, core)`, stated as the invariant that makes the merge correct. Those three go into `dev`'s paragraph at the places they speak about, with the offsets spelled `len + lo_c` as `dev` has them.
