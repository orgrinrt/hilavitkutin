## New crate: hilavitkutin-sym

### `mock/crates/hilavitkutin-sym/README.md.tmpl` (create)

Short feeder summary (3 to 10 lines) for the root design assembly. States: a `no_std`, no-alloc, zero-ecosystem-dependency interned-identity core; the `Sym` 4-byte integer-equality handle tagged by a 4-bit domain `kind`; two producer shapes, an `Interner` for deduplicated values and a `Generator` for minted fresh identities; strings are one consumer domain (in `hilavitkutin-str`). Depends only on `arvo`, `arvo-bits`, `notko`.

### `mock/crates/hilavitkutin-sym/DESIGN.md.tmpl` (create)

The shipping contract. Sections, each with the backticked type names that must exist in source by IMPL lock:

- Framing prose (3 to 4 paragraphs): what an interned identity is, why the handle and its integer-equality identity are domain-agnostic, and how a domain acquires a handle either by interning a value or by minting a fresh one.
- `Sym`: the `#[repr(transparent)]` 4-byte handle over `SymLayout` (an `arvo::bitfield!` over `Bits<32, Hot>`) with `id: 28 at 0`, `kind: 3 at 28`, and `flag: 1 at 31`. Integer-equality identity across the whole layout; two `Sym`s of differing `kind` never compare equal. Accessors `kind()`, `id()`, `flag()`, `to_bits()`; constructors `Sym::new(kind, id)` and `Sym::with_flag(self, bit)`. (Refinement of the topic's "4-bit kind": the domain tag is the 3 reserved bits and the origin stays a 1-bit domain-private flag, so the string domain is a single kind rather than two, which lets `StringInterner` be a genuine single-`KIND` `Interner<StrDomain>` implementer. Byte-compatibility is unchanged: const is still nibble `0b0000`, runtime `0b1000`, binder `0b0001`.)
- `SymKind`: newtype over `Bits<3, Hot>` naming the domain tag. `SymKind::new(raw)`. The kind-assignment table (documented convention, owned here so two domains cannot claim one tag): `0b000` the string domain (const/runtime distinguished by the flag bit, not by tag; the constant defined in `hilavitkutin-str`, mandatory for byte-compatibility), `0b001` recorded as vehje's minted-binder domain (defined in its own crate), `0b010` through `0b111` free.
- `Domain`, `InterningDomain`, `GenerativeDomain`: the marker-trait ladder. `Domain` carries `const KIND: SymKind`. `InterningDomain: Domain` adds `type Value`. `GenerativeDomain: Domain` marks the mint-only mode.
- `Interner<D: InterningDomain>`: the trait for the dedup-and-resolve producer. `intern(&self, value: &D::Value) -> Sym` and `resolve(&self, sym: Sym) -> Maybe<&D::Value>` (exact method shape stated against the string-domain implementation the str crate ships).
- `Generator<D: GenerativeDomain>`: the concrete mint-only producer. A monotonic counter over the 28-bit id width; `mint(&mut self) -> Maybe<Sym>` returns a fresh `Sym` tagged `D::KIND`, or `Maybe::Isnt` at the 28-bit boundary rather than wrapping. No allocation, no arena.
- Why monomorphic handle plus typed producers (not a phantom `Sym<D>`): the erasure-boundary rationale from the topic.

## Updated crate: hilavitkutin-str

### `mock/crates/hilavitkutin-str/DESIGN.md.tmpl` (rewrite the affected sections)

- Opening: note the dependency on `hilavitkutin-sym` for the `Sym` handle and the `Interner`/`Domain` traits. `hilavitkutin-str` supplies the string domains and the string-specific machinery (linker section, FNV, arena).
- `Str` section: `Str` is now a `#[repr(transparent)]` view over a `Sym` restricted to the string kinds. State the string-kind constants `STR_CONST` (`0b0000`) and `STR_RUNTIME` (`0b1000`), defined here, chosen to equal the previous `origin`/`reserved` bit patterns so every baked handle is byte-identical. `Str::__make` builds a kind-`STR_CONST` `Sym`; `Str::__runtime` builds a kind-`STR_RUNTIME` `Sym`. `is_const` is "kind is exactly `STR_CONST`". Keep `id()`, `to_bits()`, the mask forwards. Drop the standalone `StrLayout` description (the layout now lives on `SymLayout` in `hilavitkutin-sym`); `Str` no longer declares its own bitfield.
- `str_const!`, `StaticStrEntry`, the linker-section exemption rationale: unchanged in behaviour and layout. `StaticStrEntry`'s `#[repr(C)]` `hash: Str` field is the same four bytes. Keep the sections as-is except where they reference `StrLayout` internals.
- `StringInterner<A>`: add that it implements the generic `Interner` for the string domain; the const linker-section table plus the host arena is that domain's dedup-and-resolve implementation. `intern`/`intern_static`/`resolve` keep their string-typed convenience signatures; the generic `Interner` impl is the trait-level view of the same machinery.
- `ArenaInterner`, `AsStr`, `IntoStr`, content hashing, design rule: unchanged.
