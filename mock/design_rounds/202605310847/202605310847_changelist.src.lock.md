# Source changelist: order-independent RAW in build_dag

`build_dag` walks only the upper triangle (`i < j`) and adds a RAW edge
`i to j` when the higher-indexed unit reads what the lower-indexed unit
wrote. This drops the dependency when the writer is registered after the
reader, and the resulting graph is acyclic by construction so
`topo_sort`'s cycle signal is unreachable from any registration. The
change makes RAW detection order-independent: the writer sorts before
the reader for every store-overlapping pair, regardless of input order.
WAW serialisation stays lower-index-first (deterministic). WAR is out of
scope (a tracked #339 follow-up).

TDD: two red tests land first in `plan_runner.rs`. The reorder test
registers a reader at the lower input index and its writer at the
higher, then asserts `unit_meta` places the writer first; it fails on
the forward-only graph (no edge, ascending order) and passes once RAW is
order-independent. The cycle test registers two units that each read
what the other writes and asserts `PlanError::Cycle`; it fails on the
forward-only graph (only one forward edge, no cycle) and passes once the
back-edge appears.

## CHANGE: `build_dag` RAW edge generation FROM forward-only (`i < j`) TO order-independent all-pairs
File: `mock/crates/hilavitkutin/src/plan/steps.rs`
The nested loop becomes `for s in 0..n { for t in 0..n { if t != s ... } }`,
appending a RAW `Read` edge `s to t` when `reads[t]` overlaps `writes[s]`
(the writer `s` before the reader `t`), for every ordered pair. The WAW
`Write` edge `s to t` is added only when `s < t` (deterministic
lower-index-first serialisation). The outer loop walks the source `s` in
ascending order, preserving `add_edge_kind`'s CSR append-order invariant
(an edge's source is never smaller than the prior frontier). The
trailing-sink finalize that pads zero-out-degree rows is unchanged.
Verification: `cargo test -p hilavitkutin --test plan_runner` passes, including the new reorder and cycle tests; the existing forward-graph tests (`empty_input_yields_empty_plan`, `single_unit_yields_one_phase_one_fiber`, `phase_config_heuristics_apply_low_record_count`) still pass because they register no overlapping read/write masks.
