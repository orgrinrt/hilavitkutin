# Src changelist: Plannable + the HintExt slot

**Date:** 2026-07-17
**Round:** `202607171733_topic.plannable-declaration-split`
**Phase:** IMPL
**Scope:** Add `Plannable<Schedule>` (with its blanket impl over every `WorkUnit`) and the `HintExt`
extension slot on `SchedulingHint`. Additive only: no existing item's shape changes, no implementor
or consumer edits.

## CHANGE: add `pub trait Plannable<Schedule>` and its blanket impl
File: `mock/crates/hilavitkutin-api/src/work_unit.rs`
New trait carrying the declaration half (`type Read`, `type Write`, `type Hint`), parameterised by
`Schedule = Always`, plus `impl<W: WorkUnit<S>, S> Plannable<S> for W` forwarding the three
associated types. The schedule sits in the trait parameters so `S` is constrained (schedule-free
form fails E0207, proven by the round sketch).
Verification: `grep "pub trait Plannable" mock/crates/hilavitkutin-api/src/work_unit.rs` returns one
match; `grep "impl<W: WorkUnit<S>, S> Plannable<S> for W" mock/crates/hilavitkutin-api/src/work_unit.rs`
returns one match; `cargo check -p hilavitkutin-api` passes with no change to any existing impl.

## CHANGE: add `pub trait HintExt` and the 4-tuple SchedulingHint arm
File: `mock/crates/hilavitkutin-api/src/hint.rs`
New open marker trait `HintExt: 'static`, plus the additive sealed + `SchedulingHint` impls for
`(U: UrgencyValue, D: DivisibilityValue, S: SignificanceValue, X: HintExt)`. No `HintExt` markers
are defined. The existing 3-tuple impls are untouched.
Verification: `grep "pub trait HintExt" mock/crates/hilavitkutin-api/src/hint.rs` returns one match;
`grep "X: HintExt" mock/crates/hilavitkutin-api/src/hint.rs` returns the two impl lines; the existing
`SchedulingHint for (U, D, S)` impl is unchanged.

## CHANGE: export `Plannable` and `HintExt` from the crate root
File: `mock/crates/hilavitkutin-api/src/lib.rs`
Re-export `Plannable` from `work_unit` and `HintExt` from `hint` alongside the existing `WorkUnit`
and `SchedulingHint` exports.
Verification: `grep "Plannable" mock/crates/hilavitkutin-api/src/lib.rs` and
`grep "HintExt" mock/crates/hilavitkutin-api/src/lib.rs` each return a match.

## Tests
File: `mock/crates/hilavitkutin-api/tests/plannable.rs` (new)
- A `WorkUnit<Always>` is accepted at a `T: Plannable<Always>` bound via the blanket, with its
  `Read`/`Write`/`Hint` recovered through `Plannable`.
- A non-`WorkUnit` local type hand-implements `Plannable` and is accepted at the same bound (this is
  the GPU-runner shape).
- A 4-tuple hint `(Immediate, Atomic, Normal, TestExt)` with a test-local `HintExt` marker satisfies
  `SchedulingHint`, and the existing 3-tuple still does.
These fail to compile before the src edits land (the traits do not exist) and pass after.

## Non-changes (stated so the audit is honest)

  untouched.
- No existing `impl WorkUnit` anywhere in the workspace changes.
- The 3-tuple `SchedulingHint` impl is untouched.
