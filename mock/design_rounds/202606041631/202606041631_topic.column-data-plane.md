# Topic: column data plane (input columns through dispatch)

**Date:** 2026-06-04
**Phase:** TOPIC
**Scope:** hilavitkutin engine (`mock/crates/hilavitkutin`), one crate. Round 1 of the column-data-plane arc on branch `feat/hilavitkutin-column-data-plane`.
**Source topics:** dispatch-build-plan memo (`mock/research/202605282100_engine-dispatch-build-plan.md`, Phase B keystone + 5.1 accumulator drain); the unified-storage arc (#654); HILA-RUNTIME C2/C5 (#340, #343).

The engine dispatches resource-only WorkUnits today. A WorkUnit that reads or writes a `Column<T>` cannot enter dispatch: the per-fiber collection (`CollectFiber` / `fiber_shim`, `dispatch/fiber_codegen.rs`) carries `ColPtrNil: ColProject<Read/Write, Empty, Out = ColPtrNil>` bounds that hold only for column-free access sets, and `run()` passes `&ColPtrNil` as the column source. The column buffers themselves are not reserved: the `Column<T>` arm of the bindings drain (`resource/bindings.rs`) records a dangling `ColumnPtr<T>` and a zero record count, with a comment deferring real reservation to "a later round" because it needed a record count. This round is that round.

The per-WorkUnit Context is already built for columns. `EngineCtx::project` (`dispatch/engine_ctx.rs`) takes a column source, `ColProject` recurses the `Column<T>` members of an access set and pulls a `ColumnPtr<T>` per member via `ColSelector`, and the `read<T>(i)` / `write<T>(i, v)` accessors already index `morsel.start + i`. `ArenaColumnStorage` (`hilavitkutin-providers`) already reserves real 64-byte-aligned buffers via `reserve<T>(id, len)` and hands out `column_ptr_mut<T>(id)`. The gap is between these two: nothing reserves the column buffers sized to a record count, records the live `ColumnPtr<T>` in the bindings, feeds the bindings as the column source, or lifts the resource-only dispatch bound.

## The locked decisions

op's design call (2026-06-04): the column surface distinguishes **input columns** (records present before the frame, sized to a record count, read and written by index) from **accumulator columns** (records appended during the frame, growing from zero to a capacity, drained to persistence at PassEnd) from the start, rather than assuming a single global record count and deferring accumulators. This arc honors that: round 1 ships input columns fully; a following round on this branch adds the accumulator role (a sibling store marker with an append accessor and a live-length counter); the PassEnd persistence drain wires later with the persistence spine (#344 / #134).

Two design forks were resolved with a neutral domain-expert read plus a trait-solver sketch:

**Column source shape (Shape A).** The bindings cons-list serves as BOTH the resource source (`Selector` / `Project`, already built) AND the column source (`ColSelector` / `ColProject`, new). One witness list into the one `ColumnStorage`, which is the unified-storage directive (#654). The alternative (a separate column-only `ColPtrCons` list built from the bindings) sidesteps interleaved traversal but adds a second list to build and keep in sync, and grows a new extraction arm per column role. Shape A grows by one impl group per node kind per selector, and the accumulator role drops in as a third node kind on the same mechanism.

Shape A requires closing a pre-existing traversal gap: `Selector` is implemented only on `ResourceBinding` nodes, so a resource declared after a column in the registration order is unreachable (it works today only because tests register resources first). Shape A adds `Selector` pass-through `There` impls on `ColumnBinding` and `VirtualBinding`, and the mirror `ColSelector` impls (`Here` on `ColumnBinding<T>`, pass-through `There` on all node kinds), so both selectors traverse the full interleaved list.

The sketch at `mock/research/sketches/202606041631_column-source-dual-selector/` confirms the dual co-implementation compiles and resolves unambiguously: a resource behind a column node and a column behind a resource node both resolve to the correct pointer, indices fully inferred. Two gotchas surfaced, both already handled by the real `EngineCtx::project` (the projection call must be fully-qualified `<A as ColProject<Set, Idx>>::col_project(a)`, not method syntax; the pointer wrappers impl `Copy` unconditionally).

**Reservation timing (Timing X).** Columns reserve at `build()`, not per frame. The column pointer is then stable for the scheduler's lifetime, there is no per-frame allocation (which would violate the no-alloc-per-frame discipline), and the `ColumnPtr<T>` is valid to hand out at projection time. The per-frame live record count is metadata, not a re-allocation. This fits schedule-once-reuse-across-frames and accommodates the accumulator role (reserve to max capacity at build, live-length counter advanced per append at run).

## Round 1 changes (input columns through dispatch)

1. **Reserve input column buffers at build, sized by the record count.** `build()` / `build_with()` gain the frame record count as the column-reservation dimension and feed it to the plan computation in place of the current `USize::ZERO`. The `Column<T>` drain arm in `resource/bindings.rs` stops recording a dangling placeholder: it reserves the column in the `ColumnStorage` (`reserve::<T>(id, record_count)`) at a continued `StoreId` from the resource drain, and records the real `column_ptr_mut::<T>(id)` and the count in the `ColumnBinding`.

2. **Make the bindings the column source (Shape A).** Add `ColSelector<T, I>` on the bindings nodes and the `Selector` / `ColSelector` pass-through `There` impls per the sketch, so the bindings cons-list resolves both resource and column lookups over the interleaved list.

3. **Lift the resource-only dispatch bound.** `fiber_shim` / `CollectFiber` replace the `ColPtrNil: ColProject<..., Empty, Out = ColPtrNil>` bounds with `A: ColProject<Read, RCIdx> + ColProject<Write, WCIdx>`, using the fully-qualified projection form. `run()` passes the bindings as the column source to `EngineCtx::project` instead of `&ColPtrNil`, with the morsel range covering the record count (single morsel for now; the morsel-loop split that windows the record range into multiple morsels is the C5 round, #343).

## Test plan (red-first)

A producer WorkUnit writes a `Column<T>` at indices `[0, N)`; a consumer WorkUnit (ordered after it by the plan's data dependency) reads the column back and writes the readback into a second column or a resource for assertion. The test builds the scheduler with a record count of `N`, runs it, and asserts the consumer observed exactly what the producer wrote. Red first: the test cannot compile against the current `ColPtrNil`-only dispatch (a column-bearing WorkUnit fails the resource-only bound), and once the bound is lifted but before the drain reserves real buffers, the readback reads from the dangling placeholder. Both failure modes precede the green state.

## Out of scope for round 1 (later rounds on this branch)

- Accumulator columns: the sibling store marker, the append accessor, the live-length counter. Next round.
- The PassEnd persistence drain of accumulator columns. Lands with the persistence spine (#344 / #134).
- The morsel-loop split (windowing the record range into multiple morsels with micro-morsel sync points). The C5 round (#343).
- The capacity-versus-live-count split (reserve to a max capacity at build, set a per-frame live count `<=` capacity at run). Round 1 reserves to the record count directly; the split lands when multi-frame reuse or accumulators force it.
- Sub-byte bitpacked column reads (`ColumnValue::BIT_WIDTH`). The accessors treat the buffer as `[T]`-shaped at `size_of::<T>()` stride, matching the current B3 simplification.
