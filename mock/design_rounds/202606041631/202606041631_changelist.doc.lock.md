# Doc changelist: column data plane (input columns through dispatch)

**Date:** 2026-06-04
**Phase:** DOC
**Round:** 202606041631 (column-data-plane, branch `feat/hilavitkutin-column-data-plane`)

The round lands input columns through dispatch. The engine DESIGN prose
currently frames column dispatch as a future extension point: the
`RunFiber` / `CollectFiber` walk is described as resource-only, the
`build` description says column buffers are deferred because they need
the record count, and the per-WU Context prose names columns as a
type-level slot wired in later. Round 1 wires them. The doc edits update
those three passages to describe column dispatch as it now is, while
keeping the genuinely-later pieces (accumulator columns, the morsel-loop
split, the PassEnd persistence drain) marked as later.

## File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`

### Current state

- The per-WU Context paragraph (the `EngineCtx` description) says the
  walk's first slice walks resource-only units and names columns as "a
  type-level extension point for the slice that wires per-frame column
  buffers in".
- The `Scheduler::run` paragraph calls `CollectFiber` "the resource-only
  sibling of `RunFiber`" and closes with "The morsel loop and per-frame
  column buffers are later still."
- The scheduler-builder `build` paragraph says column buffers "need the
  plan-phase record count" and are deferred, alongside Kit-contributed
  units.

### Changes proposed

- Update the `EngineCtx` paragraph: a column-bearing unit now dispatches.
  The per-frame column source is the scheduler bindings themselves (the
  bindings cons-list resolves both resource lookups via `Selector` and
  column lookups via `ColSelector`), so the walk no longer excludes
  column-bearing units. Keep the note that sub-byte bitpacking and the
  morsel-loop split are later.
- Update the `Scheduler::run` paragraph: `CollectFiber` projects columns
  as well as resources (the lifted bound is `ColProject` over the Read
  and Write sets, fully-qualified, mirroring `EngineCtx::project`).
  `run` dispatches over a single morsel covering the build-time record
  count. Mark the morsel-loop split (windowing the record range into
  multiple morsels with micro-morsel sync points) as the later round.
- Update the `build` paragraph: `build` / `build_with` gain the frame
  record count as the column-reservation dimension and feed it to the
  plan computation in place of the zero placeholder. The `Column<T>`
  drain arm reserves a real column sized by the record count at a
  `StoreId` continued past the resource columns and records the real
  `ColumnPtr<T>` and count in the `ColumnBinding` (no longer a dangling
  placeholder). Keep accumulator columns, the PassEnd persistence drain,
  and Kit-contributed units marked as later.

## Out of scope (later rounds, doc stays as-is)

- Accumulator-column prose (the append accessor, the live-length
  counter). Next round on this branch.
- The morsel-loop split prose (#343).
- The PassEnd persistence-drain prose (#344 / #134).
