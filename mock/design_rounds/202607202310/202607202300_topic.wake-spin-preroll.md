# Topic: the Wake Spin Pre-Roll (GATE-2 Deviation 3)

**Date:** 2026-07-19
**Scope:** wire the canonical spin-then-park middle tier into the frame
waits, as the deviation-3 canonical build under evidence-then-bless.
**Related:** seed governance item 5 deviation 3; the pre-freeze batch.

## The finding that shapes the round

The canonical three-tier parking machinery already ships in
`thread/parking.rs` (`WakeStrategy` with the Topic 6 axis K budgets,
`pick_tier`, `spin_budget_for`, `spin`); the frame waits in
`thread/frame.rs` simply never call it, parking immediately. The
ledger's gate is real: full `pick_tier` selection needs the
`predicted_wait_ns` telemetry, which is undriven (always zero), and a
zero prediction selects the unbounded spin-only tier, which must not
guard an unbounded between-frames wait. Park-immediately was the safe
wrong tier.

## What this round builds

The safe canonical increment: the UNCONDITIONAL middle tier. The
worker frame wait and the scheduler done wait spin a bounded budget
(re-checking the word each iteration, so the lost-wakeup discipline is
untouched) and then park through the same load-check-wait pattern as
today. The budget is a consumer-tunable `RunCfg` const defaulting to
the canonical P-core 128 (toolbox-not-policer), with zero restoring
park-immediately exactly; the shutdown wait stays park-only (latency
irrelevant). The telemetry-driven `pick_tier` wiring remains the
D-phase follow-up the ledger names.

## Evidence exit

The wake_policy bench pair (budget 0 versus default) on a real
parallel carrier measures the frame wake cost both ways; the numbers
plus this build are the deviation-3 evidence for the bless-or-rebuild
ruling. If the middle tier wins or ties, the canonical shape ships as
the default and the deviation dissolves; if it loses, the numbers say
so and park-now gets blessed with the tier left tunable.
