# Topic: CtxFor computed per-WorkUnit Context type

**Date:** 2026-06-19
**Crate:** hilavitkutin (engine, dispatch/engine_ctx.rs)
**Tracked:** completion-arc P0.2

## Problem

A consumer WorkUnit hand-spells the nine-parameter `EngineCtx` alias for its
`Ctx<'frame>` GAT, repeating the projected bundle types
(`PtrCons`/`ColPtrCons`/`AccPtrCons`/`VirtCons` chains + the meta pointer)
that are pure type functions of its Read/Write access sets and schedule.
Error-prone and verbose (see the `ConsumerCtx`/`EndCtx` aliases in
`tests/gate2_meta_metrics.rs`).

## Decision

Add an engine-side computed alias plus four pure fold traits, the shape proven
by sketch `mock/research/sketches/202606111430_ctxfor-computed-ctx`
(OUTCOME WORKS, dev+release, nightly-2026-05-28; identity-asserted against the
hand-spelled aliases, run-proven over column / virtual-firing / meta-bridge
DAGs):

```
pub trait ResourceBundleOf { type Out; }      // R -> PtrCons chain / PtrNil
pub trait ColBundleOf { type Out; }           // -> ColPtrCons chain / ColPtrNil
pub trait AccumBundleOf<'frame> { type Out; } // -> AccPtrCons chain / AccPtrNil
pub trait VirtBundleOf<'frame> { type Out; }  // -> VirtCons chain / VirtNil

pub type CtxFor<'frame, R, W, S = Always> = EngineCtx<
    'frame, R, W,
    <R as ResourceBundleOf>::Out,
    <R as ColBundleOf>::Out,
    <W as ColBundleOf>::Out,
    <W as AccumBundleOf<'frame>>::Out,
    <W as VirtBundleOf<'frame>>::Out,
    <S as MetaPtrFor<'frame>>::Ptr,
>;
```

Each fold has four disjoint impls keyed on the access-set head's store kind
(`Cons<Resource<T>,_>` / `Cons<Column<T>,_>` / `Cons<Accum<T>,_>` /
`Cons<Virtual<T>,_>`) plus the `Empty` leaf, the same kind dispatch the shipped
`Project`/`ColProject`/`AccumProject`/`VirtualProject` traits use, no
specialization. The contributing kind conses its node, the other three pass
the tail; output order is the kind-filtered subsequence of set order, matching
the runtime projection value order node-for-node. MP keys off the schedule via
the shipped `MetaPtrFor` (`MetaNil` for `Always`/`On<V>`, `MetaRef<'frame>` for
`OnMeta<V>`). `S` defaults to `Always`.

Engine-side only (every output it names is an engine type; the api must not
depend on the engine, and `WorkUnit::Ctx` is already an unconstrained GAT, so a
consumer assigning the alias is the existing contract). No api change, no
dispatch change: the `RunFiber` projection-equality bounds already normalize
against the computed form.

## Scope

This round lands `CtxFor` + the four traits + re-export + an identity test
asserting `CtxFor` equals the hand-spelled `EngineCtx` aliases. Mechanically
migrating the in-repo test/bench WUs off hand-spelled aliases is a follow-up
(the alias is additive; adoption is incremental, no break).
