# Disjointness by construction, because two laws covered one instance

**Date:** 2026-08-10
**Phase:** TOPIC
**Scope:** `hilavitkutin-sym`, `docs/`

Round nine found the collision reachable and answered it with two laws. The
eighth review found the collision still reachable, past both of them, and it is
right.

## What the laws miss

They reject origins placed **past** the id field. They say nothing about origins
placed **inside** it that overlap each other.

A shape with four origin bits and a twenty-four bit counter, whose bases are
spaced by 2^20 rather than by the counter's own span, gives origin zero the run
`[0, 16777215]` and origin one the run `[1048576, 17825791]`. Every base and
ceiling is inside the id field, so the fit law passes. Each span is exactly
`2^COUNTER_BITS - 1`, so the span law passes. **Origin zero's 1048576th mint is
origin one's first.**

Same defect, same silence, one round later.

## Why laws were the wrong instrument here

Both laws were written to reject the construction that had just been found. Each
succeeded at that and neither described the property. The property is that
distinct origins own disjoint runs, and a law can only ever sample the shapes
that exist.

**The mechanism should make the illegal state unrepresentable rather than
detectable.** A shape currently supplies `origin_base` and `origin_ceiling` as
free functions returning `Uint<28, Hot>`, which is an invitation to compute an
arbitrary pair of numbers, and three rounds of numbers have now been wrong.

## The shape of the fix

A shape declares **which minter an origin is**, not where it starts:

```
fn origin_index(origin: Self::Origin) -> ...      // required
fn origin_base(origin)    = origin_index << COUNTER_BITS      // provided
fn origin_ceiling(origin) = origin_base + (1 << COUNTER_BITS) - 1   // provided
```

Distinct indices then own `[i << C, ((i+1) << C) - 1]`, which are disjoint for
every distinct `i` by arithmetic rather than by assertion. There is no pair of
numbers for a shape to get wrong, and the overlapping shape above cannot be
written at all.

Three things fall out rather than being fixed separately. The hand-written `24`
in `SixteenMinters::origin_base`, which restated `COUNTER_BITS` with nothing
tying them, disappears. The `Uint<28, Hot>` hardcoded in the trait, which is
`Standard`'s id width sitting where a shape cannot override it, disappears with
it. And the fit law becomes a consequence of the existing sum law rather than a
separate assertion, since `index < 2^ORIGIN_BITS` and `ORIGIN_BITS + COUNTER_BITS
== ID_BITS` together put every base inside the field.

What remains as a law is much smaller and is about the shape's own mapping:
distinct origins map to distinct indices, and an index fits `ORIGIN_BITS`.
