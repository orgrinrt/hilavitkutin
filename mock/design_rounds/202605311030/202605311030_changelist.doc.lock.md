# Doc changelist

The dispatch and scheduler prose in `DESIGN.md.tmpl` currently states that
`run()` dispatches in registration-list order and that dependency-topological
order is a later slice. This round lands that later slice, so the prose moves
from "registration-list order, topological is future" to "topological order,
computed at build". Two passages change; the `RunFiber` primitive description
stays (it remains the per-unit projection mechanism the new slot shim reuses).

## File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`

### CHANGE: dispatch-walk paragraph (the `Scheduler::run` drive paragraph)

The paragraph that reads "The walk order is registration-list order this
slice: the builder prepends, so the last-registered unit runs first.
Dependency-topological order from the execution plan is the plan-driven
slice" is rewritten. New prose: `run()` materialises a type-erased dispatch
slot per retained unit via `CollectFiber` (the resource-only sibling of
`RunFiber`: same projection bounds, records a slot instead of running inline),
then dispatches the slots in the plan's topological order. The order comes
from `compute_execution_plan`'s `unit_meta` permutation, computed at
`build()`; a reader registered ahead of its writer runs after it. The morsel
loop and per-frame column buffers stay later rounds.

New backticked names introduced here that must exist as pub items in source:
`CollectFiber` (pub trait, `dispatch/fiber_codegen.rs`, re-exported from
`dispatch`). `RunFiber`, `run_fiber_walk`, `EngineCtx`, `compute_execution_plan`
already exist.

### CHANGE: scheduler-build paragraph (the `build` retains + `run` walks passage)

The passage that reads "run walks that list (resource-only, registration-list
order) by constructing each retained unit's `EngineCtx` from the arena and
calling `execute`. Column buffers (which need the plan-phase record count),
dependency-topological dispatch order, and Kit-contributed units ... are later
rounds" is rewritten. New prose: `build` computes the execution plan from the
registered bundle before draining the store arena (a dependency cycle returns
`BuildError::PlanFailed` without allocating) and stores the topological
permutation on the scheduler; `run` dispatches in that order. Column buffers
and Kit-contributed units stay later rounds; dependency-topological order is
dropped from the "later rounds" list because it lands here.

New backticked names: `BuildError::PlanFailed` (`BuildError` is an existing
pub enum; the `PlanFailed` variant is added in the src round).
