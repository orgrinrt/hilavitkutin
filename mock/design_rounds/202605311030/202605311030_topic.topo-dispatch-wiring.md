# Plan-derived topological dispatch

The scheduler retains its registered WorkUnit instances on a value-carrying
cons-list and, today, dispatches them in registration-list order: `run()`
drives `run_fiber_walk` over the retained list, so the last-registered unit
runs first and a unit that depends on another may run before it. The plan
stage already computes a dependency-respecting topological order (the
`unit_meta` permutation produced by `compute_execution_plan`), but nothing
reads it at dispatch time. This round wires that permutation into `run()`.

The wiring became meaningful only after the `build_dag` slice (#115). Before
it, the dependency graph was forward-only (an edge existed only from a
lower-indexed writer to a higher-indexed reader), so the topological order
was always the ascending input index, which coincided with the registration
walk for every input. Dispatch wired onto that order would have been
observably inert and the `PlanError::Cycle` path unreachable. With
order-independent RAW hazard detection in place, the plan reorders a reader
registered ahead of its writer behind that writer, and the reorder is
observable: it is the red-first test this round is built around.

## Current state

`Scheduler::run` calls `run_fiber_walk(&self.wu_values, &self.arena, morsel)`,
which recurses the retained `WuCons` list head-first, projecting each unit's
`EngineCtx` and calling `execute` in cons-list position order. The scheduler
carries a `_dims: PhantomData<D>` marker for its plan dimensions but computes
no plan: `build` drains the store arena and returns without touching the plan
stage. The plan permutation lives only inside `compute_execution_plan`'s
return value, which `build` never calls.

## Changes proposed

Compute the plan at `build()` and dispatch in its topological order.

1. A new `dispatch/fiber_codegen.rs` adds a type-erased dispatch slot
   (`FiberSlot`) and a `CollectFiber` walk that records one slot per retained
   unit at its registration index, mirroring `RunFiber`'s resource-only
   projection bounds. The slot's shim casts the erased instance pointer back
   to its concrete WorkUnit type, projects the unit's `EngineCtx`, and runs
   `execute`. The cons-walk only records the slot; dispatch order is chosen by
   the caller.

2. `Scheduler` replaces `_dims: PhantomData<D>` with a real
   `topo_order` permutation array plus a live `topo_count`. `build` /
   `build_with` compute the plan from the registered bundle before draining
   the store arena (so a dependency cycle returns `BuildError::PlanFailed`
   without allocating), read the permutation off `unit_meta`, and store it.

3. `run()` materialises the slot array from the retained units via
   `CollectFiber`, then walks `topo_order[0 .. topo_count]`, dispatching each
   step's slot. A reader registered ahead of its writer now runs after it.

The alignment that makes this sound: the builder prepends the unit bundle
(`Wus`, the `BundleProject` index space) and the value list (`WuVals`, the
`CollectFiber` slot space) in lockstep, so a unit's `unit_meta` id index (a
`Wus` position) equals its `WuVals` slot index.

`RunFiber` and `run_fiber_walk` stay as the slice-1 primitive and keep their
own test. The morsel loop, per-frame column buffers, and the LLVM codegen
tier remain later rounds; this round is the generics-only dispatch reorder.

## Out of scope

Column-reading or column-writing units (the walk stays resource-only: a
column projection is non-empty and fails the bound). WAR anti-dependencies
(a tracked plan-chain follow-up; this round dispatches the order the plan
produces, whatever hazards it encodes). Storing the permutation on
`ColumnStorage` as a meta-resource (a later storage-arc step; the permutation
is a scheduler field this round).
