# SRC changelist: c2 build-captures-wus

**Date:** 2026-05-30
**Phase:** IMPL
**Round:** 202605300957

Retain registered WorkUnit instances on a builder value-list that
survives into the `Scheduler`, and drive the slice-1 `RunFiber` walk
from `Scheduler::run`. The WorkUnit-value-list types move from the
engine to `hilavitkutin-api` so the builder (in api) can construct them;
the engine re-exports them next to the walk. Pre-1.0, additive,
in-crate: no compatibility shim per the no-legacy-shims rule.

## CHANGE: `WuNil` / `WuCons` MOVE FROM `hilavitkutin/src/dispatch/fiber_walk.rs` TO `hilavitkutin-api/src/work_unit_values.rs`
File: `mock/crates/hilavitkutin-api/src/work_unit_values.rs` (new), `mock/crates/hilavitkutin/src/dispatch/fiber_walk.rs`
The value-carrying WorkUnit cons-list (`WuNil` terminator, `WuCons<W, Tail>` cell with `pub head` / `pub tail`) is defined in a new api module so the builder can construct it. The engine `fiber_walk` imports both from `hilavitkutin_api::work_unit_values` and re-exports them; the `RunFiber` trait and impls (which reference engine types `EngineCtx` / `Project` / `ColProject`) stay in the engine.
Verification: `grep "pub struct WuCons" mock/crates/hilavitkutin-api/src/work_unit_values.rs` returns one match; `! grep "pub struct WuCons" mock/crates/hilavitkutin/src/dispatch/fiber_walk.rs`; `grep "pub use hilavitkutin_api::work_unit_values::{WuCons, WuNil}" mock/crates/hilavitkutin/src/dispatch/fiber_walk.rs` returns one match.

## CHANGE: type `WorkUnitKind` ADDED in `hilavitkutin-api/src/store_values.rs`
File: `mock/crates/hilavitkutin-api/src/store_values.rs`
New placement kind tag. Its `Place` impl prepends a registered value onto the WorkUnit-value list and passes the store list through. Joins the existing `StoreKind` (prepend store, pass WU) / `UnitKind` (drop both) / `PlatformKind` (drop both) tags.
Verification: `grep "pub struct WorkUnitKind" mock/crates/hilavitkutin-api/src/store_values.rs` returns one match.

## CHANGE: `RouterKind for UnitDispatch<W>` FROM `type Kind = UnitKind` TO `type Kind = WorkUnitKind`
File: `mock/crates/hilavitkutin-api/src/store_values.rs`
A registered WorkUnit's value now routes to the retain kind. `RunCfgDispatch` and `KitDispatch` keep routing to `UnitKind` (drop), and `PlatformDispatch` keeps `PlatformKind` (drop), so only directly-registered WorkUnit instances are retained.
Verification: `grep -A2 "impl<W> RouterKind for UnitDispatch<W>" mock/crates/hilavitkutin-api/src/store_values.rs` shows `type Kind = WorkUnitKind`.

## CHANGE: trait `Place<P>` FROM single-list `{ type Next<L: StoreValues>; fn place<L>(P, L) -> Next<L> }` TO two-list `{ type NextStores<S: StoreValues>; type NextWus<W>; fn place<S, W>(P, S, W) -> (NextStores<S>, NextWus<W>) }`
File: `mock/crates/hilavitkutin-api/src/store_values.rs`
The placement view routes one registered value onto both the store-value list and the WorkUnit-value list at once (the single value is consumed once and lands on exactly one list). The four kind impls each prepend onto one list and pass the other through: `StoreKind` prepends store, `WorkUnitKind` prepends WU, `UnitKind` / `PlatformKind` pass both through.
Verification: `grep "type NextWus" mock/crates/hilavitkutin-api/src/store_values.rs` returns one match in the trait plus one per impl.

Adds the WorkUnit-value-list parameter (defaulting to `WuNil`) and a `wu_values: WuVals` field. The `BuiltScheduler` alias, the `builder()` / `Default` / `Drop` impls, and the method impl block update to carry it.
Verification: `grep "pub struct Scheduler<" mock/crates/hilavitkutin/src/scheduler/mod.rs` followed by the four-parameter list including `WuVals`.

## CHANGE: struct `SchedulerBuilder` FROM `<Wus, Stores, Platform, Vals>` TO `<Wus, Stores, Platform, Vals, WuVals>`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Adds the WorkUnit-value accumulator field `wu_values: WuVals`. `with` routes the registered value through the reshaped `Place` onto both lists; `build` / `build_with` move both lists into the `Scheduler`.
Verification: `grep "pub struct SchedulerBuilder<" mock/crates/hilavitkutin/src/scheduler/mod.rs` shows the five-parameter list.

## CHANGE: method `Scheduler::run` FROM no-op `fn run(&mut self) -> Cfg::Out` TO walk-driving `fn run<Witnesses>(&mut self) -> Cfg::Out where WuVals: RunFiber<Arena, Witnesses>`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
`run` walks the retained WorkUnit-value list via `run_fiber_walk` over a single full-range morsel (`MorselRange::new(USize::ZERO, USize::ZERO)`), then returns `Cfg::Out::default()`. The added witness parameter is inferred at the call site, so `scheduler.run()` is unchanged for callers. Resource-only; registration-list order; no plan computation, no morsel loop.
Verification: `grep "run_fiber_walk" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match in `run`.
