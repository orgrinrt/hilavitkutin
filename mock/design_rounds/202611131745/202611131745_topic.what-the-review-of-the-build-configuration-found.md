# What the review of the build configuration found

Follow-up to round 202611131717, on the same branch, job `hilavitkutin-and-kaski-take-hilavitkutin-build-with-a-first`. A local review of that round's branch returned "merge after fixes". Its findings are the work of this round.

## Current state

- FastMath writes `cargo::rustc-cfg=arvo_fast_math` for the crate whose build script runs `configure`. A `rustc-cfg` directive reaches that crate alone. The one reader of the cfg is arvo's `Float` alias (`arvo/src/float.rs:217-226` at `1b2796e`), resolved inside arvo's own build, which no consumer's build script reaches. No hilavitkutin crate reads the cfg. So the design's sentence "kaski's deterministic simulation crates turn FastMath off this way" describes a choice that changes nothing in arvo.
- `configure_with` applies the caller's `tune` and checks nothing after it. Removing FastMath from the release set leaves MathPeephole, which the design marks "Requires: FastMath". `requirements.rs` still says LoopOptimization requires the pass plugin, while it now writes its five built-in options with no plugin.
- Two tests do not test what they say: `no_flag_is_one_the_pinned_toolchain_refuses` checks only that three names are absent, and `configure_reads_profile_and_features_through_the_closure` compares `configure` with the very composition it is built from. Nothing tests what the wrapper does.
- The wrapper takes effect only where cargo finds `.cargo/config.toml` from the directory it runs in. From the repository root hilavitkutin's `mock/.cargo` is not found, and the flags are dropped without a word.
- `mockspace.toml:157,161,162,163` forbid `hilavitkutin_build::*` for providers, extensions, extensions-macros and api-macros, with reasons saying they must not depend on build-time crates. Each now has a build script calling it.
- `bootstrap.rs` uses a `macro_rules!` for the variable's name to pass `no-bare-static-str`; `flags.rs` holds a `[&str; 5]`; several `lint:allow` markers sit on lines with no bare string.
- The README and the crate docs do not say a consumer commits the wrapper and the config, nor that the flags reach only workspace members.
- The design says the wrapper runs "on any host"; a Windows host without `sh` fails every rustc call.
- The topic of 202611131717 says each flag was checked by compiling a one-function library, and no probe is committed. The bench it promised lives in kaski, as `build-config`.
- `$HILAVITKUTIN_BUILD_RUSTFLAGS` is expanded unquoted, so a flag holding a glob character would be expanded against the directory.

## Changes proposed

1. The design says what FastMath reaches: the cfg is for code in the configured crate that gates on it, and arvo's `Float` takes it only from a build that sets `--cfg arvo_fast_math` for every crate, a choice of the binary's builder. A deterministic simulation never makes it. The `configure_with` example stays, as the crate's own guard, worded as that. Whether arvo should let a crate choose per crate is a question ticket.
2. `PragmaSet::coherent` drops a pragma whose required pragma is absent (MathPeephole without FastMath, Profiling without Pgo or Bolt), and `configure_with` applies it after `tune`. The LoopOptimization row keeps the plugin as the requirement of its plugin passes only, said in the design table.
3. The flag test runs the pinned `rustc` with the release flags on a one-function library and asserts it succeeds, which is the committed probe; a control with a refused flag shows it fails. The tautological test asserts the literal directives. A test runs the committed wrapper with `echo` standing in for rustc, the variable unset, empty, set, and holding a glob.
4. `configure` reads `RUSTC_WORKSPACE_WRAPPER` through the closure and writes `cargo::warning` when it has flags to hand over and cargo names no wrapper.
5. The four layering reasons say the rule binds runtime source, and a build script's build-dependency on `hilavitkutin-build` is allowed. The lint's not reading build scripts is a ticket.
6. The bare-string positions get the treatment the lint wants, with the dodge removed, or a ticketed `lint:allow`; the markers on lines with nothing to allow go.
7. README and crate docs name the two committed files and the workspace-member limit.
8. "On any host" becomes "on a host with a POSIX `sh`", and the Windows entry in the backlog says the build fails there until it lands.
9. The wrapper sets `set -f` before `exec`.
