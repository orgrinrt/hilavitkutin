## What is left of the arc

The first slice moved `plan_dirty`, the grouping caps, and the `PlanDims` surface onto
`Capacity` associated types; `PlanDims` already carries `Units`, `Cores`, `AccumsPerCore`,
`PlanAffecting`. The residual is that the scheduler's scratch fields and two neighbours still
size themselves by the three fixed constants the trait was built to replace:

1. `Scheduler` fields (`scheduler/mod.rs`): `worker_ctxs: [WorkerCtx; MAX_CORES]`,
   `gate2_phase`/`gate2_trunk: [USize; GATE2_MAX_UNITS]`,
   `gate2_accum_live: [AtomicUsize; MAX_CORES * GATE2_MAX_ACCUMS]`,
   `phase_ema`/`phase_accum: [Cell<Nanos>; GATE2_MAX_UNITS]`, and
   `pool: PoolFrame<'static, MAX_CORES, 1>`.
2. `classify_cores` (`thread/class.rs`) returns `[CoreClass; MAX_CORES]`.
3. `PoolFrame<'arena, const MAX_CORES: usize, const MAX_PHASES: usize>`
   (`hilavitkutin-api/src/platform.rs`): instantiating it from `D` would need a
   `cap_size(...)` anon const in type position, the exact GCE wall the sketch's s0 documents.

## The change, per the proven s1 shape

Every field becomes a `Capacity` GAT projection off the `D: PlanDims` the scheduler already
carries: `<D::Cores as Capacity>::Array<WorkerCtx>`, `<D::Units as Capacity>::Array<USize>`,
and the publish array as the nested two-dimensional composition
`<D::Cores as Capacity>::Array<<D::AccumsPerCore as Capacity>::Array<AtomicUsize>>` (a product
needs a const expression; nesting needs only two projections). `merge_accums` and the worker
publish sites index `[core][accum]` instead of `core * GATE2_MAX_ACCUMS + accum`; that nested
interface is #690. Non-`Copy` cells (atomics, `Cell<Nanos>`) initialise through
`Capacity::from_fn`. `classify_cores` gains a capacity parameter and returns
`C::Array<CoreClass>` (two callers). `PoolFrame` re-types over capacity axes,
`PoolFrame<'arena, C: Capacity, P: Capacity>`, fields as projections; the engine instantiates
`PoolFrame<'static, D::Cores, Dim<1>>`. The phase axis stays `Dim<1>`: widening it to real `P`
is B2, and the re-typed signature is exactly the shape B2 widens into.

With no users left, `GATE2_MAX_UNITS`, `GATE2_MAX_ACCUMS`, and `MAX_CORES` are deleted
outright (pre-1.0, no legacy shims), and the `UnitsFitGate2` build guard is retired: its
message says "reduce Units or wait for the #690 lift onto Units", and this round is that lift.
The consumer consequence is the A1-2 goal: a consumer shrinks every one of these budgets by
one `PlanDims` impl, and the default scheduler stops carrying 256-core scratch for
single-core apps.
