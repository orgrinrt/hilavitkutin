Slice 3a ships the first working consumer meta hook end to end: a consumer reads
a meta resource (`SchedulerMetrics`) that hilavitkutin populates, via an
`OnMeta<ScheduleEnd>` work unit, and observes per-pass data. No new firing
mechanism, no kernel change: it rides slice-2's `OnMeta` band dispatch plus an
ordinary `Resource<SchedulerMetrics>`.

## What this round locks

- `SchedulerMetrics` (the slice-2 `meta::SchedulerMetrics` marker) gains a
  `pass_count` field, a `Cell<USize>` mutated through the shared resource
  reference (the same interior-mutability pattern as the virtual stamp cells).
  It starts with `pass_count` only; the other canonical fields
  (`ema_pass_duration_ns`, `active_units`, `stolen_count`, `idle_ns`) land with
  their data sources (a `Clock` for timing, the engine-to-meta bridge for
  `active_units`, the parallel path for `stolen_count` / `idle_ns`), not as dead
  fields now.
- hilavitkutin ships `SchedulerMetricsWu`, a meta work unit scheduled
  `OnMeta<PassStart>`, that reads `Resource<SchedulerMetrics>` and increments
  `pass_count` once per pass through the shared cell. "hilavitkutin provides the
  measurement data" (`:1989`) is realized as a provided work unit the consumer
  registers, not auto-magic: a consumer wanting metrics registers
  `SchedulerMetricsWu` plus their own `OnMeta<ScheduleEnd>` hook.
- The lifecycle band order (slice 2) sequences them: `PassStart` (rank 2) runs
  `SchedulerMetricsWu` before consumers (rank 3), and the consumer hook
  (`OnMeta<ScheduleEnd>`, rank 4) runs after consumers, reading the
  `pass_count` this pass set. No stamp firing; pure band placement.

## Why no kernel write

A kernel that writes `SchedulerMetrics` only when registered needs a structural
"write the `ResourceBinding<SchedulerMetrics>` if present else no-op" over the
bindings, whose head-is-`SchedulerMetrics` vs head-is-other impls overlap
(E0119), and the witness path (`Selector<SchedulerMetrics, I>`) requires the
resource be present, so it cannot express "absent -> no-op". Structural
membership testing walls without specialization. A provided work unit
side-steps it entirely: the metrics WU reads and writes a normal,
consumer-registered resource through the existing `ctx.resource()` accessor and
the cell; the grouping tolerates a unit touching one store (the RAW edge check
skips `i == j`); no kernel special-casing.
