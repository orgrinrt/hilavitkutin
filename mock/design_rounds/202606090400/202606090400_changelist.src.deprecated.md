# SRC changelist: GATE-2 E4 slice 3 — engine-to-meta bridge + SchedulerMetrics + consumer hook

**Date:** 2026-06-08
**Phase:** IMPL
**Round:** 202606090000 (GATE-2, task #685, branch `feat/hilavitkutin-parallel-engine-gate2`)
**Doc CL:** `202606090400_changelist.doc.lock.md`
**Bridge sketch:** `mock/research/sketches/202606090300_e4-slice3-meta-bridge-accessor/` (candidate 1, WORKS).

Builds the engine-to-meta bridge: an engine-owned `MetaBlock` the scheduler
writes each pass, read by an `OnMeta<ScheduleEnd>` consumer hook through a
`MetaAccess`-gated Ctx accessor a consumer Ctx cannot name. Single core; the
`run_parallel` worker-side `MetaRef` threading is the follow-on parallel pass.

## CHANGE: `SchedulerMetrics` gains a `pass_count` cell + `MetaField`
File: `mock/crates/hilavitkutin-api/src/meta.rs`
Verification: `grep "pub pass_count" mock/crates/hilavitkutin-api/src/meta.rs`; `grep "trait MetaField" mock/crates/hilavitkutin-api/src/meta.rs`.

`SchedulerMetrics` becomes `{ pub pass_count: Cell<USize> }` with `Default`. A
`MetaField` trait (`fn project(block: &MetaBlock) -> &Self`) lets the accessor
pull a meta resource out of the block; `MetaBlock` is engine-side, so `MetaField`
is declared in api over an opaque block handle OR (simpler) `MetaField` lives
engine-side next to `MetaBlock`. Decide in impl: keep `MetaField` engine-side
(the api only needs the `SchedulerMetrics` value type + `MetaAccess`).

## CHANGE: `EngineCtx` gains a meta-pointer parameter + `meta` accessor
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`
Verification: `grep "MP = MetaNil" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`; `grep "fn meta<" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`.

`EngineCtx<'frame, R, W, RBundle, RCols, WCols, WAccum = AccPtrNil, WVirt = VirtNil, MP = MetaNil>`
gains a `meta_ptr: MP` field (defaulted `MetaNil`, so existing consumer Ctx
aliases are unchanged, mirroring `WVirt = VirtNil`). `from_projected` / `project`
take a `meta_ptr` (built per WU). Add `MetaNil`, `MetaRef<'frame>`, a
`BuildMetaPtr<'frame> { fn build(block: &'frame MetaBlock) -> Self }` (MetaNil
ignores the block; MetaRef captures it), and a `meta::<T: MetaAccess + MetaField>()`
accessor implemented ONLY on `EngineCtx<..., MetaRef<'frame>>`. A consumer Ctx
(`MP = MetaNil`) has no `meta`, so consumers cannot reach meta state (compile-time
`MetaAccess` enforcement, no extra bound).

## CHANGE: `MetaBlock` on the `Scheduler` + per-pass write
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (+ a `MetaBlock` home, e.g. `dispatch/engine_ctx.rs` or a small `meta` module)
Verification: `grep "meta_block" mock/crates/hilavitkutin/src/scheduler/mod.rs`; new test green.

`MetaBlock { metrics: SchedulerMetrics }` is a `Scheduler` field, initialised at
build. `run` increments `meta_block.metrics.pass_count` once per pass (a direct
field write). The block reference threads through the single-core dispatch chain
to the Ctx construction exactly as the slice-1 `epoch` value threads
(`dispatch_trunks` -> `dispatch` -> `RunFiber` / `wu_fn`); at Ctx construction the
per-WU `meta_ptr` is `<MP as BuildMetaPtr>::build(meta_block_ref)`, yielding
`MetaNil` for consumers and `MetaRef(&block)` for `OnMeta` work units.

## CHANGE: behavioral test `tests/gate2_meta_metrics.rs`
File: `mock/crates/hilavitkutin/tests/gate2_meta_metrics.rs` (new)
Verification: `cargo test -p hilavitkutin --test gate2_meta_metrics` green.

Record-less pipeline (unit-outer path, every WU once per pass). Registers a
consumer plus an `OnMeta<ScheduleEnd>` hook whose Ctx carries a `MetaRef`; the
hook reads `ctx.meta::<SchedulerMetrics>().pass_count` into a test-observable
cell. Two frames: the observed count is 1 then 2 (the engine maintained
`pass_count` per pass and the hook read it after consumer work). A compile-fail
fixture (consumer Ctx naming `meta`) is the `MetaAccess`-enforcement negative,
added as a doc-commented note or a trybuild case (decide in impl; the positive
test is the gate).
