# SRC changelist: GATE-2 E4 slice 3a — SchedulerMetrics + provided metrics WU + consumer hook

**Date:** 2026-06-08
**Phase:** IMPL
**Round:** 202606090000 (GATE-2, task #685, branch `feat/hilavitkutin-parallel-engine-gate2`)
**Doc CL:** `202606090200_changelist.doc.lock.md`
**Resolution:** `mock/research/202606090100_e4-slice3-resolution.md`

Ships the first end-to-end consumer meta hook: a provided `SchedulerMetricsWu`
maintains `SchedulerMetrics.pass_count` per pass; a consumer `OnMeta<ScheduleEnd>`
hook reads it. No kernel change, no new trait mechanism: ordinary `OnMeta` band
dispatch (slice 2) over a normal `Resource<SchedulerMetrics>`.

## CHANGE: `SchedulerMetrics` gains a `pass_count` field
File: `mock/crates/hilavitkutin-api/src/meta.rs`
Verification: `grep "pub pass_count" mock/crates/hilavitkutin-api/src/meta.rs` returns one match.

`SchedulerMetrics` becomes `pub struct SchedulerMetrics { pub pass_count:
Cell<USize> }` with a `Default` impl (`pass_count` zero). It stays the
`MetaAccess` sealed marker (the impl is on the type, unaffected). The `Cell` is
mutated through the shared resource reference (the interior-mutability pattern
the virtual stamp cells already use). Other canonical fields
(`ema_pass_duration_ns`, `active_units`, `stolen_count`, `idle_ns`) land with
their data sources, not as dead fields now.

## CHANGE: add engine `meta` module with `SchedulerMetricsWu`
File: `mock/crates/hilavitkutin/src/meta.rs` (new), `mock/crates/hilavitkutin/src/lib.rs`
Verification: `grep "pub struct SchedulerMetricsWu" mock/crates/hilavitkutin/src/meta.rs`; `grep "pub mod meta" mock/crates/hilavitkutin/src/lib.rs`.

`SchedulerMetricsWu` is a provided meta work unit, schedule `OnMeta<PassStart>`,
`Read = Cons<Resource<SchedulerMetrics>, Empty>`, `Write = Empty`. Its `execute`
reads `ctx.resource::<SchedulerMetrics, _>()` and increments `pass_count`
through the cell. It lives in the engine crate (its `Ctx` is `EngineCtx`) and is
re-exported from the engine `lib.rs`. A consumer registers it plus their hook.

## CHANGE: behavioral test `tests/gate2_meta_metrics.rs`
File: `mock/crates/hilavitkutin/tests/gate2_meta_metrics.rs` (new)
Verification: `cargo test -p hilavitkutin --test gate2_meta_metrics` green.

Record-less pipeline (so the unit-outer path runs every work unit once per pass,
dodging incremental skip, as the slice-2 test does). Registers
`Resource<SchedulerMetrics>`, `SchedulerMetricsWu`, an `Always` consumer, and a
consumer `OnMeta<ScheduleEnd>` hook that reads `pass_count` and records it into a
second resource cell (`HookSaw`). Runs two frames; asserts `pass_count` is 1
after frame 1 and 2 after frame 2 (the metrics WU ran each pass), and
`HookSaw == pass_count` each frame (the hook ran after the metrics WU, in
lifecycle band order). Strict / fail-first: written before the metrics WU lands.

## Out of scope (slice 3b / follow-on)

`MetaAccess` compile-time `Context` enforcement; the engine-to-meta bridge for
engine-internal metrics (`active_units`, etc.) which needs the always-present
meta-state mechanism (sketch then); `ema_pass_duration_ns` (Clock, #341);
`stolen_count` / `idle_ns` (parallel); `run_parallel` meta parity (one pass).
