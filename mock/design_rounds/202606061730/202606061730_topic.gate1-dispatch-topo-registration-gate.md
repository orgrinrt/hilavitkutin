# Build-time topological-registration gate

## Current state

After D1d-a (round 202606061446) the builder appends the WorkUnit carrier, so the
retained carrier order equals registration order, and the unit index in the
`DependencyGraph` (registration position) equals the carrier slot. The dispatch
walk currently still indexes through the plan's `topo_order` permutation, which
reorders an anti-topological registration into a dependency-respecting walk. That
runtime-reorder path is what D1e deletes: under the dispatch pivot (spec R6,
"static composition, adaptive parameters") the WU set and dispatch order are
fixed at build time so the type-level cons-list walk devirtualises. A walk over
the carrier in registration order has no permutation to consult; it visits slot
0, 1, 2, ... directly.

The plan layer is, and stays, order-independent. `build_dag` constructs RAW edges
for every ordered pair regardless of registration order (a reader registered
before its writer still gets the edge), and `compute_execution_plan` linearises
that into a topological `unit_meta` order. The plan test
`build_dag_orders_writer_before_reader_regardless_of_registration` pins this
contract and must stay green. The plan answers "what is the correct order"; it
does not constrain how the consumer registered.

## Changes proposed

Once the dispatch walk follows carrier order directly (D1e), the carrier order
MUST already be topological, or the static walk runs a reader before its writer
and reads uninitialised records. The pivot makes registration order load-bearing.

This round adds the build-time precondition that enforces it, ahead of the D1e
walk rewrite, so the invariant the walk will rely on is gated from the moment the
constraint becomes real:

- A new `BuildError::NonTopologicalRegistration { producer, consumer }` variant.
  It names the offending pair by carrier slot index: a `producer` slot that
  writes what a `consumer` slot reads while being registered after it.
- The check runs in the scheduler build path (`compute_plan`), not in
  `compute_execution_plan`. The plan layer stays order-independent; the scheduler
  enforces the provisional registration constraint. The check reuses the canonical
  edge construction (`build_dag`) so "what is a dependency edge" has one
  definition: it walks the dag edges and rejects the first edge whose source slot
  index is not less than its destination slot index (a back-edge in carrier
  space).

This is the PROVISIONAL / TEMPORARY constraint per the standing call (engine
roadmap r2 §8, op call b): registration order is required to be topological only
until RCM-row recovery auto-orders the carrier (the §7-6 const-position-guarded
walk proved this is achievable). When that lands, the carrier is reordered to the
RCM/topological order without the consumer registering in dependency order, and
this gate relaxes. D1d-c (next round) extends the error to name the recommended
registration order; this round establishes the gate and the variant.

### Test consequence (handled in this round's src CL)

`tests/phase_sequential_dispatch.rs` deliberately registers anti-topologically
(consumer, then transform, then producer) to exercise the runtime reorder. Under
the new gate that build is rejected, so the test is rehabbed to register in
topological order (producer, transform, consumer) and its purpose narrows to what
the engine actually does under the pivot: the phase flatten dispatches the chain
in dependency order and visits every unit. A new test asserts the gate itself: an
anti-topological registration returns `BuildError::NonTopologicalRegistration`.

The plan-layer test (`build_dag_orders_writer_before_reader_regardless_of_registration`)
is untouched and stays green: it exercises `compute_execution_plan` directly, the
order-independent plan layer, not the scheduler build path.
