# Topic: morsel-relative iteration indices

**Date:** 2026-06-04
**Phase:** TOPIC
**Scope:** hilavitkutin engine (`mock/crates/hilavitkutin`), `dispatch/engine_ctx.rs`. Round 2 on branch `feat/hilavitkutin-column-data-plane`, a post-review fix surfaced by the PR #119 review of the column-data-plane round.

The column-data-plane round wired input columns through dispatch. Reviewing it surfaced a latent contract inconsistency in the per-WorkUnit Context iteration accessors.

`read(i)` / `write(i)` (`ColumnReaderApi` / `ColumnWriterApi`) compute the absolute column index as `morsel.start + i`, so they take a morsel-RELATIVE `i`. This matches the dispatch-build-plan memo (Phase B): "per-WU column impls carry the `MorselRange` so `read(i)` / `write(i)` index `base + (morsel.start + i)`".

The iteration accessors (`EachApi` / `ReduceApi` / `BatchApi`) yield ABSOLUTE indices: `each().run` iterates `i` over `[morsel.start, morsel.end())` and hands the absolute `i`; `batch().run` hands `(morsel.start, morsel.end())`. So the canonical body `ctx.each().run(|i| ctx.writer().write(i, v))` double-adds `morsel.start`: it writes at `morsel.start + (morsel.start + relative)`. The two halves of the contract disagree.

This is correct only because every morsel today has `start = 0` (the single-morsel `run`). The morsel-loop split (#343), which sets `start > 0`, would make the canonical write land out of bounds. The inconsistency predates the column-data-plane round, but that round is the first to wire `each` together with `write` through real dispatch, so the fix belongs here, before #343.

## The fix

Make `EachApi` / `ReduceApi` / `BatchApi` yield morsel-RELATIVE indices, matching the relative `i` that `read` / `write` already expect: `each` / `reduce` iterate `[0, morsel.len)`, `batch` hands `(USize::ZERO, morsel.len)`. The accessors that consume the index (`read` / `write`) add `morsel.start` to recover the absolute column index, so a WorkUnit body works for any morsel start.

At `start = 0` (every current morsel) the relative range `[0, len)` equals the absolute range `[start, end)`, so existing behaviour is unchanged. The only caller of `each` / `reduce` / `batch` in the crate is the column-data-plane round-trip test, which runs at `start = 0` and stays green; the change makes it exercise the relative-indexing contract the engine actually intends.

## Out of scope

- The morsel-loop split that introduces `start > 0` and a `start > 0` regression test. That is the C5 round (#343); this round only fixes the index contract so #343 inherits it correct.
