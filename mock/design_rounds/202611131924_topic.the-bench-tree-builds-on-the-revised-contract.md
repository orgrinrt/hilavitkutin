# The Bench Tree Builds on the Revised Contract

**Date:** 2026-11-13
**Scope:** `mock/benches/` and one accessor of the engine
**Follows:** round `202611130617-h6mb`

Round `202611130617-h6mb` revised the api in place and closed with the suites of the crates it touched green. A walk of every crate under the mock directory with `cargo mock test`, run after the close on the tree with `dev` at `271909e` merged in, found three places in the bench tree that no longer build against the revised contract. The round's own checks did not reach them, because a crate's suite does not build the bench crates and the round ran the bench crates it wrote and no others.

This is a defect of that round and is fixed alone. Nothing of the contract changes here.

## What the walk found

`engine_vs_std` and `asm_gate_fixtures` carry the same four units, each with a `RecordOp` written to the shape the trait had before: two associated types and a function from one value to one value. The trait is now one function from the read values to the written values. The four value types are not `PartialEq`, which a column listed bare asks of a value function, since a bare listing compares before it stores.

`frame_wide` came in with the merge of `dev`. Its support crate finds a column's base in a built scheduler by type, through the engine's `ColSelector`, to fill an input column and to hash the outputs from the host side. `ColSelector::get` answered a `ColumnPtr` before the revision and answers a `ColRef` now, the two bases of a column with its changed mark and its record count, and the fields of a `ColRef` are private to the engine. So the bench has the column and no way to its base. Every arm of `frame_wide` builds on the support crate, and all ten crates fail on that one line.

`resource_storage/axis_ce` fails on two `notko` crates in one build. Whether that is the trunk's own is checked on the trunk before anything is done about it.

The link of the `archive_str` test of the persistence crate fails for want of the `hilavitkutin_strings` section, as the providers crate's `smoke` test does. That is the trunk's (ticket 51630fc78396).

## What is done about it

The two crates with the four units take the revised `RecordOp`. Each of the four writes every record of its column, so the write is listed under `Written`: the store counts as changed by the write and nothing is compared. That keeps the measured loop what it was, a read, the four stages and a store, and it is what the `std` arm beside it does.

`ColRef` gains two accessors for a host that reaches through the bindings, the base reads see and the base writes land on. They are hidden from the documentation and named with the two leading underscores every such accessor of the engine carries, beside `__frozen` and `__live` on the binding itself. The bench takes the read base, which for a plain column is the one base it has. The supported host-side read and write of a column is still ticket ef57305fb5f4, and the marker in the bench stays.

The designs name neither `ColRef` nor any hidden accessor, so no design text changes.

## Returned to in the source window: the four writes stay bare

Listing the four writes under `Written` did not build. The fold behind `run_fused` takes a unit whose value function reads one bare column and writes one bare column, and a unit over a wrapper is not a link of it. So the lists stay bare and the four written value types gain `PartialEq`, as the engine's own test of the fused sequence has it. The measured loop is the same either way: the fused unit and the four `execute` bodies write by position, and a positional write to a bare column stores and compares nothing.

The walk also found the support crate of `single-trunk-convergence` red, and that one is the trunk's: it calls two functions of the engine's frame gate with an argument fewer than they take, on the trunk as here. `resource_storage/axis_ce` is the trunk's too. Both went on a ticket and are left.

Four `unsafe` blocks around `append` were left with nothing to cover when `append` became safe, in three of these bench crates. They are removed here with the rest.
