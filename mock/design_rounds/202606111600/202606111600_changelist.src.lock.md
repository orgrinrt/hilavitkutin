# Source changelist: D6 ASM-dispatch-gate

Wires the four-fixture ASM checklist (doc CL D1) into a standing gate (doc CL
D2 to D4). The check logic already exists and is platform-aware
(`mock/benches/src/disasm_5check.rs`); this round lifts it to a shared module,
adds a fixtures cdylib carrying the four representative GATE-1 dispatch shapes,
and adds a gate binary that builds the fixtures in release, objdumps each named
symbol, runs the five checks, and exits non-zero when check 1 (zero indirect
call) fails on any fixture.

All edits land in the `mock/benches/` bench infrastructure. No engine crate is
touched: the gate reads the real engine's emitted dispatch through the fixtures,
it does not change what the engine emits.

- `asm_gate_column_chain`: a producer to consumer `Column` chain dispatched via
  `Scheduler::run` (the morsel-outer RAW path).
- `asm_gate_fused_chain`: the four-stage linear `RecordOp` chain dispatched via
  `Scheduler::run_fused` (the register-residency fusion path).
- `asm_gate_accumulator`: a single appender WorkUnit writing `Accum<T>`

- `asm_gate_dirty_gated`: the column chain dispatched via `Scheduler::run` after
  `mark_dirty`, exercising the E7 `run_gated` predicated-branch path.

The `#[no_mangle]` export keeps each symbol stable and objdump-addressable while
the dispatch body below it fully inlines, the same `#[inline(never)]` isolation
the GATE-1 sketches used.

## Implementation note: dispatch placement under LTO

The doc CL (D1) assumed each `#[inline(never)]` fixture wrapper would carry its
dispatch body inlined, so objdumping the four wrapper symbols would suffice. The
release build showed a more nuanced placement: `Scheduler::run` is a large mono,
and under fat LTO a single-caller instantiation (`run_fused`, the accumulator
`run`) inlines into its wrapper, while a multi-caller instantiation (the
column-chain `run`, called by both the plain and the dirty-gated fixtures) stays
out-of-line and the wrappers reach it by a direct `bl`. So the gate's target set
is the union: the four fixture wrappers (covering the inlined shapes) plus any
out-of-line `Scheduler::run` / `run_fused` monos discovered via `nm`
mangled-name pattern (covering the shared shape). This matches the topic's own
framing ("the real dispatch monos are `Scheduler::run`'s and `run_fused`'s
monomorphised bodies"); the fixtures force those monos to be emitted, and the
gate checks every emitted dispatch body wherever LTO placed it. Direct `bl`s to
the build mono, allocator, and panic paths are expected and do not trip check 1
(indirect `blr` / `callq *` only). The shared `read_disasm` was also corrected to
use objdump's `--disassemble-symbols=NAME` form; the space-separated form was
parsed as a second input file and silently fell back to otool's whole-binary
dump, defeating per-symbol scoping.
