# Doc changelist: D6 ASM-dispatch-gate

Settles the four open questions the topic framed, then names the doc surface
that records the gate. The settled shape drives the src CL.

## Decisions

### D1. Fixture symbols and shapes (the gate's targets)

A dedicated gate covers four `#[inline(never)]` named fixture entries, each
wrapping one representative GATE-1 dispatch shape so the dispatch body below it
fully inlines while the entry itself stays a stable, objdump-addressable symbol:

- `asm_gate_column_chain`: a `Scheduler::run` over a producer to consumer column
  chain (the morsel-outer RAW path).
- `asm_gate_fused_chain`: a `Scheduler::run_fused` over a linear `RecordOp` chain
  (the register-residency fusion path).
- `asm_gate_accumulator`: a `Scheduler::run` over an accumulator carrier (the
  unit-outer, never-gated path).
- `asm_gate_dirty_gated`: a `Scheduler::run` over a column chain after a
  `mark_dirty`, exercising the E7 `run_gated` predicated-branch path.

These four are the minimum representative set: they cover every dispatch body
GATE-1 emits today. N-core / meta-WU shapes are out of scope until GATE-2 emits
them; the gate grows to cover them then (recorded as a forward note, not a stub).

### D2. Gate location and check-module reuse

The five-check logic in `mock/benches/src/disasm_5check.rs` is lifted into a
shared module so both the existing bench and the new gate import one
implementation rather than duplicating the platform-aware patterns. The gate
itself is a dedicated binary in the bench workspace (the established shape for
"build a release artifact and read its asm"), runnable via `cargo mock` / CI,
that builds the four fixtures in release, objdumps each named symbol, runs the
five checks, and exits non-zero when check 1 (zero indirect call) fails on any
fixture.

### D3. Per-check severity

Check 1 (zero indirect call) is a hard gate: any FAIL exits non-zero. Checks 2 to
5 are reported with PASS/FAIL but do not by themselves drive the exit code,
because they are legitimately shape-dependent: the accumulator fixture's morsel is
not a baked immediate (it runs full-range), and indexed-addressing / stack checks
vary with the fixture's column count. The report surfaces every check's outcome
for the audit trail; only the devirt invariant gates the build. This matches the
established `disasm_5check` posture (dispatch_static FAIL drives exit; the
counter-example does not).

### D4. Platform operation

The check functions already carry aarch64 and x86_64 patterns, so pattern
coverage is settled. The operational concern (is `objdump` present) is handled by
the same objdump-then-otool fallback the existing module uses, plus a clean skip
with a logged notice when neither disassembler is available, so the gate never
fails spuriously on a toolchain without a disassembler (it reports "skipped, no
disassembler" rather than passing silently or failing).
