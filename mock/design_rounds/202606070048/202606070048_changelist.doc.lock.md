## Scope

Document the trunk-nesting dispatch level: the `FiberCons` / `FiberNil` carrier (a trunk = a value-carrying list of fibers) and the `RunTrunk` walk that runs a trunk's fibers in sequence by delegating each to the shipped `RunFiber`. Single-core, output-equivalent to the flat GATE-1 walk. No parallelism, no `Scheduler::run` re-pointing (that is G2-0c).

## Files

### `mock/crates/hilavitkutin/DESIGN.md.tmpl`

Add one paragraph after the existing `RunFiber` description (the paragraph ending "...so the column projection's associated-type ties resolve.", around the current line 167). The new paragraph introduces the level directly above `RunFiber`:

- `FiberCons<F, Rest>` / `FiberNil`: the value-carrying trunk carrier, a cons-list of fibers mirroring `WuCons` / `WuNil`, each cell carrying one fiber (itself a `WuCons` unit list) plus the tail. Lives in `hilavitkutin-api::work_unit_values` next to `WuCons` so the builder constructs it.
- `RunTrunk<A, WL>`: the monomorphic walk over the trunk carrier. `WL` is a cons-list whose head is one fiber's witness list and tail is the rest, so the nest is a 2-deep witness cons-list inferred with no turbofish. The base impl on `FiberNil` is the no-op; the `FiberCons<F, Rest>` impl bounds `F: RunFiber<A, FW>` and `Rest: RunTrunk<A, RestWL>`, delegating each fiber to `RunFiber::run` then recursing. Single-core the fibers run sequentially, the same order a flat concatenation of their unit lists would; at N cores (a later round) each trunk is the core-pinned unit. The delegation introduces no indirect call, so the trunk walk devirtualises under fat LTO exactly as the fiber walk does.

State explicitly that `RunTrunk` is the inner of the trunk/phase/pipeline nest the canonical hierarchy (`pipeline -> core -> phase ↔ waist -> trunk -> fiber`) names, and that `Scheduler::run` continues to drive the flat walk in this round; consuming the nested carrier from the plan is a following round.
