# Source changelist — per-WU projected Context (B3)

Round: 202605290111. Phase: IMPL. Builds the per-WorkUnit `EngineCtx<'frame, R, W>` (op-directive round): a value holding only the projected pointers for the WU's declared `Read` / `Write`, implementing the seven `HasX` / `*Api` accessor traits. Reuses the validated `Selector` / `Project` index-witness mechanism (sketch `202605290101_ctx-projection-selector.md`). Resources resolve from the B2a arena (real); columns resolve over per-frame column buffers passed in at construction (B2a arena column nodes are dangling placeholders, so the column pointers are NOT taken from the arena, they are a separate construction input that the run-loop will supply in Phase E and tests supply by hand).

## CHANGE: `Selector<T, Index>` + `Here`/`There<I>` + `Project<R, Indices>` + `project_reads` ADDED
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` (new)
Per the sketch: `Selector<T, Index>` with `Here`/`There<I>` witnesses, impl'd over the arena resource nodes (`ArenaResourceNode<T, Tail>` from `resource/arena.rs`) and over the projected pointer bundle cons-list (`PtrCons<H, Tail>` / `PtrNil`). `Project<R, Indices>` carrying a parallel `Indices` cons-list (each index a trait type param, dodges E0207), recursing on the `Resource<T>` / `Column<T>` access-set members, with a free `project_reads::<R, _, _>(arena)` helper pinning `R` by turbofish. Sealed where the workspace pattern calls for it.
Verification: `grep -q "trait Selector" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` and `cargo check -p hilavitkutin` green.

## CHANGE: `EngineCtx<'frame, R, W>` ADDED implementing the seven `*Api` + `HasX` traits
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` (new) + `mock/crates/hilavitkutin/src/dispatch/mod.rs` (expose)
`EngineCtx<'frame, R: AccessSet, W: AccessSet>` holds: a projected resource pointer bundle (from the arena, via `Project` over the `Resource<_>` members of `R`), a projected column pointer bundle (from the per-frame column buffers passed at construction, for the `Column<_>` members of `R` and `W`), and a `MorselRange`. Implement `ResourceProviderApi<R>::resource::<T>()` (Selector over the resource bundle, `&*ptr`), `ColumnReaderApi<R>::read::<T>(i)` and `ColumnWriterApi<W>::write::<T>(i, v)` (Selector over the column bundle; bit-offset `(morsel.start + i) * T::BIT_WIDTH` over the buffer), `VirtualFirerApi<W>::fire::<V>()` (no-op flag for B3; DAG-edge semantics land with the run-loop), `EachApi`/`BatchApi`/`ReduceApi` (iterate `morsel.start .. morsel.end()`). All accessors `&self`; the unsafe read/write aliasing obligation is the scheduler's (documented SAFETY). Implement the seven `HasX` traits with `type Provider = Self`.
Verification: `grep -q "struct EngineCtx" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` and the seven `HasX` impls present; `cargo check -p hilavitkutin` green.

## CHANGE: tests for the Context ADDED

`context_resolves_resource` (hand-built arena, `ctx.resources().resource::<u32>()` returns the value); `context_column_read_after_write` (write then read back over a hand-provided column buffer); `context_each_covers_morsel` (start 5, len 3 yields indices 5,6,7); `context_batch_full_range` (start 5, len 3); `context_drives_wu_execute` (a sample `impl WorkUnit` reads a resource through the Ctx in its `execute`, proving the Ctx satisfies the `HasX` bounds end to end).
