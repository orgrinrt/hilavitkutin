# Topic — per-WorkUnit projected Context (Phase B / B3, op-directive round)

**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** build the engine `EngineCtx<'frame, R, W>` that a WorkUnit's `execute` receives: a per-WU value holding ONLY the pointers the WU declares in `Read` and `Write`, projected out of the scheduler arena, implementing the seven `HasX` / `*Api` accessor traits over resources (now real, from B2a), columns (over per-frame buffers passed in at construction), and the morsel iterators. Not the run-loop that calls it (that is Phase E).
**Source:** the validated design in `mock/research/202605282319_phase-b-data-plane-design.md` (B3 section) and the compiled feasibility sketch `mock/research/sketches/202605290101_ctx-projection-selector.md`.

This is the keystone's final B-phase slice and the round op gave a specific directive on: the Context is per-WorkUnit, scoped to that WU's declared Read and Write, and the scoping is enforced physically. A WU's Context holds only the projected pointers for the stores in `Read` union `Write`; a WU cannot reach an undeclared store because its Context does not carry that pointer, not because a type-level membership bound would reject the call. The Context is its own distinct per-WU type, not a shared or ambient object.

The type-keyed lookup this requires (resolve `resource::<T>()` to the right pointer from a heterogeneous bundle) and the projection (build the per-WU bundle from the arena) both compile on stable Rust via a frunk-style index witness, validated by the sketch: `Selector<T, Index>` with `Here` / `There<I>` index types makes the head-match and recurse impls non-overlapping without specialization, and `Project<R, Indices>` carries a parallel index cons-list (each index a trait type parameter, which dodges the E0207 unconstrained-parameter error) with a free `project_reads` helper that pins the access set by turbofish and infers the index list.

Resources are real after B2a, so resource resolution works end to end now. Column buffers are sized by a per-run record count and are allocated by the run-loop or plan phase (C/E), so the Context's column accessors operate on per-frame column buffers handed in at construction; B3 exercises them with hand-provided buffers, independent of the run-loop. Wiring the run-loop to construct the Context per morsel and call `invoke_wu_in_fiber` is Phase E.

## Current state

- `mock/crates/hilavitkutin/src/resource/arena.rs` (B2a): `ArenaFor`, `ArenaResourceNode<T, Tail>` (holds `ResourcePtr<T>`), `ArenaColumnNode`/`ArenaVirtualNode` placeholders. No lookup over the arena yet (B2a only built + dropped it).
- `mock/crates/hilavitkutin-api/src/context.rs`: the seven `*Api` raw traits (`ColumnReaderApi` / `ColumnWriterApi` / `ResourceProviderApi` / `VirtualFirerApi` / `EachApi` / `BatchApi` / `ReduceApi`) and the seven `HasX` accessor traits (generated by `provider_generic!` / `provider_generic2!`).
- `mock/crates/hilavitkutin-api/src/work_unit.rs`: `WorkUnit::Ctx<'frame>` GAT bounded on the seven `HasX` traits; `execute<'frame>(&self, ctx: &Self::Ctx<'frame>)`.
- `mock/crates/hilavitkutin/src/dispatch/wu_fn.rs`: `invoke_wu_in_fiber<W>` calls `wu.execute(ctx)` with a stub context today.
- `mock/crates/hilavitkutin/src/dispatch/morsel.rs`: `MorselRange { start, len }`.

## Changes proposed

1. `dispatch/engine_ctx.rs` (new): `EngineCtx<'frame, R: AccessSet, W: AccessSet>` holding a projected read bundle and write bundle (only `R` / `W`'s pointers) plus a `MorselRange`. The `Selector<T, Index>` (`Here` / `There<I>`) lookup over the arena and the projected bundle, and `Project<R, Indices>` plus `project_reads`, per the validated sketch.
2. Implement the seven `*Api` traits on `EngineCtx` over the projected bundle: `resource::<T>()` resolves via `Selector` over the read bundle; `read::<T>(i)` / `write::<T>(i, v)` resolve the `ColumnPtr<T>` and do bit-offset math at `(morsel.start + i) * BIT_WIDTH` over the per-frame column buffer; `each` / `batch` / `reduce` iterate the morsel. All accessors `&self` (interior mutability in the pointer math); the unsafe read/write aliasing obligation is the scheduler's.
3. Implement the seven `HasX` traits on `EngineCtx` with `type Provider = Self`. A WU's `type Ctx<'frame>` stays a `HasX`-bounds declaration; the engine names `EngineCtx<'frame, W::Read, W::Write>` only at the private monomorphised call site.
4. Tests (engine): construct an `EngineCtx` from a hand-built arena + column buffers and assert: `context_resolves_resource` (resource value read back), `context_column_read_after_write`, `context_each_covers_morsel`, `context_batch_full_range`, and a `context_drives_wu_execute` (a sample WU reads a resource through the Ctx in its `execute`, proving the Ctx satisfies the `HasX` bounds end to end). A negative trybuild fixture: a WU whose `Read` lacks `Resource<T>` cannot resolve it (no `Selector` path in the projected bundle).

Out of scope (later phases): the run-loop constructing the Context per morsel and calling `invoke_wu_in_fiber` (Phase E); column buffer allocation (run-loop/plan, C/E); the typed `ResourceSnapshot<'phase, R>` (B4) and persistence drain (B5).
