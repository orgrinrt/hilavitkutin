# Doc changelist — per-WU projected Context (B3)

Round: 202605290111. Phase: DOC. Adds a brief note to the engine DESIGN dispatch section naming the per-WorkUnit `EngineCtx` as the concrete Context the engine constructs. B3's new types (`EngineCtx`, `Selector`, `Project`, the projected bundle, index witnesses) are engine-internal and source-only; the `design-doc-source-mismatch` lint checks only first-cell backtick names in DESIGN table rows, so no DESIGN table entry is required for them.

## File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`

The dispatch section (domain 17) describes the rust-pipe fused-pipeline pattern but does not name the concrete Context type the engine hands a WorkUnit. Add a short note that the engine constructs a per-WorkUnit `EngineCtx<'frame, R, W>` scoped to that WU's declared `Read` / `Write`: it holds only the projected pointers for those stores (a WU cannot reach an undeclared store), implements the seven `HasX` accessor traits with `Provider = Self`, resolves resources from the arena, reads and writes columns over the per-frame column buffers, and iterates the morsel. The engine names `EngineCtx<'frame, W::Read, W::Write>` only at the monomorphised dispatch call site; the WorkUnit's `Ctx<'frame>` stays a `HasX`-bounds declaration.

## Not changed

No `*.md.tmpl` table rows reference the new engine-internal types, so no lint surface is touched. The `HasX` / `*Api` accessor traits and the `WorkUnit::Ctx` GAT are already documented in `hilavitkutin-api/DESIGN.md.tmpl`; B3 implements an engine type against those existing contracts and does not change them.
