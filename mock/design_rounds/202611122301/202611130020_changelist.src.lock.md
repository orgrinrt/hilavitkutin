# Src changelist: the suite can fail

**Date:** 2026-11-13
**Phase:** SRC
**Round:** 202611122258 (suite-can-fail, branch `work/suite-can-fail`)

The engine's suite passes against engines that are broken: twelve builder tests discard their result, the one negative contract is a comment, the incremental skip is checked by counts only, and the accumulator append is described as a drop in the api docs while the engine asserts. This changelist makes the suite able to fail and corrects the text that disagrees with the engine. The doc changelist (`202611122301_changelist.doc.lock.md`) already corrected `DESIGN.md.tmpl` and the README Status paragraph. No engine behaviour changes.

## CHANGE: the engine runs compile-fail fixtures as pairs
Files: `mock/crates/hilavitkutin/Cargo.toml`, `mock/crates/hilavitkutin/tests/ui.rs`, `mock/crates/hilavitkutin/tests/ui/*.rs`, `mock/crates/hilavitkutin/tests/ui/*.stderr`.
`trybuild = "1"` joins the engine's dev-dependencies, as in `hilavitkutin-api`. `tests/ui.rs` runs three pairs, each a `_fail.rs` with its compiler diagnostic committed as `.stderr` and a `_pass.rs` twin that differs only in the offending token: `unregistered_store` (a unit reading `Resource<InA>` with the resource never registered; the twin adds the `.with(Resource::new(InA(1)))` line), `undeclared_read` (a body calling `reader().read::<Cb, _>` on a unit that declares `Read = Column<Ca>`; the twin reads `Ca`), `append_fused` (a unit appending to an `Accum` run through `run_fused`; the twin calls `run`). The first pair closes H19, the second is its body-side half, the third is the `run_fused` half of H25: appends cannot reach the fused entry, so the two-frame append test there is the refusal itself, with `run` as the twin.
Verification: `grep -c "verified manually" mock/crates/hilavitkutin/tests/scheduler_builder.rs` returns 0; `CARGO_INCREMENTAL=0 cargo test -p hilavitkutin --test ui` passes; each `_fail.rs` was shown compiling when its offending token is replaced by the twin's (the `_pass.rs` run), and each `.stderr` holds the diagnostic the compiler printed: `E0599` with `Empty: Contains<Resource<InA>>`, `E0277` with `Empty does not contain Column<Cb>`, `E0277` with `AppendWu does not declare a per-record map for fusion`.

## CHANGE: every builder test asserts its outcome
Files: `mock/crates/hilavitkutin/tests/scheduler_builder.rs`.
Each of the twelve `let _ = ....ok();` statements becomes a binding of the build result and an assertion that it is `Ok`. `smoke_fifty_wus` passed vacuously: the 4096-byte test arena returns `AllocationFailed` for fifty units, so it builds over a 65536-byte arena through `store_for_fifty()` and panics with the build error if it fails. The header comment that calls the negative case verified by hand is replaced by a pointer to `tests/ui.rs`.
Verification: `grep -c '\.ok();' mock/crates/hilavitkutin/tests/scheduler_builder.rs` prints 0. Shown failing once against a deliberate break: the test arena shrunk to 16 bytes fails four unit-bearing tests (`smoke_wu_with_sixteen_stores`, `wu_with_kit_builds`, `wu_with_raw_resource_builds`, `two_wus_with_two_kits_build`).

## CHANGE: the incremental skip is checked against an every-store-dirty run
Files: `mock/crates/hilavitkutin/tests/incremental_skip.rs`.
Two schedulers over the same four-unit chain are driven through one input history (cold frame, a clean frame, InA changed, InC changed, both changed, clean, InA set to its current value) on the single-core entry `run`. The skipping one is told only the resource that changed; the reference one has every registered store marked dirty each frame. Equal column bytes are asserted at every frame, and the reference run is also compared with a model of the chain computed in the test, so two equally stale runs cannot pass. The existing count assertions stay. A twin test changes InA without `mark_dirty` and asserts the two runs differ, which shows the comparison can see staleness. The file's inline-array `BumpProvider` is replaced by a heap-backed `StableProvider`: the inline array moves with the scheduler and the bases recorded at build point into a dead slot (ticket `6393002dea2d`), which made two schedulers in one test alias each other.
Verification: shown failing once against each of two named breaks, applied to a copy of the engine and reverted: predecessor propagation disabled in `dirty_units` fails at frame 2 (`left: [[7, 8, 9, 10], [100, 101, 102, 103], ...]`, `right: [[7, 8, 9, 10], [7, 8, 9, 10], ...]`); the read-mask seed disabled fails the reference-against-model assertion at frame 2.
