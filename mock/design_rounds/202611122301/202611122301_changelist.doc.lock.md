## CHANGE: the accumulator append paragraph FROM saturating and dropping TO asserting

File: `mock/crates/hilavitkutin/DESIGN.md.tmpl` (the `Accum<T>` drain arm paragraph), and `docs/HILAVITKUTIN.md` regenerated.

The sentence "An append saturates at the reserved capacity: once the live-length reaches the capacity the append is dropped, so it never runs past the reserved buffer." is replaced by what `resolve_append` does at `mock/crates/hilavitkutin/src/dispatch/engine_ctx/ctx_writers.rs:143-146`: it asserts the live length is below the reserved capacity before the write and panics otherwise, so an append past the capacity is a contract violation, never a silent drop and never a write past the buffer. Round `202606200300` made that decision; the paragraph was not brought along.

Verification: `grep -c 'the append is dropped' mock/crates/hilavitkutin/DESIGN.md.tmpl docs/HILAVITKUTIN.md` returns 0 for both.

## CHANGE: the root `README.md` Status paragraph FROM naming the runtime modules unshipped TO naming what ships

File: `README.md` (Status).

The sentence "The engine's runtime modules (the plan analysis chain, dispatch codegen, adapt subsystem, thread pool, morsel loop, resource resolution, plan caching) are designed and not yet shipped." contradicts the tree: `mock/crates/hilavitkutin/src` holds `plan`, `adapt`, `thread`, `resource`, `dispatch` and `scheduler` (with `run`, `run_fused`, `run_parallel`, `run_trunks`), and `mock/crates/hilavitkutin/tests/gate2_run_parallel.rs` runs the parallel entry. The replacement says the plan analysis chain, the adapt subsystem, the thread pool, the morsel loop and resource resolution ship and are exercised by the engine's tests, and that plan caching, the lowered core dispatch and the install of a replaced resource are not final. Each has a ticket: plan caching `hilavitkutin_plan_dirty_and_plan_cache_are_never_set_or_read` (`947d6843e86b`), the install `hilavitkutin_replace_resource_and_replace_value_discard_the` (`e3b717751622`), and the lowered core dispatch is the placeholder of the H22 stubs, ticketed in the source changelist. The engine crate's `BACKLOG.md.tmpl` names none of the three today (`grep -in 'plan cach\|replace_resource\|install' mock/crates/hilavitkutin/BACKLOG.md.tmpl` finds nothing). The README is a public surface and cites neither tickets nor the backlog; it only says these three are not final.

The second paragraph of Status names `generic_const_exprs` among the gates in use. That gate is forbidden by the workspace's unstable-feature rule and the tree enables it (ticket `2147c2377057`); this changelist leaves that sentence as it is and does not add the gate to any new file.
