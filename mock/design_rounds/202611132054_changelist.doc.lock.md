Round topic `202611132052_topic.the-instruments.md`. The other flat topic, `202607200100_topic.b1-cap-lifting-completion.md`, is about lifting the scheduler's scratch arrays onto the plan's capacities. Nothing here touches those arrays, and it stays flat for the round that does.

The sketch this round builds from is `202611132010_oracle-over-record-op`, committed before this changelist and unchanged by it.

## Current state

The designs describe three run entries and a planner that may split, spread, fuse and rest, and nowhere do they say what a frame computes apart from how the engine computes it. The source has no reference the entries are compared with. Each entry has its own tests, written to what that entry does.

The crate layout in `mock/DESIGN.md.tmpl` has thirteen crates. None of them holds a unit written as a consumer would write one, and nothing in the repository notices when a contract change forces an edit on a unit author. The agent rule `cargo.md.tmpl` says twelve crates, a count already one short.

The engine's design says a const assertion at `build` refuses a unit that writes a plain column it reads with a reach, folded at the dimensions `build` is handed. Round `202611132014` made the type that carries the assertion public, `ReachRule`, and the design does not name it (ticket bdf787ead0b5).

`mock/lints/` holds two lints of the repository and there is no `mock/tools/`.

## Changes proposed

### 1. A crate `hilavitkutin-conformance`

New `DESIGN.md.tmpl` and `README.md.tmpl`. The crate holds the reference runner, the digest and the laws.

Where it goes and why. The earlier branch kept the laws and the runner in a crate each, and the map of that branch says both stay as crates. This round puts them in one, with a module each. The digest makes the words the laws compare and the runner makes the run they are compared with, so nothing takes one without the others, and the layout of this repository is one crate a subsystem. Two more entries in the crate table for one kit is the kind of parallel structure the lead designer said he is wary of. It is not named `-contracts` and holds no contract: it is written against `hilavitkutin-api` and adds nothing an author or an implementor has to meet.

It depends on the api and the foundations and never on the engine. `mockspace.toml` gets a forbidden-imports rule that says so.

The frame's meaning is the seven points of the crate's design, taken from the api's and the engine's designs and not from what the engine does. Two of them are choices this round states as its reading. The runner rests no `Always` unit, on the engine design's own sentence that a skip is sound because the output is identical either way. And the runner answers only for a unit list with every firer of a virtual ahead of every `On` unit of it, refusing the rest with a value; what a virtual fired behind its consumer means across passes stays the engine design's to say.

The sketch's runner becomes `Oracle` with three changes. It refuses with a value where the sketch asserted. A window's extent is the record count the runner was built with, where the sketch took the slice's length. And it is generic over how the frame is kept and over the visiting, which is where the mutants and the second visiting come in.

The mutants were stores on the earlier branch. Here the runner owns its stores, so a mutant is a way of keeping the frame wrongly: seven named types beside `Faithful`, behind a sealed trait of constants, shipped in the crate so that anything held to the laws has the failing cases to hand. The sketch's one mutant was a cargo feature; a feature would have to be switched on by a second test run that nothing guarantees happens.

The laws keep the earlier branch's shape, a function over word slices returning a verdict that names the first failure, on arvo's types in place of that branch's own. They are named `model`, `split` and `isolation`. The third had been dropped from the map's smaller shape because that shape had no buffered store; the api has one now, so it is back.

### 2. A crate `hilavitkutin-frozen-authors`

New `DESIGN.md.tmpl` and `README.md.tmpl`. Nine value-form units over eleven stores, a hand model, and a function that writes one frame's stores down as words.

The brief asks for at least one neighbour reader on two axes and one emitter of each trigger kind. `Spread` is the first. For the second I read "trigger kind" as an accumulator append (`Cross`), a fired virtual with an `On` unit behind it (`Alarm` and `Tally`), and the changed mark under `Written` (`Tally`) and under `Differs` (`Smooth` and `Crest`). Both buffer modes are covered, `Exchange` by the heat and `Snapshot` by the level. `Warm` and `Fade` are there for `run_fused`, which takes only a carrier that is one linear chain of maps: the two alone are such a carrier.

The units name the engine's `CtxFor`, as every unit does today, so the crate depends on the engine. The brief's compile-fail twin "a unit naming an engine type" therefore cannot exist yet; ticket 3df7466ff25a is with the coordinator on that line of the api. When a unit stops naming the context, that edit is the first entry in `BREAKS.toml`.

The hand model and the recording function live in this crate and not with the instruments, because they are statements about these units: frozen with them, they cannot be bent to agree with a runner. The recording function takes slices, so the model, the reference runner and the scheduler are all recorded by the one function.

No crate of frozen implementors this round. The earlier branch's were stores and visiting sequences under its own store contract. The api's store contract has one implementation, in `hilavitkutin-providers`, and a second one under one suite is that crate's work.

### 3. Lints and a tool

`mock/lints/` gains `frozen-ledger`, `frozen-no-feature-gate` and `frozen-no-recursion-limit`, ported from the earlier branch and scoped to the frozen crate. The branch's fourth, which refused a turbofish on an item the file did not declare, is not kept: the api's value form has an author name a store by turbofish at every read, so the lint would refuse what the api documents.

`mock/tools/cross-target/` is the first tool of the repository: it builds the frozen units under the reference runner for the host and for wasm, runs both, and compares the digest streams.

### 4. The engine held to the reference

`mock/crates/hilavitkutin/DESIGN.md.tmpl` gains a section, "What the entries are held to", and `mock/DESIGN.md.tmpl` a short one, "What a frame means", with the two crates in the crate table and the dependency paragraph.

The test itself goes in the frozen crate's `tests/`, not the engine's. That crate already depends on the engine, so the engine's suite cannot take it as a dev-dependency without a cycle between the two, and it is the consumer both the engine and the reference serve. It runs `run` and `run_parallel` at one, two and four workers beside the reference, with and without the accumulator in the carrier so that both the phase loop and the unit-outer path are walked, and `run_fused` on the chain it admits. Where an entry disagrees the case is committed ignored with its ticket.
