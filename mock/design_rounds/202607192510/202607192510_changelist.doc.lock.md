# Doc changelist: nothing to change, which is itself the finding

**Date:** 2026-07-19
**Phase:** DOC
**Topic:** `202607192500_topic.delete-the-orphaned-thread-pool.md`

No template changes, because no template mentions the types being deleted. That was verified before
opening the round rather than assumed: neither `ThreadPool` nor `ThreadPoolBuilder` appears in any
`.md.tmpl` in the workspace.

The absence is the reason the deletion is safe and also the reason it went unnoticed. Two `pub`
types have sat on the crate's public API surface with no design entry, no consumer, and no test, and
the `design-doc-source-mismatch` lint could not see them: it checks that every backticked type in a
template exists in source, never that every public type appears in a template.

Recording that here rather than fixing it. The inverse check is a real gap in the doc gate, but
building it is a band 4 surface-audit question and would be scope creep in a deletion round. What
this round establishes is the evidence: at least one instance exists, found by tracing rather than
by any gate.
