# Topic: delete the orphaned ThreadPool

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** `mock/crates/hilavitkutin/src/thread/pool.rs` entire, and its re-export.
**Grounded on:** roadmap r7 band 1 item R2b, and the R2 reclassification recorded there on
2026-07-19.

`thread/pool.rs` defines `ThreadPool` and `ThreadPoolBuilder`: a struct with `new`, `builder`,
`shutdown_requested`, a `Default`, and a `Drop`; plus a builder with `with_wake_strategy`,
`with_spin_budget`, `with_thread_count` and `build`. None of it runs. The audit found the `Drop`
sets a flag nobody reads.

## Why this one is safe when most of the list is not

Four of the nine duplicate mechanisms the audit listed have now been traced, and three turned out
reserved rather than dead. `core_phase_mask` is op's chosen mechanism with its own test file and is
cited by the live code as the rule it implements. The spawn marshalling halves inverted when D2
landed and their trampoline ownership is untraced. The barriers include one that a passing test
drives and the design templates name.

This one clears every check that caught those:

- **Every reference, all crates, including tests.** Exactly one: `pub use pool::{ThreadPool,
  ThreadPoolBuilder}` at `thread/mod.rs:43`. No test constructs either type. The other workspace
  hits for the string are diagnostic messages about the `ThreadPoolApi` provider contract, which is
  a different thing entirely.
- **Named in a design template?** No. Neither type appears in any `.md.tmpl`.
- **Cited by live code as its rule?** No. The running thread pool is the `PoolFrame` plus the
  platform tiers' `ThreadPoolApi` impls, which share no code with this.

## The gap this exposes, worth naming separately

Both are `pub`. They have been on the crate's public API surface, documented nowhere, consumed by
nothing, for as long as they have existed, and no gate noticed. The
`design-doc-source-mismatch` lint runs one direction only: every backticked type in a template must
exist in source. A public type absent from every template passes silently.

That is the inverse check, and it does not exist. Whether it should is a band 4 question about the
surface audit, not this round's, but this deletion is a symptom rather than an isolated case.

## Out of scope

The spawn-marshalling halves (need the trampoline trace). `core_phase_mask` and the barriers (both
reserved). The accumulator `lo`/`hi` consolidation, which is real work rather than a deletion.
