# Deferrals PR review polish

`pr-reviewer-senior` audit on PR #76 surfaced four items:

## A1. Trybuild fixture overclaim

The fixture at `mock/crates/hilavitkutin-api/tests/trybuild/double_derive_runcfg.rs` currently carries a docstring saying it "exercises the same shape" the eventual `#[derive(Resource)] + #[derive(RunCfg)]` combination will reject. The reviewer correctly flagged this as overclaim: two duplicate `impl BuilderInput for DoubleRole` blocks trigger E0119 for any trait, regardless of `Dispatch`-slot semantics. The trait solver rejects the second impl by impl-coherence alone before inspecting associated-type choice.

The fixture's actual value: it is a harness check that trybuild is wired correctly, and a placeholder for the real derive-macro fixture that lands when the derive macros ship. The docstring needs to say that honestly.

## A2. `ema_update` stub honesty

`pub fn ema_update(dst: &mut [Sample], src: &[Sample])` is a no-op stub. A consumer integrating against the providers crate today calls it and gets nothing back, silently. The public doc comment needs an explicit "stub pending Pass 7 wiring" note.

## A3. `ema_update` slice-length assertion

The signature accepts unequal-length slices silently. The lane-wise EMA formula implies pairing. A `debug_assert_eq!(dst.len(), src.len())` either catches the mistake in dev or documents the intent.

## A4. README pointer to MIRI.md

`MIRI.md` lives at the repo root rather than `mock/crates/hilavitkutin/MIRI.md` (the locked spec's path) because the mockspace doc-gate blocks new .md files inside `mock/`. Repo-root placement is greppable but not advertised in `README.md`. A one-line pointer in the contributor section helps developers find it.

## What this round does NOT do

- Does not reshape the trybuild fixture's substantive shape. The fixture's actual rejection target lands when the derive macros ship; this round only corrects the docstring overclaim.
- Does not split `Sample` into signed / unsigned variants. The reviewer's concern #2 is design-shaped (per-axis audit needed); deferred to a follow-up audit task.
- Does not wire the `ema_update` body. Still Pass-7-or-later work.
