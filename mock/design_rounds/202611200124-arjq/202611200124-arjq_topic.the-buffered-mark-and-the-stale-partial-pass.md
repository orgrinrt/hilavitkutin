# The buffered import's mark, the stale partial pass, and the fused refusal

**Date:** 2026-11-20
**Phase:** topic
**Scope:** `hilavitkutin` host path tests, the fused entry's design text, one `SAFETY` comment

The third review of the host path found that its tests do not see the change mark on a buffered store. `Raise` and `FirstWindow` write the store they read, so they rerun every frame whether or not an import marked it, and an import that copied onto both reservations without marking would pass them all. A unit that reads the buffered store and writes another one rests on a clean frame, and only the mark wakes it after an import, so the test belongs to that unit.

The same review ran the case the ticket `a_pass_that_skips_map_in_a_window_publishes_stale_records` reasons about. Under `Exchange`, a pass that maps every window and then a pass that maps the first window only leave the last record at its value from two passes back; under `Snapshot` it holds. The case is catalogued as a red test the moment it is found, ignored with the ticket named, on the `Exchange` arm, and the `Snapshot` arm pins that it holds there.

`tests/ui/buffered_unit_fused_fail.rs` pins that `run_fused` refuses a unit over a buffered column, and both the fixture and the last round's changelist call that the fused entry's shape. The design gives the three entries one meaning and does not say so, so the refusal is a gap, written down beside the accumulator gap with ticket `the_fused_entry_refuses_a_buffered_column`. The fixture gets its `_pass` twin over a plain column, as `tests/ui.rs` requires of every pair.

The rest are small: the `SAFETY` comment in `import` still says `&mut self` means no frame is in flight, which the parallel case falsifies, and three refusals are unpinned (an empty import past the count, a refused import into a buffered store, a buffered dump at an offset).
