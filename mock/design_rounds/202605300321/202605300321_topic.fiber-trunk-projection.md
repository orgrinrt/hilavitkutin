## Problem

After C1c the per-phase trunk skeletons carry `Phase.id`, `trunk_count`, and `Trunk.id`, but `Trunk.components` is empty. The runner discards the spectral grouping (`_clusters`) and runs `group_fibers` globally, feeding only step 8 (rank/dirty). Nothing populates the fiber components of a trunk, so the plan a dispatch pass would read has no fiber structure.

## Resolution: per-block fiber formation

A trunk is a block (a maximal weakly-connected component, column-disjoint). Fibers must nest within a trunk. The consolidated core-design epic (`202604200055/202603141800_topic.hilavitkutin-core-design.md`, lines 751-755) states the order plainly: identify trunks per phase first, then form fibers within each trunk. This rules out forming fibers globally and projecting afterward: the greedy `group_fibers` walks the global topo order and rolls a fiber on out-degree, not on block boundaries, so a global pass can place the tail of one block and the head of the next into a single fiber, breaking the nesting invariant. Spectral partitioning does not straddle (disconnected blocks have independent Fiedler vectors), but the former must work for both, so fibers are formed per-block.

This round (C1d-3a) lands the per-block projection structure with the greedy former:

- `group_fibers_in_block`: the greedy walk restricted to one block's units in topo order, emitting block-local FiberIds.
- `project_fiber_components`: for each phase, map block ids to per-phase trunk indices (the same dedup `phase_trunk_counts` does), run the per-block former, build `Fiber` records (id, units, unit_count), and emit them as `TrunkComponent::Fiber` into each trunk. The former-selection point is where C1d-3b adds the width-gate spectral branch; this round always picks greedy.
- `fiber_grouping_from_trunks`: reconstruct a global `FiberGrouping` from the populated trunks so steps 8 to 11 keep their interfaces.

`Fiber.columns`, `head_tail`, and `dispatch_approach` stay at defaults (column classification is step 11, head+tail and dispatch shape are C2). `TrunkComponent::Branch` / `Bridge` are not emitted (fan-out / fan-in detection needs post-column-classification analysis).

## Deferred to C1d-3b (follow-on round)

The width-gate's wide arm: select the spectral former for wide blocks (per the C1d-2 width-gate decision, threshold per DESIGN.md.tmpl ">5 fibers"), which requires bumping the arvo dependency past the live-node-count fix (`4cec32a`) and adding a one-line `SymmetricLaplacian::live_dim` override so the engine builds against the required trait method. The narrow/greedy arm shipped here is the common case and is design-equivalent to spectral for chains, so this slice is sound on its own; the spectral arm slots into the same former-selection point.
