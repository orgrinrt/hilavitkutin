# doc changelist

Round topic `202611200518-zrf9_topic.default-impls-behind-opt-in-features.md`, the only flat topic in `design_rounds/`.

## Changes proposed

### 1. The canon carries op's ruling

`mock/registry/tenet/memory-2.toml` gains two ratified rows quoting op's answer with the options it chose among (`mock/research/202611200520_default-impls-opt-in/OP-CALL.md`): `op_ruled_that_a_released_column_gives_its_block_back_and_the_providers_over_a_consumer_buffer_stay_in_the_providers_crate` and `op_ruled_that_every_default_implementation_sits_behind_an_opt_in_feature_on_its_own_crate_and_default_features_carry_the_contracts_only`.

Three rows the ruling makes wrong are superseded by held rows that say what holds now:

- `the_arena_column_storage_reserves_64_byte_aligned_blocks_through_the_memory_provider_and_its_release_is_a_no_op` (provisional) by `the_arena_column_storage_reserves_64_byte_aligned_blocks_through_the_memory_provider_and_a_release_gives_the_block_back_as_reserved`.
- `the_platform_has_three_tiers_no_os_os_and_std` (held, "os as the default") by `the_platform_has_two_tiers_no_os_and_os_and_a_build_on_default_features_is_the_no_os_tier`.
- `the_clock_is_a_builder_slot_provider_with_an_os_tier_default_and_a_null_clock_on_no_os` (provisional, "under the default feature") by `the_clock_is_a_builder_slot_provider_starting_at_the_os_clock_when_the_os_feature_is_on_and_at_a_null_clock_otherwise`.

### 2. The engine's os tier is a feature the consumer turns on

`mock/crates/hilavitkutin/DESIGN.md.tmpl`, "Platform implementations": the os tier is the `os` feature and is off by default. It carries `OsMemoryProvider`, `OsClock` and the operating-system arms of thread parking and thread classes. A build on default features is the no_os tier, contracts only, with parking spinning and the builder starting at the null clock. `platform-os` is renamed `os`; `platform-no-os` and the check that one of the two is on are removed, since the absence of `os` is the no_os tier. A short paragraph names the engine's features: `os`, and `intrinsics-std`, which is not an implementation and stays.

The same file, the pass-duration paragraph that says the clock slot is "defaulted to the os-tier clock": the slot starts at `OsClock` under `os` and at `NullClock` otherwise.

`mock/crates/hilavitkutin/README.md.tmpl`: one sentence naming the `os` feature and that a build without it is contracts only.

### 3. Every providers implementation sits behind a feature named for what it rests on

`mock/crates/hilavitkutin-providers/DESIGN.md.tmpl`: a section "Features" after the opening, with the table of the two features of this crate and what each carries. `static` rests on memory the consumer hands in, with no operating system: `StaticBumpMemory` and `StaticFreeListMemory`. `portable` rests on the contracts alone, on any target: `ArenaColumnStorage`, `MemoryArena` with `InternerApi`, `HasInterner`, `default_interner` and `InternerKit`, `AdaptWu` with the EMA helpers and the adapt kits, and the metrics resources with `MetricsKit`. The section says that the same name means the same principle in every crate, that `os` is the engine's, and that a build on default features carries no implementation. The surface table gains a column naming each item's feature. The opening paragraph and "What this crate deliberately does not ship" stop saying `platform-os` and name `os`.

`mock/crates/hilavitkutin-providers/README.md.tmpl`: names `static` and `portable` and what each carries, and the engine's `os` in place of `platform-os`.

### 4. The api names the features where it names the tiers

`mock/crates/hilavitkutin-api/DESIGN.md.tmpl`, "Platform traits", the sentence "The os tier ships an implementation of `MemoryProviderApi` and of `ClockApi`; the no_os tier ships neither": the os tier's implementations are behind the engine's `os` feature, and a build on default features is the no_os tier.

### 5. The consumer's dependency line

`mock/WORKFLOW.md.tmpl`, "Adding hilavitkutin to a project": the example drops `default-features = false`, which no longer turns anything off, and says that a consumer names `os`, `static` or `portable` on the crate that carries the implementation it wants.

## Not changed

`hilavitkutin-linking`'s operating-system loader is that crate's own subject, not a default implementation of a contract, and the crate is overhauled by the port lane `work/port-seam-and-loader`. `the_no_os_tier_is_trait_contracts_only_and_the_consumer_provides_every_platform_implementation` stays: a build on default features is that tier. `each_platform_tier_ships_defaults_and_the_consumer_overrides_them_through_the_scheduler_builder` stays: a tier still ships its implementations, behind a feature. The release text in the providers design already says release frees (round 202611200201-yszg) and is unchanged.
