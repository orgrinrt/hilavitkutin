# Doc changelist: a pragma reaches rustc through the crate's own build script

**Date:** 2026-11-13
**Phase:** DOC
**Topic:** `202611131717_topic.every-crate-builds-through-hilavitkutin-build.md`

The design of `hilavitkutin-build` keeps its four-part model and its pragma table. What changes is how
a pragma's flags reach rustc, the flags that the pinned toolchain no longer takes, the profile names
cargo actually passes, and the always-on native target. The backlog gains the items the round leaves
for later and loses the consumer migration it does.

## Current state

The design has `configure().run()` generate a wrapper into `target/hilavitkutin-build/` that infers the
tier from `-C opt-level` in rustc's arguments, and lists `-enable-unsafe-fp-math` under FastMath,
`-vectorize-with-block-frequency` under Pgo and `-C target-cpu=native` as always on. Its Dependencies
section says the crate has none. The backlog holds the wrapper as future work and the consumer
`build.rs` migration as a separate infra round.

## Changes proposed

## CHANGE: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl`, entry point

The entry point is `configure`, with `configure_with` for a crate that tunes its pragma set. Both take
a closure that reads one environment variable and the writer the directives go to, so the crate reads
nothing itself and stays `no_std`. The build script is three lines.

## CHANGE: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl`, part 3 of the model

The wrapper is a fixed POSIX shell script committed by the consumer at
`.cargo/hilavitkutin-rustc-wrapper`, named by `.cargo/config.toml` as `build.rustc-workspace-wrapper`.
It appends `$HILAVITKUTIN_BUILD_RUSTFLAGS` to rustc's arguments. A crate's build script sets that
variable for the crate's own rustc with `cargo::rustc-env`, so the flags are per crate and the tier is
the profile the script was told, never parsed back from arguments. The text is `write_wrapper`'s, and
the consumer's copy is checked against it.

## CHANGE: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl`, cfg emission

FastMath also writes `cargo::rustc-check-cfg=cfg(arvo_fast_math)`, so a crate reading the cfg is not
warned about it.

## CHANGE: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl`, flag ownership

FastMath owns no LLVM flag: the global unsafe-fp-math option is gone from LLVM, and fast float math is
per operation, selected by the cfg. Pgo's block-frequency flag is `-loop-vectorize-with-block-frequency`.
LoopOptimization's plugin flag is written only once the build script finds the plugin. The always-on
`-C target-cpu=native` is removed. A table says which pragmas write flags today and which wait on a
tool or a profile the build script does not yet find.

## CHANGE: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl`, profiles

Cargo passes `PROFILE` as `debug` or `release`. `debug` resolves to `Dev` and `release` to `Release`.
The custom profiles in the table stay design: cargo does not tell a build script which of them it
builds, and recognising them is a backlog item.

## CHANGE: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl`, dependencies

The crate depends on `notko` only, for `Maybe`.

## CHANGE: `mock/crates/hilavitkutin-build/BACKLOG.md.tmpl`

The wrapper generation item and the consumer migration item go: the round does both. New items: the
native target CPU as an opt-in pragma, the custom profiles, finding the plugins and profiles so their
pragmas write flags, and the real schema of the config file stays.
