# Rename the resource arena to resource bindings

The `resource::arena` module, its `Arena*` types, and the scheduler's `arena`
field date from before PR #114, when the resource data plane really was a
bespoke arena: the scheduler held a `MemoryProviderApi` directly and a
`DropArena` trait freed it. PR #114 removed that. The module is now a
type-keyed cons-list of resolved `ResourcePtr` / `ColumnPtr` witnesses into
the unified `ColumnStorage`: it allocates nothing, holds only `Copy` pointers,
and the store owns and frees the bytes on its own `Drop`. The drain reserves
each resource as a one-record column through `cs.reserve`, the `ColumnStorage`
contract.

The "arena" name now misleads. A reader sees `resource::arena` /
`ArenaResourceNode` / `Scheduler::arena` and reasonably infers a surviving
bespoke allocator, which is exactly the shape the unified-storage arc
(#654) exists to retire. The name is a leftover from the pre-#114 design, not
a description of what the code does.

This round renames the resource data-plane index to "bindings": each
registered store value is bound to its resolved location in the one
`ColumnStorage`. The mapping:

- module `resource::arena` -> `resource::bindings`
- `ArenaResourceNode<T, Tail>` -> `ResourceBinding<T, Tail>`
- `ArenaColumnNode<T, Tail>` -> `ColumnBinding<T, Tail>`
- `ArenaVirtualNode<T, Tail>` -> `VirtualBinding<T, Tail>`
- `ArenaTail` -> `BindingNil` (matching the `PtrNil` / `ColPtrNil` / `WuNil` nil idiom)
- trait `ArenaFor` / `type Arena` -> `BindingsFor` / `type Bindings`
- `Scheduler::arena` field -> `bindings`; `__arena()` accessor -> `__bindings()`
- test file `tests/resource_arena.rs` -> `tests/resource_bindings.rs`

## Scope boundary

Three other things wear the word "arena" and are NOT touched, because they are
different concepts that legitimately use it:

- `ArenaColumnStorage` (in `hilavitkutin-providers`): the one canonical
  `ColumnStorage` implementation, arena-style slot allocation over a
  `MemoryProvider`. This is the unified store the arc mandates, not a bespoke
  per-subsystem arena.
- The morsel / progress scratch arena (`dispatch::progress`, `morsel`, the
  `'arena` lifetimes on `PoolFrame`, the RCM "arena-layout renumber"): a
  genuine plan-stage scratch region, not the resource data plane.
- `AdaptArena` (`adapt::arena`): a never-constructed `PhantomData` stub in a
  different subsystem, named when that subsystem is built.

This is a pure rename: no behaviour changes, no signatures change shape, the
existing test suite stays green throughout (the REFACTOR step under green
tests).
