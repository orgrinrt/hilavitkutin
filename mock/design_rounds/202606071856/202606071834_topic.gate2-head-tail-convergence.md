# Topic: GATE-2 head+tail convergence for single-trunk phases (deviation §8, slice 1)

**Date:** 2026-06-07
**Phase:** TOPIC
**Scope:** `hilavitkutin` (`dispatch/core_mask.rs` or a new convergence helper, `scheduler/mod.rs` `run_core_phase` / `worker_main`), engine tests
**Source:** consolidation spec domain 20 / Topic 6 (`:768-800`, `:1601-1611`, `:1750-1766`), deviation ledger `202606072100` §8; builds on §4 (the worker-side waist barrier, round 202606071808).

## Current state

`run_parallel` (R4c + §4) parallelises at the TRUNK level: per waist-bounded phase, `core_phase_mask` hands each core the trunks it owns (round-robin by within-phase trunk rank), and each core walks its owned trunks over the FULL record range morsel-by-morsel. A phase with fewer trunks than cores leaves the surplus cores idle for that phase. The worst case is a single-trunk phase (a serial waist section, or a fan-in): one core does all the work, the other N-1 idle until the next waist. The spec calls this the serial bottleneck phase.

## Canonical position

Spec `:770`: "Single-trunk phases: head+tail convergence (2 threads, opposite ends, ~2x parallelism)." `:1601-1611`: each core's compiled program carries "which record ranges (head half or tail half for convergence)" baked in. Bench (`:799`): trunk-parallelism alone is 0.82-0.89x vs sequential; adding convergence reaches 0.68x, halving the serial bottleneck phase. So convergence is the larger win and the canonical answer to underutilised phases.

The discipline (`:1750-1766`, domain 08): head+tail is sound for record-independent / commutative work. A fiber that accumulates into a resource non-commutatively must NOT be split (the two halves would merge out of order); those phases skip convergence. Commutative accumulation splits, each convergence thread gets its own stack-local accumulator, merged after.

## Change proposed (slice 1: record-range head+tail for underutilised phases)

When a waist-bounded phase has fewer owned trunks than available cores, assign the surplus cores to split the record range of the phase's trunk(s), so all cores do useful work in that phase.

1. **Per-(core, phase) record range.** Extend the per-core phase dispatch so a core receives not just its trunk mask but a record sub-range `[lo, hi)` for the convergence case. The single-trunk case: `ncores` cores each take an equal slice of `[0, n)` for the one trunk; `run_gated`'s morsel walk covers only `[lo, hi)`. Multi-trunk-but-underutilised cases (trunks < cores) assign leftover cores to the heaviest trunk's range (priority order per `:776`: convergence -> branches -> bridges).

2. **`run_core_phase` takes the sub-range.** Today it walks morsels over `total`; add `lo`/`hi` so a convergence core walks only its half. The existing morsel loop already windows; this bounds its start/end.

3. **Convergence-skip for non-commutative accumulators.** A phase whose trunk writes an accumulator that is not commutative (the `COMMUTATIVE` WU hint, domain 08) does NOT split: it stays single-core (correctness over the ~2x). The mask/range assignment checks the phase's accumulator commutativity and falls back to whole-range-on-one-core. (Slice 1 may conservatively skip ALL accumulator-bearing phases and handle the commutative-merge path in a later slice; decide at SRC time from what the carrier exposes.)

4. **Worker-side barrier unchanged.** Convergence threads still hit the same `waist_barrier(ncores)` at the phase end (every core participates), so §4 composes directly: more cores now do work within the phase, then all converge at the waist.

## Tests

- A single-trunk-phase fixture (one heavy producer in its own phase, N records) dispatched via `run_parallel` on >1 core: assert every record correct (the head and tail halves each wrote their range, no gap, no overlap). A broken range split shows as an unwritten or double-written record (poison the column first).
- A two-phase fixture where phase 1 is single-trunk (a fan-in) exercises convergence on the bottleneck phase plus the §4 barrier.
- Non-commutative accumulator phase: assert it stays correct (single-core fallback), i.e. the accumulator result is not corrupted by an illegal split.
- Existing `gate2_run_parallel` + full suite stay green.

## Out of scope (later §8 slices)

Pipeline parallelism (phase N+1 overlapping phase N via `progress_slots` AtomicUsize progress counters, `:772-774`) is the next slice and the reason `PoolFrame.progress_slots` exists; it needs producer/consumer fiber sync across the waist and is more involved. Commutative-accumulator convergence-merge (per-thread stack-local accumulator merged after, `:1756-1760`) is its own slice if slice 1 conservatively skips accumulator phases. Core-pinning warm-L1 trunk assignment (`:775`) is orthogonal. The compiled per-core program (deviation §1) is the separate big escalation.
