## CHANGE: `run_fused` resets the accumulators
Files: `mock/crates/hilavitkutin/src/scheduler/run_fused.rs`, `tests/fused_append.rs`.
`run_fused` takes `ResetAccumulators` beside `FirstRefusal` and calls `reset_accumulators()` at frame start, as `run` does, so the doc on `ResetAccumulators` ("every run entry calls this at frame start") is true. `fused_append.rs` gains `MapAndLogTwiceWu` and `run_fused_after_a_refusing_run_returns_ok`: a refusing `run`, then `run_fused`, returns `Ok` with a live length of zero.
Verification: `grep -n "reset_accumulators" mock/crates/hilavitkutin/src/scheduler/run*.rs` names all three entries.

## CHANGE: the regions start after the leading records (ticket `521dedc08497`)
Files: `mock/crates/hilavitkutin/src/resource/bindings/per_core.rs`, `src/scheduler/run_parallel.rs`, `tests/leading_band_appends.rs` (new), `tests/gate2_parallel_meta.rs`.
A `const fn region_start(leading, lo, cap)` gives `min(leading + lo, cap)`, and both walks use it. `RebaseBindings` offsets each accumulator to that start, reading the shared binding's `len`, and clips the region cap to the room left. `MergeAccums` starts its cursor at the shared `len`, copies each region from its start, sets `len` to the cursor and `wanted` to the cursor plus every refused append, both sums saturating. `leading_band_appends.rs` has a leading band append `K` records and a consumer one marker per core, on 1, 2, 4 and `MAX_CORES` workers over two frames: with room the run returns `Ok` and keeps `[7; K]` then the markers; with `K` equal to the reservation every marker is refused and the run returns `AccumRefused(0, Exhausted { wanted: K + markers, had: K })`. `gate2_parallel_meta.rs` drops its note that a leading-band append is unsupported.
Verification: `grep -n "region_start" mock/crates/hilavitkutin/src/resource/bindings/per_core.rs` shows the helper and its two uses.

## CHANGE: the mutant feature is fenced
Files: `mock/crates/hilavitkutin/src/lib.rs`, `Cargo.toml`.
With `mutant-truncating-append` on, a `const` assert refuses the build unless `HILAVITKUTIN_MUTANT_CHECK` is set at compile time, so a dependent's feature unification cannot turn it on silently. The mutant check is `HILAVITKUTIN_MUTANT_CHECK=1 cargo test -p hilavitkutin --features mutant-truncating-append --test overflow_is_a_value`.
Verification: the feature without the variable fails to build with the assert's message.
