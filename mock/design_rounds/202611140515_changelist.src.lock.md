# src changelist

Round topic `202611140512_topic.sound-memory-provider.md`; the doc changelist `202611140513_changelist.doc.lock.md` states the design. The flat topic `202607200100_topic.b1-cap-lifting-completion.md` needs nothing from this round, as the doc changelist says.

## Current state

`crates/hilavitkutin-api/src/platform.rs:28` declares `pub trait MemoryProviderApi`, a safe trait. Every implementation is a plain `impl`: `OsMemoryProvider` (which ignores `align`), `NullMemoryProvider`, thirty-one inline-buffer `BumpProvider`s and one `TestProvider` and one `CountingProvider` under `crates/hilavitkutin/tests`, `tests/stable_provider/mod.rs` (a leaked buffer, a `Cell` cursor behind `unsafe impl Sync`), a copy in each of eleven trybuild fixtures, `BumpMemory` and `StubMemory` in the persistence tests, `BumpProvider` and `RecordingProvider` in the providers tests, and an owning heap provider in each of four bench crates (offset-aligned over a `Box` whose alignment is one, `Cell` cursor). `hilavitkutin-providers` ships no memory provider. Under Miri `tests/resource_snapshot.rs` reads freed memory (`mock/research/202611140512_sound-memory-provider/miri-resource-snapshot-before.txt`).

## Changes proposed

### 1. The trait is unsafe

`pub unsafe trait MemoryProviderApi`, with a `# Safety` section on the trait stating the four promises from the api design, null as refusal, and the method sections as the caller's half. A plain `impl` is refused with E0200: `tests/ui/memory_provider_safe_impl_fail.rs` with its `.stderr`, driven from `tests/ui.rs`. Before the change the fixture compiles, so the compile-fail case fails (`mock/research/202611140512_sound-memory-provider/ui-safe-impl-before.txt`).

### 2. `StaticBumpMemory` in `hilavitkutin-providers`

`src/memory.rs`, exported from the crate root. `const fn new(&'static mut [MaybeUninit<u8>])`, `used`, `capacity`, and an `unsafe impl MemoryProviderApi` whose comment argues the four promises. `allocate` aligns the address, refuses a non-power-of-two `align`, a length that overflows and a block past the end, each with null and the cursor unmoved, and places a block by `compare_exchange_weak` on the cursor. `tests/static_bump_memory.rs` holds it to that: address alignment over a buffer three bytes off a boundary, disjoint blocks inside the buffer, the refusals leaving the cursor, eight threads getting disjoint blocks, and a block that keeps its value and place when the provider moves into a box. The alignment and overlap checks are each shown seeing the break they are for.

### 3. The engine's providers

`OsMemoryProvider` is an `unsafe impl`, refuses an `align` that is not a power of two or is wider than `sysconf(_SC_PAGESIZE)`, and says how each mapping keeps the promises. `tests/platform_os.rs` gains `os_memory_refuses_an_alignment_a_mapping_cannot_meet`: twice the page, three and zero are refused, a page-wide alignment is met. The old `allocate` named its alignment `_align` and returned the mapping for any of them, so the test fails against it by reading. `NullMemoryProvider` is an `unsafe impl` whose comment says it refuses everything.

### 4. Every test provider is `StaticBumpMemory`

`tests/stable_provider/mod.rs` becomes `stable_provider(cap, byte)`, a `StaticBumpMemory` over a leaked buffer of `cap` copies of `byte`, and re-exports the type. The thirty-one inline `BumpProvider`s and `scheduler_builder.rs`'s `TestProvider` go, their tests building through `stable_provider`; `resource_bindings.rs`'s `CountingProvider` wraps one and is an `unsafe impl` forwarding to it. The callers of the old `StableProvider::new` call `stable_provider`, `hilavitkutin-frozen-authors/tests/common/mod.rs` among them (it includes the module by path). The imports the inline providers needed go, along with the stale unused imports `cargo fix` removed beside them in the same files.

The eleven fixtures that carried a copy build `StaticBumpMemory::new` over a leaked buffer of the same size; the five `_fail.stderr` files change in their line numbers and gutter width only. The persistence tests take `hilavitkutin-providers` as a dev-dependency and `cold_store.rs` maps into a `StaticBumpMemory`; `context.rs`'s `StubMemory` is an `unsafe impl` that refuses everything. In the providers tests `column_storage.rs` builds on `StaticBumpMemory`, and `RecordingProvider` is an `unsafe impl` forwarding to it.

### 5. The bench providers

The four bench crates build schedulers per size, so a leaked buffer would grow with every sample. Each keeps its own owning provider (`HeapBump` in `engine_vs_std`, `variants/rcm_common` and `frame_wide/support/frame-wide-support`, `TestProvider` in `resource_storage/axis_ce`), now a `StaticBumpMemory` over a heap block the provider frees in `drop`, with an `unsafe impl` forwarding to it. That they are four copies is ticket `1cc7966457f2`. `axis_ce` does not build before or after the change, for two notko sources in its graph, ticket `d08e3f77ee5e`.

### 6. Left as recorded

The sketches under `mock/research/sketches/` each define their own provider. They are spikes in their own workspaces, run at the commit they were written at, and stay as they ran.
