# Topic: hilavitkutin-api Executor sealed private_bounds allow

**Date:** 2026-06-19
**Crate:** hilavitkutin-api
**Tracked:** #686 (api feature-gate + warning drift cleanup), final slice

## Problem

`platform.rs:322` declares `pub trait Executor: crate::sealed::Sealed`, where
`sealed::Sealed` is intentionally `pub(crate)` (the seal: only the crate's own
types may implement `Executor`). rustc's `private_bounds` lint warns that the
private supertrait is "more private than" the public `Executor`. This is the
designed sealed-trait shape, not a real leak: external crates cannot name or
implement `Sealed`, which is the point.

## Change

Add `#[allow(private_bounds)]` to the `Executor` trait declaration with a comment
naming the sealed-trait rationale. Idiomatic suppression for the sealed pattern;
clears the last hilavitkutin-api warning, completing #686.
