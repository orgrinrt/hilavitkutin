# Src changelist: accumulator columns (append surface through dispatch)

**Date:** 2026-06-04
**Phase:** SRC
**Round:** 202606041800 (accumulator-columns, branch `feat/hilavitkutin-accumulator-columns`)

Adds the accumulator store kind: columns written by APPEND during the frame, growing from zero toward a capacity. Mirrors the landed input-column machinery (a distinct marker, binding arm, selector, projection, accessor), with two differences the de-risk sketch validated: the live-length advances under `&self` via a `Cell<USize>` (interior mutability), and the accumulator projection retains a `'frame` borrow of the bindings (the live-length cell), so it projects from the `'frame`-tied `bindings` source via a GAT projection trait. Design locked by the round sketch (`mock/research/sketches/202606041800_accumulator-append-selector/`, verdict WORKS) plus a neutral `feature-dev:code-architect` read (agent ac4b8a73015e46b8d), which converged on all four design forks (A1 distinct marker, B `Cell` live-length, C fourth bundle + GAT projection from the `'frame` source, D reserve to `record_count`).

TDD red-first: a WorkUnit appends K values to an `Accum<T>` during `execute`; a hidden accessor (or a consumer WorkUnit) reads the buffer back and asserts the K values landed at `[0, K)` in append order with live-length K. Red precedes green: an appending WorkUnit cannot satisfy the dispatch bound before the accumulator bundle is projected, and reads a dangling placeholder before the drain reserves a real buffer.

## CHANGE: add `AccumBinding<T, Tail>` + `BindingsFor` / `DrainStores` arms
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
`AccumBinding<T, Tail>` holds `pub(crate) ptr: ColumnPtr<T>`, `pub(crate) len: core::cell::Cell<USize>`, `pub(crate) tail: Tail`, with hidden accessors `__ptr()` / `__len_cell()` (returns `&Cell<USize>`) / `__tail()`. New `BindingsFor` arm: `Sv<Accum<T>, L>` maps to `AccumBinding<T, <L as BindingsFor>::Bindings>`. New `DrainStores` arm (bound `T: ColumnValue`): reserve `record_count` records at a continued `StoreId` (advancing `next_id`), record the real `column_ptr_mut::<T>(id)` and a `Cell::new(USize::ZERO)` live-length, with the same zero-record/ZST dangling-pointer fallback as the `Column<T>` arm.
Verification: `grep "pub struct AccumBinding" mock/crates/hilavitkutin/src/resource/bindings.rs` and `grep "impl<T: ColumnValue, L> DrainStores for Sv<Accum<T>, L>"` each return one match.

## CHANGE: add `AccumSelector` + `AccumProject` GAT + `Selector`/`ColSelector`/`AccumSelector` pass-through over `AccumBinding`
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`
`AccumSelector<T, Index>` yielding an `AccumColPtr<T>` projected node (`{ base: ColumnPtr<T>, len: &'frame Cell<USize> }`, `Copy`): `Here` on `AccumBinding<T>`, `There<I>` pass-through on all node kinds; add `AccumSelector` `There` pass-through across `ResourceBinding` / `ColumnBinding` / `VirtualBinding`, and add `Selector` / `ColSelector` `There` pass-through over the new `AccumBinding` node. `AccumProject<'s, Set, Indices>` is a lifetime-parameterized trait with a plain `type Out` (not a GAT) mirroring `ColProject`, recursing the `Accum<T>` members of the set, projecting via `&'s self`. The de-risk sketch used a GAT `type Out<'s>` because its `project_all` was a free function naming `Out<'f>` directly; the shipped form carries the lifetime at the trait so the `project` method can tie `Out = WAccum` to the Context's accumulator parameter (a GAT cannot be equality-bound in the method where-clause). The `Project` / `ColProject` projections gain an `Accum<T>` head pass-through (skip, no node) so a Write set containing `Accum<T>` projects cleanly for resources and columns. A new projected-bundle pair (`AccPtrCons` / `AccPtrNil`) and `AccumSelector` over it.
Verification: `grep "trait AccumSelector" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` and `grep "trait AccumProject"` each return one match.

## CHANGE: `CollectFiber` / `fiber_shim` project the accumulator bundle
File: `mock/crates/hilavitkutin/src/dispatch/fiber_codegen.rs`
`fiber_shim` gains a `WAIdx` type param and an `A: AccumProject<W::Write, WAIdx>` bound; the `EngineCtx::project` call passes the bindings as the accumulator source and threads `WAIdx`. The `CollectFiber` per-unit witness element extends from the triple `(RIdx, RCIdx, WCIdx)` to the quad `(RIdx, RCIdx, WCIdx, WAIdx)`; a WorkUnit with no accumulators in its Write set infers an empty accumulator bundle (`AccPtrNil`) and dispatches unchanged.
Verification: `grep "A: AccumProject" mock/crates/hilavitkutin/src/dispatch/fiber_codegen.rs` returns matches in `fiber_shim` and `CollectFiber`.

## Tests

New `tests/accum_dispatch.rs`: a WorkUnit declares `Accum<Av>` in its Write set and appends N values during `execute`; the scheduler builds with a record count covering N, runs, and the test reads the accumulator buffer back (via the binding's hidden accessor or a consumer WorkUnit reading the populated prefix) to assert the N values landed at `[0, N)` in append order and the live-length equals N. Existing column/resource tests stay green (an accumulator-free Write set projects an empty `AccPtrNil` bundle, so the lifted bound is backward compatible); the resource-only `build` call sites are unaffected.
