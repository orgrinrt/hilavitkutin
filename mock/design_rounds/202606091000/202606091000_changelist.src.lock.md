# Src changelist: RunFiber whole-program dispatch, delete the FiberSlot path

## Summary

Replace `Scheduler::run`'s type-erased `FiberSlot` dispatch with the type-level `RunFiber` recursion over the retained `WuVals` carrier, driven whole-program (spec Approach E). Lands in two commits: D1e-a adds `RunFiber` and switches `run` (the erased shim stays defined and untouched, gated by an objdump-zero-`blr` check on the real engine `run`), D1e-b deletes the `fiber_codegen` shim. Execution order and results are unchanged for every existing test; only the dispatch mechanism changes, from a `topo_order`-indexed fn-pointer call to a monomorphised straight-line walk.

## CHANGE: trait `RunFiber` ADDED
File: `mock/crates/hilavitkutin/src/dispatch/fiber_run.rs`
Detail: new module `dispatch::fiber_run` holding `pub trait RunFiber<A, Witnesses> { fn run(&self, bindings: &A, morsel: MorselRange); }`, the named sibling of `CollectFiber`. Impl for `WuNil` (`Empty` witnesses, no-op) and for `WuCons<W, Tail>` over `Cons<(RIdx, RCIdx, WCIdx, WAIdx), WTail>` with the same bounds `CollectFiber` carries (`Project` / `ColProject` over Read and Write / `AccumProject`, and the `Ctx<'f> = EngineCtx<...>` GAT tie). The `WuCons` impl projects the head unit's `EngineCtx` via `EngineCtx::project::<A, A, RIdx, RCIdx, WCIdx, WAIdx>`, runs it through `invoke_wu_in_fiber`, and recurses on the tail. Each `execute` is a statically-known monomorphised call: no stored function pointer, so the walk devirtualises under fat LTO (proven 202606081200). Registered as `pub mod fiber_run;` in `dispatch/mod.rs` and re-exported alongside the other dispatch surface.
Verification: `grep "pub trait RunFiber" mock/crates/hilavitkutin/src/dispatch/fiber_run.rs` returns one match; `grep "pub mod fiber_run" mock/crates/hilavitkutin/src/dispatch/mod.rs` returns one match.

## CHANGE: fn `Scheduler::run` SWITCHED from `CollectFiber` to `RunFiber` dispatch
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Detail: the `where` bound changes from `WuVals: CollectFiber<<Vals as BindingsFor>::Bindings, Witnesses>` to `WuVals: RunFiber<<Vals as BindingsFor>::Bindings, Witnesses>`. The body drops the `FiberSlot` placeholder array, the `self.wu_values.collect(...)` call, and the `topo_order` / `fiber_dispatch`-indexed `live[order[k].0]` walk. It computes one whole-carrier drive decision: `unit_outer` is true if any plan fiber descriptor is non-morsel-local (an accumulator-bearing fiber) or the record count is zero. When `unit_outer`, it drives one full-range walk `self.wu_values.run(&self.bindings, MorselRange::new(USize::ZERO, USize(total)))`; otherwise it wraps the whole-carrier walk in the runtime morsel loop (`morsel` of `Cfg::MORSEL_SIZE`, guarded to at least one record). Returns `Cfg::Out::default()` as before. The `Witnesses` parameter and the turbofish-free `scheduler.run()` call shape are unchanged (the `RunFiber` impls infer the same per-unit witness quad). The `topo_order` / `topo_count` fields are retained on the scheduler (plan data, read by `dispatch::order` and used by the future per-phase nesting) via the existing `let _ = ...;` idiom; `fiber_dispatch` is still read for the `morsel_local` bits.
Verification: `grep "WuVals: RunFiber<" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match; `! grep -n "wu_values.collect\|FiberSlot<.*Bindings>" mock/crates/hilavitkutin/src/scheduler/mod.rs` (the erased-slot materialisation is gone from `run`).

## D1e-a gating proof (objdump, recorded 2026-06-09): PASS, zero `blr`

The monomorphised `Scheduler::run` in a release build of the `column_dispatch` integration test (`mock/target/release/deps/column_dispatch-*`) disassembles to a 180-instruction body with **zero `blr`** (zero indirect calls); the only two `bl` are direct calls to the monomorphised `column_dispatch` WU `execute` methods (statically-known addresses, inlined further under fat LTO). This is the devirtualisation contract: no unit dispatches through a stored function pointer. Contrast the pre-D1e `run`, whose body carried three `blr` from the `live[order[k].0]` `FiberSlot` indexed fn-pointer dispatch (the spec fail mode); D1e eliminated all three.

The objdump was taken from a release engine test binary rather than the `engine_vs_std` bench: the bench's standalone Cargo.lock resolves a newer arvo whose `waist_detect` is one-generic (`C: Capacity`), while the engine still calls it two-generic at `plan/steps.rs:313` (`waist_detect::<D::Units, Bits<64, Hot, Unsigned>>`). That is the pre-existing #668 transitive drift (lift the engine 64-node cap onto the widened arvo graph API), not a D1e regression; the engine's own mock workspace pins the matching arvo and builds clean. The `bl`-not-`blr` criterion is profile-independent (the type-level walk has no fn pointers, so calls are direct regardless of LTO), so the engine-test binary is a sound gate.
