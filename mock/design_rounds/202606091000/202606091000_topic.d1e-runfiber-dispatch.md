# D1e: RunFiber whole-program dispatch replaces the erased FiberSlot path

## What this round does

`Scheduler::run` currently dispatches through a type-erased slot array: it materialises one `FiberSlot` (an erased instance pointer plus a per-unit shim fn-pointer) per retained WorkUnit via the `CollectFiber` walk, then iterates the plan's `topo_order` permutation, calling `live[order[k].0]` per dispatch position. That indexed fn-pointer dispatch does not devirtualise: an indirect call (`blr`) survives per unit under the runtime morsel loop (measured at 2 `blr` in sketch 202606080300, the spec's named fail mode).

This round replaces the dispatch source with the type-level `RunFiber` recursion over the retained `WuVals` carrier in carrier (registration) order, driven whole-program (spec Approach E, the flat schedule-mega body). Each `head.execute()` is a statically-known monomorphised call, so the whole walk devirtualises (zero `blr`, proven under a real runtime morsel loop by sketch 202606081200, where the same workload also auto-vectorised). The erased-slot machinery is then deleted.

This is a source-to-design alignment, not a design change. `DESIGN.md.tmpl` already states the target: the sequential walk that constructs each unit's `EngineCtx` and runs `execute` "is `RunFiber`" (line 130), and "There is no type-erased per-unit dispatch slot: the column-capable walk is the only dispatch path" (lines 155-157). The shipped `CollectFiber` / `FiberSlot` source is the C2 slice-3 scaffold that drifted ahead of the doc; this round retires it so source finally matches the contract.

## Why carrier order is a valid dispatch order

D1d (shipped, round 202606061830 and predecessors) made registration order equal carrier (`WuVals`) type order via builder append, and `build()` rejects any registration whose carrier order would run a consumer before its producer (`BuildError::NonTopologicalRegistration`, naming the RCM-recommended order). So walking the carrier in its own type order is, by construction, a valid topological dispatch order. The static walk follows that order directly; no runtime permutation indirection is needed. This is the carrier-order-is-dispatch-order rationale the D1d round and the `build_rejects_anti_topological_registration` test already document.

For the three GATE-1 benches (element_wise S1 to S4, branching, accumulator) the carrier is a single fiber and the registration order is the unique topological order, which coincides with the RCM-reordered order; so the carrier walk dispatches in cache-optimal order for those workloads without any further machinery. Auto-application of a freshly-computed RCM order for non-linear DAGs (the const-position-guarded walk proven in sketch 202606090300) is the near-term follow-on per roadmap r2 op-decision (a); the manual-registration order validated by D1d is the provisional interim per op-decision (b).

## Drive shape

The locked morsel-outer / unit-outer distinction (202606051500) carries over to the flat walk as one whole-carrier decision: a carrier that writes no accumulator runs morsel-outer (the runtime morsel loop wraps the whole-carrier walk, intermediate columns stay cache-resident per morsel); a carrier bearing an accumulator runs unit-outer (one full-range walk, the cross-record-safe append path), which is also the record-less-frame path (each unit runs once over an empty morsel). The decision reads the per-fiber `morsel_local` bits the plan already computed (any non-morsel-local fiber selects unit-outer for the flat Approach E body). The per-fiber and per-phase nesting (Approach A, the sub-10K path, and the PhaseCons sub-carrier multi-phase shape proven by sketch 202606081600) is the post-GATE-1 refinement, not part of this round.
