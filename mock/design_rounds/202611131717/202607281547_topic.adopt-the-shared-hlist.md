# Topic: adopt the shared hlist

**Date:** 2026-07-28
**Phase:** TOPIC
**Scope:** replacing the local cons-list substrate with the shared crate. A substrate switch, not a
design change. No work scheduled.
**Origin:** arvo's design round, `202607281220_topic.the-ndim-and-shape-design.md`, D5 through D9.

## What changed upstream

The heterogeneous type-level list has been reinvented three times in this workspace. arvo was about to
make it a fourth, for its shape system, and instead the pattern is being extracted once into a new
crate in the notko repository, **`notko-hlist`**.

The duplication, with citations:

- `hilavitkutin/mock/crates/hilavitkutin-api/src/access.rs:50` declares `pub struct Empty;` and
  `pub struct Cons<H, T>(core::marker::PhantomData<(H, T)>);`
- `kolli/mock/crates/kolli-api/src/lib.rs:143` declares the same two, byte-identical.

## hilavitkutin is the donor as much as the adopter

This repository's version is the richest of the three, and it is what the shared crate is modelled on.
What travels upstream:

| Here today | In the shared crate |
|---|---|
| `Empty`, `Cons<H, T>` | the same, generic |
| `AccessSet` with `const LEN: USize` | `Length<N: Cardinal>`, with the count parameterised |
| `Contains<S>`, `#[marker]`, head match plus recursive tail match | the same |
| `ContainsAll<L>`, `#[marker]`, base plus recursive | the same |
| `Concat<L>` with `type Out` | the same |
| The `#[diagnostic::on_unimplemented]` messages | kept, generalised |

The diagnostics are worth naming as part of what transfers. The `recursion_limit = "1024"` hint and
the "register it with `.add_resource::<T>`" note are what make a failed bound survivable, and a
generic extraction that dropped them would be a regression however clean the types were.

## What changes here

**`AccessSet` keeps its name and its meaning, and stops declaring the list.** The count stays `USize`,
supplied by implementing the shared `Cardinal` property for it, which is legal because `USize` is
arvo's local type where the trait is notko's.

**The cell and the leaf get domain aliases**, so the generic names appear at the definition and
essentially nowhere else:

```rust
type Access<H, T> = Cons<H, T>;
type Deny         = Empty;
```

`Deny` is op's sketch and is not settled: the leaf means "the access list ends here", so whatever best
names "and nothing further is reachable" wins. That naming is this repository's call when it adopts.

The `read![T0, T1]` and `write![T0, T1]` macros expand to the same nested chain and are unaffected
beyond the type they name.

## Why this is minor

Nothing about the access-set semantics moves. `Contains`, `ContainsAll` and `Concat` keep their
meanings, the proof shapes that `.build()` carries are unchanged, and the scheduler's disjointness
reasoning is untouched. What changes is where three type declarations live and what two of them are
called locally.

The one real cost is a new dependency edge from `hilavitkutin-api` to `notko-hlist`, which is cheap:
the crate is `no_std`, allocation-free, and structural, with no numerics in it at all.

## Status

Named, not scheduled. It follows the extraction landing in notko, which follows arvo's round settling.
