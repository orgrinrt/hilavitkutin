# Topic: the origin mechanism round one described and did not build

**Phase:** TOPIC
**Scope:** `hilavitkutin-sym`. Builds the mechanism the previous round's design
document and source changelist both specify.

## Why this round exists

Round `202608082215` closed having landed the shape vocabulary, the rename of
`Generator::new` to `Generator::single`, and a documented freshness contract. Its
design document and its **locked** source changelist both go further and describe
an origin mechanism: that a generator is built for an origin, that origins
partition the counter space, that a generator under a multi-origin shape cannot
be constructed without naming which minter it is.

**None of that was built.** `single()` was token-for-token the previous `new()`:
the same zero seed, the same step, no origin field, no origin constructor. A
reviewer found it, and it holds: the round shipped under `fix:` and fixed
nothing. Two generators still emitted bit-identical handles that compared equal.

Three further consequences of the same gap, all confirmed:

- The design tier specified a mechanism the code did not have, with no `FIXME`
  marking the gap, which inverts the rule that design governs code.
- Three `CHANGE:` blocks in the locked changelist failed their own stated
  verification. `grep "type Shape" src/domain.rs` returned nothing;
  `domain.rs` was untouched.
- The changelist's lock criterion said the new test must be shown to fail
  against the pre-change generator. It was never run. `mint` was unchanged, so
  every assertion in that file passed either way and proved nothing.

Two of those tests were worse than useless. One asserted a constant against the
literal that defined it and could not fail. The other asserted that two
generators still collide, so **actually fixing the defect would have broken the
suite**.

This round builds the mechanism. Round one's locked changelist stays locked and
stays wrong about round one, which is what an audit trail is for; this topic is
the record of that, and the correction is a later round rather than a rewrite.

## What the mechanism is

**A domain declares its shape.** `Domain` gains `type Shape`, so a domain of one
shape cannot hand its tag to a producer of another and the compiler says so
rather than a store discovering it later. Declared rather than defaulted, because
`associated_type_defaults` is forbidden in this stack and the compiler refused it
when reached for.

**A shape owns the id space.** It supplies the origin type, where a minter's
counter starts, where it stops, and how a counter projects into the id field. The
one low-level numeric edge of a producer moves out of the generator and into the
shape that decides how wide the field is.

**A generator is built for an origin.** `Generator::at(origin)` is the general
constructor. Each origin starts at its own base and stops at its own ceiling, so
two minters at two origins cannot produce the same id however far either counts,
and a minter that exhausts its range refuses rather than walking into its
neighbour's.

**One origin is the degenerate case, not a default.** `Standard` has one origin
whose type has one value, so `Generator::single` needs no argument and there is no
second origin to name. Nothing changes for a consumer with one minter.

**A second shape exists.** `SixteenMinters`: same kind width, four bits naming
which of sixteen minters produced a handle, twenty-four counting within it. It
exists so the trait has a real implementation rather than a single unreachable
one, which was the reviewer's other finding: `mod shape` was private and
`SymLayoutOps` unexported, so `Standard` was not merely the only impl but the
only possible one.

## The const-traits correction, which is the more useful lesson

Round one hit `Layout: [const] SymLayoutOps` being refused on an associated type
bound, concluded const construction was unavailable generically, and shipped a
`*_const` shim on the default shape.

That was backwards. `const_trait_impl` is a vetted allowed feature, the crate
already gates on it, and this stack wants const traits wherever they apply. The
refusal was one bound spelling, not a wall. **Making `SymShape` itself a const
trait works**, and the const path is then generic over every shape:

- `pub const trait SymShape` with `type Layout: [const] SymLayoutOps`.
- `[const]` bounds belong on trait impls and on function `where` clauses, not on
  inherent impl headers. `pub const fn new(..) -> Self where S: [const] SymShape`
  is accepted; `impl<S: [const] SymShape>` is not.

So the shim is deleted and `hilavitkutin-str` returns to the plain names. The
lesson worth keeping is that a refused bound is a spelling to work around rather
than a capability to give up, which is the standing rule this round should have
read before conceding.

## What genuinely does not go

`Mul` and `Shl` are not yet const-stable, so a shape computing its origin base
does it at the raw level, at the same id-allocator boundary the mint step already
crosses, with the allowance and tracked id that boundary already carries.

Declaring a domain on a non-default shape needs `const_trait_impl` in the
declaring crate, because the tag is built in a const item. Every crate in this
stack already gates on it.

## Lock criteria for this round

- Two generators at two origins produce zero equal handles, over the first
  sixty-four mints each and over all sixteen origins pairwise.
- A minter exhausts at its own ceiling rather than walking into the next range,
  verified by walking the full span.
- **Those tests fail against origins collapsed to a single base, verified by
  collapsing them and rerunning, not by assertion.**
- The two round-one tests that could not fail are deleted rather than repaired.
- Every `CHANGE:` block's stated verification is run before the lock, and its
  output recorded.
- `cargo test` green across the workspace, and the scoped commit gate clean on
  every crate this round touches.
