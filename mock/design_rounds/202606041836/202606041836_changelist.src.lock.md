# Src changelist: plan-dims-id-width-guard

**Date:** 2026-06-04
**Phase:** SRC
**Round:** 202606041836 (plan-dims-id-width-guard, branch `fix/hilavitkutin-plan-dims-id-width-guard`)

Reject a `PlanDims` whose phase or trunk capacity exceeds the fixed-width id types' addressable range, loudly, at the top of `compute_execution_plan`. No behaviour change for `DefaultPlanDims` (its capacities equal the id widths). TDD red-first.

## CHANGE: add `ADDRESSABLE` to `PhaseId` and `TrunkId`

File: `mock/crates/hilavitkutin-api/src/dispatch_codegen.rs`
Add `pub const ADDRESSABLE: usize` to the `impl PhaseId` and `impl TrunkId` blocks: the count of distinct ids each fixed-width type names (`PhaseId` wraps `Uint<5>` so `1 << 5 = 32`; `TrunkId` wraps `Uint<6>` so `1 << 6 = 64`), co-located with the struct's `Uint<N>` so the bound tracks the width. Doc comment + `lint:allow(no-bare-numeric)` with reason, matching the `from_index` pattern in the same file.
Verification: `grep "const ADDRESSABLE" mock/crates/hilavitkutin-api/src/dispatch_codegen.rs` returns two matches (PhaseId, TrunkId).

## CHANGE: add the id-width PlanError variants

File: `mock/crates/hilavitkutin/src/plan/steps.rs`
Add `PhaseCapacityExceedsIdWidth` and `TrunkCapacityExceedsIdWidth` to `enum PlanError`, doc-commented siblings of the existing capacity-exceeded variants (`NoTrunkAssignment`, `CoreCountExceeded`).
Verification: `grep "PhaseCapacityExceedsIdWidth\|TrunkCapacityExceedsIdWidth" mock/crates/hilavitkutin/src/plan/steps.rs` returns two declaration matches.

## CHANGE: guard `compute_execution_plan` against an over-wide PlanDims

File: `mock/crates/hilavitkutin/src/plan/mod.rs`
At the top of `compute_execution_plan` (before the `n == 0` early return), return `Err(PlanError::PhaseCapacityExceedsIdWidth)` when `cap_size_phases::<D>() > PhaseId::ADDRESSABLE`, and `Err(PlanError::TrunkCapacityExceedsIdWidth)` when `cap_size(<D::Trunks as Capacity>::CAP) > TrunkId::ADDRESSABLE`. Import `TrunkId` if not already in scope (`PhaseId` already is). The check is a property of `D`, independent of the input.
Verification: `grep "PhaseId::ADDRESSABLE\|TrunkId::ADDRESSABLE" mock/crates/hilavitkutin/src/plan/mod.rs` returns the two guard comparisons.

## Tests (red-first)

A new `tests/plan_id_width_guard.rs`: two custom `PlanDims` impls, one with `Phases = Dim<33>` (one past the `PhaseId` width, all other dims copied from `DefaultPlanDims`), one with `Trunks = Dim<65>`. Each drives `compute_execution_plan` over an empty `PlanInputs::new()` and asserts the matching `Err` variant. A third assertion drives `DefaultPlanDims` over an empty input and asserts `Ok` (the aligned default does not false-positive). The over-wide cases fail before the guard exists (an empty plan returns `Ok` via the `n == 0` early return) and pass after.

## Out of scope

- A compile-time assertion form of the guard (deferred; runtime guard matches the task framing and dodges `generic_const_exprs` const-eval risk).
- Widening `PhaseId` / `TrunkId`. The widths are the deliberate engine cap.
