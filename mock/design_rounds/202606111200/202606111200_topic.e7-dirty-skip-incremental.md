## What this round builds

The engine's single-core runtime can dispatch a registered work-unit carrier in carrier order, windowing the record range into morsels, and (since the D4-linear round) fuse a linear `RecordOp` chain into register-resident form. What it cannot yet do is skip work that does not need redoing. Every `run()` re-executes every work unit unconditionally, even when the inputs that feed a unit are unchanged since the previous frame. The canonical spec calls that a batch processor and names the mechanism that turns it into an incremental one: dirty propagation with per-unit skip (Step 9, `:1418-1429`).

This round ships that mechanism for one core. Before each frame the engine seeds a dirty set from which root inputs changed, propagates the seed forward over the dependency graph in carrier order (`dirty[j] |= dirty[i]` for every edge `i to j`), and skips any work unit whose entire predecessor set is clean. A unit whose cone of inputs did not change produces identical output whether it runs or not, so skipping it is correctness-preserving; the win is that an unchanged frame runs nothing and a frame that changed one input runs only that input's transitive cone.

Two pieces compose into the result. The first is plan-time: the dependency-graph CSR already records the edges between units, so the plan derives a per-unit predecessor bitmask keyed by the same carrier position the dispatch walk threads, and exposes it to `run()`. The second is runtime: `run()` seeds the dirty set from per-root change signals (a resource swapped via `replace_resource`/`replace_value`, an input column the consumer marked changed, or the cold first frame after build where everything is dirty), propagates it over the predecessor masks, and threads the dirty mask plus carrier position into the type-level dispatch walk, which gates each unit's projection and invocation behind its dirty bit. The integration sketch `202606111000_e1-e7-dirty-gated-walk` already proved that gating the real `RunFiber` walk by a per-unit dirty bit preserves devirtualisation (zero `blr`, the whole walk inlines and the gate survives as a predicated branch); the dirty-propagation pass itself was proved by `202606062600_e7_dirty_skip`.

## Scope boundary: E7, not the meta-WU loop

The roadmap pairs E1 and E7 as the E-axis work that completes GATE-1 ("E1 at 1 core with E7 dirty-skip = Gate 1", r1 §7). E1 at one core is the static carrier driven over runtime record ranges (r2 §7), which `run()` already does through its morsel loop. The self-hosting meta-WU frame loop (fire `PlanStage`, `ScheduleReady`, `PassStart`, `ScheduleEnd`, with frame-0-full and reuse-frame pipelining) is E4, which the roadmap places under the GATE-2 N-core runtime that degenerates at one core (r1 §7; spec `:2136` names that kernel the self-hosting form). So this round does not build the meta-WU loop. It builds E7 only, plus the small honesty fixes around it: consume `plan_dirty` and `plan_cache` rather than discarding them, and correct the stale `record_count` doc comment that still claims `run()` dispatches a single morsel and cites the morsel-loop split as a future round (that round, #343, shipped).

The other half of task #345 (C7) is runtime plan recompute on a plan-affecting resource swap. That is the domain-22 adaptivity path (recompute the plan, not skip clean units), which the roadmap sequences as E8 and which the GATE-1 benches never exercise. This round wires `replace_resource`/`replace_value` to set their dirty seed bit, the behaviour those methods need for E7, and leaves the recompute-the-plan consumption to E8. Marking the bit is the real GATE-1 behaviour of those methods; the recompute is the deferred consumption, not a stub left in the skip path.

## Why the change signal is non-optional, and how the benches stay honest

E7's seed answers "which root inputs changed this frame." For a resource the signal is the swap call. For an input column there is no tracked writer at GATE-1: the perf benches host-populate the input column once through a raw pointer (`__bindings().__ptr()`), so nothing auto-bumps a generation counter. The GATE-1-correct primitive is therefore an explicit per-store change signal the consumer calls, with the cold first frame defaulting every root dirty. When a tracked column writer lands later it can call the same primitive internally; the explicit form is the primitive, not a placeholder.

This interacts with the #664 perf gate directly. That gate builds one scheduler and calls `run_fused()` in a loop over unchanged host-populated input. If skip were unconditional, every frame after the first would skip the whole carrier, and the engine would appear to beat optimal std by doing nothing while std recomputes, which is meaningless. The resolution matches what a real throughput consumer does: a frame with new data signals the input changed. The benches mark their input dirty each iteration so every frame legitimately recomputes and the gate keeps measuring compute parity. E7's incremental skip is a correctness and completeness property of the single-core runtime (#661), proved by a dedicated skip test, not a #664 perf arm. The two red #664 arms (branching, accumulator) stay red; their parity is owned by later gates and this round does not touch them.

## Changes proposed

Plan stage gains a per-unit predecessor-mask output derived from the dependency-graph CSR, keyed by carrier position, with a fail-first test that the masks match a hand-checked DAG. The scheduler gains a field holding those masks and a per-root dirty-seed array, plus the change-signal primitive; `replace_resource`/`replace_value` set the seed; `run()` and `run_fused()` seed-propagate-gate over the masks, threading the dirty mask and carrier position into the `RunFiber` walk. The dispatch walk gains the dirty-gated variant of its per-unit step. A fail-first integration test proves the skip behaviour end to end: a cold frame runs everything, an unchanged frame runs nothing (outputs identical, units not invoked), and a one-root-changed frame runs only that root's cone. The stale `record_count` doc comment is corrected and `plan_dirty`/`plan_cache` are consumed honestly.
