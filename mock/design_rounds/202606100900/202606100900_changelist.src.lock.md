# Src changelist: ResetAccumulators walk, run() resets at frame start

## Summary

Add a type-level `ResetAccumulators` walk over the bindings cons-list and call it at `Scheduler::run` entry, so each reused frame starts every accumulator's live-length at zero. The walk is a no-op at every non-accumulator binding node and one `Cell` write at each `AccumBinding`; for an accumulator-free carrier it visits no `AccumBinding` and compiles away. New integration test pins the two-frame contract (fail-first). The `engine_vs_std` accumulator bench drops its hand-reset accommodation, now that `run` performs the reset.

## CHANGE: trait `ResetAccumulators` ADDED
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
Detail: new `pub trait ResetAccumulators { fn reset_accumulators(&self); }` with five impls, one per bindings node. `BindingNil`: empty body. `ResourceBinding<T, Tail: ResetAccumulators>` / `ColumnBinding<T, Tail: ResetAccumulators>` / `VirtualBinding<T, Tail: ResetAccumulators>`: recurse into `self.tail.reset_accumulators()`, no own work. `AccumBinding<T, Tail: ResetAccumulators>`: `self.len.set(USize(0))` then recurse. Each impl is `#[inline]`. The walk is the bindings-cons-list mirror of `DrainStores`; it reuses the existing `len: Cell<USize>` field (interior mutability under `&self`, so the reset needs no `&mut`).
Verification: `grep "pub trait ResetAccumulators" mock/crates/hilavitkutin/src/resource/bindings.rs` returns one match; `grep -c "impl.*ResetAccumulators for" mock/crates/hilavitkutin/src/resource/bindings.rs` returns 5.

## CHANGE: fn `Scheduler::run` RESETS accumulators at frame start
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Detail: `run` gains the where bound `<Vals as BindingsFor>::Bindings: ResetAccumulators` (auto-satisfied: every concrete bindings node impls it) and calls `self.bindings.reset_accumulators()` as the first statement of the body, before the unit-outer / morsel-outer drive decision. `run_fused` is unchanged (a fusible chain grows no accumulator). The `ResetAccumulators` import is added to the scheduler's `use` of `crate::resource::bindings`.
Verification: `grep "self.bindings.reset_accumulators()" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match; `grep "Bindings: ResetAccumulators" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match.

## CHANGE: test `accum_per_frame_reset` ADDED (fail-first)
File: `mock/crates/hilavitkutin/tests/accum_per_frame_reset.rs`
Detail: new integration test. Builds a scheduler with one `Accum<Av>` and an appending WorkUnit that appends a fixed `K` (2) values per frame, with capacity `CAP` (4) wide enough that two frames' worth would not saturate. Runs two frames. Asserts after frame two: the binding live-length equals `K` (not `2*K`), and buffer records `[0, K)` hold the per-frame values in append order. Before the reset this is red: frame two appends from offset `K`, so the live-length is `2*K` and `[0, K)` still holds frame-one's values. The appending WU does not assert internal len (it appends unconditionally), so the failure is observed at the binding level, not via an internal panic.
Verification: `cargo test -p hilavitkutin --test accum_per_frame_reset` passes after the reset lands; the single-frame `accum_dispatch` round-trip stays green.
