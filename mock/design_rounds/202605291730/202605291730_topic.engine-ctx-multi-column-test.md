**Scope:** post-review test addition for #623 (PR #96)

PR #96 split the `EngineCtx` column bundle into a read bundle (over `R`) and a write bundle
(over `W`) so the type-keyed `ColSelector` index resolves uniquely. The shipping coverage
exercises only a single-element column bundle (`context_column_read_after_write`), where the
column resolves at index `Here` on both sides. The deeper resolution path the split exists to
disambiguate, where the read and write column sets differ so the index must infer to
`There<Here>` on one side, is untested in the engine (only in the research sketch).

This round adds an integration test with distinct read/write column sets: `R` reads `Column<u8>`
and `Column<u16>`; `W` writes `Column<u16>` and `Column<u32>`. `u16` is read-and-written (one
buffer, resolved in both bundles); `u8` is read-only, `u32` write-only. The test asserts each
column resolves to its own buffer at the morsel offset, which forces `ColSelector` to infer
`Here` and `There<Here>` on each side.
