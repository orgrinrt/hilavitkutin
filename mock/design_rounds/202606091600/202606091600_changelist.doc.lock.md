# Doc changelist: spec-free ColumnValue

**Round:** 202606091600
**Phase:** DOC
**Scope:** `hilavitkutin-api/DESIGN.md.tmpl`, `hilavitkutin-api/BACKLOG.md.tmpl`.

Rewrites the `ColumnValue` documentation to the spec-free shape this round ships: a trait-body default const plus an empty blanket impl, no `default const`, no full `specialization`, and no sub-byte width specialisations. Records that sub-byte storage width is a future bitpacking concern sourced from arvo's width traits, not a `ColumnValue` specialization behind a forbidden feature.

## DESIGN.md.tmpl — `ColumnValue trait` section

The code block changes from the `default const` blanket (described as "via min_specialization", which was itself inaccurate: the shape needed full `specialization`) to the spec-free shape: the byte default lives in the trait body, and an empty blanket impl inherits it. The prose drops "Sub-byte arvo types specialise" and instead states that any `Copy + 'static` type is column-storable with a `size_of * 8` width, and that sub-byte bitpacking width is a future storage-layer concern sourced from arvo's own width-reporting (not a `ColumnValue` specialization). The zero-friction property is unchanged.

## BACKLOG.md.tmpl — `ColumnValue specialisation coverage` note

Replaced. The old note promised per-arvo-width `min_specialization` coverage inside `ColumnValue`. The new note records the corrected direction: `ColumnValue` reports `size_of * 8` for every type; when bitpacking lands, the storage layer reads sub-byte width from arvo's width traits at the point of consumption, so no per-width specialisation is added to `ColumnValue`.
