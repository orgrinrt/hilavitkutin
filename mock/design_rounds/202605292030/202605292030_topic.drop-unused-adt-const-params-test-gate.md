# Drop the unused adt_const_params gate from the lifted integration tests

The cap-lift round (202605291845) added `#![feature(adt_const_params)]` alongside
`#![feature(generic_const_exprs)]` to the six integration test crates that name a
lifted `Cap`-dimension type. Local PR review of #101 found that gate is
declared-but-unused in those crates: they only NAME `Cap` as a const type
argument (`CoreAssignment<C8>`, `PlanInputs<C8, C16>`), they never DECLARE a
`Cap` const-generic parameter. `adt_const_params` is the feature that lets a type
be USED as a const-generic parameter; declaring `const N: Cap` needs it, naming
`Foo<some_cap_const>` does not. Only `generic_const_exprs` (for normalising the
`[(); cap_size(N)]:` bounds) is required in the consuming crate.

rustc on `nightly-2026-05-28` emits `feature adt_const_params is declared but not
used` for each of the six crates, which is exactly the stale-unstable-gate drift
`unstable-features.md` says to avoid. The engine crate root (`src/lib.rs`)
genuinely declares the `Cap` const params, so it keeps `adt_const_params`; only
the test crates drop it.

This round removes the unused gate from the six integration test files and
corrects the accompanying comment (which asserted both gates were needed). It is
the post-review fix for PR #101, kept as its own round because the cap-lift round
is already locked and closed.
