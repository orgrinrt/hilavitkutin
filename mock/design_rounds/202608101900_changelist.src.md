# Src changelist: the last id-space arithmetic leaves the shape

**Date:** 2026-08-10
**Phase:** IMPL
**Doc CL:** `202608101900_changelist.doc.lock.md`

## CHANGE: `id_from_counter` leaves `SymShape` for the layout

Files: `mock/crates/hilavitkutin-sym/src/shape.rs`, `src/handle.rs`,
`src/generator.rs`

It was a trait method a shape controlled totally, in the same
counter-to-id-space position `origin_base` occupied before round thirteen moved
that one out. A shape satisfying every width law, with an injective in-range
`origin_index`, still minted byte-identical handles from two distinct minters
through it.

It becomes `SymLayoutOps::id_from_raw`, where the bitfield fixes the `Id` type,
so what remains there is forwarding rather than arithmetic.

**This is a reduction, not an elimination, and that is stated rather than
claimed away.** A layout is hand-written and can still misproject; the round-trip
law over `set_id` and `get_id` is what constrains it. Five rounds have claimed
elimination and been wrong.

Consequence: **`Uint<28, Hot>` is now genuinely absent from the trait**, which
round thirteen's design document and src changelist both asserted while a
signature still carried it. Verified: `grep -c 'Uint<28, Hot>' src/shape.rs`
returns 0.

## CHANGE: `origin_index_in_range` is public, and `Generator::at` enforces it

Files: `mock/crates/hilavitkutin-sym/src/shape.rs`, `src/generator.rs`

The range check was private to `mod tests` and ran against three shipped shapes,
so nothing a consumer wrote could reach it, while `tests/origins.rs` said the
case was covered. An index at or above `2^ORIGIN_BITS` gives derived runs that
are disjoint in `u32` and truncate onto each other inside the id field.

It is now public, and `Generator::at` returns `Maybe<Self>` and refuses. **A
shape is an open extension point, so the point of use is the only place a check
binds for shapes nobody has written yet.**

`Generator::single` stays total, and provably: `Standard` reserves zero origin
bits, so `1 << 0` is one and its only index, zero, is always in range. Going
through `at` would force every caller to handle a refusal that cannot happen.

## CHANGE: the out-of-range shape is pinned as a test

File: `mock/crates/hilavitkutin-sym/src/shape.rs`

`IndexPastOriginBits` carries the ninth review's second construction, with two
tests: the range check rejects it, and it satisfies every width law. The second
is why a width law was never going to be the instrument.

**An earlier attempt at this insertion silently did nothing**, because the
pattern it matched had been rewrapped by the formatter. Caught by counting the
tests before and after rather than by assuming, which is the same class as round
thirteen's unexecuted edit and was one command away from repeating it.

## What this round does not close, stated plainly

A layout can still misproject. A shape can still map two origins to one index,
which the injectivity law catches for shapes that are tested and not for ones
that are not. Whether a shape should be trusted with any id-space arithmetic at
all, or whether the extension point should narrow to widths and an origin type
with everything numeric derived, is a design fork that goes to op.

Six routes to this collision have now been found by six consecutive reviews. That
count is the argument for asking rather than patching a seventh time.
