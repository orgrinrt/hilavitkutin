The second copy of an import onto the live side of a buffered column has no observer today. The boundary carries a buffered store over only after a pass marked it, and every pass that writes a buffered store writes each of its records: `map` covers the unit's whole record range, and the positional `write` reaches only a plain `Column<T>` (`hilavitkutin-api/src/write_at.rs:48-85`). So the frozen copy alone reads the same in every pass a unit can make now. The live copy stays, since it keeps the two sides agreeing over the imported range for a write that covers part of the store, but the design says that plainly instead of claiming a boundary that would drop the import.

The question the grain of the import's mark belongs to is `question::who_says_that_a_store_changed`, which the seat's notes name as Q1; the topic of `hx2c` and its ticket cited a row `what_a_host_import_into_a_built_scheduler_marks_as_changed` that was never filed.
