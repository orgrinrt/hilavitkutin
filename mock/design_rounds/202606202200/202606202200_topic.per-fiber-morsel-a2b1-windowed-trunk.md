# Topic: per-fiber morsel A2b-1 (windowed per-trunk dispatch entry)

**Date:** 2026-06-19
**Phase:** TOPIC
**Scope:** `hilavitkutin` scheduler (`Scheduler::run_one_trunk_windowed`)
**Source topics:** A2a sketch `mock/research/sketches/202606202100_a2a-per-fiber-morsel-loop/`, granular roadmap `202606201900`

## Current state

`run_one_trunk::<_,_,TRUNK>` dispatches one trunk's monomorphised program over the
WHOLE record range in one `run_trunk` call (`scheduler/mod.rs:1454-1477`). The A2a
sketch proved (source-grounded) that wrapping that call in an inner window loop
yields fiber-outer/morsel-inner dispatch with const-DCE + devirt preserved by
construction (MorselRange is a pure runtime arg; all DCE sites are compile-time and
read neither range nor dirty). For a single-fiber-per-trunk plan this IS per-fiber
morsel windowing.

## Change proposed (A2b-1)

Add `Scheduler::run_one_trunk_windowed::<Witnesses, GW, const TRUNK>(&mut self,
window: USize)`: same bounds as `run_one_trunk`, body loops `[0, total)` in windows
of `window.max(1)`, one `run_trunk` call per window (all-ones dirty, no-skip). Test
asserts the per-morsel starts are `[0, w, 2w, ...]` (window 4 over total 10 ->
`[0, 4, 8]`), distinguishing windowed from whole-range (one call).

## Not in scope

A2b-2: lift `run()` to drive fibers fiber-outer keyed by `FiberDispatch.morsel_size`
(needs the `fiber_mask & dirty` selector for multi-fiber-trunk granularity, per the

proven windowed-trunk entry only.
