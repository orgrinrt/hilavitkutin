# Topic: DependencyGraph to CsrBidirectional adapter (Phase C C1a)

**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** `mock/crates/hilavitkutin/src/plan/graph.rs` (one new method + test)
**Source topics:** Phase C arc (`mock/research/202605290230_phase-c-arvo-analysis-wiring.md`), Topic 9 axis B (CSR canonical), `#638`, umbrella `#339`

## Current state

The plan stage builds a `DependencyGraph<MAX_UNITS, MAX_EDGES>` in CSR form
(`row_offsets` + `col_indices` + `edge_kinds`, plus live `unit_count` /
`edge_count`). After the C0 Cap-lift (`#637`, merged `b278890`) the two
dimension params are `arvo::Cap`, sized through `cap_size(N)`, exactly matching
the shape arvo's `arvo_sparse::Csr<ROWS, NNZ, W>` uses.

Three plan steps that need real dependency structure are still dead ends: step 4
(`rcm_reorder`), step 5 (`block_diagonalise`), step 6 (`spectral_partition`).
Each of arvo-sparse's structural algorithms (`rcm_reorder_via`,
`block_diagonal_via`, the spectral path) consumes a `CsrBidirectional` (forward
adjacency plus a pre-computed transpose for cheap predecessor queries). The
engine has no way to hand its graph to those algorithms today.

The loose-CSR work in arvo (`#634`, merged `0d6fb4f`) parameterised
`Csr`/`CsrBidirectional` over runtime `live_rows` / `live_nnz` so a
fixed-capacity buffer with slack never iterates its unused tail. `node_count()`
reports the live row count, not the cap, and `with_transpose` ignores the slack
tail (no phantom edge into the default `NodeId(0)` slot). That property is the
reason the adapter must set live counts rather than leave the matrix packed.

## Changes proposed

Add `DependencyGraph::to_csr_bidirectional(&self) -> CsrBidirectional<MAX_UNITS,
MAX_EDGES, EdgeKind>`. Because both types now share the same `Cap` params and the
same `cap_size(N)` array sizing, the generics pass straight through with no
`cap()` bridge. The body builds a `Csr` via `with_live_counts(unit_count,
edge_count)`, copies `row_offsets` into `row_ptr` and each `col_indices` entry
into `col_idx` (converting `UnitId` to `NodeId` through `.index()`), copies
`edge_kinds` into `values`, then calls `with_transpose()`. `EdgeKind` is `Copy +
Default` (default `Read`), satisfying the `W` bound.

This is the foundation sub-round of Phase C. C1b (rcm), C1c (block-diagonal +
trunks), and C1d (spectral + fibers) each consume the adapter output and
populate progressively more of the plan structures. They follow in their own
rounds; this round ships the adapter and its test only.

The test builds a small known DAG, adapts it, and asserts forward successors
match the source edges, the transpose carries reverse adjacency, `node_count()`
equals the live unit count rather than the cap, and nodes past the live range
carry no predecessors. That last assertion is the loose-CSR property: a packed
`Csr::new()` would let the default-`NodeId(0)` slack tail pollute node 0's
in-degree, so the test fails if the adapter forgets `with_live_counts`.
