# Src changelist: csr-bidirectional-adapter

**Date:** 2026-05-29

**Topic:** `202605292215_topic.csr-bidirectional-adapter.md`

## Summary

Add the `DependencyGraph` to `arvo_sparse::CsrBidirectional` adapter and a strict
test. The adapter is the foundation sub-round of Phase C: the three dead-end plan
steps (rcm, block-diagonal, spectral) all consume a `CsrBidirectional`, and this
gives the engine its first way to produce one from the graph it already builds.

## CHANGE: method `DependencyGraph::to_csr_bidirectional` ADD

File: `mock/crates/hilavitkutin/src/plan/graph.rs`

Added inside the main `impl<const MAX_UNITS: Cap, const MAX_EDGES: Cap>
DependencyGraph<MAX_UNITS, MAX_EDGES>` block (the impl carries the
`[(); cap_size(MAX_UNITS)]:` / `[(); cap_size(MAX_EDGES)]:` bounds, so the
method inherits them; no redundant where-clause). Signature:

```rust
pub fn to_csr_bidirectional(&self)
    -> arvo_sparse::CsrBidirectional<MAX_UNITS, MAX_EDGES, EdgeKind>
```

Body builds `Csr::with_live_counts(self.unit_count, self.edge_count)`, copies
`row_offsets[0..unit_count]` into `row_ptr`, each `col_indices[e]` into
`col_idx[e]` (via `NodeId::new(uid.index())`), each `edge_kinds[e]` into
`values[e]` for `e in 0..edge_count`, then returns `csr.with_transpose()`. The
two `Cap` params pass straight through to arvo's `ROWS` / `NNZ` positions; no
`cap()` bridge, because after the C0 lift the engine graph is already
`Cap`-parameterised. `EdgeKind` satisfies `W: Copy + Default` (default `Read`).

Verification: `grep -n "pub fn to_csr_bidirectional" mock/crates/hilavitkutin/src/plan/graph.rs` returns one match; `cargo +nightly-2026-05-28 test -p hilavitkutin --test csr_adapter` passes.

## CHANGE: test file `tests/csr_adapter.rs` ADD

File: `mock/crates/hilavitkutin/tests/csr_adapter.rs`

New integration test crate carrying `#![feature(generic_const_exprs)]` +
`#![allow(incomplete_features)]` at its root (per the C0 cross-crate
generic_const_exprs finding: a crate naming a `[(); cap_size(N)]`-bounded type
must enable the feature so its own trait solver normalises the bound;
`adt_const_params` is not needed because the test only names `Cap` values via
`cap(N)`, it does not declare a `Cap` const param). Builds a diamond DAG
(0->1, 0->2, 1->3, 2->3) in a slacked cap `<{cap(8)}, {cap(16)}>` and asserts:

- forward successors per node match the source edges
- the transpose carries reverse adjacency (predecessors)
- `node_count()` equals the live unit count, not the cap
- nodes past the live range carry no predecessors (the loose-CSR property: a
  packed `Csr::new()` would pollute node 0's in-degree from the default
  `NodeId(0)` slack tail, so this assertion fails if the adapter omits
  `with_live_counts`)

Verification: `cargo +nightly-2026-05-28 test -p hilavitkutin --test csr_adapter` passes all cases.
