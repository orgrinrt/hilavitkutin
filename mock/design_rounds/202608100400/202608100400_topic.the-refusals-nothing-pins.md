# The refusals nothing pins, and the checks that were done by hand and thrown away

**Date:** 2026-08-10
**Phase:** TOPIC
**Scope:** `hilavitkutin-sym`

This crate's argument is that illegal states are unrepresentable. It asserts that
in prose in three places and pins it in one doctest.

**A refusal nothing guards can be deleted by accident.** Loosen a bound, and every
remaining test still passes, because none of them names the case that stopped
being refused. `harness-the-type-system.md` says this directly: when the right fix
makes a case unrepresentable, the case becomes a compile-fail test asserting that
it stays unrepresentable.

## The refusals this crate claims and does not test

- **Two shapes' handles cannot be compared.** `DESIGN.md.tmpl:61` says they are
  not comparable and must not meet in one store. Verified by hand just now:
  `E0308`. Nothing pins it.
- **A domain of one shape cannot hand its tag to a producer of another.**
  `DESIGN.md.tmpl:143` says the shape declaration is what stops it.
- **`SymKind::from_raw` exists on `Standard` alone**, because the literal is
  three bits wide and a wider-tag shape would truncate it silently. That is the
  reason the method is scoped, and nothing asserts the scoping holds.
- **A non-generative domain cannot be given a `Generator`.** This one is tested,
  as a doctest, and its `Domain` impl omits `type Shape`, so it emits `E0046`
  beside the intended `E0277`. It fails for the right reason plus a wrong one,
  and it ships an uncompilable `Domain` example to anyone reading the rustdoc.

`trybuild` is already a dependency of two crates in this workspace, so the
mechanism exists and is not being invented here.

## The larger point, and it is now a workspace rule

Every one of the constructions this arc relied on was built by hand, run once,
and deleted: the lying width, the converting accessor, the field overlap, the
derive regression, the colliding origin. Two became tests. The four that did not
are exactly the four whose defect class came back.

The rule is `a-hand-check-becomes-a-test-every-time.md`. A check performed by
hand is committed as a test before the work moves on, in whichever of the three
shapes fits: a unit test for a runtime property, a compile-fail test for a
refusal, and a **negative test** for a construction that compiles but is wrong.

That third shape is the one this crate kept declining, on the reasoning that
committing a broken shape would fail the suite. It would, where it was built. It
does not have to be built there: a wrong shape declared inside a test module,
with the law expressed as something that returns rather than asserts, lives
permanently on the right side of the suite. **Round nine's collision construction
is exactly that case and this round commits it.**
