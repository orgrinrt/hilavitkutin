# Doc changelist: state the fiber-descriptor coverage invariant

**Date:** 2026-07-19
**Phase:** DOC
**Topic:** `202607191100_topic.fiber-descriptor-coverage-invariant.md`

## Scope

One file. The design describes both dispatch paths as walking fiber descriptors and
passing per-fiber member masks, and says nothing about what that requires of the
descriptor set. Since the union of those masks replaced the all-ones mask, the
requirement is now load-bearing for correctness and belongs in the shipping contract.

## File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`

**CHANGE: the dispatch section GAINS the descriptor coverage invariant.**

After the paragraph describing the fiber-outer walk on both paths, state that the
descriptor set must cover every live unit, because the dispatch mask is the union of the
per-fiber member masks, so a unit no descriptor names does not run. Name where that is
established (the flatten in `derive_phase_dispatch_order`, whose per-fiber assignment is
what makes the union total) and note that the invariant is currently checked by
debug assertions only, with the release-visible guard tracked as follow-up.

The point of stating it: a future change to the flatten bounds, or to how descriptors
are sized, currently has nothing written down to check itself against. Both dispatch
paths silently depend on it.

Verification: `grep -c "cover every live unit" mock/crates/hilavitkutin/DESIGN.md.tmpl`
returns one, and the paragraph names both the union and the debug-only status.

## Not in scope

Making the truncation release-visible, which changes the `build` contract and needs its
own round and its own decision about the error shape. The catalogued test this round adds
tracks it.
