## Scope

Two one-line parity items from the PR #171 review, and one catalogued test for the
coverage invariant the doc CL just stated. The release-visible guard for the truncation
is deliberately not here; it changes the `build` contract and wants its own round.

## CHANGE: `Scheduler::run_core_phase` GAINS the descriptor-count debug assert

File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (fiber branch, before the walk)

`run` carries `debug_assert!(topo_count == 0 || fcount > 0, ...)` guarding the "live
units but no descriptors dispatches nothing" case. The parallel branch omitted it while
depending on the same invariant. Add it for parity.

Verification: `grep -c "live units but no fiber descriptors" mock/crates/hilavitkutin/src/scheduler/mod.rs`
returns two.

## CHANGE: `Scheduler::run_core_phase` DROPS the `let _ = all;` discard

File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (end of the fiber branch)

`all` is still consumed by the record-less branch above, so the binding is live and the
discard suppresses nothing. Noise; remove.

Verification: `! grep -q "let _ = all;" mock/crates/hilavitkutin/src/scheduler/mod.rs`.

## CHANGE: `tests/fiber_descriptor_coverage.rs` IS ADDED (catalogued red)

File: `mock/crates/hilavitkutin/tests/fiber_descriptor_coverage.rs`

Both dispatch paths now run under the union of the per-fiber member masks, so a live unit
no descriptor covers does not run. The flatten truncates silently once the descriptor
pool is full, so in a release build that degrades into units that never execute rather
than a build failure.

The test states the intended behaviour: a plan whose fibers exceed the descriptor
capacity must not silently under-dispatch. It is catalogued red via
`#[ignore = "catalogue: ..."]` because the fix is the release-visible guard, which is a
`build` contract change out of this round's scope. Per the catalogue discipline the case
is written down now with the intended assertion, so it cannot be lost, and the ignore
reason names the blocker.

Verification: `cargo test -p hilavitkutin --test fiber_descriptor_coverage -- --ignored`
lists the case; the default run reports it ignored, keeping the catalogued-red count
honest at eleven.

## Not in scope

The release-visible truncation guard (its own round), and the `FiberCons` nest deletion,
which the wireability sketch confirmed is dead machinery and which belongs to G2C-0's
deletion audit alongside the head+tail types.
