# suite-as-an-instrument

The suite of `hilavitkutin` and the api crates should be an instrument: every fail fixture refuses, every test asserts something that can fail, a check over every target prints nothing, and no lint is silenced. This round is the first set of track 5 of the hilavitkutin triage (kaski channel doc `research/hilavitkutin-triage-202611131900.md`), run after the api revision landed on dev (`9b7bf4ea`, then `8236de3c`). The brief is `briefs/job-hv-suite-surface.md` on the kaski channel. The tickets are rows of the workspace lane `tickets-hilavitkutin.toml`, named here by key.

The engine's `scheduler/`, `plan/` and `dispatch/` are overhauled tonight by the lane `hv-engine-path`, so this round edits no file under them. Where a ticket reaches into them, its part there is handed to that lane and named.

## What the round asks

None of it is a change of design. A test that cannot fail is made to observe what it names or is deleted, a silenced lint is satisfied, and a file over the limit splits along its fixtures. The one question with a design edge is `AdaptArena`: it is in `src/`, and whether it is deleted or used is read off the engine design before it is touched.
