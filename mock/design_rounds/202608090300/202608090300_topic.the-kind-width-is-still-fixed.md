# Topic: the kind width is still fixed, and the widths are decorative

**Phase:** TOPIC
**Scope:** `hilavitkutin-sym`. Delivers the half of the branch's stated purpose
that two rounds have now missed, and removes the ceremony standing in for it.

## What the review found

The branch set out to fix two things: a minted handle colliding across peers,
and a kind width hardcoded at three bits. The second round fixed the first. The
second is **still not delivered**.

Both shipped shapes share one `Layout`, `SymLayout`, whose bitfield gives the
kind three bits. So `SymShape` varies how the *id* divides and nothing else. A
consumer wanting four domains or sixteen still gets eight, which is the exact
complaint the branch opened with.

Worse, the widths that make it look delivered are **decorative**. `KIND_BITS`,
`ORIGIN_BITS`, `COUNTER_BITS`, `ID_BITS` and `ORIGINS` are read by nothing
outside tests. Nothing ties them to the `Layout` they claim to describe, so a
shape may declare `KIND_BITS = 4` over a three-bit bitfield and compile clean. A
constant that cannot be wrong is not a contract, it is a comment with a type.

And the tautology the previous round said it deleted came back twice:
`assert_eq!(Standard::ORIGINS.0, 1)` restates the literal that defines it. Both
occurrences are structurally incapable of failing.

## What this round does

**A shape brings its own layout, and the kind width actually varies.** A third
shape declares a second `bitfield!` with a different kind width, which is what
makes the trait's central claim true rather than merely stated. Until one exists,
`SymShape` is a parameter over one value.

**The widths become load-bearing or they go.** A width that no code reads and no
check constrains is removed. What survives is what the mechanism actually
consumes, plus a law asserted **for every shape rather than for `Standard`
alone**, which is the sampling failure the workspace rule names: choosing which
instantiations to test is choosing what not to find out.

**The two restatements are deleted, not repaired.**

## Two smaller things the review caught

`Generator::mint`'s rustdoc still says it exhausts at the 28-bit id space. It
exhausts at the origin's ceiling, which is the mechanism the previous round
built, so the doc contradicts the round that wrote it.

An unused `Identity` import and a `MAX_ID` now dead outside tests ship two
warnings.

## A record defect worth stating, because it will recur

The previous round's locked changelist names
`grep -c 'impl const SymShape for SixteenMinters'`, and the source reads `const
impl`. The verification **was** run and **was** true when run. The pre-commit
autofix then ran rustfmt, which rewrote the keyword order, and the locked
changelist shipped naming a command that returns zero against the source it
describes.

So a claim verified before a commit can be falsified by that commit's own
formatter. Verify against what landed, not against the working tree. The
workspace rule now says so.

The locked changelist stays locked and stays wrong in that one command. This
topic is the correction.

## Lock criteria

- A shape exists whose kind width is not three, with its own bitfield, and a
  domain declared on it mints handles that carry a tag wider than three bits.
- Every width the trait still declares is consumed by something other than a
  test, or is gone.
- Both width laws asserted for every shipped shape, not for `Standard` alone.
- Zero assertions that restate a literal defined in the same crate.
- `cargo build` emits no warning from this crate.
- Every `CHANGE:` verification run **after** the commit hook's autofix, against
  `git show HEAD`, with output recorded.
