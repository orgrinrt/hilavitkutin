# Doc changelist: the kind width, and widths that mean something

**Phase:** DOC
**Topic:** `202608090300_topic.the-kind-width-is-still-fixed.md`
**Scope:** `mock/crates/hilavitkutin-sym/DESIGN.md.tmpl`.

## CHANGE: the `SymShape` section

Say that a shape brings its **own layout**, not merely its own division of a
shared one, and that this is what lets the kind width vary. The previous rounds
implied it and no shipped shape demonstrated it.

State that a width the trait declares is a width something consumes. A constant
no code reads and no check constrains is a comment with a type, and the design
should not present one as a contract.

## CHANGE: the shape list

Add a third shape with a kind width other than three, and say plainly that it
exists so the kind width is demonstrably variable rather than nominally so.

Correct the signatures the design gives, which drifted: the handle is
`Sym<S = Standard>`, the tag's inner type is the layout's associated kind rather
than a `S::Kind`, and the generator takes its shape from its domain rather than
as a second parameter.

## CHANGE: the `Generator` section

Its own rustdoc says exhaustion happens at the 28-bit id space; the mechanism
the previous round built exhausts at the origin's ceiling. Say the latter.

## Lock criteria

- Every signature in the document matches source, checked by grep.
- No sentence claims a width varies that no shipped shape varies.
