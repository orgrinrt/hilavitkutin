# Doc changelist: load-bearing widths, and the signatures that drifted

**Phase:** DOC
**Topic:** `202608090500_topic.assertions-that-describe-do-not-constrain.md`
**Scope:** `mock/crates/hilavitkutin-sym/DESIGN.md.tmpl`, repo `README.md`.

## CHANGE: `DESIGN.md.tmpl`, the `SymShape` section

The document already says a width the trait declares is a width something
consumes. That was aspiration: a shape could declare any width and compile.
State the mechanism that makes it true, which is that a layout reports its own
widths and a law ties each shape's declaration to its layout's fact.

## CHANGE: `DESIGN.md.tmpl`, the `Domain` section

It omits `type Shape` entirely, which is the mechanism this branch's central fix
rests on: a domain belongs to a shape, so a domain of one shape cannot hand its
tag to a producer of another. Add it, and correct `const KIND` to carry the
domain's shape.

## CHANGE: `DESIGN.md.tmpl`, the `Interner` and `mint` signatures

Both show a bare handle where the source has one carrying its shape.

## CHANGE: `README.md`

It says `hilavitkutin-build` runs as a build-dependency stub. This branch removed
the last `[build-dependencies]` and no `build.rs` remains in the workspace, so
the sentence was made false by this branch's own hand.
