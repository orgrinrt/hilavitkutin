Round topic `202611192051-ers6_topic.interner-deduplicates.md`, from ticket `hilavitkutin_memoryarena_arena_intern_never_deduplicates_tho` and the expert seat's read (`mock/research/202611191955_consumer-surface-seat/NOTES.md` section 4). No canon row changes.

## Changes proposed

### 1. The arena contract carries the law

`mock/crates/hilavitkutin-str/DESIGN.md.tmpl`, "`ArenaInterner`, host-implemented trait": the contract states that `arena_intern` returns the id it already holds for a string equal to one it stored, so equal strings give equal handles through `StringInterner`, and that `arena_resolve` of an id the arena did not issue returns the empty string and reads nothing outside its storage. "`StringInterner<A>`, wrapper" says the wrapper relies on the arena for runtime deduplication and does it for const strings by the section lookup.

### 2. `MemoryArena` deduplicates and stays inside its table

`mock/crates/hilavitkutin-providers/DESIGN.md.tmpl`, "`MemoryArena<BYTES, ENTRIES>`": `arena_intern` first scans the entries for one of equal length and equal bytes and returns its id; only a string not held is appended, with the next sequential id. `arena_resolve` checks the id against the live entry count, so the overflow sentinel, which reaches it masked to 28 bits, and any id from another arena resolve to the empty string. The masked sentinel is id 2^28 - 1, the largest the 28-bit field holds, so the arena issues ids below it only: an `ENTRIES` of 2^28 or more, whose last slot would carry the sentinel's own id and resolve an overflow handle to a real string, fails the build at `MemoryArena::new`. The cost is a scan linear in the entries held, per runtime intern; the overflow behaviour (sentinel id, empty resolution) is unchanged.
