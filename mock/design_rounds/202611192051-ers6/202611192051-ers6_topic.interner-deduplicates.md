# Topic: the default interner deduplicates, and resolve stays inside its table

**Date:** 2026-11-19
**Phase:** TOPIC
**Scope:** `hilavitkutin-str` (`ArenaInterner` contract), `hilavitkutin-providers` (`MemoryArena`)
**Source topics:** ticket `hilavitkutin_memoryarena_arena_intern_never_deduplicates_tho` (loru-coord's ask 5 of 19 November); the expert seat's read, `mock/research/202611191955_consumer-surface-seat/NOTES.md` section 4, with its probe at `mock/research/sketches/202611191955_consumer-surface-seat/`

## What the record says

The sym design states the law every interner keeps: equal values give equal handles (`mock/crates/hilavitkutin-sym/DESIGN.md.tmpl:16-18`). The str crate says the same of its domain (`hilavitkutin-str/src/interner.rs:15-16`, "`intern` deduplicates a `&str` into a stable handle"). The canon is silent on whether the law is kept by `StringInterner` or by the arena behind it. The providers design describes `MemoryArena` as giving each runtime-interned string a sequential id, and capacity overflow as the sentinel `u32::MAX` (`hilavitkutin-providers/DESIGN.md.tmpl`, "`MemoryArena<BYTES, ENTRIES>`"), matching the provisional row `the_memory_arena_is_an_inline_storage_interner_with_const_generic_byte_and_entry_caps_and_overflow_returns_a_sentinel_id`. The `MemoryArena` doc says the sentinel resolves to the empty string.

## Where the code diverges

`MemoryArena::arena_intern` appends unconditionally, so two interns of one runtime string through `default_interner` give unequal handles (probe results 1 to 3). The sentinel passes through `Bits::<28, Hot>::from_raw` and is masked to `0x0FFF_FFFF`; `arena_resolve` compares against `u32::MAX`, never matches, and reads entry 268435455 of the table, which killed the probe with SIGSEGV (results 4 and 5). Any handle from another interner instance takes the same unchecked read. `ENTRIES` past 2^28 would alias ids silently. The one test asserting deduplication, `hilavitkutin-str/tests/interner.rs` `runtime_intern_dedups`, passes because its own `VecInterner` fixture deduplicates; it proves the fixture and nothing of a shipped type.

## Decision for this round

Derived, not asked, since the job runs unattended and the fix changes no signature. The law goes on the `ArenaInterner` contract, where the host implementing an arena reads it, and `MemoryArena` keeps it: `arena_intern` returns the id it already holds for an equal string, found by a scan of its entry table that compares length before bytes. `arena_resolve` checks the id against the live entry count and returns the empty string for any id it did not issue, which is what the design already says of the sentinel, so the overflow handle and a foreign handle resolve to `""` and never read past the table. `MemoryArena::new` refuses at compile time an `ENTRIES` above 2^28.

The tautological str test is deleted; the law is asked of the shipped arena in providers, through `ArenaInterner`, `InternerApi` and `Interner<StrDomain>`, with the overflow handle resolved through `StringInterner`.

What this round leaves: two strings that both overflow still share the sentinel handle, and `intern` cannot say that the arena is full. Both need a signature change, put to op with the placement of the index in question `where_string_deduplication_lives_in_hilavitkutin_and_what_a`; the reach of the interner from a unit is question `how_a_work_unit_reaches_the_string_interner_and_whether_hasi`. The scan is linear in the entry count; the seat's one-index-per-interner shape, which also folds the const-section lookup into the same probe, is option a of the first question.
