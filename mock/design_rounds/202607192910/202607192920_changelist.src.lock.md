## CHANGE: `dispatch/phase_run.rs` IS DELETED, with its re-export and its test

Files: `mock/crates/hilavitkutin/src/dispatch/phase_run.rs`,
`mock/crates/hilavitkutin/src/dispatch/mod.rs`,
`mock/crates/hilavitkutin/tests/phase_pipeline_dispatch.rs`

`RunPhase` and `RunPipeline` are the nested-carrier type construction: `TrunkCons` / `PhaseCons`
nests walked by witness recursion. A1 registry item 3 records the design decision that replaced them:
"r4 (`202606070700`) replaces r3's G2-0c nested-carrier type construction with the const-eval
grouping + const-gated DCE mechanism."

Sketch `202607191200_a4-fibercons-nest-wireability` independently establishes the nest is unwireable
from flat registration (FAILS: partition-by-key walls on `specialization`, which is forbidden), so
this is not a mechanism awaiting wiring.

The module's local `waist_barrier` (`:105`), a third spin-only barrier implementation, goes with it.

The test goes with the module. It asserts the superseded walk matches the flat walk, which is
coverage of the replaced mechanism, not of a live contract.

Verification: `! test -f mock/crates/hilavitkutin/src/dispatch/phase_run.rs`,
`! grep -q "phase_run" mock/crates/hilavitkutin/src/dispatch/mod.rs`,
`! test -f mock/crates/hilavitkutin/tests/phase_pipeline_dispatch.rs`.

## CHANGE: the `phase_barrier_*` family IS DELETED

Files: `mock/crates/hilavitkutin/src/thread/barrier.rs`,
`mock/crates/hilavitkutin/src/thread/mod.rs`

`phase_barrier_arrive`, `phase_barrier_reset`, `phase_barrier_observe` and `BarrierArrival` implement
an arrive-plus-separate-reset protocol over `pool.phase_arrived`, the same word the live
sense-reversing `waist_barrier` drives with an incompatible reset discipline. Nothing calls them; the
`pub use` at `thread/mod.rs:29` is what kept the dead-code lint quiet.

Two protocols on one word is a trap for whoever wires the second one, and the design paragraph
promising to wire it has been removed by the doc CL, so nothing is left pointing at it.

Verification: `! grep -q "phase_barrier" mock/crates/hilavitkutin/src/thread/mod.rs` and
`cargo check -p hilavitkutin` clean.

## Whatever the deletions orphan follows them

Each orphan gets its own check before removal: every reference across all crates including `tests/`,
and whether a design template names it. Anything still referenced stays; anything a template names
stays until that template is dealt with.

## Expected test movement

The suite loses `phase_pipeline_dispatch` (one case). Everything else is unchanged: 131 binaries
green rather than 132, same ignored count.

That is a reduction in the number, not a regression. Stated here so the drop is expected rather than
investigated later.

## Not in scope

`core_phase_mask` and the `dispatch::order` const fold: r8 records both as canonical-target
substrate, the former being an op-blessed deviation with a live escalation path rather than a
replaced mechanism.
