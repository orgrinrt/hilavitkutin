# frozen-lints-scope-themselves

**Date:** 2026-11-20
**Scope:** `mockspace.toml`, the four frozen lints under `mock/lints/`, the ledger section of `mock/crates/hilavitkutin-frozen-authors/DESIGN.md.tmpl`.
**Source:** ticket `hilavitkutin_dev_fails_cargo_mock_on_a_lint_admits_no_crate`.

`cargo mock` on `dev` fails on the mockspace-extra-lints lint `a-lint-admits-no-crate-list`, which refuses any `[lints.*]` table holding a `crates` key: a list of the crates a lint is let loose on leaves every crate made later outside the gate. `mockspace.toml` gives `frozen-no-outside-source`, `frozen-no-feature-gate`, `frozen-no-recursion-limit` and `frozen-ledger` each `crates = ["hilavitkutin-frozen-authors"]`.

The four lints already hold their own scope. Each checks `scan::applies_to(ctx.crate_name)` before reading anything, and that takes every crate whose name starts with `hilavitkutin-frozen-`, so the list in the config only repeats what the code says, narrower. Recognising a frozen crate by its `LEDGER.toml` instead was weighed and does not fit: `frozen-ledger` refuses a frozen crate that carries no ledger, and a scope read off the ledger would let that crate through silent. The name family is what makes a crate frozen here, the ledger is what a frozen crate owes.

So the `crates` keys go, the scope stays in the code where it already is, and the design says so. Each of the three scan lints gains a test through the runner that the same offending text in a crate outside the family reports nothing, beside the existing ones that it reports in the frozen crate. `frozen-ledger` already has both (`a_crate_with_no_ledger_is_refused_through_the_runner`, `a_crate_that_is_not_frozen_needs_no_ledger`). No canon row changes, no lint is weakened, no exemption is added.
