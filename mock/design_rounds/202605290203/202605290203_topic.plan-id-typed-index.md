# Typed id-to-index accessors replace transmute_copy

The plan stage and the engine-id Debug impls project the typed engine ids
(`UnitId`, `FiberId`, `PhaseId`, `TrunkId`) to and from raw container integers
with `core::mem::transmute_copy` over the `repr(transparent)` chain
`<Id> -> Uint<N> -> Bits<N, Warm, Unsigned> -> <container>`. This is the first
correctness item the engine-dispatch build plan flags (risk R1): the projection
is layout-coupled. It assumes a specific container byte width per id (probed at
4 / 2 / 2 / 2 bytes on 2026-05-11) and reinterprets exactly that many bytes. If
arvo's `Warm` container dispatch ever retunes which primitive backs a given
width, every `transmute_copy` reads the wrong byte count with no compile error.
Four `const _: () = assert!(size_of::<Id>() == N)` blocks exist purely to make
that drift a compile failure, which is a workaround, not a fix.

There are roughly twenty `transmute_copy` sites across `plan/graph.rs`,
`plan/steps.rs`, `plan/mod.rs`, `plan/core_program.rs`, and the four Debug impls
in `dispatch_codegen.rs`. Each carries one or two `lint:allow` directives whose
`reason` cites `#428` (an arvo Debug task, since completed); the tracking ref is
stale, and the allows mark a layout assumption the type system should be
enforcing instead.

## Current state

`UnitId(pub Uint<16>)` and siblings are `repr(transparent)` newtypes over arvo
`Uint<N>`, which is `UFixed<{ibits(N)}, {fbits(0)}, Warm>`. arvo already ships
the defined container projection: `UFixed::to_raw(self) -> <container>` and
`UFixed::from_raw(bits) -> Self`, both `pub const fn`. The plan code does not use
them; it transmutes instead. `arvo::USize` is `USize(pub usize)`, and arvo's own
`UFixed::logical_width()` constructs a `USize` with `USize(<value> as usize)`,
which is the idiom this round reuses.

## Changes proposed

Add to each engine id a typed `const fn index(self) -> USize` and
`const fn from_index(USize) -> Self`, built on `to_raw` / `from_raw`. The
accessors are the single boundary where a typed id becomes a raw array index;
the unavoidable container-to-`usize` crossing lives there under one
`lint:allow(no-bare-numeric)` per id type, instead of twenty scattered `unsafe`
transmutes with stale allows.

Replace every `transmute_copy` projection in the plan stage and the Debug impls
with the accessor. Delete the four `size_of` layout-assertion consts: `to_raw`
is strategy-aware, so the drift they guarded against can no longer silently
misread. Net effect: no `unsafe` in the id projection path, no layout coupling,
the lint-allow surface drops from roughly thirty directives to one per id type,
and the projection is verified by the type system rather than by a hand-probed
byte count.

The change is `hilavitkutin`-internal: it consumes existing arvo `const fn`s and
adds no arvo surface, so no cross-repo round is needed. It hardens the id-index
projection that the later Phase C plan-chain rounds build on.
