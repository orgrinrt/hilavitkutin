# Source changelist

Replace `transmute_copy` id projection with typed accessors built on arvo's
`to_raw` / `from_raw`. Verified by `cargo test -p hilavitkutin -p hilavitkutin-api`
and the greps below.

## CHANGE: add `index` + `from_index` to `UnitId`
File: `mock/crates/hilavitkutin-api/src/dispatch_codegen.rs`
`UnitId` gains `pub const fn index(self) -> USize` and `pub const fn from_index(USize) -> Self`, built on `Uint<16>::{to_raw, from_raw}`.
Verification: `grep -c "pub const fn index\|pub const fn from_index" dispatch_codegen.rs` returns 8 (one pair per id type).

## CHANGE: add `index` + `from_index` to `FiberId`, `PhaseId`, `TrunkId`
File: `mock/crates/hilavitkutin-api/src/dispatch_codegen.rs`
Same accessor pair on `FiberId(Uint<7>)`, `PhaseId(Uint<5>)`, `TrunkId(Uint<6>)`, each over its own `Uint<N>`.
Verification: covered by the count above.

## CHANGE: rewrite the four engine-id `Debug` impls to use `index`
File: `mock/crates/hilavitkutin-api/src/dispatch_codegen.rs`
The `Debug` impls for `UnitId` / `FiberId` / `PhaseId` / `TrunkId` print `self.index()` instead of `transmute_copy`.
Verification: `! grep -n "transmute_copy" dispatch_codegen.rs`.

## CHANGE: delete the four `size_of` layout-assertion consts
File: `mock/crates/hilavitkutin-api/src/dispatch_codegen.rs`
The `const _: () = assert!(size_of::<Id>() == N)` blocks are removed; `to_raw` is strategy-aware so the drift they guarded cannot silently misread.
Verification: `! grep -n "size_of::<PhaseId>\|size_of::<UnitId>\|size_of::<FiberId>\|size_of::<TrunkId>" dispatch_codegen.rs`.

## CHANGE: replace `transmute_copy` projections in the plan stage with accessors
Files: `mock/crates/hilavitkutin/src/plan/graph.rs`, `plan/steps.rs`, `plan/mod.rs`, `plan/core_program.rs`
Every `transmute_copy` that projects an id to a raw int (for indexing) or a raw int back to an id becomes `id.index()` / `Id::from_index(USize(..))`. Array-index sites read the `usize` via the `USize` accessor.
Verification: `! grep -rn "transmute_copy" mock/crates/hilavitkutin/src/plan/`.

## Note on the remaining `lint:allow`
The container-to-`usize` crossing lives once per id type inside `index` / `from_index` (the typed-id to array-index boundary), under `lint:allow(no-bare-numeric)` with a `tracked: #339` reason. This replaces roughly thirty scattered allows (two per transmute site, plus the four layout-assertion-const allows) whose reasons cited the stale `#428`.
