## A1. Trybuild fixture for double-derive rejection

Per Topic 3 S2 + audit-2 M5 (referenced in the megaround src CL): the engine must reject the `#[derive(Resource)] + #[derive(RunCfg)]` combination on the same type with a coherent compile error. The locked CL placed the fixture at `mock/crates/hilavitkutin-api/tests/trybuild/double_derive_runcfg.rs` and named the verification command `test -f` against that path. The file did not ship in PR #75.

This round ships the fixture and the `trybuild` test harness wiring needed to run it. `trybuild` is a dev-dependency; the test enumerates expected-fail cases and asserts the compile-error message matches.

The fixture itself is a `.rs` file containing the double-derive combination. The expected error message becomes the golden `.stderr` file alongside it. The test runner declared in `crates/hilavitkutin-api/tests/trybuild.rs` (new) loads the `tests/trybuild/` directory and runs each fixture.

## A3. `ema_update` slice-type pivot

Per the post-review-fix round 202605232000's "out of scope" section, reviewer concern #6: `ema_update`'s `&mut [USize]` slice type uses `USize` (platform-pointer-width) where the EMA samples are not pointer-shaped. EMA samples are timing nanoseconds (u64-ish), record counts (u32-ish), or cache-residency ratios (u16-ish). The right shape is a domain-specific `Sample` alias rooted on a workspace-fixed `UFixed<{ibits(64)}, {fbits(0)}, Hot>` (or similar concrete width).

This round pivots `ema_update`'s signature from `&mut [USize]` / `&[USize]` to `&mut [Sample]` / `&[Sample]` where `Sample` is a `pub type` alias declared alongside `BlendFactor` in `adapt_ema.rs`. The body remains the structural stub; the bench-validated kernel still lands with the executor wiring in a subsequent round.
