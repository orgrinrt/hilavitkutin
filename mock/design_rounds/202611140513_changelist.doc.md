# doc changelist

Round topic `202611140512_topic.sound-memory-provider.md`. The other flat topic, `202607200100_topic.b1-cap-lifting-completion.md`, is about lifting the scheduler's scratch arrays onto the plan's capacities. This round changes the memory provider contract and the providers that implement it, none of those arrays, so it needs nothing from this round and stays flat for the round that does.

The evidence is the Miri run committed at `mock/research/202611140512_sound-memory-provider/miri-resource-snapshot-before.txt`, which the topic quotes. No sketch stands under the round: the shape is the api's own trait marked unsafe, and the provider's soundness is shown by Miri over the moved tests, not by a spike.

Canon: `later_modules_of_the_providers_crate_add_column_storage_clock_and_memory_defaults_per_consumer_demand` (held) and `clock_and_libc_unix_memory_provider_defaults_land_in_their_own_rounds_when_consumer_demand_surfaces` (provisional, stamped) place a memory default in `hilavitkutin-providers`, in its own round, on demand; `every_crate_is_no_std_with_no_allocation_and_the_consumer_provides_the_memory_provider` keeps it a provider the consumer chooses, not one the engine installs. The canon is silent on whether the provider trait is safe or unsafe; the round decides it from what the engine's unsafe code relies on, which is mechanism and the api design's to state.

## Current state

`hilavitkutin-api/DESIGN.md.tmpl` names `MemoryProviderApi` as a platform contract and as what `ColumnStorage` allocates through, and says nothing of what an implementation must keep. The code declares it a safe trait.

`hilavitkutin-providers/DESIGN.md.tmpl` ships the interner and `ArenaColumnStorage` and lists the memory provider default as deliberately not shipped. Its `BACKLOG.md.tmpl` lists ColumnStorage, Clock and memory defaults as future modules, though the ColumnStorage default has landed. Its `README.md.tmpl` says the same.

`hilavitkutin/DESIGN.md.tmpl` (Platform implementations) says the os tier maps memory with mmap and does not say how that keeps any contract.

## Changes proposed

1. `hilavitkutin-api/DESIGN.md.tmpl`, a new subsection under Unified columnar storage, "The memory provider is an unsafe trait": the trait is `pub unsafe trait MemoryProviderApi`, the four promises an implementation makes (aligned and valid for `len`; valid at one address until `deallocate` or drop, across moves of the provider; disjoint; callable from several threads), null as the refusal, and the per-method `# Safety` sections kept as the caller's half.
2. `hilavitkutin-providers/DESIGN.md.tmpl`: `StaticBumpMemory` in the intro, a row in the Surface table and a section of its own (built over `&'static mut [MaybeUninit<u8>]`, address-aligned bump by compare-exchange, null past the end or on a non-power-of-two align, `deallocate` and `protect` do nothing, how it keeps the four promises). The "does not ship" bullet narrows to the Clock and operating-system memory defaults.
3. `hilavitkutin-providers/BACKLOG.md.tmpl`, Future provider modules: the Clock and operating-system memory defaults remain; ArenaColumnStorage and StaticBumpMemory are recorded as landed.
4. `hilavitkutin-providers/README.md.tmpl`: names what ships, `StaticBumpMemory` among it.
5. `hilavitkutin/DESIGN.md.tmpl`, Platform implementations: how the os tier's provider keeps the promises (a fresh mapping per block, freed only by `munmap`), that an `align` wider than a page or not a power of two is refused with null, and that the null provider refuses everything.
