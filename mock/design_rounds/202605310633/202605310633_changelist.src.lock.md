# Source changelist: route the resource arena through ColumnStorage

The engine becomes generic over `CS: ColumnStorage` where it was generic
over `M: MemoryProviderApi`. The resource arena reserves its per-resource
memory through the store instead of allocating directly. Resources
tighten to `ColumnValue`. Zero-sized resources skip the reserve and
record a dangling pointer. `DropArena` and the scheduler's `Drop` are
removed; the store frees resource memory on its own `Drop`.

TDD: the red test lands first as the adapted `resource_arena.rs` round
trip building over a `ColumnStorage`; it fails to compile against the
pre-migration `build<M: MemoryProviderApi>` signature, then passes once
the source migrates.

## CHANGE: `DrainStores::drain` FROM `fn drain<M: MemoryProviderApi>(self, mp: &M)` TO `fn drain<CS: ColumnStorage>(self, cs: &mut CS, next_id: &mut USize)`
File: `mock/crates/hilavitkutin/src/resource/arena.rs`
The resource arm reserves a one-record column under `StoreId(*next_id)`
via `cs.reserve::<T>`, increments the counter, writes the value through
`cs.column_ptr_mut::<T>`, and records `ResourcePtr::new_unchecked` of
that pointer. A zero-sized `T` (`size_of::<T>() == 0`) skips the reserve
and records `NonNull::<T>::dangling()`. Column and virtual arms pass the
counter through unchanged. On `reserve` error the partial arena is
dropped trivially (Copy pointers, no destructors) and
`BuildError::AllocationFailed` returns.
Verification: `grep "fn drain<CS: ColumnStorage>" mock/crates/hilavitkutin/src/resource/arena.rs` returns one match; `! grep "MemoryProviderApi" mock/crates/hilavitkutin/src/resource/arena.rs`.

## CHANGE: `DrainStores` resource-arm bound FROM `T: 'static` TO `T: ColumnValue`
File: `mock/crates/hilavitkutin/src/resource/arena.rs`
The `Sv<StagedResource<T>, L>` `DrainStores` impl requires
`T: ColumnValue` so `cs.reserve::<T>` / `cs.column_ptr_mut::<T>` are
callable. `ArenaFor` arms keep `T: 'static` (they only name the arena
shape and never reserve); `ColumnValue: Copy + 'static` so `ArenaFor`
stays satisfied.
Verification: `grep "T: ColumnValue, L" mock/crates/hilavitkutin/src/resource/arena.rs` matches the resource DrainStores impl.

## CHANGE: trait `DropArena` REMOVED
File: `mock/crates/hilavitkutin/src/resource/arena.rs`
With `Copy` resources the arena holds only raw pointers; the store frees
the bytes on its own `Drop`, so no per-node destructor walk exists. The
`ArenaFor::Arena: DropArena` supertrait bound is dropped to `type Arena`.
Verification: `! grep "DropArena\|drop_arena" mock/crates/hilavitkutin/src/resource/arena.rs`.

## CHANGE: struct `NullColumnStorage` ADDED
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
A no-op `ColumnStorage` (`type Error = ()`; `reserve` returns
`Outcome::Err(())`; `column_ptr` / `column_ptr_mut` return null; `count`
returns `USize::ZERO`; `release` no-op). It is the default `CS` for the
bare `Scheduler` type, mirroring `NullMemoryProvider`. Used only as the
no-store default; a scheduler that owns resources is built with a real
store.
Verification: `grep "pub struct NullColumnStorage" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match; `grep "impl ColumnStorage for NullColumnStorage" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match.

## CHANGE: `Scheduler` parameter FROM `M: MemoryProviderApi = NullMemoryProvider` TO `CS: ColumnStorage = NullColumnStorage`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
The `memory_provider: M` field becomes `storage: CS`. The `__arena`
accessor stays; `__memory_provider` is removed (its only users were
tests now reworked). `NullMemoryProvider` stays (the providers and the
api still use the `MemoryProviderApi` trait; the engine just no longer
parameterises `Scheduler` on it directly).
Verification: `grep "CS: ColumnStorage" mock/crates/hilavitkutin/src/scheduler/mod.rs` matches the struct and impl headers; `! grep "memory_provider" mock/crates/hilavitkutin/src/scheduler/mod.rs`.

## CHANGE: `Scheduler` `Drop` impl REMOVED
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
The `storage: CS` field's own `Drop` reclaims resource memory; the arena
field holds only Copy pointers. No scheduler `Drop` remains.
Verification: `! grep "impl.*Drop.*for.*Scheduler" mock/crates/hilavitkutin/src/scheduler/mod.rs`.

## CHANGE: `SchedulerBuilder::build` / `build_with` FROM `(self, memory_provider: M)` TO `(self, storage: CS)`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
`build<CS: ColumnStorage>(self, storage: CS)` threads `&mut storage` plus
a fresh `USize::ZERO` drain-order counter into `DrainStores::drain`, then
moves `storage` into the `Scheduler`. `BuiltScheduler` alias and the
return types update from `..., M>` to `..., CS>`.
Verification: `grep "fn build<CS: ColumnStorage>" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match.

## CHANGE: `hilavitkutin-providers` ADDED as dev-dependency

`[dev-dependencies] hilavitkutin-providers.workspace = true` so the

## CHANGE: resource-arena tests rehabbed to the ColumnStorage build shape
File: `mock/crates/hilavitkutin/tests/resource_arena.rs`
`Ra` / `Rb` / `Rc` gain `#[derive(Copy, Clone)]` (they are `ColumnValue`
now). `.build(provider)` becomes `.build(ArenaColumnStorage::new(provider))`.
The `resource_arena_drop_runs_destructor` (`DropCounter`) test is removed:
non-Copy destructor resources are no longer supported. The
`build_records_one_allocation_per_resource` test is removed: its only
mechanism was `__memory_provider`, and the alloc-per-resource and
no-premature-dealloc properties are already asserted by
`resource_arena_drop_deallocates`. `allocation_failure_returns_err`
builds over `ArenaColumnStorage::new(NullMemoryProvider)`.
Verification: `cargo test -p hilavitkutin --test resource_arena` passes; `! grep "__memory_provider\|DropCounter" mock/crates/hilavitkutin/tests/resource_arena.rs`.

## CHANGE: scheduler_builder / engine_ctx / fiber_walk / scheduler_run_walk tests rehabbed
File: `mock/crates/hilavitkutin/tests/{scheduler_builder,engine_ctx,fiber_walk,scheduler_run_walk}.rs`
Every `.build(provider)` / `.build(provider())` wraps the provider in
`ArenaColumnStorage::new(...)`. Resource value types registered via
`.with(Resource::new(...))` gain `#[derive(Copy, Clone)]`: `Interner`
and `S0`..`S15` (ZSTs) in scheduler_builder; `Ra` / `Rb` in fiber_walk
and scheduler_run_walk. `Workspace` is Kit-owned only (never drained),
so it needs no derive. engine_ctx registers `u32` resources only (already
`ColumnValue`).
Verification: `cargo test -p hilavitkutin` builds and passes all five integration test files.
