# Route the resource arena through ColumnStorage

The unified columnar storage arc (task #654) puts all engine runtime
state behind one `ColumnStorage` contract over a `MemoryProvider`, with
no bespoke per-subsystem arenas. The contract and a naive arena-backed
default impl already landed (`hilavitkutin-api::ColumnStorage`,
`hilavitkutin-providers::ArenaColumnStorage`). This round migrates the
first real bespoke arena onto that contract: the resource arena that
`Scheduler::build` drains from the registered store values.

## Current state

`mock/crates/hilavitkutin/src/resource/arena.rs` holds a type-level
cons-list arena. `DrainStores::drain<M: MemoryProviderApi>(self, mp)`
allocates one block per registered `Resource<T>` directly through the
`MemoryProvider` (`mp.allocate(size_of::<T>(), align_of::<T>())`),
`ptr::write`s the moved-in value, and records a `ResourcePtr<T>` in an
`ArenaResourceNode<T, Tail>`. `DropArena::drop_arena<M>(&mut self, mp)`
runs the inverse on scheduler drop: `drop_in_place` then
`mp.deallocate`. `Scheduler` is generic over `M: MemoryProviderApi`,
holds the provider in a `memory_provider` field, and its `Drop` walks
the arena to free every block. Column and virtual nodes are no-alloc
placeholders.

This is the bespoke arena the arc forbids: it allocates outside the
`ColumnStorage` contract, so resource memory is not part of the unified
store the columnar engine will later own and reclaim.

## Changes proposed

Route the resource arena's per-resource allocation through a
`ColumnStorage` instead of a raw `MemoryProvider`. Each registered
`Resource<T>` reserves a one-record column in the store and the node
records a `ResourcePtr<T>` derived from the column base pointer. The
store owns the bytes and frees them on its own drop.

Concretely:

1. The engine becomes generic over `CS: ColumnStorage` where it was
   generic over `M: MemoryProviderApi`. The engine depends on the
   storage trait (in `hilavitkutin-api`, already a dependency), not on
   the default impl (in `hilavitkutin-providers`). Consumers and tests
   wire the concrete storage, the same way they wire a provider today.
   This keeps the layering clean: the engine never depends on
   `hilavitkutin-providers`.

2. `DrainStores::drain` takes `&mut CS` and a drain-order counter. Per
   `Resource<T>` it reserves a one-record column under a private
   drain-order `StoreId`, writes the value through the store's mutable
   column pointer, and stores the resulting `ResourcePtr<T>` in the same
   `ArenaResourceNode<T, Tail>`. The node shape is unchanged, so the
   per-WorkUnit `EngineCtx` resource accessor (a type-keyed `Selector`
   over the node's recorded pointer, which never reads a `StoreId`) is
   unchanged.

3. Resources tighten from `T: 'static` to `T: ColumnValue`. The
   `ColumnValue` blanket impl (`impl<T: Copy + 'static> ColumnValue`)
   means any `Copy + 'static` resource qualifies directly, with no
   `Decompose` derive. Non-`Copy` resources with destructors are no
   longer supported as a resource value: the store frees bytes but runs
   no per-element destructor, so a resource that needs `Drop` has no
   place to run it. This drops a previously-tested capability
   (destructor-running resources), accepted as a consequence of the arc.

4. Zero-sized resources skip the reserve entirely and record a dangling,
   well-aligned pointer (`NonNull::dangling`). A ZST occupies no bytes,
   so a zero-byte column reservation would hand back a null base pointer
   (the store has nothing to allocate), and `ResourcePtr` is non-null by
   construction. Writing and reading a ZST through any aligned non-null
   pointer is sound. This is the ZST-resource guard tracked as #622.

5. `DropArena` is removed. With `Copy` resources the arena holds only
   raw pointers (no destructors to run), and the store frees the bytes
   on its own `Drop`. The scheduler's `Drop` impl is removed; the
   store field's `Drop` reclaims all resource memory.

6. The engine ships a `NullColumnStorage`: a no-op `ColumnStorage` that
   reserves nothing and hands back null pointers. It is the default
   `CS` parameter for the bare `Scheduler` type (mirroring the existing
   `NullMemoryProvider` default), so a no-store scheduler needs no
   dependency on `hilavitkutin-providers`.

## De-risk

The load-bearing correctness invariant is that a recorded
`ResourcePtr<T>` survives subsequent reserves: the node records the
pointer at drain time and the accessor dereferences it later at run
time. `ArenaColumnStorage` is a flat slot table indexed by `StoreId`,
where each reserved column is a separate `MemoryProvider` allocation in
its own slot. Reserving a distinct `StoreId` allocates independently and
does not touch other slots, so recorded pointers stay valid across the
remaining drains. The drain assigns each resource a distinct
drain-order `StoreId`, so the re-reserve path (which would free a prior
allocation) is never taken.
