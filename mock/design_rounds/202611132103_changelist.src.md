## CHANGE: the cross-target check
Files: `mock/tools/cross-target/Cargo.toml`, `mock/tools/cross-target/Cargo.lock`, `mock/tools/cross-target/src/lib.rs`, `mock/tools/cross-target/src/tests.rs`, `mock/tools/cross-target/run.cjs`, `mock/tools/cross-target/probe/Cargo.toml`, `mock/tools/cross-target/probe/Cargo.lock`, `mock/tools/cross-target/probe/src/main.rs`.
The tool of section 3 of the doc changelist. `mock cross-target <target>` builds the probe beside it for the host and for the target named, runs both, and compares the two digest streams frame by frame. A frame that differs is a finding at error. A build or a run that fails, and a target it has no runner for, make the run inconclusive. The probe runs the nine units under the faithful runner for eight frames and prints the digest of each frame's stores. Run here it reports the same eight digests for the host and for `wasm32-unknown-unknown`.

The target is a required argument, which is the tool's reason for not being a lint in the terms the tool contract offers: it takes a question. The design says "for the host and for wasm". Wasm is the one target the tool has a runner for, and a second target is one more line in its table.

The probe is a workspace root of its own and takes the four frozen files by `#[path]`, where the design's sentence would have it depend on the frozen crate. It cannot. The frozen crate takes the engine's default platform tier, that tier does not compile for wasm, and a second crate in the same graph that asks for the tier without an operating system turns both on, which the engine refuses. So the probe names the engine's tier per target in its own manifest and compiles the frozen files themselves, the same bytes the ledger holds. Ticket 3b60507373b9 is the engine's side of it, and it bears on 429c63bdea5c, a unit naming the engine's context type.

A wasm build is run under node, by `run.cjs` beside the tool: node is the wasm runtime this machine has. The probe hands each digest to an imported `emit`, and the script prints it the way the host's build prints its own.

The tool is a root of its own as well, the shape `mock test` reaches a tool in, and both roots commit their lockfile as the other nested roots of the repository do.

Its tests hold the parsing of a stream and the comparison over words written by hand, and run the whole path twice: the probe as it is, which has to leave no difference, and the probe with its `skew` feature, under which the wasm build folds one word more into the last frame, which has to leave exactly one, at frame 8.
