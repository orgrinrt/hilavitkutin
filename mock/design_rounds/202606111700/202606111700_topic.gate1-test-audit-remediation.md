# GATE-1 test-audit remediation

Before the GATE-1 capstone PR, the all-green pre-merge audit walked the
`hilavitkutin` engine test suite. The suite passes green, and most of it
(dispatch walk, column round-trip, accumulator, morsel windowing, phase
sequencing, incremental skip one-hop) exercises real contracts and would catch
regressions. The audit surfaced three items that fail the meaningfulness bar and
one coverage gap that must close before the suite is sound enough to gate the
merge. This round remediates them. Test-only; no engine source or doc surface
changes.

## What the audit found

Two dead placeholder tests survive from before the real dispatch landed, and
their framing is now stale:

- `tests/scheduler_run.rs` (`scheduler_run_returns_default_outcome`) builds a
  zero-unit `Scheduler::default()` and asserts `run()` returns `Ok(())`. Its doc
  comment calls `run` a "no-op transitional body" waiting on the real morsel
  loop. The real dispatch shipped rounds ago; this test runs no unit, walks no
  morsel, and cannot fail on any dispatch bug. The real `run` behaviour is
  covered by `scheduler_run_walk`, `column_dispatch`, `morsel_outer`,
  `incremental_skip`, and `fused_linear_chain`.
- `tests/dispatch_codegen.rs` (`_dispatch_codegen_validated_in_followup`) is an
  empty test body reserving the file for "subsequent rounds". The codegen tier
  shipped; the real path is exercised by the dispatch tests above.

Both are removed: a dead placeholder that cannot fail is worse than no test (it
reports coverage that does not exist).

One test has a fragile readback:

- `tests/fused_linear_chain.rs` reads the `Cv` output column through
  `__bindings().__tail().__tail().__tail().__ptr().as_ptr() as *const u32`, a
  hardcoded three-deep tail walk cast straight to `u32`. The cast erases the
  binding node's type, so a future change to column registration order would
  silently read a different column. The fix pins the node type at compile time
  (`let cv_ptr: ColumnPtr<Cv> = ...`), so a registration reorder that moves `Cv`
  off the third tail fails to compile rather than reading the wrong buffer.

One coverage gap:

- `incremental_skip` tests a single RAW hop (producer to consumer). The
  canonical Step 9 contract is that dirt propagates transitively over the
  predecessor masks, so a two-hop chain (root to A to B) must re-run both
  dependents when only the root is marked. A second test adds a producer to
  consumer to second-consumer chain plus an unrelated unit, marks only the root,
  and asserts the whole three-unit cone re-runs while the unrelated unit stays
  clean and skipped. This proves propagation at depth two, which the one-hop
  test cannot.

## Out of scope

The audit also noted that `scheduler_run_walk`'s topological-order test uses a
fixture where registration order and topological order coincide. That is the
provisional GATE-1 design (registration order is build-validated to be
topological; RCM auto-ordering that would diverge them is post-GATE-1, op call
(a)/(b) in the roadmap). The positive ordering test plus the
build-rejects-anti-topological test cover the current contract; the diverging
case lands with the RCM recovery work, not here.
