## CHANGE: remove dead placeholder test `scheduler_run.rs`
File: `mock/crates/hilavitkutin/tests/scheduler_run.rs` (deleted)
Verification: `! test -f mock/crates/hilavitkutin/tests/scheduler_run.rs`.

The test built a zero-unit `Scheduler::default()` and asserted `run()` returns
`Ok(())`. The doc comment framed `run` as a "no-op transitional body"; the real
dispatch shipped rounds ago. The test runs no unit and cannot catch a dispatch
bug. The real `run` behaviour is covered by `scheduler_run_walk`,
`column_dispatch`, `morsel_outer`, `incremental_skip`, `fused_linear_chain`.

## CHANGE: pin `fused_linear_chain` readback store identity at compile time
File: `mock/crates/hilavitkutin/tests/fused_linear_chain.rs`
Verification: `grep "ColumnPtr<Cv>" mock/crates/hilavitkutin/tests/fused_linear_chain.rs` returns one match; `cargo test -p hilavitkutin --test fused_linear_chain` passes.

The `Cv` readback walked three `__tail`s and cast straight to `*const u32`,
erasing the binding node type. Annotate the node pointer
`let cv_ptr: ColumnPtr<Cv> = sched.__bindings().__tail().__tail().__tail().__ptr();`
so a registration reorder that moves `Cv` off the third tail fails to compile
rather than silently reading another column.

## CHANGE: add two-hop dirty-propagation test to `incremental_skip.rs`
File: `mock/crates/hilavitkutin/tests/incremental_skip.rs`
Verification: `grep "two_hop" mock/crates/hilavitkutin/tests/incremental_skip.rs` returns matches; `cargo test -p hilavitkutin --test incremental_skip` passes.

Add a second test with a producer to consumer to second-consumer RAW chain
(root `Resource<InA>` -> `Column<Ca>` -> `Column<Cb>` -> `Column<Cd>`) plus an
unrelated `Resource<InC>` -> `Column<Ce>` unit. After the cold and clean frames,
marking only `Resource<InA>` must re-run all three chained units (propagation at
depth two over the predecessor masks) and skip the unrelated unit. The existing
one-hop test cannot exercise depth-two transitive propagation.
