## CHANGE: the engine's spawn-site gate FROM checked by hand TO a repo lint

Files: `mock/lints/engine_spawn_through_gate.rs` (new), `mock/lints/engine_spawn_through_gate/tests.rs` (new), `mock/mockspace.toml` (`[lints.engine-spawn-through-gate]`, error at every gate).

`engine-spawn-through-gate` reads every file under the `hilavitkutin` crate's `src/`. It refuses a `spawn` method or path call (`.spawn(`, `::spawn(`, with or without a turbofish) outside the body of `fn spawn_one_pointer`, and a `spawn` inside that body that no earlier `let () = OnePointerClosure::<..>::FITS;` precedes. Comments, doc comments, string and char literals are not read; a lifetime does not open a char literal. The escape is `lint:allow(engine-spawn-through-gate)` on the line. The tests sit in a subdirectory because the lint discovery reads only `mock/lints/*.rs`, and a sibling file there would be taken for a lint; the split keeps both files under 500 lines after the commit hook's rustfmt.

Eighteen unit tests, run by `cargo mock test` (and by `cargo test` in the generated lint crate): the shipped shape clean; look-alikes that must pass (`spawn_one_pointer(` calls, `spawned`, `respawn`, a `fn spawn` declaration, comments, block comments across lines, strings, escaped quotes, char literals, the allow); and every refused shape (a direct spawn elsewhere, eight call spellings, the forcing deleted, the forcing as `let _ =`, as a bare statement, naming another const or another type, the forcing after the spawn, a spawn after the gate body closes, a one-line gate fn without the forcing, a gate fn by a longer name).

Negative controls on the lint: with the forcing no longer required inside the body, four tests failed; with spawns outside the body no longer reported, six failed. Both restored and re-run green.

Planted in the real engine, `cargo mock --lint-only`:

- `let () = OnePointerClosure::<F>::FITS;` deleted from `spawn_one_pointer`: `[engine-spawn-through-gate] hilavitkutin/src/scheduler/run_parallel.rs:59: [error] `spawn_one_pointer` spawns before ...`, `lint check failed: 1 violation(s)`, exit 1.
- `spawn_one_pointer(pool, move || {` replaced by `pool.spawn(move || {`: `[engine-spawn-through-gate] hilavitkutin/src/scheduler/run_parallel.rs:184: [error] a `spawn` call outside `spawn_one_pointer` ...`, `lint check failed: 1 violation(s)`, exit 1.

Both restored; `git status` clean on the engine afterwards.

Verification: `cargo mock lints | grep engine-spawn-through-gate` shows `error  set here`, and `cargo mock --lint-only --strict` passes on the tree as committed.

## CHANGE: the thread-count bound FROM unstated in code TO a `FIXME:` and a catalogue test

Files: `mock/crates/hilavitkutin/src/scheduler/run_parallel.rs` (comment), `mock/crates/hilavitkutin/tests/gate2_worker_count.rs`.

The `FIXME:` at the `runnable_worker_count` call says the engine hands out one closure per clamped worker where the principles bound it at `min(worker_count, parallelisable_width + 1)`, and what the fix needs: the widest phase's trunk count off the `phase` and `trunk` arrays computed just above, and every reader of `gate2_ncores` checked against a count below the executor's.

`an_executor_wider_than_the_plan_gets_width_plus_one` is `#[ignore = "catalogue: ..."]`: an executor reporting 8 runs the fan-in, whose widest phase carries two trunks (the split `gate2_run_parallel.rs` relies on), and expects 3 closures. Run with `--ignored` it fails `left: 8, right: 3`, the right failure. `an_executor_narrower_than_the_plan_gets_its_own_count` passes and pins the other side of the `min`: an executor reporting 2 gets 2. When the bound lands, `an_executor_reporting_past_max_cores_runs_the_frame_on_max_cores` changes with it, since it expects 256 closures for a width-two plan.
