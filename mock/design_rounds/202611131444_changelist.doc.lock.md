# doc changelist

**Round:** 202611131444
**Phase:** DOC
**Source topics:** `202611131438_topic.the-workflow-pack-and-its-tools.md`

The registry round left the canon tools for the day the shared pack carried them. The pack carries them now, behind its `workflow` feature, and this changelist turns the feature on and puts the registry in the shape its lints hold. No crate design changes, and no template under a crate is touched.

The feature is one switch. It brings the tools that read the canon and search what was said, the ticket tools, and seven lints over the registry and the placeholder markers, all at error. Four of the seven fire on the tree as it stood, and the topic counts them. Each is met by changing what it found, and `mockspace.toml` gains no exemption and changes no severity.

The trunk was merged before this changelist opened, since it had moved by seven commits and carried a closed round of its own. Its merge is commit `f254a3d`, and the citations it shifted were moved in `510088e`.

## Changes

### CHANGE 1: `mockspace.toml`, the pack and its feature

The `[lint-crates]` entry names the pack by the repository's present name, `mockspace-extra-lints`, where it named the one the repository had before. The old name still redirects, so nothing was failing. The entry gains `features = ["workflow"]`, in the commit that also carries the marker edits of CHANGE 6, because the feature's lint on markers is red until they are made.

### CHANGE 2: `mockspace.toml`, the pack's kinds

The kinds the feature reads and writes beside `subject` and `tenet` are declared as the pack declares them: `note`, the ticket kinds (`ticket_state`, `ticket_kind`, `ticket`, `ticket_move`), planning (`milestone`, `milestone_merge`, `plan_span`, `milestone_scope`, `member`, `window`, `plan_slot`, `plan_kind_role`, `plan_state_role`), `change`, `landing`, `review`, `repo` and `known_red`. One path in their descriptions, garbled in the pack's file, is written as the directory it means.

`mock/registry/ticket/states.toml`, `mock/registry/ticket/kinds.toml` and `mock/registry/plan/roles.toml` are the rows the pack starts a registry from, copied unchanged.

### CHANGE 3: `mockspace.toml` and the tenet rows, `rules_out` and `rejects`

`rules_out` takes the pack's description: the words and names a tenet rules out of designs, code and content, which the lint `a-retired-word-stays-out` and `cargo mock canon contradicts` match against the tree. The readers had written prose in it, 238 entries on 137 rows. A tenet gains the field `rejects` for that prose, described as what the source passage says the tenet rejects, and every entry moves there unchanged.

`rules_out` is then empty on every row. That is a statement about the tree and not about the record: the principles do retire words, and no design or source line has been cleared against these rows yet, so no word is held by this lint today. The dead terms stay held where they were, by the repository's own `vocabulary-discipline` lint. Naming the retired words row by row, each in the change that clears the tree of it, is work a later round does.

### CHANGE 4: the tenet rows, `cites` and `related`

`cites` holds the tenets a row's `what` and `because` name by id, and nothing else, which is how the pack's graph reads it. No row's words name another row by id, so `cites` is empty on every row, and the 450 relations it held move to `related` as `tenet::` links, where the pack keeps a relation the words do not make. No relation is dropped: 450 entries in `cites` and 43 in `related` before, 493 in `related` after.

### CHANGE 5: the tenet rows, `subject` beside `id`

`subject` is written on the line after `id` in every tenet row. The pack's lint on subjects reads the files by line and takes a quote line that opens with a bracket for the start of a table, which hid the `subject` of two rows. The order of fields in a row carries no meaning.

### CHANGE 6: tasks for the placeholder markers

`cargo mock owed` files one task per group of placeholder markers under `mock/registry/ticket/` and rewrites each marker to cite its task. There are 18 markers in five crates: 13 cite no ticket, and 5 cite four tickets of the workspace's tracker, which this registry does not have. The task filed for those carries the workspace ticket's id in its title. The edits to source are comments only, and the src changelist lists them.

### CHANGE 7: `mockspace.toml`, the tools' tables

`already-said`, `unearth`, `corpus`, `tackle` and `tickets` are given `maintainer_words` and `maintainer_names`. The captured words are kept by the workspace this repository is cloned into, one directory up, so the path is relative and leaves the repository. In a clone that stands alone the tools say the directory was not read and answer from the repository's own record. `owed` is given no holder, so the tasks it files are held by nobody until somebody takes them.
