# Src changelist: no source change, and two corrections to this round's own doc CL

**Date:** 2026-08-10
**Phase:** IMPL
**Doc CL:** `202608101600_changelist.doc.lock.md`

No source file changes. This changelist exists to close the round and to record
two defects in the doc changelist that this round locked, both of the class the
round is about.

## CORRECTION: the verification did not run before the lock

The doc CL says its verification is "run as a command against `git show HEAD`
before this changelist locks". It was not. The changelist was written, committed
and locked, and only then was the edit made and the command run.

The result is the same and the process was not, which is exactly the gap the
topic names: at the moment a verification line is written, the intent to make an
edit is indistinguishable from having made it. Writing that sentence into a
changelist did not stop it happening in the same changelist.

## CORRECTION: the second verification is case-wrong as stated

The doc CL says `grep -c 'stale rendering'` returns 1. The file says
`A STALE RENDERING`, so the literal command returns **0**.

The substance holds and the stated check does not, which is the harder version to
catch, because the claim reads as verified. `grep -ci 'stale rendering'` returns
1, and that is the command that should have been written.

**The file is not being edited to make the grep true.** Bending a subject to match
a check that was written wrongly is how a check stops measuring anything, and the
correction belongs to the changelist rather than to the file.

## Verified, against `git show HEAD` rather than the working tree

`grep -c 'no template behind this file'` returns 0. `grep -ci 'stale rendering'`
returns 1. Both run after the autofix, against what landed.

## What is owed and is not this round's

failed twice in two rounds, which is worth knowing when the lint is prioritised.
