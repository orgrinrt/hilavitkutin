# Src changelist: morsel dispatch doc + per-morsel execute contract

**Date:** 2026-06-04
**Phase:** SRC

Rustdoc-only. Three doc comments updated to match the windowed dispatch landed in round 202606041609. No behaviour change.

## CHANGE: `Scheduler::run` rustdoc describes windowed dispatch
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Replace the "over a single full-range morsel" / "over a single morsel covering the record count" sentences in the `run` doc comment with the windowed-dispatch description: `run` windows `[0, record_count)` into morsels of `RunCfg::MORSEL_SIZE` and dispatches each unit once per morsel (unit-outer). The separate note that the full phase-sequential, codegen'd morsel loop waits on later tiers is retained.
Verification: `! grep "single morsel covering" mock/crates/hilavitkutin/src/scheduler/mod.rs` (the stale phrase is gone).

## CHANGE: `WorkUnit::execute` rustdoc states the per-morsel calling convention
File: `mock/crates/hilavitkutin-api/src/work_unit.rs`
Add to the `execute` doc that the engine invokes `execute` once per morsel, and that all per-record and accumulating work must flow through the morsel-aware Context accessors (`each` / `reduce` / `batch` / `read` / `write` / `append`); a side effect placed in `execute` outside those accessors runs once per morsel.
Verification: `grep "once per morsel" mock/crates/hilavitkutin-api/src/work_unit.rs` returns a match.

## CHANGE: `AccumWriterApi::append` rustdoc notes per-record append
File: `mock/crates/hilavitkutin-api/src/context.rs`
Add a one-line note to `append` that appends should be driven by the per-record loop so the total equals the record count across morsels, not issued as a fixed count in `execute`.
Verification: `grep "per-record" mock/crates/hilavitkutin-api/src/context.rs` returns a match in the append doc.
