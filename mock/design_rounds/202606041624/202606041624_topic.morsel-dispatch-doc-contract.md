# Topic: morsel dispatch doc + per-morsel execute contract

**Date:** 2026-06-04
**Scope:** rustdoc only, in `hilavitkutin` (`scheduler/mod.rs`) and `hilavitkutin-api` (`work_unit.rs`, `context.rs`). Post-review fix on branch `feat/hilavitkutin-morsel-loop`, atop round `202606041609`.
**Source topics:** the morsel-loop-windowing round (`202606041609`); the PR #121 local review.

The morsel-loop round windowed `Scheduler::run`'s dispatch but left two rustdoc surfaces describing the pre-windowing world:

1. `Scheduler::run`'s own doc comment still says it dispatches "over a single full-range morsel" and "runs `execute` over a single morsel covering the record count". That is exactly what the round changed. The design doc (`DESIGN.md.tmpl`) was updated; the method rustdoc, which renders to docs.rs, was not.

2. `WorkUnit::execute`'s doc says only "run one pass" with no statement of the calling convention. Windowing changed `execute` from once-per-frame to once-per-morsel. The contract that makes this safe is unstated: per-record and accumulating work flows through the morsel-aware accessors (`each` / `reduce` / `batch` / `read` / `write` / `append`), which the run-loop windows correctly; a side effect placed in `execute` outside those accessors runs once per morsel, so it multiplies by the morsel count once `record_count` exceeds `MORSEL_SIZE`. The model is morsel-driven bodies; this round states it.

## Round changes (rustdoc only)

1. `Scheduler::run` rustdoc (`scheduler/mod.rs`): replace the "single morsel" sentences with the windowed-dispatch description (windows `[0, record_count)` into morsels of `RunCfg::MORSEL_SIZE`, dispatches each unit once per morsel, unit-outer). The separate note that the full phase-sequential / codegen'd morsel loop still waits on later tiers stays.

2. `WorkUnit::execute` rustdoc (`work_unit.rs`): state that `execute` is invoked once per morsel, and that all per-record and accumulating work must flow through the morsel-aware Context accessors; a non-morsel-driven side effect in `execute` runs once per morsel.

3. `AccumWriterApi::append` rustdoc (`context.rs`): a one-line note that appends should be driven by the per-record loop (so the total appends equal the record count across morsels), not issued as a fixed count in `execute`.

## Out of scope

No source-behaviour change; the windowing logic landed in round `202606041609` is unchanged. The phase-sequential morsel loop and the per-fiber model remain later arc.
