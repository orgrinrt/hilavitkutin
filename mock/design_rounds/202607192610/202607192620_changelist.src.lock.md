## CHANGE: `accum_slice` IS ADDED, and both sites call it

File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`

A private helper returning the per-core accumulator region:

```rust
fn accum_slice(total: USize, ncores: USize, core: USize) -> (USize, USize)
```

It returns `(lo, len)` for the given core, deriving `per = ceil(total / ncores)` internally. A
companion `accum_per(total, ncores) -> USize` exposes just the stride, since `merge_accums` takes
that rather than a slice.

`accum_slice` is written in terms of `accum_per`, so there is exactly one place the ceiling is
computed. `worker_accum_unit_outer` calls `accum_slice`; `run_parallel` calls `accum_per`. Neither
spells the arithmetic.

Verification: the ceiling appears exactly once in the file, inside `accum_per`; the old spelling
`ncores0 - 1) / ncores0` is gone from both sites; both call the helpers.

**One consequence the changelist did not anticipate.** `lo` and `region` become `USize` rather than
raw `usize`, so two downstream `MorselRange::new(USize(lo), USize(region))` call sites were
double-wrapping and stopped compiling. They now pass the values through directly, which is the
better shape: the helper returns the domain type and the call sites stop re-deriving it. Four type
errors, all at the same seam, all resolved by removing wrapping rather than adding it.

## CHANGE: the `:956` comment STATES what the slice is

File: same

It currently reads "Head+tail record slice for this core (mirrors run_core_phase's split)". Both
halves are false. `run_core_phase`'s split was deleted in round `202607192400`, so there is nothing
to mirror; and this is the accumulator's N-way regioning, which canon specifies at
`202606111800:452-456`, not head+tail convergence, which is 2-way and unbuilt.

It becomes a statement of what the slice is and why it is exclusive, with the canon reference.

Worth recording that the round which deleted the branch is the round that left this pointing at it.
I checked the design templates for stale references and did not check source comments in the same
file. The check was one grep for the function name and I did not run it.

Verification: `! grep -q "mirrors run_core_phase" mock/crates/hilavitkutin/src/scheduler/mod.rs`.
