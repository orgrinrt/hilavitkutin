# Src changelist: GATE-2 G2-N core-pinned per-trunk dispatch

**Date:** 2026-06-08
**Phase:** SRC (IMPL)
**Round:** 202606080600
**Scope:** `dispatch/trunk_dispatch.rs`, `scheduler/mod.rs`, `tests/gate2_run_parallel.rs`

## Summary

Re-point the parallel worker's per-(core, phase) dispatch from the runtime-mask
path (`core_phase_mask` + per-unit `run_gated`) onto the G-e compiled per-trunk
monos. A core-aware walk fires `RunGatedTrunk::<TRUNK = root>` for the in-phase
trunk-roots it owns (within-phase rank modulo core count), replicating the R4a
ownership rule per trunk-root instead of per unit, with each per-trunk mono
staying devirtualised and the non-owned trunks dead-code-eliminated from the
core's program. The head+tail convergence branch (single-trunk phase, record-slice
ownership) is unchanged.

## CHANGE: trait method `RunTrunkDispatch::dispatch_core` ADDED
File: `mock/crates/hilavitkutin/src/dispatch/trunk_dispatch.rs`
A core-aware sibling of `dispatch`: `fn dispatch_core<M: BitAccess>(&self, full: &Full, p: USize, core: USize, ncores: USize, rank: &mut USize, bindings: &A, morsel: MorselRange, dirty: M)`. `WuNil` impl no-ops. `WuCons` impl: at a position that `IsRoot::IS` with `PhaseAt::VAL == p.0`, it is an in-phase-`p` trunk-root; fire `RunGatedTrunk::run_trunk` iff `ncores.0 != 0 && rank.0 % ncores.0 == core.0`, then increment `rank` for every in-phase-`p` root (owned or not), then recurse on the tail. The `rank` threading mirrors `core_phase_mask`'s "count of in-phase roots below".
Verification: `grep "fn dispatch_core" mock/crates/hilavitkutin/src/dispatch/trunk_dispatch.rs` returns the trait decl plus the two impls; `cargo test -p hilavitkutin --test gate2_run_parallel` green.

## CHANGE: `Scheduler::run_core_phase` ordinary + record-less branches FROM `run_gated(core_phase_mask)` TO `dispatch_core`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Gains a `GW` grouping-witness generic and the bound chain `WuVals: RunTrunkDispatch<.., 0>`, `WuVals: BundleMasks<Stores, GW, D::Stores>`, `D::Units: ConstCapacity`, `D::AdjRow: BitAccess + Identity` (the same chain `run` carries). The `tphase == 1 && ncores > 1` convergence branch keeps `run_gated(phase_mask)` over the per-core record slice. The ordinary branch and the record-less branch call `dispatch_core` (all-ones dirty, fresh `rank = 0` per morsel) instead of building `core_phase_mask` + `run_gated`.
Verification: `grep "dispatch_core" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns the two call sites; `cargo test -p hilavitkutin` green.

## CHANGE: `Scheduler::run_parallel` ADD RunTrunkDispatch bound chain + thread `GW` to `worker_main`

## CHANGE: test `gate2_run_parallel::run_parallel_three_trunks_two_cores_matches_single_core` ADDED
File: `mock/crates/hilavitkutin/tests/gate2_run_parallel.rs`
Three column-disjoint producers in phase 0 (three trunks) plus a combiner in phase 1, run on a 2-worker pool. With three trunks over two cores, core 0 owns ranks 0 and 2, core 1 owns rank 1, so the `rank % ncores` wrap (a core owning more than one trunk) is exercised. Asserts the combiner output is correct, which holds only if every phase-0 trunk was dispatched exactly once across the two cores and the phase-1 combiner ran after the waist.
Verification: `cargo test -p hilavitkutin --test gate2_run_parallel run_parallel_three_trunks_two_cores` green.
