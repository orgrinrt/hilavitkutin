## Current state (truth-of-impl, this round's starting point)

`run_parallel` is ALREADY real-threaded, contrary to the "sequential core-sweep" framing in older notes. It spawns a persistent pool once (`worker_main` per core via `pool.spawn`), workers park between frames, the main thread does one `frame_publish` / `frame_await_done` per frame, workers cross interior waists worker-side via the shipped sense-reversing `waist_barrier`, and the §9 threaded-accumulator per-core-region + post-frame `merge_accums` is wired. E2 (spawn-once pool), the waist barrier, and the accumulator merge are all SHIPPED.

What is NOT yet done: the worker's per-(core, phase) dispatch (`run_core_phase`) uses the RUNTIME-MASK path. It computes `core_phase_mask` (a runtime `D::AdjRow` of the trunks this core owns this phase) and walks the flat carrier via the shipped `run_gated<M: BitAccess>` (a runtime per-unit ownership branch). That is the R4b-inline interim op chose, not the canonical compiled per-core program. It is output-correct and threaded, but each unit pays a runtime mask-bit test and the walk is one shared monomorphisation, not the per-trunk member-only monos. The `#664` branching / accumulator perf arms stay RED because the runtime-mask per-unit overhead plus per-frame pool/barrier cost dominates; the compiled per-trunk monos (sketch B2's devirt-clean 2.84x) are what move them.

## The change (G2-Na assignment + G2-Nb concurrent, on the shipped threading)

Re-point the worker dispatch from the runtime-mask `run_gated` path onto the G-e compiled per-trunk monos, keeping every trunk's `RunGatedTrunk::<TRUNK = root>` a separate devirt-clean / DCE'd monomorphisation, while runtime-selecting the subset this core owns.

The G-e outer dispatcher `RunTrunkDispatch` already walks the carrier and, at each const trunk-root whose const phase equals the runtime pass `p`, fires that trunk's mono. G2-N adds a runtime core-ownership filter to that walk:

- New core-aware entry (a variant of `RunTrunkDispatch::dispatch`, or a `dispatch_core` method): takes runtime `core`, `ncores`, plus a running within-phase trunk-rank counter threaded through the recursion.
- At each position that is a const trunk-root (`IsRoot::IS`) whose const phase (`PhaseAt::VAL`) equals runtime `p`: it is an in-phase-`p` root. Check `rank % ncores == core` (the shipped ownership rule from `core_phase_mask`: within-phase rank modulo core count). If owned, fire `RunGatedTrunk::<TRUNK = POS, Here>` over the morsel with the dirty mask. Increment `rank` for EVERY in-phase-`p` root (owned or not), so the rank matches `core_phase_mask`'s "count of roots below".
- The per-trunk mono stays compiled (POS reaches `TRUNK` by identity, zero GCE const-arg, exactly as G-e); only the ownership test is the added runtime branch, applied once per trunk-root (not per unit, unlike the current per-unit `run_gated` mask test).

`run_core_phase` then drives this core-aware walk per morsel instead of `run_gated` + `core_phase_mask`. The head+tail convergence branch (single-trunk phase, `tphase == 1`) stays as-is (it is the orthogonal record-range split, spec `:770`); only the ordinary trunk-rank-ownership branch is re-pointed. Single-core (`ncores == 1`) is the degenerate case: rank `% 1 == 0 == core 0`, so core 0 fires every trunk = the full per-trunk walk (no special path).

Sketch B already proved the concurrency this rides on: trunks on distinct threads share the immutable bindings (`SyncBind`, Send+Sync; disjoint write columns = no aliasing), joined only by the shipped waist barrier. The threading, barrier, and merge are unchanged; only the per-phase dispatch body changes.
