# Topic: regenerate stale extensions-macros trybuild goldens

**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** `hilavitkutin-extensions-macros/tests/fixtures/fail/*.stderr` goldens
**Source:** task #632 (trybuild RED on dev since PR #73)

## Context

`hilavitkutin-extensions-macros` runs a `trybuild` harness: negative fixtures
under `tests/fixtures/fail/*.rs` must fail to compile with a stable error
captured in a sibling `*.stderr` golden. PR #73 (the unified-Provider rename,
`Capability` to `Provider`) renamed the fixtures and changed the macro's
diagnostics but did not regenerate the goldens. The result is a long-standing
red `trybuild_fixtures` test on dev. It went unnoticed because merges run `cargo
check` rather than full `cargo test`, and earlier all-green audits counted
`test result: ok` lines without scanning for `FAILED`.

Three concrete drifts:

1. `provider_type_missing_impl.rs` (renamed from `capability_type_missing_impl.rs`)
   has no `.stderr` golden, so `compile_fail` cannot match and the test fails.
2. `unknown_attr.stderr` still lists the pre-rename supported keys
   (`required_host_caps`, `capabilities`); the macro now emits
   `required_host_providers`, `providers`.
3. `capability_type_missing_impl.stderr` is an orphaned pre-rename golden with no
   matching `.rs` fixture.

## Changes proposed

Regenerate the goldens to match the current macro diagnostics on the pinned
nightly (`TRYBUILD=overwrite`), and remove the orphan:

1. Add `provider_type_missing_impl.stderr` capturing `error[E0277]: the trait
   bound NotACap: ProviderExport is not satisfied`. This is the expected error
   and confirms `#[export_extension]` enforces the `ProviderExport` bound on
   provider types.
2. Update `unknown_attr.stderr` so the supported-keys list names the renamed
   `providers` / `required_host_providers` keys.
3. Remove the orphaned `capability_type_missing_impl.stderr`.

No source `.rs` or `.md.tmpl` changes. The goldens are generated artifacts that
capture compiler output; the fix realigns them with the diagnostics PR #73
introduced.

## Process note

Going forward, all-green audits must scan for `FAILED` and `[1-9][0-9]* failed`,
not only count `test result: ok` lines, so a red target interleaved among
passing ones is not missed. Recorded in #632.
