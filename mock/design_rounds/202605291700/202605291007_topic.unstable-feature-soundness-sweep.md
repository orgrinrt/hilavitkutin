**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** hilavitkutin unstable-feature soundness: remove full `specialization` (EngineCtx accessor redesign), remove `associated_type_defaults`, apply `min_specialization` carve-out discipline
**Source:** workspace unstable-feature soundness sweep (design talk, 2026-05-29)

hilavitkutin enables full `specialization` in both hilavitkutin-api and the engine, and `associated_type_defaults` in hilavitkutin-api. Full `specialization` (rust-lang/rust#31844) is unsound by design: it can cause undefined behaviour without `unsafe` via lifetime-dependent dispatch (the still-open hole #40582), and the sound subset `min_specialization` was split off precisely because the full feature cannot be made sound. It will not stabilise. Under the discipline, a feature known unsound with no prospective fix is forbidden outright, with no carve-out. This topic removes it.

The full-spec dependence is the per-WorkUnit `EngineCtx` type-keyed accessor in `dispatch/engine_ctx.rs`. The fixed-signature accessor `resource::<T>()` resolves `T` against a heterogeneous pointer cons-list `PtrCons<H, Tail>` via `TryHeadResource` / `TryHeadColumn`: a `default fn` on a blanket impl plus a type-equality specializing impl keyed on `H == T`. Swapping the gate to `min_specialization` fails with "specializing impl repeats parameter T", confirming the mechanism requires the full, forbidden feature and is not min-compatible. The rest of the EngineCtx machinery, `Selector<T, Here | There<I>>` plus `Project` and `ColProject`, is specialization-free and already works. This accessor was introduced by the per-WorkUnit `EngineCtx` work (PR #93, merged to dev), which regressed the soundness state a prior locked audit had already flagged.

The replacement is to route the accessor through that existing `Selector` / `Project` machinery. The index witness becomes an engine-internal inferred parameter rather than a type-equality specialization. This preserves the public `resource::<T>()` signature and the entire hilavitkutin-api Context contract (`ResourceProviderApi`, `HasResourceProvider`, `WorkUnit::Ctx`); the blast radius is confined to the engine crate. The one open property, whether the index witness can be inferred at fetch time without naming it and without re-introducing the impl overlap that forced specialization, is a trait-solver claim. A sketch de-risks it before the refactor commits. If the sketch fails, the fallbacks are an explicit turbofish `resource::<T, I>()` (which changes the api contract workspace-wide) or a precomputed index array (which would couple to the const-array decision in the arvo soundness topic); neither is taken unless the sketch shows the witness cannot be inferred.

## Current state

- `specialization` (full) enabled in `hilavitkutin-api/src/lib.rs` and `hilavitkutin/src/lib.rs`.
- The api-side gate is vestigial. The only `specialization` use in hilavitkutin-api is the `ColumnValue::BIT_WIDTH` blanket-plus-concrete pattern in `column_value.rs`, which a prior audit found min_specialization-compatible. The engine-side gate is the real use (the EngineCtx accessor).
- `min_specialization` enabled in hilavitkutin-api alongside the full gate.
- `associated_type_defaults` enabled in hilavitkutin-api. Sole use is the default `type Init = Self;` on the `BuilderInput` trait in `builder_input.rs`. The other associated type, `type Dispatch`, has no default. Zero-data markers such as `ExtensionSurface` already override `type Init = ();` explicitly.
- `generic_const_exprs` enabled in hilavitkutin-api and hilavitkutin-str, used only to consume arvo's const-array types.

## Changes proposed

### Remove full specialization; redesign the EngineCtx accessor (Mechanism A, sketch-first)

- Write a sketch under `mock/research/sketches/` proving the Selector-routed accessor: the index witness inferred at the engine impl without being named at the call site, no overlapping impls, deterministic resolution. Verify it compiles under `min_specialization` or with no specialization gate at all.
- On success: rewrite the EngineCtx accessor so `resource::<T>()`, `read`, and `write` route through `Selector` / `Project`; delete `TryHeadResource` / `TryHeadColumn`; remove `#![feature(specialization)]` from the engine crate root.
- Drop the vestigial full-spec gate from hilavitkutin-api after confirming `column_value.rs` compiles under `min_specialization` alone.
- Fallbacks only if the sketch fails: Mechanism C (explicit `resource::<T, I>()`, an api-contract change) or Mechanism D (precomputed index array, which couples to the arvo const-array decision).

### Remove associated_type_defaults; redesign BuilderInput

- Drop `type Init = Self;`. Every `impl BuilderInput` spells out its `type Init` (mechanical, roughly 24 sites, mostly `= Self`, markers `= ()`).
- Remove `#![feature(associated_type_defaults)]` from hilavitkutin-api. Rationale: the feature (#29661) is flagged unsound in the next-generation trait solver, no core, std, or rustc internal usage grounds the carve-out, and the convenience it bought is a single default not worth carrying contested soundness for.

### Apply min_specialization carve-out discipline

- `min_specialization` (#31844, the sound subset split out via PR #68970) is greenlit: it is the sound subset and std uses it internally. No stable wrapper replaces the `ColumnValue::BIT_WIDTH` blanket-plus-concrete pattern in `column_value.rs`, so the carve-out discipline applies: a `// SAFETY:` justification at the use site, a `// SAFETY:` note above the `#![feature(min_specialization)]` gate, and a recorded audit of the feature's known rough edges.

### generic_const_exprs in hilavitkutin-api and hilavitkutin-str

- Both enable `generic_const_exprs` only to consume arvo's const-array types. They follow arvo's resolution (the arvo soundness topic, same date). If arvo migrates to `min_generic_const_args`, these follow; if arvo holds GCE as WATCH, these inherit the same scoped, SAFETY-commented treatment.

## Consequences

- Removing full `specialization` closes a real undefined-behaviour-class soundness hole in shipped dev code.
- The api Context contract is preserved if Mechanism A holds, so consumer WorkUnits are unaffected.
- The parked Phase C engine arc resumes after the sweep; the EngineCtx redesign touches the same dispatch module, so the sweep lands first by sequencing.
