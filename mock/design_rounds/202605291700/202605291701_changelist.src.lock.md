Replace the engine's type-keyed accessor lookup, which used forbidden full
`feature(specialization)` via `TryHeadResource` / `TryHeadColumn` (`default fn` +
type-equality specialising impls), with the existing spec-free `Selector` / `ColSelector`
index witness. The keyed api accessors gain an inferred index generic and a `Resolve*<T, I>`
bridge bound; the engine implements the bridge by delegating to the bundle's index witness.
The index resolves uniquely at the concrete WU call site, so no specialization is needed.

## CHANGE: `EngineCtx` splits the single R-union-W column bundle into read + write bundles
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`
`EngineCtx<'frame, R, W, RBundle, WCols>` becomes `EngineCtx<'frame, R, W, RBundle, RCols,
WCols>`; the single `cols` field (projection over `R union W`) splits into `read_cols: RCols`
(column projection over `R`) and `write_cols: WCols` (over `W`). `from_projected` takes both;
`project` builds both with two `ColProject` bounds (over `R`, over `W`), dropping the
`R: Concat<W>` bound and the `Concat` import. Reason: a column in both `R` and `W` appeared
twice in the `R union W` bundle, making the inferred `ColSelector` index ambiguous (E0283).
Per-side projection keeps each bundle's column types distinct, so the index resolves
uniquely; a read-write column resolves in both bundles to the same buffer pointer.
Verification: `grep "read_cols" mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` returns matches; `cargo +nightly-2026-05-28 test -p hilavitkutin` passes (incl. `context_column_read_after_write`).

## CHANGE: hilavitkutin-api crate root RETAINS `#![feature(specialization)]` (finding: not vestigial)
File: `mock/crates/hilavitkutin-api/src/lib.rs`
The 2026-05-29 audit recorded the api full-spec gate as vestigial (only `column_value.rs`,
claimed min-compatible). That is WRONG: `column_value.rs:27` `ColumnValue::BIT_WIDTH` is a
blanket `default const` overridden by sub-byte impls, which `min_specialization` rejects
(E0658). So the api full-spec gate is RETAINED here, now carrying a tracked-exception comment
naming the `column_value` use and that #623 removed the engine use. Removing the api gate
needs a spec-free `ColumnValue` redesign (drop the blanket, trait-body default, explicit
per-type impls) — a substrate-contract change filed as task #631. `min_specialization` stays.
Verification: `grep "feature(specialization)" mock/crates/hilavitkutin-api/src/lib.rs` returns one match (the retained gate with its tracked-exception comment).
