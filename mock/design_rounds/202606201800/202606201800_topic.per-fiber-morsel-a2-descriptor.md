# Topic: per-fiber morsel slice A1 (FiberDispatch per-fiber size field)

**Date:** 2026-06-19
**Phase:** TOPIC
**Scope:** `hilavitkutin` scheduler (`FiberDispatch` + `derive_phase_dispatch_order`)
**Source topics:** per-fiber morsel blueprint `202606201400` (slice 2), corrected roadmap `202606201700` Phase A

## Current state

`morsel_windows` is renamed (A-S1, PR #151) but unconsumed by dispatch. The
`FiberDispatch` descriptor (`scheduler:482`) carries `start`/`len`/`morsel_local`
but no per-fiber morsel size; the dispatch loop windows uniformly by the const
`Cfg::MORSEL_SIZE`. The loop-inversion that consumes a per-fiber size (A2) needs
the size on the descriptor first.

## Changes proposed (A1, additive)

1. `FiberDispatch` gains `morsel_size: USize` and `fiber_plan_idx: USize` (Default
   ZERO). `fiber_plan_idx` records the plan CSR fiber index because the
   `fiber_dispatch[..]` dispatch-order index differs from the `morsel_windows[f]`
   CSR index.
2. `derive_phase_dispatch_order` reads `plan.morsel_windows`; at the fiber-loop
   body (CSR index `f`, `scheduler:437`) it sets `fiber_plan_idx: USize(f)` and
   `morsel_size: morsel_windows[f]` (bounds-guarded). No dispatch behaviour change
   yet (the field is populated, not consumed; A2 consumes it).
3. White-box `__fiber_morsel_size(USize) -> USize` accessor + a test asserting the
   descriptor's `morsel_size` equals the plan's per-fiber value (for a 1-fiber
   carrier with N records, `morsel_windows[0]` is the placeholder partition `N`,
   so `__fiber_morsel_size(0) == N`).

## Not in scope

A2 loop inversion (consume the field), A3 L1 formula, A4 GATE-2 parallel.
Dispatch is byte-identical this slice.
