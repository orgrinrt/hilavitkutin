# Topic: the spawn-gate lint accepts a forcing that gates nothing

**Date:** 2026-09-19
**Phase:** TOPIC
**Scope:** one finding a third review raised against the `engine-spawn-through-gate` lint landed in `202609191001/`, and one sentence in the principles, fixed in one round on branch `feat/hilavitkutin-on-arvo-dev`.

## Authority

The same as the round closed at `202609191001/`: hilavitkutin declares no `canon_paths`, so its design stands in for a canon. The gate the lint checks is the one the api design declares, `OnePointerClosure::<F>::FITS` forced on the closure the engine hands its executor.

## The items

### N1: the forcing the lint accepts need not name the spawned closure

`forcing_offsets` in `mock/lints/engine_spawn_through_gate.rs` accepts any `let () = ...;` whose right-hand side starts with `OnePointerClosure` and ends with `::FITS`. `let () = OnePointerClosure::<()>::FITS;` or `::<u8>::FITS` passes the lint and checks a type that is never spawned. That is the likely regression: an edit that widens the engine closure hits the post-monomorphisation E0080, and retyping the turbofish silences it with the lint still green. A `#[cfg(any())]` on or directly above the forcing line also passes, because the lint reads no attributes, and the statement is compiled out.

The fix: the turbofish type of the forcing must be the declared type of the argument the body passes to `spawn`, read off the gate fn's parameter list; a forcing carrying a `#[cfg` attribute on its line or on the line directly above it does not count. Both refused shapes become tests, each shown failing with its check disabled.

### The principles state an implementation status

`mock/PRINCIPLES.md.tmpl`, Pre-allocated thread pool, ends the thread-count paragraph with "The engine does not honour this yet: it hands out one closure per worker whatever the plan's width." That is the state of the code, not a principle. The `FIXME:` in `run_parallel.rs` and the ignored catalogue test in `gate2_worker_count.rs` carry it already. The sentence goes and `docs/` regenerates.
