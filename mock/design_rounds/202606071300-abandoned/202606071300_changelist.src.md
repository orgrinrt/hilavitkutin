**Phase:** IMPL
**Scope:** `mock/crates/hilavitkutin/src/plan/grouping.rs`, `src/scheduler/mod.rs` (the `run` morsel-outer path), and a test.

## CHANGE: `phases` one-shot grouping accessor
File: `mock/crates/hilavitkutin/src/plan/grouping.rs`
Verification: `grep -q "pub const fn phases" mock/crates/hilavitkutin/src/plan/grouping.rs`
`phases::<Wus, Stores, Witnesses, CU, CS>() -> ([USize; GATE2_MAX_UNITS], USize)` returns the per-unit phase array and the unit count in one pass (folds masks via `MaskProject`, runs `compute_phases` once), so the run loop does not recompute the grouping per position. No-arg const fn, so it const-folds.

## CHANGE: phase-section `Scheduler::run`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep -q "phases::<" mock/crates/hilavitkutin/src/scheduler/mod.rs` and `cargo test -p hilavitkutin` green.
`run` gains an inferred grouping-witness generic `GW` (the per-unit `(RI, WI)` MaskProject witness list, inferred at the call site like the projection `Witnesses`; bound `WuVals: BundleMasks<Stores, GW, <D as PlanDims>::Stores>`). The morsel-outer branch becomes: read `(phase_arr, n) = phases::<WuVals, Stores, GW, D::Units, D::Stores>()`; derive `nphases` (max phase + 1 over the first `n`); `for p in 0..nphases { build phase_mask_p = { pos<n : phase_arr[pos] == p } as a D::AdjRow; gate = dirty.bitand(phase_mask_p); for morsel { wu_values.run_gated(bindings, morsel, gate, ZERO) } }`. Phases run in order (each fully before the next), the waist sectioning; single-core the sequencing is the degenerate barrier (no explicit barrier call; the real `phase_barrier_arrive` is G2-N). The accumulator-bearing / record-less unit-outer branch is unchanged. The per-frame incremental-skip `dirty` is intersected with each phase mask, preserving E7 skip.

## CHANGE: phase-sectioned run test
File: `mock/crates/hilavitkutin/tests/gate2_phased_run.rs` (new)
Verification: `cargo test -p hilavitkutin --test gate2_phased_run` passes; fail-first before the re-point.
A 2-phase column DAG (a producer writing `Column<Av>` in phase 0, a consumer reading `Av` and writing `Column<Bv>` in phase 1; the RAW edge puts the consumer in a later phase). `scheduler.run()` dispatches both phases in order; assert the consumer read back exactly what the producer wrote (the phase-sectioned dispatch ran the producer's phase fully before the consumer's). Plus a record-count > morsel-size case so the phase loop wraps multiple morsels per phase, proving phase-outer ordering holds across morsels.

## Note

The const-gated per-trunk monos (round 2a, `run_one_trunk` / `RunGatedTrunk`) are not used by single-core `run`; they are the G2-N per-core building block. Single-core needs only phase-ordered execution with waists, which this round provides without per-`(phase, trunk)` mono enumeration (avoiding the count-bound explosion and the `{N+1}` const-recursion overflow). How N-core enumerates per-core programs for an arbitrary grouping is a separate G2-N design.
