# Topic: GATE-2 phase-sectioned single-core run re-point (round 2b)

**Date:** 2026-06-07
**Phase:** TOPIC
**Scope:** hilavitkutin engine, `scheduler` (the `run` morsel-outer path). Round 2b of the GATE-2 carrier mechanism. Rounds 1 (const grouping), 2a (const-gated per-trunk walk) are closed.
**Source:** canonical spec domain 17 (per-core programs, `:822`), phases-between-waists (`:739-746`), single-core trivially-ordered (`:605`), execution strategies (`:768-779`); roadmap r4 (`mock/research/202606070700`); sketch B (`202606070400`, concurrency proof).

## What this round does

Re-point `Scheduler::run` (the morsel-outer dispatch path) to execute the registered units PHASE BY PHASE, in phase order, with a waist barrier between phases. Single-core, output-equivalent to the current flat walk; `#664` no-regress. This establishes the phase-sectioned dispatch structure (the waist sectioning op's correction requires before parallelising); G2-N swaps the degenerate barrier for the real one and pins each phase's trunks to cores.

## Design (resolved by spec grounding)

Single-core output-equivalence does not need per-`(phase, trunk)` monomorphisation. The const-gated per-trunk monos (round 2a, `run_one_trunk` / `RunGatedTrunk`) are the G2-N per-core building block; enumerating every `(phase, trunk)` at single-core would hit a count-bound mono-explosion (and the `{N+1}` const-recursion overflow round 2a already resolved for the position axis). Single-core needs only phase-ordered execution with waists, and degenerate single-core barriers are no-ops, so the output is unchanged.

The shape:

1. Thread a grouping-witness generic `GW` on `run` (inferred at the call site, exactly as the projection `Witnesses` is, and as `compute_plan` threads `BWit`). `GW` is the per-unit `(RI, WI)` MaskProject witness list the round-1 grouping const fns consume.
2. Compute `nphases = phase_count::<WuVals, Stores, GW, CU, CS>()` and, per phase `p`, the unit mask `{ pos : phase_of(pos) == p }` as a runtime `AdjRow` bitmask (the round-1 grouping const fns are callable at runtime; the mask is built once per frame).
3. Replace the single morsel-outer walk with a phase loop: `for p in 0..nphases { for morsel { wu_values.run_gated(bindings, morsel, dirty & phase_mask_p, ZERO) }; waist_barrier(degenerate) }`. This reuses the shipped `RunFiber::run_gated` (the mask-gated walk) and the degenerate `waist_barrier` (`dispatch::phase_run`, G2-0b). The per-frame incremental-skip `dirty` mask (E7) is intersected with the per-phase mask.

No const enumeration, no `{N+1}` recursion, no GCE overflow: the phase loop is a runtime loop over `nphases`, the masks are runtime, `run_gated` is the existing walk.

The accumulator-bearing unit-outer path stays unchanged (accumulators reset + re-append per frame, a later-gate concern; phase-sectioning applies to the RAW-recompute morsel-outer path).

## Why output is unchanged single-core

For a morsel-local (element-wise) workload that is a single phase, the phase loop runs once (`p = 0`, all units), identical to the current flat walk: `#664` element_wise stays green. For a multi-phase workload, phase-outer runs each phase fully before the next, which for single-core produces the same result as the current morsel-outer flat walk (units run in topological order either way; phases respect the RAW deps). The `#664` branching arm is red by design (a GATE-2 parity target via real parallelism, not a single-core stopgap), so changing its single-core ordering is acceptable. The degenerate waist barrier is a one-arriver no-op single-core.

## What this is not (G2-N, a following design)

How N-core enumerates and assigns per-core programs (the `run_one_trunk::<P, T>` monos) for an arbitrary grouping in pure Rust is a separate G2-N design question: the bridge between runtime core-assignment and const per-trunk monos (a count-bound enumeration). Candidates: a carrier walk gated by "trunk assigned to this core" (assignment runtime), or the codegen-flattener (spec domain 17, op's Option 1 direction). Round 2b does not depend on resolving it; it is charted at G2-N.

Bench is the GATE-2 oracle; the `#664` branching/accumulator red arms turn green via real trunk parallelism + waisting, never single-core stopgaps.
