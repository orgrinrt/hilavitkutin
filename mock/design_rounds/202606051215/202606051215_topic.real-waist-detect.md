# Topic: real waist detection via arvo_graph::waist_detect

**Date:** 2026-06-05
**Scope:** hilavitkutin engine (`mock/crates/hilavitkutin`), the plan stage's `compute_waists`. First slice of GATE-1 Phase C (#339), the canonical plan algorithm chain.
**Source topics:** the dispatch-build-plan memo (`mock/research/202605282100_engine-dispatch-build-plan.md`, Phase C(b)); op's 2026-06-05 decision that single-core is done only when it matches the canonical formalised design in full.

`compute_waists` (`plan/steps.rs:220`) computes the plan's phase boundaries. Its current body is a crude placeholder: it walks the topological order and treats any unit with out-degree zero as a waist, emitting a phase boundary after it. The memo flags this as over-segmenting: every leaf becomes a waist, so a pipeline that fans out to several independent sinks splits into far more phases than its actual synchronization structure warrants. The canonical design detects a waist as a concurrent-path-minimum: a depth in the dependency DAG whose level width is a strict local minimum, which is the natural narrowing point where a phase barrier belongs.

arvo ships exactly this. `arvo_graph::waist_detect` (`arvo-graph/src/waist.rs:27`) takes a DAG adjacency plus the topological order and returns a mask whose bit `k` is set when the node at `topo_order[k]` sits at a depth whose level width is a strict local minimum relative to the occupied depths on either side. This is the concurrent-path-minimum the design wants. The engine already depends on arvo-graph and arvo-bitmask, and the design memo's correction notes the arvo graph primitives are shipped and complete; this slice is a wiring exercise, not blocked on substrate.

The one shape detail: `waist_detect` consumes a `BitMatrix<Bits<64, Hot, Unsigned>>` adjacency, a 64-node bit matrix. The engine's `DefaultPlanDims::Units` is `Dim<64>`, so the 64-node matrix is an exact fit for the default dimensions, not a cap that bites. The engine's `DependencyGraph` is CSR-backed; this slice builds the bit-matrix adjacency from the CSR edges for the dispatch into `waist_detect`. A future custom `PlanDims` with more than 64 units is the memo's Phase C(g) concern (branch dense-bitmask versus CSR-sparse versus spectral by node count); it is out of scope here and tracked there, not solved by widening arvo for this slice.

## Changes proposed

`compute_waists` builds a `BitMatrix<Bits<64, Hot, Unsigned>>` from the `DependencyGraph` (set the edge bits), calls `arvo_graph::waist_detect` over it with the topo order, and translates the returned waist mask into the existing `PhaseBoundaries` shape: a set waist bit at topo position `k` opens a phase boundary at `k`. The crude out-degree-zero heuristic is removed. No change to the `PhaseBoundaries` type or to `compute_waists`'s signature; only the body. A diamond-shaped fixture discriminates the new behaviour from the old (the old heuristic over-segments; the real detector finds the width-minimum waists).
