# Src changelist: real waist detection

**Date:** 2026-06-05
**Phase:** SRC
**Round:** 202606051215 (real-waist-detect, branch `feat/hilavitkutin-real-waist-detect`)

`compute_waists` (`plan/steps.rs`) computes phase boundaries with a crude placeholder: any out-degree-zero unit in topo order is treated as a waist, which over-segments (every leaf becomes a boundary). This slice replaces it with real concurrent-path-minimum waist detection via `arvo_graph::waist_detect`, the algorithm the design doc already attributes to arvo-graph. Scoped to the default 64-unit dimensions (`waist_detect` consumes a `BitMatrix<Bits<64, Hot, Unsigned>>`, an exact fit for `DefaultPlanDims::Units = Dim<64>`); the arbitrary-N generalization is a separate arc.

## CHANGE: `compute_waists` detects waists via `arvo_graph::waist_detect`
File: `mock/crates/hilavitkutin/src/plan/steps.rs`
The body builds a `BitMatrix<Bits<64, Hot, Unsigned>, D::Units>` from the `DependencyGraph` (one `set_edge(i, j)` per directed edge `i -> j`), projects the topo `UnitId` array into a `NodeId` array, calls `arvo_graph::waist_detect(&matrix, &topo_nodes)`, and translates the returned waist mask (bit `k` set when topo position `k` is a width-local-minimum depth) into `PhaseBoundaries`: phase 0 starts at position 0, and each waist position `k` with `k + 1 < unit_count` opens a phase boundary at `k + 1` (the waist unit is the last of its phase). The out-degree-zero heuristic is removed. Signature unchanged.
Verification: `grep "waist_detect" mock/crates/hilavitkutin/src/plan/steps.rs` returns the call; `cargo test -p hilavitkutin` green including the new waist fixture.

## NEW: waist-detection test (bowtie discriminator)
File: `mock/crates/hilavitkutin/tests/` (new `waist_detect.rs`) or an inline `#[cfg(test)]` in `plan/steps.rs`, whichever the existing plan-test convention uses.
A bowtie DAG `{A, B} -> C -> {D, E}`: two sources fan into C, C fans out to two sinks. C sits at depth 1 with level width 1, a strict local minimum between the width-2 source and sink depths, so it is the sole waist. The test asserts `compute_waists` opens one interior phase boundary at C's successor position (phase 0 = the two sources plus C, phase 1 = the two sinks). The crude out-degree-zero heuristic instead splits at a sink (the two parallel sinks are not a sequential boundary), so the test fails red against the placeholder and passes once `waist_detect` drives the boundaries.
