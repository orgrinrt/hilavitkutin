**Phase:** TOPIC
**Scope:** #627 remove forbidden `associated_type_defaults` from hilavitkutin-api

`associated_type_defaults` (#29661) is FORBIDDEN per the 2026-05-29 unstable-feature design
talk: the next-gen trait solver flags it unsound, and no core/std-internal use grounds the
carve-out. hilavitkutin-api's only use is the `type Init = Self` default on the `BuilderInput`
trait (`builder_input.rs`).

The default is already dead: every one of the 22 `impl BuilderInput` sites in the workspace
(including the two `macro_rules!`-emitted ones) declares `type Init` explicitly, and there is
no `BuilderInput` derive macro that would emit it implicitly. `DESIGN.md.tmpl` already
documents the trait with `type Init;` (no default), so removing the default brings the source
into line with the shipped design rather than changing it.

This round drops the `type Init = Self` default to a bare `type Init;`, refreshes the three
`builder_input.rs` doc comments that describe the default, and removes the
`#![feature(associated_type_defaults)]` gate from the crate root. No `*.md.tmpl` change (the
design doc is already correct). The `WorkUnit: BuilderInput<Init = Self>` bound and the
`#[diagnostic::on_unimplemented]` note already guide impls to declare `type Init = Self;`.
