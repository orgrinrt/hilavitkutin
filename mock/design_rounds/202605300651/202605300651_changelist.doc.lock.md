## No doc-surface changes

The bundle-to-`PlanInputs` projection adds internal plan-stage machinery to the engine `plan` module (`Locate`, `MaskProject`, a peano-value trait, `BundleProject`, and the free `plan_inputs_from_bundle`). These are internal to how the scheduler turns its registered work-unit bundle into the `PlanInputs` the plan stage consumes; they are not part of the public architecture surface that `DESIGN.md.tmpl` documents.

`DESIGN.md.tmpl` already describes the plan stage as consuming `PlanInputs`; the projection is the mechanism that builds that input from the registered `(WorkUnitBundle, AccessSet)` typestate, below the documented contract. No backtick-named type in `DESIGN.md.tmpl` changes, and no new public-architecture concept is introduced that the document needs to name. So this round touches no `*.md.tmpl`.

If a later round promotes the projection into the documented surface (for example when `Scheduler::run` wires it in and the run path becomes the documented entry point), that round edits `DESIGN.md.tmpl` then.
