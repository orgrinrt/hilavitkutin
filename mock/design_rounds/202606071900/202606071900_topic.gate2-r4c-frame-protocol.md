# Topic: GATE-2 R4c round A, frame wake-word protocol

**Date:** 2026-06-07
**Phase:** TOPIC
**Scope:** `hilavitkutin-api` (`platform.rs` PoolFrame), `hilavitkutin` (`thread/`)
**Source:** roadmap r2 + GATE-2 R4c; sketches 202606071600, 202606071700

## Current state

`PoolFrame` (api `platform.rs`) carries the per-phase waist barrier
(`phase_arrived`), the shutdown flag, the adapt accumulators, and the progress
slots, but nothing for the per-FRAME orchestration the threaded executor needs:
no frame-start wake word, no frame-completion counter, no worker-exit counter.

The engine `thread/` module has `barrier.rs` (the per-phase `phase_barrier_*`
helpers) and `parking.rs` (`atomic_wait` / `atomic_wake_all`, the real
futex/__ulock/WaitOnAddress primitive), but no per-frame protocol: the
spawn-once, park-between-frames worker lifecycle the persistent pool runs.

Both R4c de-risk sketches proved this protocol inline (sketch 202606071600 the
mechanism, 202606071700 the ThreadPoolApi contract mapping). This round extracts
the proven protocol into named, tested engine functions so round B (the
`run_parallel<P: ThreadPoolApi>` keystone) calls them rather than re-deriving the
atomics inline.

## What changes

Add three `AtomicU32` fields to `PoolFrame`:

- `seq`: frame sequence / worker wake word. The main thread bumps it (Release) and
  wakes to publish a new frame; workers park on it.
- `done`: frame-completion counter / main wake word. Each worker increments it on
  finishing a frame; the last one wakes the parked main thread.
- `exited`: worker-exit counter. Each worker increments it on observing shutdown;
  the main thread waits on it before the PoolFrame (and the carrier it points at)
  can drop. This is the join with no join method (the ThreadPoolApi contract is
  fire-and-forget; workers are detached).

Add a `thread/frame.rs` module with the lost-wakeup-safe protocol over
`&PoolFrame`, mirroring the proven sketch logic. Main side: `frame_publish`
(reset `done`, bump `seq`, wake), `frame_await_done(expected)` (park on `done`),
`request_shutdown` (set flag, bump `seq`, wake), `await_exit(expected)` (park on
`exited`). Worker side: `frame_await(last_seen) -> u32` (park on `seq`),
`frame_done_arrive(expected)` (bump `done`, last wakes main), `frame_exit_arrive`
(bump `exited`, wake main). Every park is the load-check-`atomic_wait(word,
observed)` form, so a bump racing in after the load returns immediately instead
of sleeping through the wakeup.

## Test

A fail-first engine integration test (`tests/frame_protocol.rs`) constructs a real
`PoolFrame`, spawns std threads acting as workers, and drives several frames plus
shutdown through the new helpers. Workers each write a disjoint slice; the test
asserts formula-exact output per frame (proving the publish + done-barrier
handoff) and that shutdown joins every worker via the exit counter
(deadlock-clean under a bounded check). The test fails before the helpers exist
(they are referenced but unimplemented) and passes after.

## Out of scope

The Scheduler-owned arena PoolFrame, worker contexts, `run_parallel<P>` spawn
lifecycle, the `HybridExecutor::run` mainloop, and `Scheduler::Drop` are round B
(the keystone) on this branch. This round ships only the protocol primitives and
their tests.
