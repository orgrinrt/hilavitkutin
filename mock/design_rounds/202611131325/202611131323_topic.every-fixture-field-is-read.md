# every-fixture-field-is-read

**Date:** 2026-11-13
**Phase:** TOPIC
**Scope:** the five `#[allow(dead_code)]` attributes that `work/recover-landing-source` adds over `dev`, in two bench variant crates and two engine tests.
**Source:** the landing tool's refusal of the branch at `5d2fbd7`, relayed by the coordinator.

The landing refuses a branch that adds a suppression, and this one adds five. All five came over from the recovery branch with the fixtures they sit on. Each marks a record type whose one field the compiler sees written and never read, because the code that reads it does so through a pointer cast to the raw integer.

A suppression there hides two different things. In the tests it hides that the fixture reads its own column as a `u32` or `u64` where the column holds a named record type, so the type the test declares is never the type the test looks at. In one test it hides that a column is written and never looked at at all. In the bench crates it hides nothing: the types are public items of a library with a public field, which the compiler does not report.

So there is no suppression to keep in any of the five places. Where the field is read through a cast, the read goes through the record type and its field. Where the column is never read, the test reads it and holds it to what the unit wrote, which is a check the test lacked. Where the attribute does nothing, it goes.

The class is every `allow` or `expect` attribute the branch adds over `dev`. A search of the branch's diff against `dev` for added lines carrying one finds these five and no other. `dev` carries the same attribute in files this branch does not add, the fixture `a2b_loop_inversion.rs` among them; those are on `dev` already and are ticket `8584ba621931`, not changed here.

## The five

- `mock/benches/variants/grid_common/src/lib.rs` and `mock/benches/variants/rcm_common/src/lib.rs`: the column types a macro declares, each `pub struct` with a `pub` field in a library crate. The attribute is removed and the crates must build without a warning.
- `mock/crates/hilavitkutin/tests/a4_parallel_fiber_windows.rs`, `Narrow` and `Wide`: the test poisons both columns and reads them back through `*mut u32` and `*mut u64` casts. It poisons with `Narrow(u32::MAX)` and `Wide(u64::MAX)` and reads the field of each record.
- `mock/crates/hilavitkutin/tests/gate2_accumulator.rs`, `Sv`: the side unit writes `In[i] + 1` to its column and nothing looks. The test poisons the column and afterwards asserts every record holds `i + 1`, so the second trunk is shown to have walked every record, which the probe's own comment says is what happens there.
