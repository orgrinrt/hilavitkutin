# Topic — builder value retention, the first data-plane round (Phase B / B1)

**Date:** 2026-05-28
**Phase:** TOPIC
**Scope:** stop `Resource::new` dropping its argument; give the scheduler builder a place to hold registered store values until `build()`; thread the platform accumulator so the `MemoryProvider` reaches `build()`.
**Source:** `mock/research/202605282319_phase-b-data-plane-design.md` (round B1 section) and `mock/research/202605282100_engine-dispatch-build-plan.md` (Phase B).

This is the first implementation round of the engine-dispatch arc's data-plane keystone. The data plane (the storage WorkUnits read and write) does not exist: the builder discards every value passed to `.with`, and `Resource::new(value)` drops its argument. Nothing can be stored, so no WorkUnit can read anything real, so `Scheduler::run` has nothing to dispatch. B1 is the smallest coherent slice that makes the engine retain a registered value instead of dropping it. The arena that the retained values move into lands in B2; the per-WorkUnit Context that reads them lands in B3.

The current builder is `SchedulerBuilder<Wus, Stores>` holding only `PhantomData`. `.with<P: BuilderInput>(self, _provider: P)` advances the `Wus`/`Stores` typestate accumulators and then drops `_provider`. The platform accumulator (`Dispatch::NextPlatform`) is computed by every router but the two-parameter builder ignores it, so a registered `MemoryProvider` has nowhere to live. `Resource<T>` is itself the `BuilderInput` (`Init = T`), and `Resource::new(_value: T) -> Self` discards the value at the call site.

B1 makes the value survive. It adds a sealed value-carrying cons-list (`StageList`: `StageEmpty`, `Stage<H, T>`) that holds the actual registered values, distinct from the type-level `AccessSet` cons-list that tracks store identity. `Resource::new(value)` returns a value carrier (`StagedResource<T>`) that impls `BuilderInput<Init = T, Dispatch = StoreDispatch<Resource<T>>>`, so the marker type still routes into `Stores` while the value rides in the carrier. `BuilderInput` gains `into_init(self) -> Self::Init` so `.with` can move the construction value out of the carrier and onto the `Staged` list. The builder reshapes to `SchedulerBuilder<Wus, Stores, Platform, Staged>`, threading the platform accumulator (so a registered `MemoryProvider` is carried) and the staged-value list. Per the pre-1.0 no-legacy-shims rule this is a clean delete-and-replace; consumers that build through inference are unaffected.

The round proves only retention: that a value passed to `.with` is reachable from the builder afterward, not dropped. The move into a `MemoryProvider`-allocated arena is B2.

## Current state

- `mock/crates/hilavitkutin/src/scheduler/mod.rs`: `SchedulerBuilder<Wus, Stores>(PhantomData)`; `.with<P>(self, _provider: P)` discards `_provider`; `builder() -> SchedulerBuilder<Empty, Empty>`.
- `mock/crates/hilavitkutin-api/src/store.rs`: `Resource<T>(PhantomData<T>)`, `impl BuilderInput for Resource<T> { type Init = T; type Dispatch = StoreDispatch<Self>; }`, `Resource::new(_value: T) -> Self` drops.
- `mock/crates/hilavitkutin-api/src/builder_input.rs`: `BuilderInput { type Init = Self; type Dispatch; }` (no value-extraction method); routers including `PlatformDispatch` whose `NextPlatform` is unused by the builder.

## Changes proposed

1. New `mock/crates/hilavitkutin/src/scheduler/stage.rs`: sealed `StageList` with `StageEmpty` and `Stage<H, T: StageList>` carrying a real `H` value at the head.
2. `hilavitkutin-api/src/builder_input.rs`: add `StagedResource<T>(T)` with `impl BuilderInput<Init = T, Dispatch = StoreDispatch<Resource<T>>>`; add `fn into_init(self) -> Self::Init` to `BuilderInput` (default `self`; carriers and zero-data markers override).
3. `hilavitkutin-api/src/store.rs`: `Resource::new(value: T)` returns `StagedResource<T>` carrying the value instead of dropping. `Column`/`Virtual` keep `Init = ()`.
4. `hilavitkutin/src/scheduler/mod.rs`: reshape `SchedulerBuilder<Wus, Stores>` to `SchedulerBuilder<Wus, Stores, Platform, Staged: StageList>`; `.with` advances all four typestates and moves `provider.into_init()` onto `Staged`; `builder()` returns the four-param empty builder. `build()` bounds and body unchanged for now except for carrying the extra params (the arena move is B2).

Outcome: a value passed to `.with(Resource::new(v))` is retained on the builder's `Staged` list, not dropped. Verified by a test that extracts the staged value and asserts equality. The `MemoryProvider` is now carried in the `Platform` accumulator, ready for B2 to allocate the arena.
