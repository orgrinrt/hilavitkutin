# Doc changelist — builder value retention (B1)

Round: 202605282319. Phase: DOC. Updates the documented builder shape to match what B1 ships: the four-param `SchedulerBuilder` that retains each registered value instead of dropping it.

Scope note: the engine DESIGN builder section carries pre-existing drift unrelated to B1 (it names the registration trait `Provider` and a GAT-form `Dispatch::NextWus<Wus>`, while shipped source is `BuilderInput` with a parameter-form `Dispatch<Wus, Stores, Platform>`, and it shows a `Scheduler<Wus, Stores, Platform>` return that source does not have). That gap is aspirational-vs-shipped and predates this round; reconciling the whole section is a separate doc pass, not folded here. B1 edits only the lines its own change makes inaccurate (the param count and the drop-vs-retain behavior), and leaves the broader terminology drift for that later pass.

## File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`

The builder typestate line documents `SchedulerBuilder<Wus, Stores, Platform>` with `Scheduler::builder()` at `<Empty, Empty, Empty>`. B1 adds a fourth accumulator, `Staged`, that carries the registered values (the cons-list of `BuilderInput::Init` values) so they survive to `build()` rather than being dropped at `.with`. Update the type to `SchedulerBuilder<Wus, Stores, Platform, Staged>` and the initial state to `<Empty, Empty, Empty, StageEmpty>`, and add a sentence stating that `.with` now moves each registered value onto the `Staged` accumulator (the value is retained, not dropped; the move into the `MemoryProvider`-allocated arena follows in the next data-plane round).

## File: `mock/crates/hilavitkutin-api/DESIGN.md.tmpl`

The registration-contract section describes `BuilderInput` with its `Init` and `Dispatch` associated items. B1 changes `Resource::new(value)` to return a value-carrying `StagedResource<T>` (impl `BuilderInput<Init = T, Dispatch = StoreDispatch<Resource<T>>>`) instead of dropping the value, and `.with` moves each registered input onto the staged value list. Add a short note that `Resource::new` returns a carrier and that registered values are retained until `build()`. The `.with(Resource::new(value))` call-site spelling is unchanged. No method is added to `BuilderInput`: it stays `Init` + `Dispatch`, so none of the existing `impl BuilderInput` sites change. Value-extraction from a carrier into the arena is a sealed trait introduced in the arena round (B2), not a `BuilderInput` method.

## Not changed

The design-doc-source-mismatch lint checks only first-cell backtick names in DESIGN table rows; none of the affected text is a table row, and the new source-only types (`StagedResource`, `StageList`, `Stage`, `StageEmpty`) need no DESIGN table entry. The broader `Provider`/GAT-`Dispatch` drift in the engine builder section is left for a dedicated reconciliation pass.
