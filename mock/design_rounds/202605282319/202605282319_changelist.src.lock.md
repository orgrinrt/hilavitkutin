# Source changelist — builder value retention (B1)

Round: 202605282319. Phase: IMPL. Makes the scheduler builder retain each registered value instead of dropping it, by giving `.with` a value-carrying accumulator and having `Resource::new` return a carrier that owns the value. No method is added to `BuilderInput` (it stays `Init` + `Dispatch`), so none of the 24 existing `impl BuilderInput` sites change. The move of retained values into a `MemoryProvider`-allocated arena is the next round (B2).

## CHANGE: `Resource::new` FROM `(_value: T) -> Resource<T>` (drops) TO `(value: T) -> StagedResource<T>` (owns)
File: `mock/crates/hilavitkutin-api/src/store.rs`
`Resource::new(value)` returns a value-carrying `StagedResource<T>` instead of dropping. The `.with(Resource::new(value))` call-site spelling is unchanged (all current uses are `.with` arguments).
Verification: `grep -q "pub fn new(value: T) -> StagedResource<T>" mock/crates/hilavitkutin-api/src/store.rs`.

## CHANGE: type `StagedResource<T>` ADDED with `impl BuilderInput<Init = T, Dispatch = StoreDispatch<Resource<T>>>`
File: `mock/crates/hilavitkutin-api/src/store.rs`
`pub struct StagedResource<T>(T)` owning the registered value, with `into_inner(self) -> T` for the arena drain (B2) and the retention test. Its `BuilderInput` routes `Resource<T>` into the store accumulator via `StoreDispatch<Resource<T>>`. Re-export from `hilavitkutin-api/src/lib.rs`.
Verification: `grep -q "pub struct StagedResource<T>" mock/crates/hilavitkutin-api/src/store.rs` and `grep -q "impl<T: 'static> BuilderInput for StagedResource<T>" mock/crates/hilavitkutin-api/src/store.rs`.

## CHANGE: `impl BuilderInput for Resource<T>` REMOVED
File: `mock/crates/hilavitkutin-api/src/store.rs`
`Resource<T>` is now only the store marker (carried in `Stores` via `StoreDispatch<Resource<T>>` and used in `AccessSet`); it is never a `.with` argument, so its `BuilderInput` impl is dead. `StagedResource<T>` is the registered input.
Verification: `! grep -q "impl<T: 'static> BuilderInput for Resource<T>" mock/crates/hilavitkutin-api/src/store.rs`.

## CHANGE: module `scheduler::stage` ADDED (`StageList`, `StageEmpty`, `Stage<H, T>`)
File: `mock/crates/hilavitkutin/src/scheduler/stage.rs` (new)
Sealed value-carrying cons-list: `StageEmpty` leaf and `Stage<H, T: StageList> { head: H, tail: T }` (fields `pub(crate)` for the arena drain and tests). `StageList` is sealed so consumers cannot impl it.
Verification: `grep -q "pub struct Stage<H, T: StageList>" mock/crates/hilavitkutin/src/scheduler/stage.rs`.

## CHANGE: `SchedulerBuilder` FROM `<Wus, Stores>` (phantom, drops `.with` value) TO `<Wus, Stores, Platform, Staged: StageList>` (retains)
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
The builder carries `staged: Staged`. `.with<P>(self, provider: P)` moves `provider` onto `Stage<P, Staged>` and advances the typestate through `P::Dispatch as Dispatch<Wus, Stores, Platform>` (the real `Platform` accumulator, replacing the hardcoded `Empty`). `Scheduler::builder()` returns `SchedulerBuilder<Empty, Empty, Empty, StageEmpty>`. `build()` / `build_with` carry the extra parameters and consume `staged` (B1 drops it at `build()`; B2 moves it into the arena).
Verification: `grep -q "SchedulerBuilder<Empty, Empty, Empty, StageEmpty>" mock/crates/hilavitkutin/src/scheduler/mod.rs` and `cargo check` green across the mock workspace (the inference-built consumer tests still compile).

## CHANGE: retention test ADDED
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (unit test) and `mock/crates/hilavitkutin/src/scheduler/stage.rs` (unit test)
`stage_carries_value`: a `Stage<u32, StageEmpty>` yields its head value. `builder_retains_registered_value`: `Scheduler::builder().with(Resource::new(42u32))` produces a builder whose staged head `into_inner()` is 42, proving the value is retained, not dropped.
Verification: `cargo test -p hilavitkutin builder_retains_registered_value` passes.
