## Changes proposed

1. `hilavitkutin/tests/r5_core_idle_accum.rs`: `accum_frame` takes the walking-core count from its caller, given by hand as 4 at four workers and 32 at forty, and no longer works it out by the engine's slicing.
2. `hilavitkutin/tests/r5_core_idle_parallel.rs`: the pipeline runs through one function returning whether the frame idled, and two tests pin the worker count with `FixedWorkers`: four workers must record idle, one worker must record none. Both run on every machine; the sink check stays in the shared function.
3. `hilavitkutin/src/thread/frame.rs`, `hilavitkutin/src/resource/bindings/per_core.rs`: the module and item docs say what the protocol and the rebase are, and name no gate, round or deviation.
4. `hilavitkutin-providers/src/adapt_ema.rs`: the stub notice is plain prose. The task `hilavitkutin_providers_2_unmarked_placeholders` names the committed sketch `mock/research/sketches/202605101036-ema-vectorisation/` the finished body follows.
5. `mock/lints/no_process_words_in_comments.rs`: `round` counts as process only as the noun, followed by a number or led by a word that makes it one; a verb taking an object passes. Block comments are tracked across lines, so a code line led by `* ` is code, and a char literal no longer flips the string state. Each case is a test in `no_process_words_in_comments/tests.rs`.

The second error in `hilavitkutin/tests/ui/undeclared_read_fail.stderr` comes from the engine's `ColSelector` resolution in `dispatch/engine_ctx`, which this round does not edit; it goes to the engine lane as a ticket.
