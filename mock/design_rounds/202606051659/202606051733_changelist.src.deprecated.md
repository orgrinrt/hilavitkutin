# SRC CL: column-capable range-gated inline dispatch walk

This is increment 1 of the locked dispatch-codegen design: replace the per-unit type-erased function-pointer dispatch in `Scheduler::run` with the column-capable inline `RunFiber` walk, so a fiber's unit sequence monomorphises into one devirtualized body. Increments 2 (real `classify_columns` Input/Output/Internal split) and 3 (scratch-backed internal columns, the within-fiber fusion that moves the `#664` perf gate) are follow-on rounds on this branch; this round lands the devirtualization precondition.

## Current state

`Scheduler::run<Witnesses>` (`scheduler/mod.rs:659-741`) materializes a runtime `live[]` slot array of `FiberSlot` (an erased instance pointer plus a per-unit `fiber_shim`) from the flat `wu_values` cons-list via `CollectFiber`, then walks the per-fiber `fiber_dispatch` descriptors and dispatches each unit by indexing `live[order[k].0]` and calling its shim. The dispatch is per-fiber morsel-outer (accum-free fibers) or unit-outer (accum-bearing fibers). The per-unit indexed function-pointer call is the dispatch class the ideal-vs-actual audit measures at the 12.6x devirtualization pathology; LLVM cannot devirtualize across the runtime-walked slot array.

`RunFiber` (`dispatch/fiber_walk.rs`) is the compile-time-recursive inline walk that constructs each unit's `EngineCtx` and calls `execute` with no function pointer, but it is resource-only: its bound forces `ColPtrNil` / `Empty` column projections and an `AccPtrNil` accumulator projection, so a column-reading, column-writing, or accumulator-writing unit does not satisfy it. A `compile_fail` doctest (`fiber_walk.rs:111-141`) asserts that a column-writing unit does not compile through the walk.

The `202606051601` sketch proved the column-capable generalization compiles and devirtualizes (release ASM: no dispatch symbol survives) for a flat heterogeneous column chain.

## Changes

## CHANGE: trait `RunFiber` FROM resource-only TO column-capable, with range-gating and dispatch mode
File: `mock/crates/hilavitkutin/src/dispatch/fiber_walk.rs`
Detail: Generalize the `WuCons` impl past the resource-only bound. The per-unit witness becomes the tuple `(RIdx, RCIdx, WCIdx, WAIdx)` (resource index, read-column index, write-column index, accumulator-witness index) per the `202606051601` sketch impl; the bound carries `A: Project<W::Read, RIdx>`, `A: ColProject<W::Read, RCIdx>`, `A: ColProject<W::Write, WCIdx>`, `for<'f> A: AccumProject<'f, W::Write, WAIdx>`, and the GAT tie restates each Ctx projection over `A` (resolved with `A` pinned by `Scheduler::run<Witnesses>`). The walk recurses the whole flat cons-list tracking the unit's registration position, and dispatches a unit only when its position lies in the active fiber's `[start, end)` range; out-of-range cells recurse without dispatching. The dispatch obeys the fiber's mode: morsel-outer (the caller's morsel loop is outer, the walk dispatches each in-range unit once per morsel) or unit-outer (the walk runs each in-range unit over the full record range, windowed into morsels, before recursing). Devirtualization is preserved: each `execute` target is statically known per cons-cell, and the range check is a non-indirect runtime branch.
Verification: `grep -n "ColProject" mock/crates/hilavitkutin/src/dispatch/fiber_walk.rs` returns the column-projection bounds on the `RunFiber` impl; a new test dispatches a column-reading-and-writing fiber through the walk and asserts the written column matches the expected per-record transform.

## CHANGE: delete `CollectFiber`, `FiberSlot`, `fiber_shim`, `noop_fiber_shim`

Detail: The type-erased slot dispatch is replaced by the inline walk, so the slot-collection machinery is deleted outright (no retained fallback, per the pre-1.0 no-legacy-shims norm). `dispatch/fiber_codegen.rs` is removed or emptied of these items; the `mod` declaration and re-exports adjust accordingly.
Verification: `! grep -rn "CollectFiber\|FiberSlot\|fiber_shim" mock/crates/hilavitkutin/src/` returns no match.

## CHANGE: `Scheduler::run` dispatch FROM per-unit fn-pointer slot array TO range-gated inline walk
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs:659-741`
Detail: Drop the `live[]` slot materialization and the `WuVals: CollectFiber<...>` bound. Keep the per-fiber descriptor loop (`fiber_dispatch[0 .. fiber_dispatch_count]`) and the morsel-outer / unit-outer branch. Per fiber, invoke the column-capable `RunFiber` walk over `self.wu_values` gated to the fiber's `[start, end)` registration range, with the fiber's `morsel_local` mode and the record windowing. The `Witnesses` parameter becomes the per-unit `(RIdx, RCIdx, WCIdx, WAIdx)` witness-tuple list, still inferred at the call site.
Verification: `cargo test -p hilavitkutin` stays green; the `#664` perf-gate runtime ratios do not regress (devirtualization may improve them).

## CHANGE: add registration-order build-time validation
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (build path) or `plan/`
Detail: The inline walk dispatches in registration order, so registration order must be a valid dispatch order with each fiber a contiguous registration sub-sequence. `build` validates the plan's derived dispatch order against registration order and returns a `BuildError` when they diverge (a unit registered ahead of its producer, or a fiber whose units are not contiguous in registration order). This makes the registration-equals-dispatch-order invariant enforced rather than assumed, which is what lets the range-gated walk map a fiber's `[start, end)` to cons-list positions. The exact predicate (identity-permutation check on the derived order versus a dependency-validity check) is settled in implementation against the existing tests.
Verification: a new test registers two WorkUnits with the consumer ahead of the producer and asserts `build` returns `BuildError`; the existing engine and gate tests, which register in dependency order, continue to build.

## CHANGE: delete or rewrite the resource-only `compile_fail` doctest
File: `mock/crates/hilavitkutin/src/dispatch/fiber_walk.rs:111-141`
Detail: The doctest asserts a column-writing unit does not compile through the walk. The column-capable generalization inverts that, so the doctest is removed; a passing example dispatching a column-bearing fiber replaces the module-level illustration if one is warranted.
Verification: `cargo test -p hilavitkutin --doc` passes with no `compile_fail` block asserting column WUs are rejected.
