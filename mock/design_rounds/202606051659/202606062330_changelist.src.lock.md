# SRC CL: dispatch-order keystone machinery + dispatch-path cleanup

This increment lands the proven dispatch-ORDER keystone machinery (the compile-time-foldable topological order derived from the work units' `AccessSet` types) plus the dispatch-path cleanup (delete the superseded `RunFiber` sequential walk, which `CollectFiber` replaced). `Scheduler::run` keeps its canonical per-fiber morsel-locality walk (the locked-round 202606051500 shape, the spec's domain-17 per-fiber local slices); its dispatch ORDER source stays the plan's `topo_order` field this increment. Sourcing the order from the compile-time-foldable `carrier_order_dyn` (so LLVM devirtualises the per-unit dispatch, the #664 perf-gate half) requires a fiber-grouped compile-time carrier: the flat carrier order interleaves independent components, so its segments do not line up with the plan's per-fiber descriptors. That flattener bridge is the remaining keystone step, tracked as #669; this increment lands and proves the order machinery it consumes.

## Comparison to deprecated changelist

The deprecated src CL `202606051733` attempted the dispatch rewrite but stalled on the open mechanism its own increment-1 note flagged: "how the plan-computed RCM order becomes the compile-time order of the dispatch cons-list while still devirtualizing ... the plan-order-to-compile-time-order bridge is the genuine hard part." That fork (full type-level partition vs plan-computed + carried) was the muddle that triggered the chart-the-path routine. It is now resolved (D1b, 202606061400): the fiber GROUPING is a runtime plan computation (the shipped `group_fibers`); the codegen flattener EMITS the per-fiber/per-core type-level carrier from the plan (canonical domain 17 "the flattener emits a monomorphised function ... derived from the WU declarations' Read/Write sets"); the trait solver devirtualises the walk over the emitted carrier. This increment lands the order machinery that flattener consumes and proves it devirtualises in isolation; the flattener that wires it into a fiber-grouped `run` dispatch (full devirt + per-fiber locality together) is #669.

The deprecated CL's per-header dispositions follow. Its core approach (extend `RunFiber` to a column-capable range-gated walk and make it the dispatch path) is fully SUPERSEDED: `CollectFiber` is the shipped dispatch mechanism, and `RunFiber` is deleted rather than extended.

## CHANGE: add `dispatch::order` const topological dispatch order
File: `mock/crates/hilavitkutin/src/dispatch/order.rs` (new) + `mock/crates/hilavitkutin/src/dispatch/mod.rs`

## CHANGE: add `carrier_order_dyn` (GCE-safe dispatch order over `Capacity::Array`)
File: `mock/crates/hilavitkutin/src/dispatch/order.rs`
The const `carrier_order` returns `[USize; N]`; using it in a generic body (N = `cap_size(D::Units::CAP)`) overflows `generic_const_exprs` well-formedness (E0275) at instantiation. A RUNTIME-computed order devirtualises identically (proven: sketch `202606071400_runtime-order-devirt`, objdump zero `blr` + zero `bl`; LLVM folds the pure topo over the post-monomorphisation-constant masks). Add `pub fn carrier_order_dyn<Bundle, Stores, Witnesses, U: Capacity, CS: Capacity>() -> <U as Capacity>::Array<USize>`: a NON-const empty-aware Kahn over `<U as Capacity>::filled` mask arrays (placeholders sorted last), the GCE-safe `Capacity::Array` form (no const-generic N). The const `topo_order`/`carrier_order` + tests stay (the const fold path the dyn one reuses for the mask fold). This is the order form a fiber-grouped-carrier `run` dispatch consumes; #669 wires it in.
Verification: `grep "pub fn carrier_order_dyn" mock/crates/hilavitkutin/src/dispatch/order.rs`; `cargo test -p hilavitkutin --lib dispatch::order` (`carrier_order_dyn_reorders_prefix`: `WuCons<WuB, WuCons<WuA, WuNil>>` over `Dim<8>` yields live prefix `[1, 0]`).
