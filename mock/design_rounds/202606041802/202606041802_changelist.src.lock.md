# Src changelist: plan-projection hardening

**Date:** 2026-06-04
**Phase:** SRC
**Round:** 202606041802 (plan-projection-hardening, branch `chore/hilavitkutin-plan-projection-hardening`)

Two correctness-hardening edits to the plan projection in `scheduler/mod.rs`, clearing the PR #122 `topo_count` note and #657. No behaviour change for a complete partition / unchanged column offsets; the existing tests stay green.

## CHANGE: guard `derive_phase_dispatch_order` against an incomplete partition
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
At the end of `derive_phase_dispatch_order`, add `debug_assert_eq!(next, plan.unit_count.0, ...)` so a fiber partition that fails to place every unit (a silent dispatch drop) surfaces in debug and test builds. Reword the `topo_count` field doc from "registered unit count" to "the flattened dispatch total (equals the registered unit count when the fiber partition is complete)".
Verification: `grep "debug_assert_eq!" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match (the multiline assert in `derive_phase_dispatch_order`); `grep "flattened dispatch" ...` returns one match (the reworded `topo_count` field doc).

## CHANGE: `column_id` exhaustive match + `PlanColumn::COUNT`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Replace `column_id`'s `base + (c as usize)` with `base + match c { Phases => 0, Trunks => 1, Fibers => 2, UnitMeta => 3, MorselSizes => 4, RcmOrder => 5 }` so the per-variant offset is explicit (reordering the enum no longer shifts offsets) and adding a variant is a compile-forced change (non-exhaustive match). Add an associated `const COUNT: usize` on `PlanColumn` (= 6) and reference it in the `store_plan` doc in place of the literal `6`.
Verification: `grep "let offset = match c" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match (in `column_id`); `grep "const COUNT" ...` returns one match (the `PlanColumn::COUNT` declaration); `grep "PlanColumn::COUNT" ...` includes the `store_plan` doc reference.

## Tests

A focused test pins the `column_id` offset contract: build a scheduler with a known plan, then assert the `PlanHandle` accessors return contiguous offsets off the base in the documented order (`phases_id` through `rcm_order_id` at base+0 through base+5). This discriminates a wrong match arm. The `topo_count` guard has no discriminating red-first test (the partition is complete, so it passes); it is exercised passing by the existing dispatch tests in debug builds. Existing column / accumulator / morsel / phase-sequential tests stay green (offsets and dispatch behaviour are unchanged).

## Out of scope

- The major engine tiers (#339 / #340 / #342 / #344) and the arvo-graph widening; this round hardens the existing projection only.
