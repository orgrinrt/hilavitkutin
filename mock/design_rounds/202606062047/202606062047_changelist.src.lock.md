# Source changelist

Lift the engine's 64-node waist cap by carrying the adjacency / waist row word as
a concrete `PlanDims::AdjRow` associated type instead of the hardcoded
`Bits<64, Hot, Unsigned>` inside `compute_waists`. Sketch
`mock/research/sketches/202606101000_d668-cap-width-row-word` proves this is the
only shape that compiles (the inline `Bits<{cap_size(...)}>` derive hits arvo's
symbolic-N container-projection wall).

## CHANGE: trait `PlanDims` GAINS associated type `AdjRow`
File: `mock/crates/hilavitkutin/src/plan/dims.rs`
Add `type AdjRow: BitSequence + BitAccess + BitLogic + Copy + Default + Identity;`
to the trait. Imports gained: `arvo::{Bits, Hot, Unsigned, Identity}`,
`arvo_bitmask::{BitAccess, BitLogic, BitSequence}` (contract traits reached via
the L2 arvo-bitmask re-export, not L1 `arvo_bits`).
Verification: `grep "type AdjRow:" mock/crates/hilavitkutin/src/plan/dims.rs` returns one match.

## CHANGE: `DefaultPlanDims` SETS `AdjRow = Bits<64, Hot, Unsigned>`
File: `mock/crates/hilavitkutin/src/plan/dims.rs`
The default 64-node budget keeps a 64-wide row (`Units = Dim<64>`), unchanged behaviour.
Verification: `grep "type AdjRow = Bits<64, Hot, Unsigned>;" mock/crates/hilavitkutin/src/plan/dims.rs` returns one match.

## CHANGE: `compute_waists` USES `D::AdjRow` not `Bits<64, Hot, Unsigned>`
File: `mock/crates/hilavitkutin/src/plan/steps.rs`
Both occurrences (the `BitMatrix<_, D::Units>` row word and the
`waist_detect::<D::Units, _>` / `Mask<_>` row word) become `D::AdjRow`. The step
doc comment's "arbitrary node counts above 64 are a separate arc" text is
rewritten to state the cap is now `D::AdjRow`-wide.
Verification: `! grep "Bits<64, Hot, Unsigned>" mock/crates/hilavitkutin/src/plan/steps.rs` (no 64-hardcode remains in this file).

## CHANGE: every `PlanDims` impl SETS `AdjRow`
Files: `mock/crates/hilavitkutin/src/thread/mod.rs` (TestDims), and the test
PlanDims impls in `tests/{block_diagonalise,plan_runner,plan_id_width_guard,
waist_detect,plan_types,rcm_reorder,synthesise_core_programs,fiber_projection,
spectral_partition,csr_adapter}.rs`. All use `Units <= Dim<8>`, so each sets
`AdjRow = Bits<64, Hot, Unsigned>` and gains `Bits, Hot, Unsigned` imports.
Verification: `cargo test -p hilavitkutin` compiles (no missing-associated-type error).

## CHANGE: new >64-node waist test proving the lift
File: `mock/crates/hilavitkutin/tests/waist_detect.rs`
Add `WideDims` (`Units = Dim<128>`, `AdjRow = Bits<128, Hot, Unsigned>`) and a
fixture of two length-33 parallel chains merging into one waist node then fanning
to two sinks (69 nodes). The merge node sits at topo position 66, past the old
64 cap, so the boundary opens at position 67. Under the former hardcoded
`Bits<64>` the high-index edges drop and the boundary is misplaced; with the
widened row the waist is detected correctly.
Verification: `cargo test -p hilavitkutin --test waist_detect` passes the new test.
