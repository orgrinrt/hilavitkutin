# clippy-driver-wrapper-warning

Op, 15 November, on the output of a commit in kaski: "Fix the commit output asap". Every commit there printed one `cargo::warning` per engine crate, twice over, saying that `hilavitkutin-build` chose rustc flags and no workspace wrapper appends them.

The warning comes from `configure_with` in `hilavitkutin-build/src/bootstrap.rs`. The commit hook runs `cargo clippy`, and clippy names `clippy-driver` as the workspace wrapper in place of `.cargo/hilavitkutin-rustc-wrapper`. A plain `cargo check` in the same tree prints none. The flags the build script hands over are LLVM loop options and `-Zthreads=0`: they steer code generation only, and a clippy check generates no code, so nothing is lost when they are dropped there. The warning under clippy reports a loss that does not happen.
