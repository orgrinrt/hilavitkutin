# Topic: GATE-2 accumulator unit-outer threaded path (deviation §9)

**Date:** 2026-06-07
**Phase:** TOPIC
**Scope:** `hilavitkutin` (`scheduler/mod.rs` run_parallel + worker_main, the accumulator/unit-outer dispatch), possibly `hilavitkutin-api` (`PoolFrame` per-core accumulator slots / `Accum` live-length), engine tests; a de-risk sketch first.
**Source:** deviation ledger `202606072100` §9; consolidation spec convergence-accumulator (`:1750-1766`), Topic 6 head+tail (`:770-771`).

## Current state

`run()` (single-core) dispatches two fiber shapes: a `morsel_local` fiber morsel-outer (cache-resident intermediates) and an accumulator-bearing fiber **unit-outer** (each unit completes its full record range before the next, the cross-record-safe form for an `Accum` whose append advances a single live-length cell). `run_parallel` (GATE-2 R4c + §4 + §8) handles ONLY the morsel-local pure-RAW path: it resets accumulators (`ResetAccumulators`) then dispatches the morsel-local gated walk. The unit-outer accumulator carrier that `run()` routes specially is NOT handled threaded (deviation ledger §9). So accumulator workloads cannot use the parallel engine: the #664 accumulator perf arm runs single-core, red-by-design, and there is no threaded accumulator path at all. This is a correctness/completeness gap, not just a perf gap.

## Canonical position

Spec `:770-771`: single-trunk phases use head+tail convergence, "skip for non-commutative resource accumulation." `:1750-1766`: "each convergence thread gets its own stack-local accumulator (same caching pattern). After convergence: merge." Non-commutative resource accumulation skips convergence (stays single-core for correctness). So the canonical threaded accumulator is: per-thread (per-core) accumulator region, each core appends its record-slice in order, merge the per-core regions after the phase; a non-commutative accumulator is NOT split (single-core fallback).

## The unknown to de-risk first (sketch, cl-claim-sketch-discipline)

`Accum<T>` is an append surface with ONE live-length cell; `append` advances it and saturates at reserved capacity. Concurrent cores appending to one `Accum` race on the live-length. The sketch must prove the per-core-region + merge mechanism on the real `Accum`/storage:

- **Per-core append regions.** Either (a) each core appends into its own reserved sub-region of the accumulator's arena (offset = core * per_core_cap) with its own live-length, merged (compacted) after; or (b) a `PoolFrame` per-core accumulator-slot array the cores append through, merged at phase end. Prove ONE compiles + is race-free + order-preserving (core c handles a contiguous record slice, appends in record order, merge concatenates slices in core order → global append order preserved).
- **Merge / compaction.** After the phase, the per-core live regions are concatenated into the single `Accum`'s contiguous live prefix (the shape `run()` and downstream readers expect). Prove the merge produces the same byte-identical result as the single-core unit-outer append.
- **Non-commutative fallback.** A WU hint (domain 08 `COMMUTATIVE`) decides split-vs-single-core. Confirm the hint is reachable at dispatch and the single-core fallback is correct.

Sketch outcome `WORKS` / `FAILS WITH <error>`; if the per-core-region mechanism walls (e.g. the arena/storage cannot express per-core sub-regions without a contract change that ripples), it is a Step-11 op-decision (roadmap-shaping).

## Change proposed (after the sketch clears)

`run_parallel`/`worker_main`: for an accumulator-bearing (unit-outer) phase, dispatch the canonical convergence-accumulator path: per-core accumulator region, each core appends its `[lo,hi)` record slice (reusing the §8 record-range split) in order, a post-phase merge concatenates the per-core regions into the `Accum`'s live prefix; non-commutative accumulators stay single-core. The morsel-local path is unchanged (§8 convergence). Then the #664 accumulator arm can be measured threaded.

## Tests

- A single accumulator-append WU over N records dispatched via `run_parallel` on >1 core: assert the `Accum`'s live prefix is byte-identical to the single-core `run()` result (same values, same order), proving per-core append + merge correctness. Poison the accumulator region first.
- A non-commutative accumulator stays correct (single-core fallback): assert the result is not corrupted by an illegal split.
- Existing accumulator single-core test + full suite stay green.

Pipeline parallelism (§8 slice 2, phase overlap via progress counters) is the other unbuilt §8 piece, independent. The compiled per-core dispatch (§1) is the separate bench-gated escalation. This round does the accumulator threaded path only.
