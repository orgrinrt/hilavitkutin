## Current state

`run_parallel` dispatches only the morsel-local pure-RAW path. An accumulator
carrier currently cannot use `run_parallel` soundly: the append resolves an
`AccumColPtr` from the single shared `AccumBinding` whose `Cell` live-length is
non-atomic (`resource/bindings.rs:117`), so concurrent workers would race. `run()`
(single-core) handles accumulators via the unit-outer whole-carrier walk
(`scheduler/mod.rs:1047-1055`, `RunFiber::run` over the full range).

## Design (cleaner than the projected-bundle rebase; reuses RunFiber::run)

Rebase the BINDINGS per core, not the projected bundle. Each worker builds a
per-core copy of the bindings where every `AccumBinding` is offset to the core's
head+tail record-slice start `lo_c` (`base + lo_c`, fresh zero `Cell`, cap =
`hi_c - lo_c`); column / resource / virtual nodes copy their (Copy) pointers
unchanged. The worker then calls the EXISTING `RunFiber::run(&per_core_bindings,
MorselRange[lo_c, hi_c-lo_c])` (unit-outer, ungated, the same call `run()` uses),
so the whole projection + append path runs unchanged against the per-core regions.
Disjoint byte ranges plus per-core cells = no shared mutable state. After the
phase, each worker publishes its per-accumulator live counts; the main thread
forward-compacts each accumulator's per-core regions (`[lo_c, lo_c+live_c)`) in
ascending core order into the shared binding's `[0, sum)` prefix and sets the
shared live length. Byte-identical to single-core `run()`. First slice scopes to
the unit-outer (accumulator-bearing) carrier with the `<=1`-append-per-record
convergence pattern; non-commutative stays single-core (follow-up), and per-phase
accum-vs-RAW routing (running RAW phases morsel-local while accum phases go
unit-outer) is a perf follow-up (running all unit-outer is correct, just less
cache-optimal).

## CHANGE: trait `RebaseBindings` ADDED to `resource/bindings.rs`
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
`fn rebase_accums(&self, lo: USize, region_cap: USize) -> Self` over the bindings
cons-list. `BindingNil -> BindingNil`; `ResourceBinding`/`ColumnBinding`/
`VirtualBinding` copy their fields and recurse; `AccumBinding` produces a node with
`ptr` advanced by `lo` (via `ColumnPtr::new_unchecked(ptr.as_ptr().add(lo))`),
`len = Cell::new(USize(0))`, `cap = region_cap`, recursing on the tail. Returns the
same bindings type (each node maps to itself).
Verification: `grep "trait RebaseBindings" mock/crates/hilavitkutin/src/resource/bindings.rs` returns one match.

## CHANGE: trait `CollectAccumLive` ADDED to `resource/bindings.rs`
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
`fn collect_accum_live(&self, out: &mut [USize], idx: &mut USize)`: writes each
`AccumBinding`'s `len.get()` into `out[idx]` in carrier-accum order, advancing
`idx`; no-op at non-accum nodes. Lets a worker publish its per-core live counts.
Verification: `grep "trait CollectAccumLive" mock/crates/hilavitkutin/src/resource/bindings.rs` returns one match.

## CHANGE: trait `MergeAccums` ADDED to `resource/bindings.rs`
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
`fn merge_accums(&self, per, ncores, total, live, accum_idx)`: for each
`AccumBinding` (accum index a), forward-compacts the per-core live regions into the
shared buffer's prefix (`write_pos += live[c][a]`, `ptr::copy` from `lo_c` to
`write_pos`; `write_pos <= lo_c` so the copy is forward-safe) and sets the binding
`len` to the total; recurses with `a+1`. Runs on the shared bindings post-phase.
Verification: `grep "trait MergeAccums" mock/crates/hilavitkutin/src/resource/bindings.rs` returns one match.

## CHANGE: const `GATE2_MAX_ACCUMS` + unit-outer accum branch ADDED to `scheduler/mod.rs`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
`GATE2_MAX_ACCUMS` bounds the worker-stack live-count array and the scheduler
publish array. `run_parallel`/`worker_main` gain a unit-outer branch: when the
carrier is unit-outer (any non-`morsel_local` fiber, the same check `run()` makes),
each worker builds its per-core bindings via `rebase_accums(lo_c, hi_c-lo_c)`, runs
`RunFiber::run` over `[lo_c, hi_c)`, collects its live counts via
`collect_accum_live`, and publishes them to a scheduler per-core atomic array
(`AtomicUsize`, Relaxed store before `frame_done_arrive`); the morsel-local branch
is unchanged. After `frame_await_done`, the main thread loads the array (acquire via
the done counter) and calls `merge_accums` on the shared bindings.
Verification: `grep "GATE2_MAX_ACCUMS" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns matches; `cargo test -p hilavitkutin` builds.
