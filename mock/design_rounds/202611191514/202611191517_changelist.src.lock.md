## Current state

`CeilingDiv` and `Ceil` are nowhere in the tree since round `202611191347` deleted them. The engine's seal `EngineOnly` closes `Executor`, `DispatchCodegen` and `FiberShape`, and nothing tests that an outside impl is refused. `tests/engine_id_index.rs` checks three or four hand-picked indices of each id. The plan module's doc says the per-aggregate dimensions are not "CeilingDiv-derived".

## Changes proposed

### 1. `CeilingDiv` in the engine

`hilavitkutin/src/plan/ceiling_div.rs` declares `CeilingDiv<N, D>` and its one implementer `Ceil<N, D>`, as the api declared them, with `RESULT = N.div_ceil(D)`; `plan/mod.rs` declares the module and re-exports both. Its doc says what the design says: a heuristic offered beside the plan dimensions, read by nothing in the engine. The plan module's doc says the per-aggregate dimensions are their own capacity types and names `CeilingDiv` as the pick a consumer may make. `tests/ceiling_div.rs` holds it to an exact quotient, a remainder rounded up, a numerator below the divisor, a zero numerator and a divisor of one.

### 2. The seal is tested

`tests/ui.rs` gains three compile-fail fixtures with their stderr: `executor_outside_the_engine_fail.rs`, `dispatch_codegen_outside_the_engine_fail.rs` and `fiber_shape_outside_the_engine_fail.rs`. Each implements one sealed trait for a local type and is refused with E0277 on `hilavitkutin::sealed::EngineOnly`, the seal itself, so the fixture fails for the reason it names.

### 3. The id test walks each range whole

`tests/engine_id_index.rs` asserts the round trip at every index of `UnitId` (2^16), `FiberId` (2^7), `PhaseId` and `TrunkId` (their `ADDRESSABLE`), where it sampled a few.

### 4. The stranded-branch scripts

`mock/research/202611191400_stranded-branches/scripts/` holds the three scripts the note was measured with, each taking the clone's path first, and the note names them.
