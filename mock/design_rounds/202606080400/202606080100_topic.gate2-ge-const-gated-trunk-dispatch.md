## Current state

G-a..G-d (the const grouping infra) landed. `plan/grouping.rs` ships: `BundleMasks` (const fold of per-unit read/write masks over the registered `Stores` access-mask space), the const fns `compute_phases_waist` + `compute_trunks`, and the queryable `group_n` / `phase_of` / `trunk_of` / `is_member<.., const PHASE, const TRUNK>` / `phase_count`, all parameterised `<Wus, Stores, Witnesses, CU, CS, Adj>`. So the compile-time grouping (phase + within-phase column-disjoint trunk per carrier position) is computable from the registered WU types today.

What is NOT built: the dispatch side. `Scheduler::run` (single-core) still walks the flat `wu_values` carrier via `RunFiber` directly (one monomorphic flat walk, no per-trunk isolation). `run_parallel` dispatches per-(core,phase) via a RUNTIME mask path (`run_core_phase` reads the `gate2_phase`/`gate2_trunk` runtime arrays + `core_phase_mask` + `run_gated`), which is the R4b-inline interim, not the canonical compiled mechanism. The G2-0a/0b walks `RunTrunk`/`RunPhase`/`RunPipeline` exist but consume a NESTED `PhaseCons<TrunkCons<FiberCons<WuCons>>>` carrier type, which is the type-level N-way partition that WALLED (roadmap r4 "why r3's G2-0c walled"); they are not the G-e path.

## Canonical mechanism (proven, to port)

The flat carrier stays flat; the partition lives in const data (`GROUPING`), and const-eval + DCE is the flattener. Per-trunk isolation via a `POS`-threaded, const-gated walk over the flat `WuVals`:

- `trait RunTrunkSel<A, WL, const POS, const TRUNK>` with `impl for WuCons<H, T> where T: RunTrunkSel<A, TW, { POS + 1 }, TRUNK>` (the `{ POS + 1 }` GCE threading), body: `if const { is this carrier position a member of TRUNK } { RunFiber::run(&WuCons{head, tail: WuNil}, ..) } self.tail.run(..)`. The gate uses the shipped const grouping (`trunk_of(POS) == TRUNK`, or `is_member::<.., PHASE, TRUNK>()` for the phase-scoped form). `WuNil` terminates.
- `run_one_trunk::<.., const TRUNK>(carrier, bindings, morsel)` is the per-trunk program: monomorphising once per `TRUNK` value, DCE removes every non-member position's dispatch, leaving a member-only, devirt-clean (zero `blr`) program output-equivalent to the flat walk restricted to that trunk. (sketch 071230 objdump-proven; 071330 proved the same driven by the real computed grouping.)

## The new integration piece (the only un-proven-as-a-whole bit)

The sketches proved ONE trunk mono. `Scheduler::run` must dispatch ALL trunks across ALL phases in phase order (waist between phases), single-core, output-equivalent to the flat walk. Trunk ids are component-min carrier positions (`trunk_of(s) == s` marks a trunk root). So the dispatcher is a compile-time iteration over carrier positions `0..N`: for each position `s` that is a trunk root in phase `p`, monomorphise `run_one_trunk::<.., TRUNK = s>`; iterate phases `0..phase_count` outermost with a (degenerate single-core) waist between them. This const-range trunk-root dispatcher (recursive const-generic over the position, gating trunk-roots at const time, phase-outer) is the new build-integration; the per-trunk mono it calls is proven. De-risk the const-range recursion shape in the first src slice (or a one-file sketch) before locking if the `{ N }`-bounded recursion has a const-eval/GCE wrinkle.

## Change proposed

1. New `dispatch` module (e.g. `trunk_sel.rs`): `RunTrunkSel` trait + `WuCons`/`WuNil` impls (const-gated, POS-threaded, RunFiber-delegating) + `run_one_trunk::<TRUNK>` entry, ported from the sketches onto the real carrier and the real `trunk_of`/`is_member` grouping.
2. The const-range trunk-root + phase dispatcher that drives `run_one_trunk` for every (phase, trunk) over the flat carrier, waist between phases (degenerate single-core).
3. Re-point `Scheduler::run` to that dispatcher (single-core, sequential). Keep `run_parallel` on its current path for now; G2-N later re-points it to run these monos per core.

## Tests / gates (strict, fail-first)

- objdump each per-trunk mono: zero `blr` (devirt-clean) + member-only (non-member WUs' code absent). Mirrors the sketch proof, now on the real engine.
- Output bit-identical to the pre-G-e flat `Scheduler::run` across the existing engine test suite (column/accum/fiber dispatch tests) — output-equivalence is the correctness gate.
- `#664` perf gate no-regress (element_wise stays GREEN; branching/accumulator stay RED by design — G-e is single-core re-point, not the parallelism that closes them).

## Out of scope

G2-N core-pinning (assign each per-trunk mono to a pool thread, concurrent zero-sync, real waist barriers) is the NEXT stage after G-e and the step that turns the `#664` red arms green via real parallelism. The `run_parallel` runtime-mask path stays until G2-Na re-points it onto these monos. Bench escalation (compiled monos vs runtime mask) is decided by the GATE-2 benches at G2-N, not here.
