# Doc changelist: topological dispatch prose

The slice-2 prose states the walk order is registration-list order and
names dependency-topological order as "the plan-driven slice". Slice 3 is
that slice. The engine `DESIGN.md.tmpl` updates to describe the
plan-derived topological dispatch and the type-erasure mechanism that
makes a runtime permutation indexable over a heterogeneous unit list.

All new type and function names are introduced in PROSE only. No table
rows are added for them, because the `design-doc-source-mismatch` lint
checks backticked names in markdown tables against source, and the source
lands in the src CL phase that follows this doc lock.

## DOC CHANGE: dispatch-codegen walk paragraph

File: `crates/hilavitkutin/DESIGN.md.tmpl` (the `RunFiber` walk paragraph,
currently around line 116 to 131).

The sequential `RunFiber` walk paragraph stays (it is still the
list-order primitive, exercised directly by `tests/fiber_walk.rs`). A
following paragraph is added describing the type-erasure ordering tier:
the engine walks the typed `WuCons` list once into a uniform array of
`(erased instance pointer, monomorphised shim)` slots via a recursive
collect trait; each shim casts the erased pointer back to its concrete
unit, projects that unit's resource-only `EngineCtx`, and runs `execute`;
the slot array is then walked in the plan's topological permutation,
which a type-positional cons-list walk cannot produce. Names the
self-referential-struct reason the slots are materialised per `run()`
call rather than stored on the scheduler.

## DOC CHANGE: `Scheduler::run` order paragraph

File: `crates/hilavitkutin/DESIGN.md.tmpl` (the `Scheduler::run` paragraph,
currently around line 133 to 138).

Rewrites the "walk order is registration-list order this slice" claim to
"dispatch order is the plan's topological order": `build()` projects the
registered bundle into `PlanInputs`, runs `compute_execution_plan`,
extracts the topological permutation off `unit_meta`, and stores it on the
scheduler; `run()` rebuilds the slot array from the retained units and
walks it in that stored order. Notes the per-`Cfg` plan-dimension lift
stays deferred (fixed engine-budget constants this slice, the same shape
as the `[AtomicBool; 256]` plan-dirty width) and the morsel loop plus
per-frame column buffers are later still.
