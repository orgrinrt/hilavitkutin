# Src changelist: plan-derived topological dispatch

Slice 2 made `run()` walk the retained units in registration-list order
via the slice-1 `RunFiber` recursion. This slice makes `run()` dispatch in
the plan's topological order. The mechanism is type erasure: walk the
typed `WuCons` list into a uniform `(erased instance pointer,
monomorphised shim)` slot array, then walk that array in the topological
permutation the execution plan already computes. The permutation is
computed at `build()` (where the `Wus` bundle and `Stores` types are in
scope) and stored on the scheduler; the slot array is materialised inside
each `run()` from the retained units (a stored instance pointer would be a
self-referential struct).

## CHANGE: type `FiberSlot` + trait `CollectFiber` + fn `fiber_shim` ADDED in `crates/hilavitkutin/src/dispatch/fiber_codegen.rs`
File: `crates/hilavitkutin/src/dispatch/fiber_codegen.rs` (new file)
`FiberSlot<A> = (*const (), fn(*const (), &A, MorselRange))` is the erased
dispatch slot. `fiber_shim::<A, W, RIdx>` casts the erased pointer back to
`&W`, projects that unit's resource-only `EngineCtx` via
`EngineCtx::project::<A, ColPtrNil, RIdx, Empty, Empty>`, and runs
`invoke_wu_in_fiber`. `CollectFiber<A, Witnesses>` walks the value-carrying
`WuCons` / `WuNil` list (re-exported from `fiber_walk`), emitting one slot
per unit in list position into a caller-provided `&mut [FiberSlot<A>]`. The
per-unit bound matches the slice-1 `RunFiber` impl exactly (the `for<'f>`
`Ctx` GAT equality plus the two `ColPtrNil` column-projection bounds that
encode the resource-only boundary).
Verification: `grep -n "pub trait CollectFiber" crates/hilavitkutin/src/dispatch/fiber_codegen.rs` returns one match; `cargo test -p hilavitkutin --test scheduler_topo_dispatch` passes.

## CHANGE: struct `Scheduler` GAINS fields `topo_order: [USize; cap_size(ENGINE_MAX_UNITS)]` + `topo_count: USize`
File: `crates/hilavitkutin/src/scheduler/mod.rs`
The stored topological permutation: `topo_order[step]` is the list
position of the unit dispatched at topological position `step`;
`topo_count` is the live unit count. Plain index data, no borrows, movable
with the scheduler. Type parameters `<Cfg, WuVals, Vals, M>` are unchanged.
Verification: `grep -n "topo_order:" crates/hilavitkutin/src/scheduler/mod.rs` returns matches in the struct, `build`, `build_with`, and `Default`.

## CHANGE: enum `BuildError` GAINS variant `PlanFailed`
File: `crates/hilavitkutin/src/scheduler/mod.rs`
`compute_execution_plan` returns `Err` on a dependency cycle (and other
plan-feasibility failures); `build()` maps that to
`BuildError::PlanFailed`. `BuildError` is already `#[non_exhaustive]`, so
the addition is additive.
Verification: `grep -n "PlanFailed" crates/hilavitkutin/src/scheduler/mod.rs` returns matches.

## CHANGE: method `SchedulerBuilder::build` / `build_with` COMPUTE the plan and fill `topo_order` / `topo_count`
File: `crates/hilavitkutin/src/scheduler/mod.rs`
Both gain a `BWit` generic parameter (the per-unit `BundleProject` witness
list, inferred at the call site exactly as `run`'s `Witnesses` infers) and
the bound `Wus: BundleProject<Stores, BWit, ENGINE_MAX_UNITS,
ENGINE_MAX_STORES>`. Each projects the registered bundle into `PlanInputs`
(`plan_inputs_from_bundle`), runs `compute_execution_plan`, reads the
topological permutation off `unit_meta[u].id.index()` into `topo_order`,
and sets `topo_count = unit_count`. On plan `Err`, returns
`Err(BuildError::PlanFailed)` (after the arena is freed). The store-arena
drain and `MemoryProvider` handling are unchanged.
Verification: `grep -n "compute_execution_plan" crates/hilavitkutin/src/scheduler/mod.rs` returns matches in `build` and `build_with`.

## CHANGE: method `Scheduler::run` FROM list-order `RunFiber` walk TO topo-order `CollectFiber` walk
File: `crates/hilavitkutin/src/scheduler/mod.rs`
`run<Witnesses>` rebuilds a `[FiberSlot<Arena>; cap_size(ENGINE_MAX_UNITS)]`
from `&self.wu_values` via `CollectFiber`, then walks `topo_order[0 ..
topo_count]`, dispatching `slots[topo_order[step]]` at each step. The
`WuVals: RunFiber<Arena, Witnesses>` bound becomes `WuVals:
CollectFiber<Arena, Witnesses>`. Resource-only carries forward; the single
`(ZERO, ZERO)` morsel is unchanged this slice.
Verification: `grep -n "CollectFiber" crates/hilavitkutin/src/scheduler/mod.rs` returns a match in `run`'s bound; `! grep -n "RunFiber" crates/hilavitkutin/src/scheduler/mod.rs` (run no longer references RunFiber).

## CHANGE: `Scheduler` `Default` + `build`/`build_with` constructors INIT `topo_order` / `topo_count`
File: `crates/hilavitkutin/src/scheduler/mod.rs`
`Default` (empty `SvEmpty` scheduler) fills `topo_order` with `USize::ZERO`
and `topo_count` with `USize::ZERO`. The `build`/`build_with` constructors
fill them from the computed plan.
Verification: `grep -n "topo_count: USize::ZERO" crates/hilavitkutin/src/scheduler/mod.rs` returns a match in `Default`.

## Tests

New integration test `crates/hilavitkutin/tests/scheduler_topo_dispatch.rs`:
a resource-writer unit (`type Write = Cons<Resource<R>, Empty>`) and a
resource-reader unit (`type Read = Cons<Resource<R>, Empty>`) registered so
the registration-list order disagrees with the topological order. The
writer is registered first and the reader second, so the builder's prepend
puts the reader at list position 0 and the writer at position 1;
registration-list order would dispatch reader-then-writer. The
write-before-read dependency forces the plan to order writer-then-reader.
The test asserts the dispatch order is writer-then-reader (topological),
which fails under the slice-2 list-order walk and passes only under
topological dispatch. A second case asserts a single unit dispatches once.
The existing `tests/scheduler_run_walk.rs`, `tests/fiber_walk.rs`, and the
plan tests are unaffected (the slice-2 run-walk test's two units have no
inter-dependency, so its list order and topo order coincide; it still
passes).
