# one-slice-definition-and-tests-that-can-fail

**Date:** 2026-11-13
**Phase:** TOPIC
**Scope:** four places on `work/recover-landing-source` where the source landed by round `202611131112` does not do what its design text or its changelist says, and two smaller ones beside them.
**Source:** a reading of the branch at `672b8e7` by a reviewer with no part in the work.

Round `202611131112` carried the source of the July and August rounds onto `dev`'s present shape. A reading of the result found four places where what landed is weaker than what is written about it. None of them is new work. Each is a sentence in a design template or a locked changelist that the code or the test under it does not yet make true, and this round makes them true or removes the sentence.

The round changes no behaviour of the engine. One function moves, two tests are replaced by ones that reach the code they name, one test asserts by fiber where it compared sorted pairs, and one design paragraph loses two sentences of history.

## The accumulator split is written twice

The engine design says the worker's region boundaries and the merge's read offsets are "the same function of `(total, ncores, core)`, computed once and shared rather than spelled twice", and round `202607192610` asked for exactly that. What landed shares the stride only. The slice start `(c * per).min(total)` is written in `accum_slice` in `scheduler/worker.rs` and again in the merge in `resource/bindings/per_core.rs`.

The merge lives in the bindings module and the worker in the scheduler, and the scheduler already depends on the bindings, never the other way. So the one definition goes where both can reach it without turning that around: `accum_slice` moves into `resource/bindings/per_core.rs`, beside `region_start`, which is the other half of where a core's region sits. The worker imports it. The merge calls it. `PerCoreCounts` then has no use for a stride of its own, so `per` leaves the struct and `accum_per` becomes private to the module, since `run_parallel` computed it only to pass it in.

## Two tests that cannot fail

`column_free_sees_the_alignment_its_reserve_used` in the engine's `tests/resource_bindings.rs` calls `allocate` and `deallocate` on the test provider itself with 64 and asserts the provider saw 64. No code of the engine or of the store runs between the two. It came over verbatim from the recovery branch, and the changelist of round `202611131112` claimed it checks that the alignment a column was reserved with reaches its free. It does not.

The property is real and has two sites in `hilavitkutin-providers/src/storage.rs`: the free in `Drop`, and the free of the old block when an id is reserved a second time. The replacement drops a scheduler built on the counting provider and reads the alignment its column was freed with, and a second test reserves one id twice on a store and reads the alignment the first block was freed with. Both are shown failing against a store that frees with another alignment before they count.

`the_out_of_range_shape_still_satisfies_every_width_law` in `hilavitkutin-sym/src/shape_tests.rs` adds four literals declared eleven lines above it and compares the sum to 32. Its twin `the_collapsing_shape_still_satisfies_every_width_law` does the same for the other fixture, so the class is two tests. Neither calls the width laws it names, which are closures inside three other tests and so cannot be called from anywhere.

What the two tests are for is worth keeping: each fixture is built to be wrong in one way only, and the rejection test beside it means something only if the fixture is sound in every other way. So the three width laws become verdict functions, the way the origin laws in the same file already are, the shipped-shape tests assert them, and the two fixture tests call the same functions. The third law compares a shape's declared widths with the widths its layout has, which a fixture's own literals do not decide, so the fixture tests can now fail.

## A test that passes when two fibers trade windows

`tests/a4_parallel_fiber_windows.rs` sorts the two observed morsel counts and the two expected ones before comparing. If the narrow fiber were walked by the wide fiber's window and the reverse, the sorted pairs still match. That is the defect class `a1_fiber_morsel_size.rs` catalogues for the single-core path.

The fixture knows which unit writes which column, and the test already reads each column through a known binding position. A 4-byte column windows wider than an 8-byte one under the same budget, so the narrow unit's count is `ceil(records / max(w0, w1))` and the wide unit's is `ceil(records / min(w0, w1))`. The test asserts each by name. Its header also still speaks of taking "the ordinary trunk-rank branch rather than the head+tail one"; there is no such second branch since the N-way split was deleted, and the header says so.

## Two smaller things

`Generator::single` lost the `const` that `Generator::new` had on `dev`. It builds as a `const fn`, so it is one again.

The engine design's paragraph on single-trunk phases tells what an earlier engine did and what the paragraph used to say. A design template says what the design is. The two sentences go; what is built and what is not stays.
