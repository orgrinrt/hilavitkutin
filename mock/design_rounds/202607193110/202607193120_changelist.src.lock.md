# Src changelist: remove the install, keep the signature, catalogue the case

## CHANGE: `replace_value` DROPS the install

File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`

The `Selector`-resolved pointer write goes, along with the `Selector` import and the
`Bindings: Selector<V, Index>` bound that only the write needed. The body returns to marking the
store dirty.

The doc comment states what is missing and why, so the function is honest about doing nothing rather
than silently doing the wrong thing: the install is a member-by-member copy per
`202606210600`, the per-leaf column slots do not exist yet, and the work is behind the unified
columnar storage item.

Verification: `! grep -q "Selector::<V, Index>::get" mock/crates/hilavitkutin/src/scheduler/mod.rs`
and `cargo check -p hilavitkutin` clean.

## NOT CHANGED: the signature

`replace_value<V: Replaceable, Index>(&mut self, new: V)` stays. The previous signature had `T`
unifying to `Resource<Ra>`, a `PhantomData` marker carrying no value, so it could not express an
install under **any** mechanism, member-by-member included. The value-typed parameter is correct for
the decomposed install too, since the leaves are decomposed from the value.

Reverting it would re-introduce a signature that cannot be implemented, which is a different defect
from the one being corrected.

## CHANGE: the install test BECOMES a catalogued red

File: `mock/crates/hilavitkutin/tests/resource_bindings.rs`

`replace_value_installs_into_the_data_plane` asserts the right thing: the new value reaches the data
plane. That assertion is what the member-by-member install must satisfy, so the case is kept, marked
`#[ignore = "catalogue: ..."]` naming the storage-model dependency.

Leaving it green would leave a test certifying an install that is not the designed one. Deleting it
would lose a case that is already written and already correct.

Verification: the default run reports it ignored; `-- --ignored` lists it.

## Expected test movement

`resource_bindings` goes from eight passing to seven passing and one ignored. Workspace ignored count
rises by one. No failures.

## Not in scope

`replace_resource` (#696). The decomposed drain (#654), which is what unblocks the catalogued case.
