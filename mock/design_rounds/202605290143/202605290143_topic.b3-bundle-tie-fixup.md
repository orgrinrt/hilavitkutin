# Topic — B3 review fixup: tie the Context bundle types to the access sets

**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** close the PR #93 soundness finding by tying `EngineCtx`'s projected bundle types to its `Read` / `Write` access sets in the type system, so the bundle-exhausted `unreachable!` is genuinely unreachable rather than reachable from a compiling program.

The PR #93 (per-WU Context) review found one hard gate. `EngineCtx<'frame, R, W, RBundle, WCols>` leaves `RBundle` / `WCols` as unconstrained free type parameters, and exposes a `pub fn new` that takes pre-built bundles. The `*Api` accessor impls only bound `RBundle: ResourceBundle`, with no tie that `RBundle` is the projection of `R`. So `resource::<T>()` proves `R: Contains<Resource<T>>` but resolves through `RBundle` by type-equality, which is unrelated to `R`. A caller can construct `EngineCtx::<ReadU32, Empty, PtrNil, _>::new(...)`, satisfy the `Contains` bound, and hit the `unreachable!` at runtime. The physical-projection invariant the round claims is enforced by construction discipline, not by the type system. That is a latent panic on the public surface and contradicts the round's stated soundness property.

The fix harnesses the type system (per the workspace rule and op's directive): the only public way to build an `EngineCtx` projects the bundle from a source whose `Project` bound is on the access set, so the bundle type is forced to be `<Source as Project<R, _>>::Out`. A bundle unrelated to `R` then cannot be supplied, `R: Contains<Resource<T>>` genuinely guarantees a matching node in the projected bundle, and the `unreachable!` is type-guaranteed dead. A compile-fail check replaces the commented-out negative demonstration.

## Current state

- `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`: `EngineCtx<'frame, R, W, RBundle, WCols>` with a `pub` bundle-taking constructor and free, untied bundle params; `ResourceBundle for PtrNil::fetch` (and the column analogue) end in `unreachable!`.
- `mock/crates/hilavitkutin/tests/engine_ctx.rs`: constructs the Context by hand; the negative case is a commented-out non-wired demonstration about the `Contains` bound, not the bundle invariant.

## Changes proposed

1. Make the bundle-taking constructor private (`pub(crate)` or an internal `from_projected`); the only public constructor projects from a source via the `Project` bound, so `RBundle` / `WCols` are forced to be the projection outputs of `R` / `W`. A mismatched or insufficient source for a non-empty access set fails to compile.
2. With the tie in place, the `unreachable!` arms are genuinely unreachable; keep them with a corrected comment (the bundle is the projection of the access set, so a `Contains`-proven type is always present) or fold the base case so it cannot be reached.
3. Update the tests to construct via the projecting constructor. Add a `compile_fail` check proving a mismatched bundle (the reviewer's `EngineCtx::<ReadU32, Empty, PtrNil, _>` shape, or an empty source projected against a non-empty access set) is rejected at compile time.

Outcome: the per-WU projection invariant is type-enforced; no reachable `unreachable!`; the negative case is a real compile-fail. The specialization-based accessor lookup (verified sound by the review) is unchanged.
