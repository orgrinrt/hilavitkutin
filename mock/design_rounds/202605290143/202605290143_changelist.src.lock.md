# Source changelist — B3 bundle-tie fixup

Round: 202605290143. Phase: IMPL. Closes the PR #93 review hard gate: tie `EngineCtx`'s projected bundle types to its access sets so the bundle-exhausted `unreachable!` is genuinely unreachable, not reachable from a compiling program.

## CHANGE: `EngineCtx` construction tied to the access-set projection
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`
The bundle-taking constructor that accepts arbitrary pre-built `RBundle` / `WCols` becomes private (`pub(crate)` or an internal `from_projected`). The only public constructor projects the bundle from a source via the `Project` bound, forcing `RBundle = <Source as Project<R, _>>::Out` (and the column analogue for `W`). A bundle unrelated to `R`, or an insufficient source for a non-empty access set, then cannot be supplied to build an `EngineCtx`, so `R: Contains<Resource<T>>` genuinely guarantees a matching node in the projected bundle and the `ResourceBundle for PtrNil` / `ColumnBundle for ColPtrNil` `unreachable!` arms are type-guaranteed dead (correct their comments to state the now-true invariant).
Verification: the reviewer's shape `EngineCtx::<ReadU32, Empty, PtrNil, _>::new(...)` (a mismatched/insufficient bundle for a non-empty Read set) no longer compiles; `cargo test -p hilavitkutin engine_ctx` still passes (tests construct via the projecting constructor with a hand-built arena).
