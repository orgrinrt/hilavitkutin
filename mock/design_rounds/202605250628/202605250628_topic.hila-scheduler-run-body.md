# Topic: Scheduler::run no-op body via Cfg::Out::default()

**Date:** 2026-05-25
**Phase:** TOPIC
**Scope:** hilavitkutin engine `scheduler/mod.rs::Scheduler::run`. THE umbrella surface.

## Current state

After PRs #80 (assign_cores), #81 (select_approach), and #82 (codegen_fiber + codegen_core), `Scheduler::run` at `scheduler/mod.rs:140` is the last remaining engine surface that panics. Body is `unimplemented!("Scheduler::run body lands at Pass 7 + Pass 8 wiring of runtime megaround 202605101036")`.

The function returns `Cfg::Out`, a generic associated type. The only consumer-defined RunCfg impl is `DefaultRunCfg` with `type Out = notko::Outcome<(), ()>`. The signature is unconstrained on `Cfg::Out: Default` so the body has no constructible return value without trait modification.

Notko PR #21 (just merged) adds `impl<T: Default, E> Default for Outcome<T, E>`. This makes `Outcome<(), ()>` Default-constructible as `Ok(())`. With that landed, hilavitkutin's `Scheduler::run` body can be `Cfg::Out::default()` once a `Cfg::Out: Default` bound is added on the Scheduler impl block.

## Why this slice

Replacing `unimplemented!()` with a no-op return value unblocks:
1. viola-cli runtime testing. Slice 8b.2 shipped `scheduler.run()` which currently panics; after this lands, it returns cleanly without panic.
2. Mockspace v2 `0.0.0-d01` release shippability. The engine's signature-stable surface combined with honest no-op runtime semantics is a defensible release point.
3. End-to-end runtime testing across the viola → hilavitkutin chain.

The real morsel-loop body (per Topic 6 axes + the runtime megaround design) remains deferred to the LLVM-driven follow-up alongside codegen_fiber/codegen_core real bodies. The no-op stub explicitly documents this transitional state.

Workspace inventory: the only source-level RunCfg impl is `DefaultRunCfg` (per `hilavitkutin-api/src/run_cfg.rs:123`). Its `Out = Outcome<(), ()>` becomes Default once notko PR #21 lands. The documentation example in `hilavitkutin-api/DESIGN.md.tmpl:923` is illustrative, not a real consumer. So the constraint is effectively a no-op for current consumers.
