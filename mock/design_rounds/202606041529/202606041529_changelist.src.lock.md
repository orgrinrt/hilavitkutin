# Src changelist: accumulator append saturates at capacity

**Date:** 2026-06-04
**Phase:** SRC
**Round:** 202606041529 (accumulator-append-saturates-at-capacity, branch `feat/hilavitkutin-accumulator-columns`)

Brings the append in line with round 202606041800's Fork D: the live-length is checked against the reserved capacity, and an append past capacity is dropped (saturates) instead of writing out of bounds. The accumulator binding records its reserved capacity so the append accessor can check it.

TDD red-first: a saturation test appends more values than the reserved capacity; before the clamp lands the append writes past the buffer, after it the overflow appends are no-ops and the live-length stops at the capacity.

## CHANGE: `AccumBinding` records the reserved capacity
File: `mock/crates/hilavitkutin/src/resource/bindings.rs`
`AccumBinding<T, Tail>` gains `pub(crate) cap: USize` (the reserved record count) alongside `ptr` / `len` / `tail`, plus a `__cap()` hidden accessor. The `Sv<Accum<T>>` drain arm sets `cap` to the `record_count` it reserved to.
Verification: `grep "cap: USize" mock/crates/hilavitkutin/src/resource/bindings.rs` returns one match in the `AccumBinding` struct.

## CHANGE: `AccumColPtr` carries the capacity; append saturates
File: `mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs`
`AccumColPtr<'frame, T>` gains a `cap: USize` field; `AccumSelector::get` reads it from the `AccumBinding` (`__cap()`) and copies it through `AccPtrCons` projection. `ResolveAccumAppend::resolve_append` returns early when the live-length has reached `cap` (the append is dropped, the live-length stays at `cap`, no write past the buffer). `resolve_len` is unchanged. The `SAFETY` comment and the `AccumWriterApi::append` doc move from "the caller's contract keeps the live length within capacity" to "the append saturates at capacity".
Verification: `grep "live.0 >= " mock/crates/hilavitkutin/src/dispatch/engine_ctx.rs` returns one match in `resolve_append`.

## Tests

Extend `tests/accum_dispatch.rs` with a saturation case: a WorkUnit appends more values than the accumulator's reserved capacity; after `run()`, the live-length equals the capacity and the buffer holds exactly the first `capacity` values in append order (the overflow appends dropped, no out-of-bounds write). The existing in-capacity round-trip test is unchanged.

## Out of scope (unchanged from round 202606041800)

- The PassEnd persistence drain reading `[0, live_length)` (#344 / #134).
- A distinct per-accumulator capacity dimension (capacity equals `record_count` this round).
- A multi-core atomic live-length.
