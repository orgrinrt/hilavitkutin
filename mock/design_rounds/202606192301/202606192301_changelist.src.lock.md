## CHANGE: `Scheduler` gains field `phase_ema: [Cell<Nanos>; GATE2_MAX_UNITS]`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep "phase_ema: \[Cell<Nanos>; GATE2_MAX_UNITS\]" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match; the three constructor sites init it to `[const { Cell::new(Nanos::from_raw(0)) }; GATE2_MAX_UNITS]`.

Engine-internal per-phase duration EMA. Phases are bounded by units, so the
unit cap bounds it. Interior mutability via `Cell` (single-core dispatch is
`&self`); written only by the main thread in `dispatch_trunks` (workers never
call it), the same single-threaded-write discipline as the existing
`store_dirty: Cell`.

## CHANGE: `dispatch_trunks` folds per-phase duration into `phase_ema`
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs` (the per-phase dispatch loop)
Verification: `grep -n "phase_ema\[p\]" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns at least one match.

Around each phase's `dispatch` call, sample `self.clock.now_ns()` before and
after, fold the raw-nanos delta into `phase_ema[p]` with `fold_ema(prev, dur,
seed)` where `seed = Bool(self.first_frame.load(Relaxed))` (frame 1 stores the
raw duration, later frames fold at 1/8). Bounds-guarded by `phase_ema.len()`.

## CHANGE: add white-box `Scheduler::__phase_ema` accessor
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Verification: `grep -n "pub fn __phase_ema" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns one match.

Reads `phase_ema[p]`. Per-phase EMA is engine-internal (feeds the eventual
`select_adapt_config`), with no `OnMeta` consumer read, so the white-box accessor
lets a test assert the recorded per-phase durations.

## NEW TEST: `tests/r7_phase_ema.rs`
File: `mock/crates/hilavitkutin/tests/r7_phase_ema.rs`
Verification: `cargo test -p hilavitkutin --test r7_phase_ema` builds and passes.

Edge-case catalogue:

- `multi_phase_records_per_phase_ema`: a multi-phase single-core `run` under a
  strictly-increasing counter clock; each phase's EMA is positive after one
  frame (every phase's before/after pair brackets a positive delta).
- `single_phase_only_slot_zero`: a single-phase carrier touches only
  `__phase_ema(0)`; a higher slot stays zero.
- `parallel_path_leaves_phase_ema_zero`: `run_parallel` does not call
  `dispatch_trunks`, so `phase_ema` stays zero there (the single-core invariant
  that the parallel path does not spuriously write it).
