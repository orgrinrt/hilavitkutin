## File: `mock/crates/hilavitkutin/DESIGN.md.tmpl`

After the `idle_ns` paragraph, add a short note on the per-phase duration EMA:

- It is ENGINE-INTERNAL (a `phase_ema` store on the scheduler, not a
  `SchedulerMetrics` field), because per-N EMA detail feeds the tuning logic
  (`select_adapt_config`) rather than being consumer-named through the meta
  bridge (`SchedulerMetrics` stays non-generic for `ctx.meta::<SchedulerMetrics>()`).
- It is sampled on the single-core dispatch path: the per-phase `dispatch` loop
  reads the clock before and after each phase and folds the delta with the same
  1/8 EMA the pass-duration fold uses (seed on the first frame).
- The parallel-path per-phase timing and the `select_adapt_config` consumption
  are follow-ups.

No new public backticked type name (`phase_ema` is a private engine field), so
the design-doc-source-mismatch lint is unaffected.
