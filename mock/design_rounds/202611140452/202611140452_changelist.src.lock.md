# src changelist

Round topic `202611140452_topic.run-parallel-skip-differential.md`; the doc changelist `202611140452_changelist.doc.lock.md` changes no design text. The flat topic `202607200100_topic.b1-cap-lifting-completion.md` needs nothing from this round, as the doc changelist says.

## Current state

`hilavitkutin/tests/incremental_skip.rs` holds its four units, their value types, the scheduler macro, the snapshot, the model and a seven-step history in one file, with the counters in a `thread_local` that a `run_parallel` worker never bumps. No test drives that history through `run_parallel`. Six value types carry `#[allow(dead_code)]`, since the snapshot read their records through a cast to the bare number.

## Changes proposed

### 1. The fixture is one module, `tests/skip_chain/`

`tests/skip_chain/mod.rs` holds the four units, their value types, the store and column helpers (`store`, `start`), the counters and `Serial`, and the macros that build the scheduler and reach its stores (`four_chain_scheduler!`, `set_inputs!`, `snapshot!`, `mark_every_store!`). `tests/skip_chain/history.rs` holds `Step`, `START`, `HISTORY`, `apply_step!`, `trace!`, `Seen`, `Trace`, `Difference`, `first_bytes_difference`, `first_ran_difference`, `bytes_of`, `model`, `model_trace` and `cone_trace`. Both files are under 500 lines.

The counters are a static array of atomics, so a worker thread bumps the one the test reads. `serial()` takes the fixture's lock and resets them, `Serial::counts` and `Serial::ran_since` are the only reads, and `four_chain_scheduler!` takes a `Serial` first, so building the four-unit scheduler needs the lock; `incremental_skip_runs_only_the_changed_cone`, which builds a three-unit one by hand, takes it too. Every test in the two binaries takes it. The snapshot reads each record through its value type and field, so no value type needs an `allow` attribute: the six go.

`InA` implements `Replaceable` and `InC` implements `PlanAffecting`, so the history reaches both swaps. `HISTORY` keeps the seven steps and gains a `replace_value` of `InA`, a clean frame, a `replace_resource` of `InC` and a clean frame. `cone_trace` is the skip rule's oracle for which units run in each frame (row `a_unit_whose_inputs_are_all_clean_skips_the_pass`, the spec `:1418-1424`), and `model_trace` the model's bytes after each frame. The comparisons return the first `Difference` and assert nothing.

### 2. `tests/incremental_skip.rs` runs on the fixture

Its four tests keep their assertions. The differential runs the extended history and also asserts the skipping run's executed units equal `cone_trace`, which `run` passes.

### 3. `tests/run_parallel_skip_differential.rs` drives the history through `run_parallel`

At 1, 2, 3, 4 and `MAX_CORES` workers, each through `FixedWorkers`, and reporting every count that fails rather than the first:

- `skipping_run_parallel_matches_every_store_dirty_at_every_worker_count`: the every-store-dirty run equals the model, and the skipping run's bytes equal it, at every frame. Green.
- `run_parallel_runs_only_the_changed_cone_at_every_worker_count`: the skipping run's executed units equal `cone_trace`. Red at every count on this tree (frame 1, the producer runs on a clean frame), committed ignored under the catalogue row of `run_parallel_dispatches_every_unit_each_pass_and_never_asks`.
- `skipping_run_parallel_diverges_when_a_mutated_store_is_not_marked`: the twin of `incremental_skip.rs`'s unmarked-change test. Red at every count, ignored under the same row.
- `the_comparison_reports_a_runner_that_altered_one_record`: the byte comparison run against a `run_parallel` whose `Column<Cd>` record 0 is altered after frame 3 reports exactly that record and frame. Green; it is the byte comparison's control while the workers skip nothing.

### 4. The catalogue row

`mock/catalogue.md` gains the row `run_parallel_dispatches_every_unit_each_pass_and_never_asks`, which the two ignores cite.

## Proving checks

`cargo test -p hilavitkutin --test incremental_skip --test run_parallel_skip_differential` passes, two ignored. With `--include-ignored` the two ignored tests fail at all five worker counts and the other six pass. `cargo mock --lint-only` passes, and clippy reports nothing in the three new or rewritten test files.
