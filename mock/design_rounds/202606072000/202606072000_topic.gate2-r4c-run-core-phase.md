# Topic: GATE-2 R4c round B1, extract run_core_phase primitive

**Date:** 2026-06-07
**Phase:** TOPIC
**Scope:** `hilavitkutin` engine, `scheduler/mod.rs`
**Source:** roadmap r2 + GATE-2 R4c; sketches 202606071600/1700/1930

## Current state

`Scheduler::run_parallel` (the R4b-inline form) runs the per-(core,phase) masked
dispatch as a single-threaded sweep: `for phase p { for core c { core_phase_mask;
morsel loop run_gated } }`, phase-outer so the waist barrier between phases is the
loop boundary. The per-(core,phase) walk (compute the mask, then the morsel loop)
is written inline in that double loop.

The threaded executor (round B2) needs each worker to run exactly that
per-(core,phase) walk for its own core, with `phase_barrier_arrive` between
phases. Today the walk lives inline in `run_parallel`, so a worker mainloop would
have to duplicate the mask + morsel logic.

## What changes

Extract the per-(core,phase) walk into a private method
`Scheduler::run_core_phase`: given the `phase` / `trunk` arrays, `n`, the core
index, the phase index, `ncores`, and the frame's `total` record count + morsel
size, it computes `core_phase_mask` and runs the morsel loop (or the single
empty-morsel walk for a record-less frame) via `wu_values.run_gated`. The
single-threaded `run_parallel` sweep calls it in the existing phase-outer,
core-inner loops. Behaviour is identical: this is a pure extraction, output
unchanged.

`run_core_phase` is the primitive the B2 worker mainloop will call per phase
(`for p in 0..nphases { run_core_phase(self_core, p, ...); phase_barrier_arrive }`),
so the threading round adds only the spawn + park + barrier wiring, not a copy of
the dispatch logic. Its bound is `WuVals: RunFiber<Bindings, Witnesses>` (the
carrier walk); the grouping witness `GW` stays on `run_parallel` (it fills the
`phase` / `trunk` arrays once, before the per-core walks).

## Test

This is a behaviour-preserving refactor; the existing `tests/gate2_run_parallel.rs`
(2 disjoint phase-0 producers + a phase-1 combiner, ncores=1 and ncores=2,
asserting the exact fan-in sums) is the equivalence guard. It must stay green
across the extraction, plus the full engine suite. No new fail-first test: the
extraction adds no new behaviour, and a refactor is guarded by the tests that
already pin the behaviour it preserves.

## Out of scope

The threaded `run_parallel<P: ThreadPoolApi>(self: Pin<&mut Self>, pool)` with
spawn-once workers, the `PoolFrame` + worker-ctx inline fields, the worker
mainloop, and `Scheduler::Drop` are round B2 (the proven Pin shape from sketch
202606071930). This round only factors the shared dispatch primitive.
