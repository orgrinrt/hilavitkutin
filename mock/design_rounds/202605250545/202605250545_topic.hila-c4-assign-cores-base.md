### Algorithm

The contract: `CoreAssignment<MAX_LANES>` has parallel arrays sized `MAX_LANES`, one slot per core. `trunk_index[i]` tells the executor which trunk core `i` owns. `NO_TRUNK` sentinel means "core has no trunk this run".

The execution model: assignment is pipeline-wide (not per-phase). Each phase reuses the same core-to-trunk mapping. The width of parallelism is bounded by the phase with the most trunks. Cores beyond that width stay `NO_TRUNK`.

Concrete steps:

1. Compute `max_trunks_needed = max over phases 0..phase_count of phase.trunk_count`.
2. Set `width = min(max_trunks_needed, core_count, MAX_LANES)`.
3. For `i in 0..width`: `trunk_index[i] = USize(i)`. The trunk addressed is the i-th trunk slot, which maps to whichever phase-local trunk i is the i-th column of in each phase.
4. Set `assigned_count = width`.
5. Leave `fiber_assignments[i]` at `FiberId::ZERO` (the existing default per `CoreAssignment::new()`); a follow-up slice wires real fiber assignment once `compute_execution_plan` populates per-fiber metadata that maps trunks to fibers.
6. Leave `morsel_size_multiplier[i]` at `USize(100)` (existing default = 1.0x); CoreClass-aware multiplier (200 for P, 100 for E) lands in the follow-up.

### Tests

Three tests cover the base behaviour:

1. Empty plan (`phase_count = 0`): returns `CoreAssignment::default()` with `assigned_count = 0`.
2. Single-phase, single-trunk plan, 4 cores: `trunk_index[0] = USize(0)`, slots 1..3 stay `NO_TRUNK`, `assigned_count = 1`.
3. Three-phase plan with `[2, 3, 1]` trunks per phase, 4 cores: `assigned_count = min(3, 4) = 3`; trunk_index = [USize(0), USize(1), USize(2), NO_TRUNK].
