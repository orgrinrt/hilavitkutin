## CHANGE: a column found by type answers its bases to a host
Files: `mock/crates/hilavitkutin/src/dispatch/engine_ctx/lists.rs`, `mock/crates/hilavitkutin/tests/buffered_column.rs`.
`ColRef` gains `__read` and `__write`, the base reads see and the base writes land on, as `const fn` hidden from the documentation. `ColSelector::get` answered a `ColumnPtr` before round `202611130617-h6mb` and a `ColRef` with private fields since, so a host outside the engine could find a column by type and reach nothing of it.

The test `a_column_found_by_type_answers_the_bases_of_its_binding` runs under both buffer modes. It finds a buffered column and a plain column of one value type by type and holds the two accessors to `__frozen` and `__live` of the buffered binding and to the one base of the plain binding. It was shown failing under both modes with `__read` answering the write base, at the assert on the buffered column's frozen side.

## CHANGE: the bench crates take the revised contract
Files: `mock/benches/engine_vs_std/src/element_wise.rs`, `mock/benches/engine_vs_std/src/accumulator.rs`, `mock/benches/asm_gate_fixtures/src/lib.rs`, `mock/benches/frame_wide/support/frame-wide-support/src/engine.rs`, `mock/benches/single-trunk-convergence/support/src/engine.rs`.
The four units of `engine_vs_std::element_wise`, and the copy of them the gate fixtures carry, write `RecordOp` as one function from the read values to the written values. Their lists stay bare, since the fold of `run_fused` takes a unit over one bare read column and one bare write column and no other, and the four written value types gain `PartialEq`, which a value function's return for a bare column asks. The fused unit and the four `execute` bodies write by position, which stores and compares nothing, so the measured loop is still a read, the four stages and a store.

The topic first had these writes listed under `Written`. That does not build, as the fold refuses the wrapper, and the topic's appended section says so.

`frame_wide`'s `column_base` takes the read base of the column it found by type. The columns it reaches are plain. The marker for the supported host-side read and write of a column stays (ticket ef57305fb5f4).

Four calls of `append` sat in `unsafe` blocks that the safe `append` of the round before left with nothing to cover: one in `engine_vs_std::accumulator`, one in the gate fixtures, two in the support crate of `single-trunk-convergence`. The blocks are gone and each comment says what still holds. The two in `single-trunk-convergence` are not compiled, since that crate does not build on the trunk either (below).

Checked: `engine_vs_std` and `asm_gate_fixtures` build with their tests; the eleven crates of `frame_wide` build, the support crate's two tests pass, and `frame_wide`'s own tests run against the arms built in release.

No number of these benches was taken again. Their tracked results are of the contract before the revision.
