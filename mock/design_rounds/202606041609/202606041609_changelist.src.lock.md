# Src changelist: morsel-loop windowing (single-core, unit-outer)

**Date:** 2026-06-04
**Phase:** SRC
**Round:** 202606041609 (morsel-loop-windowing, branch `feat/hilavitkutin-morsel-loop`)

Windows `Scheduler::run`'s single full-range morsel into multiple morsels, unit-outer: each topological step dispatches its unit once per morsel of `RunCfg::MORSEL_SIZE` records (guarded to at least one), the unit completing its range before the next step. Correct for every plan (preserves the topological-order invariant); validates the morsel-relative read/write contract at `start > 0`.

TDD red-first: a position-agnostic self-transform WU over a record count spanning multiple morsels (a small `MORSEL_SIZE`) asserts every record across every morsel is visited exactly once with the right absolute index. With the pre-windowing single morsel, a `MORSEL_SIZE` below the record count is ignored, so `start > 0` morsels never run.

## CHANGE: add `RunCfg::MORSEL_SIZE`
File: `mock/crates/hilavitkutin-api/src/run_cfg.rs`
A new `RunCfg` associated const `MORSEL_SIZE: USize`, default `USize(256)` (a multiple of the 64-record `MICRO_MORSEL_INTERVAL`), documented as the single-core morsel window the run-loop windows the record range into, consumer-tunable per `arvo-toolbox-not-policer.md`, with the Phase C per-fiber `L1_usable / sum(write_sizes)` formula noted as its eventual superseder.
Verification: `grep "const MORSEL_SIZE" mock/crates/hilavitkutin-api/src/run_cfg.rs` returns one match.

## CHANGE: window `Scheduler::run` dispatch into morsels
File: `mock/crates/hilavitkutin/src/scheduler/mod.rs`
Replace the single `MorselRange::new(USize::ZERO, self.record_count)` + one `shim` call per step with a unit-outer / morsel-inner loop: for each topological step, walk `[0, record_count)` in strides of `msize = max(Cfg::MORSEL_SIZE, 1)`, dispatching the step's shim once per windowed `MorselRange::new(start, min(msize, record_count - start))`. The slot materialisation, the topological-order walk, and the shim signature are unchanged. The `max(_, 1)` guard prevents a zero `MORSEL_SIZE` from producing zero-length morsels that silently skip all work.
Verification: `grep "MORSEL_SIZE" mock/crates/hilavitkutin/src/scheduler/mod.rs` returns a match in `run`.

## Tests

New `tests/morsel_loop.rs`. `RunCfg` is sealed (its `sealed::Sealed` supertrait is private to the api crate), so a test cannot define a custom config; the test uses the default `MORSEL_SIZE` (256) via `DefaultRunCfg` and a record count above it to force multiple morsels.

A self-transform (read+increment) does not discriminate windowing: it yields the same per-record result whether the range is one morsel or many. The discriminating probe is a WU that writes the morsel-RELATIVE index it receives from `each`: `each(|i| write::<Tv, _>(i, Tv(i.0)))`. `write(i)` lands at the absolute index `morsel.start + i`, so under windowing `col[k] == k % MORSEL_SIZE` (each morsel restarts the relative index at zero), whereas the pre-windowing single morsel writes `col[k] == k`. The test registers one `Column<Tv>` and the probe WU (`Read` and `Write` both the column), builds with a record count of 600 (three morsels under the 256 default: `[0,256)`, `[256,512)`, `[512,600)`), pre-fills every record with a sentinel through the binding pointer, runs, and asserts `col[k] == k % MORSEL_SIZE` for every `k` in `[0, 600)`. This is red against the single full-range morsel (`col[256]` would be 256, not 0) and catches a skipped morsel (the sentinel survives), a wrong morsel boundary, or a miscomputed `start`. Existing tests keep record counts below 256, stay single-morsel, and are unaffected.
