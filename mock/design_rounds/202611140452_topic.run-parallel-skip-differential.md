# run-parallel-skip-differential

Job 1 of the engine-path plan (`mock/research/202611140100_engine-path-plan/PLAN.md`, "1. The differential, before anything it will judge"), tickets `run_parallel_skip_logic_has_no_differential` (triage 49) and the test half of `run_parallel_dispatches_every_unit_each_pass_and_never_asks` (triage 157). The brief is `briefs/job-hv-engine-path.md` on the kaski channel.

## Current state

`tests/incremental_skip.rs` drives a skipping scheduler and an every-store-dirty scheduler through a seven-step input history on `run` and asserts equal column bytes after every frame, with the every-store-dirty run checked against a model of the four units (`:481-519`), and a twin asserts the two runs differ when an input changes without a mark (`:532-549`). Nothing drives that history through `run_parallel`. The units count their executions in a `thread_local`, which a worker thread never sees, so the counts cannot be read under `run_parallel` at all.

The workers ask no dirty mask: the record-less dispatch passes an all-ones mask (`src/scheduler/worker.rs:307-328`) and the windowed walk the fiber's member mask alone (`:340-388`), so under `run_parallel` every unit runs every frame. While that holds, the bytes of a skipping `run_parallel` equal the every-store-dirty run's for a trivial reason, and the twin cannot fail: the unmarked change reaches both runs.

The history has no `replace_value` and no `replace_resource`, so the skip is never judged on the frame a swap marks, nor on the clean frame after it.

## What the round does

One fixture, shared. The four units, their value types, the scheduler macro, the snapshot, the model and the history move out of `tests/incremental_skip.rs` into a test module of their own, used by `incremental_skip.rs` and by a new `tests/run_parallel_skip_differential.rs`. The counters become atomics a worker can bump, read only through a guard that serialises the tests of one binary, so a count is never read without the lock that keeps another test's units out of it.

The history gains a `replace_value` of the producer's input, a clean frame, a `replace_resource` of the unrelated unit's input, and a clean frame. Each frame records the column bytes and the set of units that ran. The set is judged against the cone the skip rule gives for the step (the spec `:1418-1424`, row `a_unit_whose_inputs_are_all_clean_skips_the_pass`, ratified): the cold frame runs all four, a frame that marks the producer's input runs the producer and its two readers, one that marks the unrelated input runs the unrelated unit, a clean frame runs none. `run` is judged against that cone too.

The comparison is a function that returns the first difference rather than asserting, so a negative test can run it against a runner known to be wrong: a `run_parallel` whose columns are altered by one record after a frame, asserted reported. That is the byte comparison's control while the workers skip nothing, the way `a_wrong_runner_is_caught_on_the_authors` catches a wrong runner in `hilavitkutin-frozen-authors`.

Worker counts are 1, 2, 3, 4 and `MAX_CORES`, through `FixedWorkers`, never the host's count, since trunk ownership is round-robin (`dispatch/trunk_dispatch.rs:246-253`).

## What fails, and how it is kept

The executed-set comparison under `run_parallel` fails at every worker count on today's tree. It is committed ignored under a catalogue row of `run_parallel_dispatches_every_unit_each_pass_and_never_asks`, as is the twin under `run_parallel`, and job 5 un-ignores both. The byte comparison and its broken-runner control are green now.

No design text changes: the engine's design already says one frame body is held to the reference, and the test is that holding. No source under `src/` moves.
