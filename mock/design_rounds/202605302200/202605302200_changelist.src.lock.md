## Intent

Ship `ArenaColumnStorage<M, D>` in `hilavitkutin-providers`: the naive arena-backed `ColumnStorage` impl from round 202605302100's contract. A behavioral test (reserve, write, read back, count, slot isolation) drives it test-first over a bump-arena test `MemoryProvider`.

## Design notes

`D: Capacity` needs `arvo-tensor` (`Capacity` / `Dim` live there; the `arvo` facade does not re-export them), so the round adds that dependency. The test uses a bump-arena provider with a no-op `deallocate` rather than the engine's `StdMemoryProvider`: `StdMemoryProvider::deallocate` reconstructs the `Layout` with word alignment, so freeing a 64-byte-aligned block under `std::alloc` is a layout mismatch (UB). A bump arena (no per-block free) honors the 64-byte alignment on `allocate` and sidesteps the dealloc-align round-trip entirely, which is exactly the shape the production os-tier provider (`mmap` / `munmap`, no align on free) already has.
