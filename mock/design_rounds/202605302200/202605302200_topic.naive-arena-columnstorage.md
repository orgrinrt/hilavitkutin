# Topic: naive arena-backed ColumnStorage

Round 202605302100 (archived) landed the `ColumnStorage` and `Decompose` contract in `hilavitkutin-api`, trait-only. The arc's phase 2 is a naive arena-backed impl so functions and methods bound on `ColumnStorage` have a real backing to call against while the columnar engine matures. Correctness and the trait shape matter, not its performance; the columnar engine replaces it later without touching any `CS: ColumnStorage` consumer.

The impl lives in `hilavitkutin-providers`, the crate already reserved for default `ColumnStorage` / `Clock` / `Memory` providers (see the engine `DESIGN.md.tmpl` crate-layout note). The stack's dependency-injection pattern keeps the engine generic over `CS: ColumnStorage`; consumers wire in this default. Round 202605302100's api DESIGN already states the default ships here.

## Shape

`ArenaColumnStorage<M: MemoryProviderApi, D: Capacity = Dim<256>>`. A fixed slot table `D::Array<Maybe<ColumnSlot>>` indexed by `StoreId`, where `ColumnSlot` records the column's base pointer, byte length, and record count. `reserve<T>` allocates `count * size_of::<T>()` bytes 64-byte aligned through the bound `MemoryProvider`, recording the slot (a resizing re-reserve frees the prior block first). `column_ptr` / `column_ptr_mut` return the recorded base cast to the requested scalar type. `count` reads the slot. `release` is a no-op on the naive impl (the reader-count reclamation is a columnar-engine concern). `Drop` deallocates every live slot through the provider.

`D` caps the number of distinct columns. `Dim<256>` matches the engine's `Mask256` store ceiling; consumers needing more pick a wider `Dim<N>`.

## Test

A behavioral test with a `std::alloc`-backed test `MemoryProvider` (the integration-test crate can use std): reserve a column of N records, write through `column_ptr_mut`, read the same indices back through `column_ptr`, assert the round-trip and the `count`. A second column proves slot isolation. Drop runs clean (no leak under the test allocator's accounting where observable).

## Out of scope

The `Decompose`-driven multi-column reserve (folding an aggregate's leaves into per-leaf columns), the `evict` / `inject` persistence boundary, and the engine migrations (plan store-backing, resource arena, adapt, dispatch buffers) are later rounds and PRs on the arc.
