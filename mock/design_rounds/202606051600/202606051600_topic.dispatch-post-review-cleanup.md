# Topic: post-review cleanup for the fiber-structured dispatch

**Date:** 2026-06-05
**Scope:** hilavitkutin engine. Post-review fixes on the same branch as round 202606051500 (the per-fiber dispatch).
**Source:** the `pr-reviewer-senior` review of PR #129 raised two items.

## Changes proposed

1. Delete the now-dead `AccumFreeBindings` trait and its five impls (`resource/bindings.rs`). Round 202606051500 removed its only consumer (the whole-pipeline dispatch guard in `build` / `build_with`) when it replaced it with the per-fiber `morsel_local` bit, but left the declaration and its stale doc comment behind. Per `no-legacy-shims-pre-1.0`, the mechanism's removal deletes the declaration in the same arc.
2. Add a `debug_assert_eq!(fd, plan.fiber_count.0, ...)` after the fiber walk in `derive_phase_dispatch_order` (`scheduler/mod.rs`), matching the existing unit-count-completeness assert. The descriptor emit is gated on `fd < fd_cap` while the unit emit into `order` is not, so a (today unreachable) `fiber_count > fd_cap` would emit a unit's slot to `order` with no `FiberDispatch`, which `run` would silently skip. The invariant `fiber_count <= cap_size(D::Fibers::CAP)` holds for any valid plan, but the dedicated assert makes the truncation loud in debug/test like the unit path.

No behaviour change in release builds; the deletion removes dead code and the assert is debug-only.
