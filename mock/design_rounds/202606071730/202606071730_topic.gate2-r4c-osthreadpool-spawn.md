# Topic: GATE-2 R4c slice 1, real OsThreadPool::spawn

**Date:** 2026-06-07
**Phase:** TOPIC
**Scope:** `hilavitkutin` engine, `platform/os.rs` (os tier)
**Source:** roadmap r2 + GATE-2 R4c; sketches 202606071600, 202606071700

## Current state

The os platform tier (`platform/os.rs`) backs the `hilavitkutin_api::ThreadPoolApi`
contract with `OsMemoryProvider` (real, mmap) and `OsClock` (real, clock_gettime),
but `OsThreadPool` is a pre-implementation skeleton: `spawn<F>` is a no-op
(`let _ = _f;`, with a comment deferring "generic-closure dispatch" to sub-round
5a4) and `worker_count` returns a hardcoded `USize(1)`. The standalone `spawn_fn`
helper drives a bare `fn()` over a pthread trampoline, but the generic-closure
contract entry that the threaded executor will program against does nothing.

This is the first build slice of GATE-2 R4c (the threaded executor keystone). The
later slices (PoolFrame wake words, Scheduler-owned worker contexts, the
HybridExecutor parked mainloop, `run_parallel` rework, shutdown via the
exit-counter barrier) all depend on a real `spawn`.

## What changes

Implement `OsThreadPool::spawn<F: FnOnce() + Send + 'static>` with no allocation,
no `Box`, no `dyn`, on the os target (raw pthread). The mechanism is proven by
sketch `202606071700_gate2-threadpoolapi-contract`:

- The closure is copied by value into the pthread `*mut c_void` argument via
  `transmute_copy`, guarded by `const { assert!(size_of::<F>() <= size_of::<*mut
  c_void>() && align_of::<F>() <= align_of::<*mut c_void>()) }`. The engine's
  worker closure captures exactly one pointer (a Send-wrapped `*const WorkerCtx`),
  so it is pointer-sized and fits. A fatter closure is a compile error here, never
  a heap allocation. The original `F` is held in `ManuallyDrop` so its destructor
  does not run at the call site (the trampoline owns it).
- A monomorphic `tramp::<F>` reconstructs `F` from the argument and calls it once.
- The thread is spawned DETACHED (pthread attr `PTHREAD_CREATE_DETACHED`). The
  contract is fire-and-forget; shutdown ordering for the persistent pool comes from
  a worker-exit-counter barrier owned by the Scheduler (a later slice), not from
  `pthread_join`, so no thread id is retained.

Implement `OsThreadPool::worker_count` via `sysconf(_SC_NPROCESSORS_ONLN)`, with a
floor of `USize(1)` when the syscall returns a non-positive count.

The `std` platform tier stays a stub (op decision 2026-06-07: os and no_os are the
focus tiers, the std tier is deferred). `spawn_fn` may stay as the bare-`fn()`
convenience or be folded into `spawn`; this slice keeps it and adds the generic
`spawn`.

## Test

A fail-first engine integration test (`tests/`) builds under the default
`platform-os` feature, constructs `OsThreadPool`, spawns a pointer-sized closure
(an `Arc<AtomicBool>` clone, pointer-sized and Send) that flips the flag, and
spin-waits the flag, proving the closure actually ran on a worker thread. It also
asserts `worker_count() >= 1`. The test fails before the implementation (the
no-op spawn never flips the flag) and passes after.

## Out of scope

PoolFrame wake words, Scheduler-owned worker contexts, the HybridExecutor parked
mainloop, `run_parallel` rework, and the exit-counter shutdown barrier are later
R4c slices on this branch.
