# Doc changelist: hilavitkutin on arvo's current dev

**Date:** 2026-09-18
**Phase:** DOC
**Topic:** `202609181401_topic.hilavitkutin-on-arvo-dev.md`

The move onto `65c1634d` stays handed back; the topic carries the map for it and nothing here decides it. The three design conflicts the topic handed back are settled: op ruled the std tier and persistence on 2026-09-18, and the workspace rule forbidding `extern crate std` settles `hilavitkutin-build`. The design documents change to match, below.

## CHANGE: the platform tiers lose the std tier, and no tier spawns threads

Files: `mock/crates/hilavitkutin/DESIGN.md.tmpl` (module table, Platform implementations), `mock/DESIGN.md.tmpl` (module table), `mock/PRINCIPLES.md.tmpl` (no_std, no alloc), `mock/crates/hilavitkutin-api/DESIGN.md.tmpl` (platform defaults, what this crate does not contain).

Op, choosing "hilavitkutin ships only the executor contract (a trait). The OS-thread executor lives in the consumer, or in a crate outside the hilavitkutin* family, gated per target and feature.": "Consumer supplies it". The std fallback tier is gone, and the os tier no longer creates pthreads: it ships mmap for `MemoryProvider` and clock_gettime for `Clock`. `ThreadPoolApi` is the whole of the engine's side, and the design says the engine hands the executor one pointer-sized closure per worker, so an executor carries it without allocating.

## CHANGE: the threading backlog and the post-review notes

File: `mock/crates/hilavitkutin/BACKLOG.md.tmpl`

The Windows os-tier item drops CreateThread. The threading follow-ups drop OS-thread spawning behind a `threading-std` feature, and core pinning becomes a hint on the executor contract with the pinning itself the consumer executor's. The work-stealing item names the v2 method, `Executor::try_steal` behind a `work-stealing` feature, instead of the `steal_fallback` stub the src changelist deletes. The two post-review notes about `spawn_fn` and `OnceLock` in `std_tier.rs` go with the code they described.

## CHANGE: hilavitkutin-build takes values and returns text

Files: `mock/crates/hilavitkutin-build/DESIGN.md.tmpl` (entry point, part one of the configuration model, PGO staleness), `mock/crates/hilavitkutin-build/BACKLOG.md.tmpl` (consumer build.rs migration).

The crate is `no_std` and touches neither the environment nor the filesystem. The build script reads `PROFILE` and the `CARGO_CFG_*` values, and passes them in; the crate writes the directives and the config file text into a `core::fmt::Write` the script supplies. PGO's profile presence and HEAD's distance from the profiled commit are read by the script and passed in the same way. `configure().run()` keeps its builder shape and takes that input.

## CHANGE: persistence builds on str and api

File: `mock/agent/rules/cargo.md.tmpl` (per-crate dependency rules).

Op: "Builds on str and api". The rule said persistence and str do not depend on each other; it now says persistence builds on `hilavitkutin-str` and `hilavitkutin-api`, never on the engine or `hilavitkutin-ctx`, matching the persistence design and the corrected `forbidden-imports` line in `mock/mockspace.toml`.

## CHANGE: the identity spellings in the api design

File: `mock/crates/hilavitkutin-api/DESIGN.md.tmpl`

Three `USize::ZERO` and one `USize::ONE` name constants arvo at `1b2796e9` does not have. They read `<USize as Identity<Additive>>::IDENTITY` and `<USize as Identity<Multiplicative>>::IDENTITY`, the spelling the source already uses since the src changelist's identity migration.

## CHANGE: the foundations section of the cargo agent rule

File: `mock/agent/rules/cargo.md.tmpl`

The section shows every arvo dependency pinned by `branch = "dev"` over https. The workspace pins them by `rev =` over ssh since `48e6717`, at `1b2796e9`, the last arvo `dev` revision carrying the crates the design names. The section says so, and says why a branch pin is wrong here: arvo's `dev` no longer carries these crates at all, so a branch pin does not resolve.
