# Topic — B2a review fixups: remove the hollow retention test

**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** delete the hollow `builder_retains_registered_value` test surfaced by the PR #92 review; record the zero-sized-resource arena edge as a tracked follow-up (#622).

The PR #92 (resource arena, B2a) review found one hard gate: the `builder_retains_registered_value` test in `tests/resource_arena.rs` asserts nothing. It binds the staged carrier, notes that `StagedResource` has no `&self` getter, and ends with `let _ = carrier`, so it passes regardless of whether the value was retained or dropped. That is the hollow happy-path shape the all-green audit and the strict-by-design rule forbid.

The test is also redundant. `resource_arena_round_trip` proves retention end to end: it registers `Resource::new(99u32)`, builds the arena through a real `MemoryProvider`, dereferences the recorded `ResourcePtr<u32>`, and asserts the value is 99. If the builder did not retain the registered value, that read would fail. So the builder-level intermediate the hollow test gestured at is already covered by a stronger test, and deleting it loses no coverage.

The zero-sized-`T` arena edge (the review's second, minor finding) is recorded as task #622 and is not touched here; no zero-sized resource is registered today.

## Current state

- `mock/crates/hilavitkutin/tests/resource_arena.rs`: `builder_retains_registered_value` (the hollow test) plus the meaningful arena tests (`resource_arena_round_trip`, `resource_arena_drop_deallocates`, `resource_arena_multiple_resources`, `resource_arena_drop_runs_destructor`, allocation-count, allocation-failure). The `Ra` / `Rb` / `Rc` helper structs are used by `resource_arena_multiple_resources`.

## Changes proposed

Delete the `builder_retains_registered_value` test function. Keep the `Ra` / `Rb` / `Rc` helper structs (used by the multiple-resources test). No other change.
