This is the first landing of the job, item 5 of the brief, a defect fix that may land ahead of the rest. `MemoryArena`, the arena behind `default_interner`, appended every runtime string, so one string interned twice gave two handles, and `arena_resolve` read its entry table unchecked, which killed the expert seat's probe with SIGSEGV on the masked overflow sentinel (`mock/research/202611191955_consumer-surface-seat/`).

The first round put the interning law on the `ArenaInterner` contract and made `MemoryArena` keep it by a scan of its entries, comparing length before bytes. `arena_resolve` reads only ids below the live count. `MemoryArena::new` refuses at build an `ENTRIES` of 2^28 or more, since at exactly 2^28 the last slot's id would be 2^28 - 1, the id the sentinel takes once masked, and an overflow handle would resolve to a real string; the compile-fail fixture asks that boundary.

The second round corrects a claim the first wrote. The first review pass found that a `Str` carries no interner identity, so a handle carried to another arena with an id below that arena's count resolves to that arena's string, where the designs had said it resolves empty. The contract and the rustdoc now say the live count is what resolve guards, and that a handle is meaningful only to the interner that issued it, which the canon row on session-specific handles already holds.

The third round takes the empty string out of the contract. The second review pass found that naming `""` as what an unissued id resolves to says the overflow handle holds `""`, so `evict_str` stores that hash, where the persistence design asks for `Missing`; and that the ignored red asked a four-byte arena to resolve a handle to a string it cannot hold. The contract now says such an id reads nothing outside the arena and gives no string it holds, and leaves what it returns open until resolve can say it holds nothing. The red asks for `Maybe::Isnt`, a persistence red asks `evict_str` of the overflow handle for `Missing`, the green tests assert the overflow and past-count handles alias no held string, and the test that pinned a carried handle aliasing another arena's string is gone. The two places that answer `""` carry `FIXME` markers naming the ticket.

The fourth round answers the third and last review pass, which found the contract still claiming more than the arena keeps: `MemoryArena` answers an unissued id with `""`, and `""` is a held string once anything interns it, so "gives no string the arena holds" was false. The contract now promises only that no read leaves the arena's storage and says the answer may equal a held empty string; the green tests are named for the non-empty strings they check, and a red interns `""` through `ArenaInterner` and asks that the past-count id and the masked overflow id not alias it, under the ticket the `FIXME` markers name. Per the review limit there is no fourth pass.

## Left as follow-ups

`evict_str` turns an unresolvable runtime handle into the hash of `""` where the persistence canon says `Missing`, because `arena_resolve` returns `&str` and cannot say it holds nothing; ticket `evict_str_turns_an_unresolvable_runtime_str_into_the_hash_of`, to go with the visible refusal of `e08a7317ab9e`. That `2^28 - 1` entries still builds is not tested: a const arena that size is gigabytes for the compiler to evaluate. Commit `d96a2192` names `MemoryArena` in its subject without backticks; it is pushed history and stays. The compile-fail fixture was not shown passing against the old bound by a run; the old `<=` bound admits `1 << 28` by arithmetic. The bound itself hard-codes the 28-bit width and does not build on a 16-bit target (`hilavitkutin_memoryarena_entry_bound_hard_codes_the_28_bit_i`). `InternerApi::intern` mutates the `!Sync` arena behind a unit's read, a race under `run_parallel` (`hilavitkutin_internerapi_intern_mutates_a_sync_memoryarena_b`). Whether `""` takes the const or the arena path depends on the target, so `the_empty_string_interns_to_one_handle` asks the law of whichever it takes; in an arena that holds `""` the overflow handle's `""` answer aliases it, one more face of the same ticket.

From the third pass, not acted on: the `ENTRIES >= 2^28` refusal is asserted only on the const-item path; `let a: MemoryArena<0, {1 << 28}> = Default::default()` passes `cargo check` and is refused at `cargo build` (E0080), so the design's "fails the build" holds and the check-time hole is not written down.
