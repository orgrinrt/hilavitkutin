# Hilavitkutin engine dispatch: build plan and design synthesis

This memo is the self-standing entry point for the engine-dispatch implementation arc. It is written to survive a context compaction: a fresh agent should be able to read this file plus the cited sources and resume the work without the prior conversation. It synthesizes one context-gathering pass plus four domain-expert passes (execution model / plan chain, dispatch codegen / monomorphisation / LLVM, data plane / Context, concurrency / adapt), all run 2026-05-28 against current `dev`.

## 0. Why this arc exists and the governing directive

The whole stack's goal of "viola runs a lint over real source end to end" bottoms out at the hilavitkutin execution engine, whose `Scheduler::run` is a deliberate transitional no-op. Every downstream consumer (viola's lint pipeline, mockspace's ported cdylib lints, eventually clause) is dead code until the engine dispatches for real. The engine was deferred during earlier work as a "ship the schema ahead of the producer" shortcut. Op has now directed that we pay that down.

Op directive (verbatim, 2026-05-28): "no minimal-correct. Let's not defer any longer. Write real, shippable code, do real, extensive, sound, principled work on these fundamentals that we should've finished some time ago, but chose to take the shortcut. It'd always pay to just work things out, especially on the upstream fundamentals, as they come up, and do principled, disciplined work as planned, instead of 'minimal' or full deferral."

Consequences for this arc:

1. No minimal-correct skeleton. No deferral of facets. The full engine ships: real data plane, real Context, the full plan algorithm chain (with the arvo graph/spectral partitioning wired, not stubbed), the dispatch codegen including the hilavitkutin-build LLVM monomorphisation hooks, the pre-allocated thread pool with per-core dispatch and phase barriers, the adapt subsystem, resource resolution plus persistence drain, and meta-WorkUnit firing.
2. Dependency order still governs WHICH piece lands first (you cannot dispatch without storage), but it does not license dropping later pieces. Every piece gets done, principledly, in order.
3. General principle going forward: when an upstream fundamental surfaces, work it out fully and principledly as planned. The shortcut is the bug.

## 1. The single sentence

`Scheduler::run` (`mock/crates/hilavitkutin/src/scheduler/mod.rs:111,127-134`) returns `Cfg::Out::default()` and dispatches nothing. The doc there says the real morsel loop "waits on codegen_fiber and codegen_core producing monomorphised bodies, which themselves wait on hilavitkutin-build LLVM plugin hooks." Make the engine real, end to end.

## 3. Three corrections that change the plan

1. **The "arvo primitives not yet shipped" premise is STALE.** `steps.rs:24-28` and `mod.rs:180` claim RCM / block-diagonal / spectral depend on arvo primitives that have not landed. They have. arvo ships, complete and tested: `arvo_sparse::rcm_reorder` / `rcm_reorder_via` (`arvo-sparse/src/rcm.rs:35,188`, `tests/rcm.rs`), `arvo_sparse::block_diagonal` / `dulmage_mendelsohn` (`block.rs:28,97`, `dm.rs:61,104`), `arvo_spectral::fiedler_vector` / `spectral_bisection` / `k_way_partition` / `SparseLaplacian` (`fiedler.rs:52`, `partition.rs:42,80`, `operator.rs:77`), `arvo_graph::{topo_sort, waist_detect, upward_rank, components, longest_path}`. Completing the plan chain is a WIRING exercise plus a CSR representation bridge, not blocked on substrate.
2. **The LLVM passes are an OPTIMIZATION layer, not correctness-gating.** `invoke_wu_in_fiber` already calls `wu.execute(ctx)` in plain monomorphised Rust; "monomorphisation IS the dispatch" (arch rule). The hilavitkutin-build ExpandedLto (fat LTO + codegen-units=1) is what makes the monomorphised tuple dispatch devirtualise, but correctness does not depend on it. Under the no-deferral directive the LLVM layer is still IN scope for this arc; it lands after the correctness path exists so it can be benched. It is sequenced late, not dropped.
3. **The real foundational gate is the DATA PLANE plus concrete Context (#344 / C6).** Not viola-cli, not the LLVM passes. Build it first; everything else reads or writes it.

## 4. The dependency-ordered build spine (no deferrals; every phase ships)

Phase A. **Resolve #335 first (ResourceSnapshot semantics).** There are two conflicting "snapshot" concepts: the engine's placeholder `ResourceSnapshot<const N>` (`resource/snapshot.rs`) and the locked design's typed `ResourceSnapshot<'phase, R>` (see `mock/design_rounds/202605101036/202605101036_topic.resource-resolution.md`). Decide and unify before any data-plane code. Recommendation: delete the placeholder (no-legacy-shims pre-1.0), ship only the typed `'phase` read-only view; re-target or delete `ResourceCache`.

Phase B. **Data plane plus concrete Context (#344, the keystone).** Stop dropping the Resource value; introduce a `ResourceArena` backed by the consumer `MemoryProvider`. The builder stages `BuilderInput::Init` values into a fixed-capacity staging buffer at `.with`, then at `build()` walks the registered `Stores` cons-list, allocates the arena via `MemoryProvider::allocate`, moves each staged value in, and records distinct-provenance `ResourcePtr<T>` / `ColumnPtr<T>` (the provenance newtypes that help LLVM prove noalias). Construct the per-WU `Context` provider tuple from the arena scoped to the WU's Read/Write sets; concrete column reader/writer and resource provider structs back the `HasX` accessors over the buffers; `&self` accessors (interior mutability in the pointer math, not `&mut self`) so LLVM does not reorder writes across fused WUs. Wire morsel windowing: per-WU column impls carry the `MorselRange` (`dispatch/morsel.rs:31`) so `read(i)`/`write(i)` index `base + (morsel.start + i)`. Each step is independently testable (arena round-trips a value; Context resolves a resource; a column read returns what was written; the snapshot enforces the `'phase` bound). Store COUNT is const-generic (bounded by the registered cons-list LEN); record COUNT is the one runtime allocation dimension from `PlanInputs::record_count` (`plan/inputs.rs:31`).

Phase C. **Complete the plan algorithm chain (#339, wiring arvo).** (a) Replace the `UnitId` `transmute_copy` projections (`steps.rs:118,138,331`, the layout-coupling hazard, see risk R1) with a typed accessor / sealed bridge. (b) Wire real `arvo_graph::waist_detect` for concurrent-path-minimum waists (current code treats any out-degree-zero unit as a waist, over-segmenting, `steps.rs:194`). (c) Bridge `DependencyGraph<MAX_UNITS, MAX_EDGES>` (already CSR, `plan/graph.rs:53`) to arvo-sparse adjacency (impl the `BidirectionalSparseAdjacency` traits on `DependencyGraph`, avoiding a copy), then consume `rcm_reorder_via` output as the locality-optimal unit ordering fed into `group_fibers` (today RCM output `_reordered` at `mod.rs:259` is discarded; consuming it is the single highest-value wiring). (d) Trunk formation: `arvo_graph::components` for narrow phases, `arvo_spectral::spectral_bisection` / `k_way_partition` on the column-sharing graph Laplacian for wide phases (the ">5 fibers" threshold). Pin the Fiedler power-iteration count as a const (the spec pins 30) so partitioning stays deterministic. (e) Populate `Phase.trunks` with the nested `Trunk`-of-`TrunkComponent` structure plus `Branch`/`Bridge` at fan-out / fan-in points (the "assign branches and bridges" step the chain skips). (f) Fuse `classify_columns` before `size_morsels` and implement the real morsel formula `L1_usable / sum(write_sizes)` clamped and aligned (read-only columns ride the L2 prefetcher and do not consume budget); the current even-split ignores per-fiber column footprint. (g) Branch on phase node count (dense bitmask vs CSR-sparse vs spectral) rather than the single 64-store-capped code path.

Phase D. **Dispatch codegen (#340).** `run_fiber<S: FiberShape>` is the real emitter: each distinct `S` monomorphises one function whose body follows the rust-pipe pattern (cache resources to a stack-local array, read input columns at morsel start, run the WU sequence as a pure-locals pipeline calling `invoke_wu_in_fiber::<W>` per WU, group output stores at loop end). CRITICAL (risk R2): reconstruct a LOCAL `&[WuFn]` slice at the call site so LLVM proves its contents and devirtualises; NEVER call through the stored `FiberDispatch.body: Maybe<WuFn>` field, which is the bench-documented 12.6x devirtualization-failure pathology. The `body` field is a plan-time identity / introspection aid (for `clause explain --schedule`), not the hot-path call target. `codegen_core` emits one `#[inline(never)]` per-core function sequencing its fibers with morsel boundaries as compile-time constants and phase sync as stack `AtomicUsize` Release/Acquire. `ScheduleMega` vs `IndirectPerFiber` is which monomorphisation shape `codegen_core` instantiates (all-trunks-inlined under fat LTO vs per-fiber functions called through the local slice); `select_approach` chooses, eventually from a plan-shape summary not just `(record_count, fiber_count)`. The hilavitkutin-build hooks integrate by FLAG EMISSION, not pass injection into the runtime crate: ExpandedLto mandatory for dispatch-bench profiles; the custom `.so` LLVM passes cfg-gated so a missing/incompatible LLVM degrades to stock; PGO/BOLT opt-in refinement. Land an ASM-checklist CI gate on the emitted dispatch functions (zero `blr`, indexed addressing, no inner-loop `[sp]` loads, immediate morsel size) as the regression oracle before tuning thresholds.

Phase E. **Concurrency runtime, single-core-correct first, then parallel (#342, #336), then adapt (#341, #338).** First make `Scheduler::run` walk phases sequentially with real morsel loops and real `RecordRange`s (replace `RecordRange::Full` in `synthesise_core_programs` with computed half-open ranges from the morsel-size formula), no barriers, no parking; get the version-stamp / poison error model right here; this single-core path is the correctness oracle. Then add the spawn-once parking pool (workers spawn at `build()` through `ThreadPoolApi`, run a mainloop: wait on a per-worker `PoolFrame` generation atomic, on wake walk phases, arrive at `phase_barrier_arrive`, last arriver resets and `atomic_wake_all`, else `pick_tier(predicted_wait_ns)`, park on the generation atomic at frame end). CRITICAL barrier fix (risk R4): add a phase generation / sense bit; arrivers wait on `generation != my_generation`, not on the counter hitting zero, else a fast worker races the reset (`barrier.rs:62`). Fire the four meta-WorkUnits (`PlanStage` on `plan_dirty`, `ScheduleReady` after plan WUs, `PassStart` at frame top, `ScheduleEnd` after the last consumer phase). Validate parallel against the single-core oracle (same `Cfg::Out` for any core count). Adapt lands last: give each `AdaptAxis` an `observe` body folding `(ema*7 + measured) >> 3`, gated by `sample_skip`, comparing against thresholds to trigger morsel re-size / per-phase config re-select / full re-plan; all adapt decisions fire between frames at `ScheduleEnd`; add hysteresis (K-consecutive-sample crossing plus dead-band plus per-trigger cooldown, re-plans rate-limited hardest) to prevent oscillation (risk R5).

## 5. Per-facet design detail

### 5.1 Data plane plus Context (keystone; deepest detail warranted)

Pattern: archetype-free SoA / columnar ECS crossed with capability-scoped dependency injection. `Column<T>` is bit-packed column storage (`ColumnValue::BIT_WIDTH` specialisation, `column_value.rs:21-45`, sub-byte UFixed widths), closer to a vectorised analytical engine than a typical ECS. The `Context` is a GAT-parameterised provider tuple, the right scoped-DI shape: the `'frame` lifetime threads from `Scheduler<'frame>` so the Ctx carries `Pin<&'frame PoolFrame>` and `ResourceSnapshot<'frame, R>` without forcing every WU to thread a lifetime. Capability-based access: a WU can only touch what its AccessSet declares, checked at monomorphisation via `Contains`. The persistence drain has two distinct mechanisms (do not conflate, this is #335): (a) the in-frame `ResourceSnapshot<'phase, R>` read-only view captured at a phase barrier for AdaptWu at ScheduleEnd; (b) the cold-store drain where a PassEnd WU drains accumulator `Column<T>`s into hilavitkutin-persistence via a `PersistenceProvider` reached as a `Resource<P>` (the engine never depends on persistence types directly, preserving the standalone-crate import rule; `PersistenceContext` already bundles `&M: MemoryProviderApi` + `&StringInterner`). Sequencing within the keystone: (1) resolve #335, (2) ResourceArena + builder retention, (3) per-WU Context tuple construction scoped to Read/Write, (4) concrete accessor impls over buffers, (5) morsel windowing into `iter_morsel` (`dispatch/morsel.rs:86`), (6) persistence drain WU.

### 5.2 Plan algorithm chain

The phase/waist/trunk/fiber/morsel decomposition is textbook morsel-driven parallelism (Leis et al), with the deliberate and correct departure that assignment is plan-time deterministic (amortised over frames) rather than runtime work-stealing. The three graph tools are NOT interchangeable: RCM is for ORDERING (cache locality, co-accessed columns adjacent), spectral bisection is for CUTTING (balanced min-cut trunk formation), block-diagonal (Dulmage-Mendelsohn) is for VALIDATION (structural-rank feasibility of phase boundaries). Wiring real block-diagonalisation makes the currently-unreachable `PlanError::PhaseAlignmentMismatch` / `FeasibilityCheckFailed` paths (`steps.rs:557-563`) live, catching genuinely infeasible phase shapes. The RCM ordering must also flow into `unit_meta` so dispatch walks units in locality-optimal order, not raw topo order. (See Phase C for the step list.)

### 5.3 Dispatch codegen / monomorphisation / LLVM

The five approaches (`approach.rs`) map onto the T6 bench matrix in the consolidation spec: `IndirectPerFiber` = 1.17x, `TrunkMega` = 1.02x, `ScheduleMega` = 0.97x, and the "12.6x FAIL" is the struct-field-fn-pointer pattern (calling through `WuFn` stored in a field, which LLVM cannot devirtualise). That negative result justifies the whole shape. ExpandedLto (fat LTO + codegen-units=1) is required for cross-fiber/core devirtualization (ThinLTO's per-module summary is insufficient); confine codegen-units=1 to release/profiling profiles, keep dev/ci on Cranelift/thin-LTO so the inner loop stays fast. Per arvo-always-optimal-internals and arvo-compile-time-last: cfg-gate the structural lowering (correct without the custom passes, faster with them), bench-gate the approach/threshold choices against committed `benches/` artefacts. Manage code bloat by having approach selection cap fusion (large pipelines with many distinct fiber shapes fall back E -> D -> C to bound function-body size). (See Phase D.)

### 5.4 Concurrency runtime / adapt

Spawn-once-park-between-frames is the right model (bench: phased-pool holds 0.68x across 2K-1M records while spawn-based is 15.54x slower at 200 records). Three-tier wake (spin / spin-then-wait / wait) driven by a predicted wait time written by adapt is the predictive-parking design (<100ns spin, 100ns-10us backoff, >10us park; a wrong guess costs at most one park/unpark). Centralised sense-reversing barrier (Mellor-Crummey-Scott) is fine below ~32 cores; the doc already flags the tree-barrier upgrade trigger (`barrier.rs:9-12`). The self-hosting meta pipeline (the scheduler schedules itself via the four meta-WorkUnits; adapt is a WU firing `On<ScheduleEnd>`) is the JIT-tiering-controller-as-managed-code idea. Determinism holds only if adapt is deterministic: all re-decisions fire between frames, EMA folds are per-slot order-independent, a frame's execution is a pure function of the plan, re-plans are version-stamped events. (See Phase E.)

## 6. Risk register

- **R1 (highest correctness risk): `UnitId` `transmute_copy` layout coupling.** `steps.rs:118,138,331` transmute through `UnitId` assuming a `repr(transparent)` u32-width container ("Warm at 16 bits picks a u32 container", `graph.rs:118`). If arvo's strategy container selection changes the Warm/16-bit lowering, every transmute silently corrupts indices with no diagnostic. Fix: a typed `UnitId::index(&self) -> USize` accessor or a sealed bridge trait. Violates the harness-the-type-system rule. Fix this FIRST in Phase C.
- **R2: the WuFn-field-call devirtualization pathology (12.6x).** Never call through `FiberDispatch.body`; reconstruct a local `&[WuFn]` at the call site. The field is identity/introspection only.
- **R3: GAT/lifetime soundness plus read/write aliasing.** A WU must not stash a `&T` from `resource()` beyond `execute`; `'frame` invariant and phase-bounded. Plan-time DAG analysis is the precondition that two concurrently-scheduled WUs never write-overlap a column index; WU bodies do not re-check (the `unsafe read/write` obligation is the scheduler's). Validate with a trybuild negative fixture (#296).
- **R4: barrier reset-vs-next-phase race plus lost-wakeup.** Add a generation/sense bit; wait on the generation value last seen; the resetter changes it before waking; re-check after every (possibly spurious) wake.
- **R5: adapt oscillation.** EMA smoothing alone is insufficient; add hysteresis (K-consecutive crossing), a dead-band, and per-trigger cooldown; rate-limit re-plans hardest.
- **R6: false sharing.** Per-core column ranges and per-worker `PoolFrame` slots must be 64-byte aligned/padded; the centralised barrier counter is itself a ping-pong point at scale (tree-barrier trigger).
- **R7: const-capacity sizing.** `MAX_PLAN_AFFECTING_RESOURCES` is hardcoded 256 because rustc rejects field-access on generic constants (`mod.rs:64-72`, tracked #345). Keep the explicit default and lint-allow at the L0 root; do not block the data plane on the rustc capability.
- **R8: morsel sizing sequencing.** `size_morsels` must run after `classify_columns` (per-fiber column footprint), which is the reverse of the current order; fuse or reorder.

## 8. How to land it (workflow)

hilavitkutin uses the mockspace v1 design-round flow with ACTIVE hooks (phase derived from flat files in `mock/design_rounds/` root; see workspace rule `mockspace-workflow.md`). Each phase above is one or more design rounds on a feature branch off `dev`: topic -> doc CL -> `cargo mock lock` -> src CL -> edit source -> `cargo mock lock` -> `cargo mock close` -> PR `--base dev` -> pr-reviewer-senior (neutral) -> merge. Because this arc is large, expect multiple sequential rounds per phase on one branch (multi-round-per-branch is canonical). Land Phase A and B behind real unit tests (the data plane is unit-testable in isolation: arena round-trip, Context resolution, column read-after-write, snapshot `'phase` bound). Wire arvo via the existing `[workspace.dependencies]` (arvo is already a dep). The engine stays `#![no_std]`, no alloc, no dyn, no runtime spawn (pool spawns once at build); vocabulary canonical (record, not row/entity).
